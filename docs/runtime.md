# 运行时、上下文与模型执行

本文定义代理运行轮次、状态投影、请求环境、工具目录与执行授权、模型协议适配及原生正文工具的完整契约。会话树与节点存储语义见 [时间线](timeline.md)；前端会话 IPC 通道见 [技术架构](architecture.md#会话与前端能力接口)。

## 执行轮次与循环

执行轮次（turn，回合）由某代理的一条用户消息与其后、该代理下一条用户消息之前的相关助手产出组成。回合是 Agent 的对话投影，停止、取消、失败、达到预算或自然停止后的显式继续都不新增回合；本次执行收束表示暂时没有工作继续写入，不表示回合永久结束。

| 层级 | Agent 领域含义 |
| --- | --- |
| block | 思考、正文、工具调用等输出块，是组织与渲染单位；delta 只是增量展示，不构成执行轮次 |
| request | 一次实际模型请求，可产生多个 block；工具结果反馈进入后续请求 |
| turn | 用户与助手的一个回合，可包含多次 request 和多次执行启停 |

provider 的 `stop_reason=end_turn` 等终态只表示 request 的协议结局。通用 `models.run` 只执行一次模型请求及该响应的工具批次，显式接收投影输入，交付内含终态的块、诊断与临时进度，并在结果中返回本次请求的 [请求诊断](#请求诊断)，不自行保存对话或发起下一请求。多次请求的循环由内置 Agent 控制器推动：Agent 将成型输出经会话提交到时间线，随后重新投影下一次输入。公共会话 API 只提供记录与观察，消费者持 Agent 领域契约解释上述含义，不增加独立 turn 实体或生命周期钩子。

每次提交或显式继续启动的执行循环独立计算请求上限 `agent.maxTurns`（空值为 32，限制模型请求数，不计用户回合数）。Agent 循环不设整次执行超时，也不提供 `timeout` 配置；循环与工具等待可以长期静置。网络请求错误由传输与模型适配层反馈，Agent 不叠加整轮或用户等待期限。显式取消协作式中止，不承诺撤销副作用。内置代理在请求之间检查上下文预算并按需生成摘要，规则见 [上下文自动压缩](context-compression.md)。命名等一次性补全消费者直接使用 `models.stream`。

整个会话 settled（所有被捕获的资源都已收束）时才允许回溯会话游标，见 [会话树](timeline.md)。

## 执行状态投影

Agent 从当前时间线中属于自身的记录投影回合状态（`empty / completed / incomplete`），再结合宿主实时运行活动得到执行状态。状态属于 Agent 领域，不另行持久化，不建立独立 turn 实体。重开会话或移动执行游标后按同一规则重建；会话列表的瞬态资源状态推送不作为判断依据。

| 执行状态 | 依据 |
| --- | --- |
| 尚无输入（empty） | 当前路径没有本代理的用户消息，等待用户输入 |
| 执行中（running） | 本代理仍有运行活动，优先于历史投影中的完成状态 |
| 正常完成（completed） | 最近一条用户消息后的最新响应已保存从零到终态序号的全部块，块均完整、不含工具调用，统一结束原因为 `stop`，之后没有中断诊断；预期下一条是用户消息 |
| 执行未完成（incomplete） | 已有用户输入，但尚未满足正常完成条件，包括尚无输出、缺少终态、输出截断、不完整块、工具批次等待后续模型请求、失败、取消或请求次数达到上限 |

新用户输入开始新的判断范围；新响应取代前次响应的完成与中断状态。错误级诊断／通知和取消通知表示中断，缓存与上下文用量等非中断提示不改变完成状态。终态属于整个响应，不能把单个块的 `complete=true` 或原始 `end_turn` 单独当作完成依据；工具结果即使全部保存，仍需后续模型响应。

后台在会话视图读取时即时计算 `AgentView.turnState`，随视图交付；运行活动通过独立进度通道更新，消费者使用领域函数组合两者。模型上下文投影按协议策略过滤 `complete=false` 的块，状态投影仍读取其完整性与诊断。正常完成不永久关闭回合，输入区按此状态提供继续或停止入口，见 [代理卡片](workbench.md#代理卡片)。

与此同时，Agent 在受理执行时通过瞬态事件总线发布 `ResourceStatusChanged`（running / completed / failed / awaiting），供侧栏会话列表展示概要徽标；工具续轮属于同次执行，不单独发完成标记。瞬态事件机制见 [插件 SDK](plugin-sdk.md#瞬态事件与插件调用)，侧栏消费规则见 [工作台](workbench.md#会话列表状态与资源通知)。

## 代理控制器与请求环境

代理是一级对象，同时可作为资源。会话中可以有任意数量的代理，也可以一个都没有；代理之间不分主子（“子代理”是通过工具创建并消费的代理资源，只读代理不能通过创建可写代理扩大权限）。

每次模型请求开始时，代理控制器一起取得消息路径、当前配置与已链接资源，组装本次环境。模型请求及该响应的工具批次使用同一份环境；期间发生的配置和资源变化即时记录到会话树，留待下一次请求取用（下次模型投影把它们放到该响应与工具结果之后）。固定授权不等于固定资源内容，外部文件在执行期间仍可能被改变。

- **context 唯一真值在时间线**：Agent 可持有选择（agent 配置 ID、模型 ID、思考等级、修订号）、计数、取消与活动状态，但不保存另一份 context；消息投影只服务当次调用。
- **事件可见性**：会话树事件以 `model: string | null` 显式提供模型正文（null 时不进入模型上下文；非空时仅投影该正文，不发送事件类型或 data）。接收代理由事件载荷声明（如链接事件的 `agentId`）；未声明接收者时向所有代理投影。资源创建与移除事件的 `model` 为 null；链接与解绑通知只发给受影响的代理。外部文件变化不通知模型，由 `resource_inspect` 返回实时状态。
- **系统提示词即时构建**：系统提示词属于环境，不属于会话，每次请求按当前状态构建，不进入会话树：
  - `harness`：从模型视角说明可操作的已链接资源、工具使用方式、链接与解绑通知，以及环境变化后的处理方式；界面概念、内部授权检查与开发原则不作为模型指令。
  - `agent`：解析后的代理职责与工作要求。
  - `context`：已链接目录中的 `AGENTS.md`，每次构建时直接读取当前内容（不经过模型，不走 `resource_call`，不缓存）；目录断开即不再出现。
  - `skill`：技能路径与描述（待接入）。

系统指令由有序结构化提示块组装，统一渲染为 XML-like 分段（如 `<system from="core">...</system>`、`<agent role="worker">...</agent>`、`<context file=".../AGENTS.md">...</context>`）。标签是文本分段约定，不建立新的指令权限。

### 请求诊断

`models.run` 的结果携带 `diagnostics`：宿主在组装最终请求时取得的现场资料，用于事后还原该请求实际发出了什么，与 provider 回报的 `usage` 并列。它只描述结构与计量，不含提示正文、工具 schema 或消息内容，也不是可重放的原始请求。诊断按分区组织，每个分区独立可选，缺失表示未测量；以后需要从发送信息中取出的其他资料以新分区加入，不另设字段或记录。

| 分区 | 内容 |
| --- | --- |
| `system` | 最终系统提示的有序块：`kind`（`system / agent / context`）、来源（`system` 的 `from`、`agent` 的 `role`、`context` 的 `file`）与正文字数；包含宿主在请求时注入的上下文文件 |
| `tools` | 本次请求实际向协议声明的一级工具名称列表；模型不支持工具时为空列表 |

字数按 Unicode 码点计，是对发送文本的精确测量，不换算为 token。provider 的 `usage.input` 只回报输入总量，不能拆分到系统、工具或消息，诊断不推测这种拆分。请求在环境组装前失败（目标不可用、内容不可读等）时没有诊断。消费者自行决定是否保存；内置代理的保存方式见 [代理上下文](workbench.md#代理上下文)。

## 工具匹配与宿主操作入口

直接出现在 provider 协议 `tools` 中的工具称**顶层工具（一级工具）**，由宿主或插件模块提供，是 agent harness 的普通工具。顶层工具在装配时声明并注册，运行期间不动态增删，不随资源 attach/detach 改变。内置宿主入口包括：

- `resource_list` / `resource_inspect`：列出已链接资源，查看资源的实时状态与可用工具及 schema。
- `resource_call(resource_id, tool, target?, args)`：以工具操作已链接资源或其内部目标。省略 target 等价于 null，是否接受由实现声明。

插件顶层工具以一份声明定义名称、说明、参数、结果和 handler，注册后即可消费，不要求先导出共享工具定义、再为资源编写实现。handler 在调用时取得宿主绑定的运行上下文，包括当前执行对象、所属会话与调用生命周期；声明不捕获某次运行的对象。需要操作当前执行者的能力通过顶层工具的上下文取得自身对象，不通过资源自链接或资源工具的自身访问豁免实现。模块装配规则见 [插件 SDK](plugin-sdk.md#工具贡献)。

顶层工具的名称与稳定 ID 唯一，插件顶层工具之间或与宿主入口重名时使该插件装配失败，不覆盖现有入口。`agent.tools / excludeTools` 按名称筛选插件顶层工具和二级资源工具，在每次请求开始时固定；宿主 `resource_*` 入口不参与筛选。静态注册目录不随资源链接变化，筛选不授予关联对象的资源操作权限。

经 `resource_call` 使用的动态资源工具称**二级工具**。资源工具的可用性由链接、支持关系和外部策略共同决定；顶层工具不要求绑定一个目标资源。内置 `resource_list / resource_inspect / resource_call` 不参加资源工具的 `agent.tools / excludeTools` 列表。两类工具共用调用过程、结局与审计语义；内置入口的视图由 Atelier 提供，插件工具可提供自己的视图，`resource_call` 将摘要、正文和图标转交选定的二级工具，外壳只显示一层视图。

资源工具与资源独立定义：
- **工具契约（`ToolContract`）**：统一规定 `id`（稳定标识）、`name`（模型调用名）、`description`（能力与场景）、`guidelines`（选定后的使用规则）与 `args` schema。
- **工具实现**：声明支持的资源类型、`target` schema、`result` schema、读写副作用、并行/顺序策略与 handler，不重复或覆写工具的 description/guidelines。`target` 由实现直接解释（如目录 list 用 `null | {path}`，文件 read 用 `{path, offset?, limit?}`，笔记 read 用 `null`），不引入通用目标解析层。args、target、result 三个 schema 均须有非空整体 description。
- **契约共享与覆盖**：工具实现必须引用同一个实际声明对象（由公共模块加载保证）；同名异契约按插件装配顺序（`atelier.builtin` 最先，外部插件按用户列表）取最后定义者生效，被覆盖契约的实现下线。不同声明占用同一 ID 或同一资源类型与工具名存在多个当前实现时明确报错。
- **能力视图匹配**：每次请求先取得已链接资源，再由工具目录匹配支持关系，最后应用 `agent.tools / excludeTools` 等外部策略。链接通知、`resource_inspect` 和实际调用共用这份能力视图与 schema。入口指导要求直接传递符合 schema 的 JSON 值（对象与 null 保持原类型，不先编码成字符串）。

## 工具调用批次、结局与执行授权

模型响应正常结束 → 校验本次可用工具与参数 → 绑定调用上下文；资源操作另校验显式 `resource_id` 与本轮有效链接 → 执行 → 结局节点保存 → 整批收束 → 下一请求。输出截断、无终态流与不完整参数不启动工具。含顺序工具的批次按原顺序执行；并行完成顺序不影响模型输入顺序，投影按序号排列。

资源工具调度器在调用时验证：
1. agent 配置等外部工具策略是否允许二级工具。
2. 资源身份能否解析，资源当前是否链接到本代理。
3. 工具是否支持该资源，权限是否满足。
4. `args` 是否符合工具契约，`target` 是否符合实现契约与访问范围。
5. 对可变内容的写操作，依据的版本是否仍满足前置条件。

工具调用经历参数填充（`input`）、等待与执行（`execution`）及终结（`result`）：
- **参数填充预览**：填充期间宽容解析部分 JSON，仅供可选动态视图展示；预览身份取自请求固定的能力目录，不准备或执行工具，修复后的 JSON 不进入执行与历史。
- **过程产出发布**：执行器可通过 `publish(data)` 持续发布当前完整产出；过程态 `{kind: "running", data}` 与终结态共用实现的 result schema，校验通过后替换最近合法产出并经 `session.progress` 送达 UI，不写历史。无产出用 null 表示。
- **六种终结结局**：`succeeded`（已知成功）、`rejected`（策略/参数/授权拒绝）、`failed`（已知失败）、`cancelled`（已取消，含只读操作中止）、`partial`（部分结果）、`unknown`（写操作抛错或中止且无法确认影响，不宣称撤销副作用）。结局保存顶层工具声明或选定资源工具实现的稳定 ID、开始与结束时间、用户数据 `data` 及模型投影 `model`；操作目标资源时另保存当次资源身份/类型/名称，不将顶层工具的发起者伪装成目标资源。失败、取消、未知等省略 data 时保留最近合法产出，显式 null 清空；终结后忽略迟到 publish。
- **模型反馈投影（`toModel`）**：实现可提供 `toModel(data)`，只在终结时调用，返回字符串或 `ModelInputPart[]`（`text | file` 部件）；未声明时 data 以 JSON 文本作为一个文字部件（只序列化一次）。文件只随成功与部分成功交付，引用执行期 `object.content.stage` 暂存的不可变内容，结果记录与内容根在同一事务登记。非成功结局的模型投影为文字，包含结局、说明与有效产出。模型适配器只消费保存的 `model`，不发送 GUI 展示数据。
- **错误自愈反馈**：参数校验返回具体字段路径及原因；执行失败说明可区分的原因、稳定错误码与可执行的下一步。需要用户干预或写入影响未知时明确说明。

### 等待用户回答

内置插件提供顶层工具 `ask_user`，通过公共工具与 Agent 界面扩展能力完成问答。工具接收 `questions`，每题以本次调用内唯一的 `id` 关联答案，声明 `type: single / multiple / text`、完整 `question`、可选导航 `label` 与 Markdown 背景 `context`；`required` 默认为 true。选择题的 `options` 至少两项，含题内唯一 ID、标题与可选简述／Markdown 详情；可选推荐引用真实选项并提供理由，不生成默认答案。模型应合并相互独立的问题、通常提供少量明确选项，依赖先前答案的问题留待后续调用。

答案整组受理，成功前按原提问校验题目与选项身份、唯一性、题型及必填约束；无效提交不结束等待。返回的 `answers` 按原题顺序包含身份、题目、题型、`answered / skipped`、所选项的原 ID 与标题、用户自行填写的 `text`，整组补充为 `message`。单选的选项与自定义答案互斥，多选允许选项和自定义并存；自定义文字只有勾选该项才提交，勾选后不能为空。已回答的文本题必须提供文字且不能选择选项。必填题不可跳过；前端将留空的可选题转成明确的 `skipped` 后提交，后台不接受空数组冒充有效回答，也不将其理解为「都不要」。整组补充说明与选项共同构成用户意图，模型不得丢弃其中限制；跳过和取消均不构成同意。历史结果中的逐题 `comment` 继续解码与展示，新提交不提供该字段。

用户取消提问返回 `cancelled` 工具结局，不提交任何草稿，也不直接取消整个 Agent。工具过程态只发布等待实例身份供界面定位，取消时清空该过程数据；成功答案和终结结局由既有工具历史保存。旧版 `{ answer: string }` 结果继续可读，不改写原记录。交互规则见 [结构化问答](workbench.md#结构化问答)。

模型响应结束后，工具可以无限期等待用户回答；等待不保持 provider 请求，不发起模型轮询或续请求。运行时存活且交互未被明确结束时，待回答项持续有效，用户离开、机器休眠及前端卸载均不构成超时或回答。界面重挂载规则见 [Agent 扩展界面](workbench.md#agent-扩展界面)。

用户等待没有默认截止时间；工具外层任务计时和通信层超时不得因等待时长自动取消问答。答案读取与提交通信的生命周期和后台工具等待分开处理，通信失联不自动等同于用户取消。等待仍属于未收束的工具调用，沿用运行活动与会话回溯限制；回答后交付工具结果，整批收束后再发起下一模型请求。

软件退出或运行时终止可以结束未完成的工具调用；待回答项与等待 Promise 不要求跨运行时重启恢复。已提交的历史保留，不把未完成调用伪装成已回答或自动重放。

## 用户输入、文件与模型协议适配

### 用户输入与文件部件

用户输入先作为 `UserMessage` 写入时间线，再投影为模型输入。输入、context 与工具结果的模型投影统一使用有序 `parts`：

```ts
type ModelInputPart =
  | { kind: "text"; text: string }
  | { kind: "file"; file: ContentRef; mediaType: string; filename?: string };
```

纯文字也使用 `text` 部件；纯文件消息同样形成 message 节点，文件不必成为工作台对象。文件身份复用宿主 `ContentRef`（见 [不可变内容](content.md)），协议不接受路径、URL、base64 或字节本体。客户端只区分文字与文件，连同如实识别的 `mediaType` 发送，不建模输入模态、不按格式拦截；端点是否接受由服务端反馈。

请求在首次异步等待前固定引用与内容资格，独立占用持续到请求收束（`run` 包括工具批次）。单文件与整次请求的文件数量／体积限额定义于 `src/shared/model-media.ts`；超限明确拒绝，不自动降级、拆页或转码。

### 请求身份

请求身份与模型内容分开：`stream / validate` 可接收调用方声明的 `userAgent / sessionId`，`run` 接收 UA 并从已校验对象取得 Session ID。内置 Agent、标题命名和上下文压缩均传入 `Atelier/<应用版本>` 与所属会话；同会话重开、分支和工具续轮保持同一 ID。身份只用于最终 HTTP 边界的传输头，不写入模型消息、历史或授权。

`customUserAgent` 按「模型 > 提供商 > 调用方」覆盖 UA，未提供时保留 SDK 默认值；显式 `opencodeSession` 才发送 `x-opencode-session`（无会话的独立调用或连接测试生成临时 UUID；模型列表发现不发送会话头）。头值必须为非空可打印 ASCII 字符串。

### 三协议编码与跨模型续接

三协议使用 Vercel AI SDK：OpenAI Responses、OpenAI Chat Completions、Anthropic Messages。工具定义不提供 SDK `execute`；关闭隐式重试与流重试。带凭据的远程端点要求 HTTPS，无鉴权模式去除认证头，禁止自动重定向。每个 SDK 调用只进行一个模型步骤。Responses 固定 `store: false`。连接测试与真实执行共用 `src/model/request-options.ts` 解释请求选项。

每次请求从公共历史向目标模型做单次目标投影，不因 provider、协议、端点或模型变化而拒绝整段上下文：
- **原生资料作用域**：签名、密文等 `continuation` 仅在来源作用域（provider 身份、协议、端点、模型）与适配版本均一致时复用；跨来源只省略不适用的原生资料，切回原模型时原先的资料仍可复用。
- **工具调用 ID 配对**：外来工具调用 ID 不满足通用字符／长度范围或与已有身份冲突时，在本次请求内确定性转换，调用和结果成对使用；本来源原始 ID 优先保留。
- **文件部件编码**：Responses 与 Anthropic 使用 SDK 原生文件表达。Chat Completions 无法承载工具结果文件时，默认在准备阶段以 `tool_files_unsupported` 拒绝；仅当显式添加 `toolFilesAsUserMessage` 兼容包时，才将同批文件搬到紧随该批工具结果之后的一条 user 消息，并在 tool 结果中保留关联说明。
- **思考能力与续接编码**：模型声明 `reasoning: true` 时校验继承后的思考等级属于可用集合；`reasoning: false` 时当前请求省略思考选项及全部历史思考部件（不改写历史或展示）。思考续接属于协议基线：
  - **Responses**：原始流按 reasoning item 的 added/done 生命周期交付一个 thinking 块（`reasoning_text.delta` 进 `text`，`reasoning_summary_text.delta` 进 `summary`，密文在结束时交付）。输入有可复用密文时发送密文与独立摘要；否则将非空 `text` 编码为 `reasoning_text`、非空 `summary` 编码为 `summary_text`。
  - **Anthropic Messages**：流增量进 `text`，签名与遮蔽资料按白名单累积。输入有可复用签名时连同原始明文发送，有 `redactedData` 时发送遮蔽块；无签名明文直接编码为 `thinking`，不伪造签名；独立摘要无法表达时省略。
  - **Chat Completions**：尚无公共思考输入编码，省略历史思考。
  - Responses 与 Messages 的思考输入通过 SDK 公开语言模型中间件固定顺序，再在发送前核对序列化结果并补充思考部件；不匹配时明确失败，不猜测位置或提供通用 JSON patch。
- **兼容包消费**：本次请求的提供商与模型兼容配置按 id 合并（模型整项优先，规则见 [模型兼容包](model-configuration.md#模型兼容包)）。`systemMessageInMessages` 将 Responses 系统提示从顶层 `instructions` 改为首条 `system` 消息；`responsesReasoning` 控制明文 `content` 的 array/object 形状及是否省略 `encrypted_content` include 与 `reasoning.summary` 请求参数。

## 原生正文工具与目录操作

内置目录与笔记共享正文的 `read / edit / write` 工具契约，目录另提供 `list` 与图片查看 `see`（按文件头识别 PNG、JPEG、GIF、WebP 并输出文件部件）。

- **`read`**：`args` 只有 `anchored?`（默认 true，输出 `LINE#HASH│正文`，四位 Crockford Base32 短哈希；false 输出行号与正文）。文件的 `{path, offset?, limit?}` 属于 `target`，使用完整文件的绝对行号；笔记以 `null` 选择完整正文。文件单次读取返回最多指定行数与 64 KiB 完整行文本，`nextOffset` 指向首个未返回行；无法容纳的单行明确报错，不将截断内容标成可编辑行。
- **`edit`**：以 `{line, hash}` 引用当前正文；`replace / delete` 的 `anchor..end` 范围含端点（仅校验被引用的端点行），`insert_before / insert_after` 保留锚点行，`append / prepend` 无需锚点。整批基于同一份当前正文校验，任一锚点或重叠范围失败则整批拒绝不写入；位移扫描仅给出重试候选，不自动移动目标。成功结果的 `data` 保存实际 unified diff 与受影响行的新锚点；`toModel` 返回摘要、按预算截取的完整行 diff（最多 64 KiB）与新锚点（最多 40 行 / 16 KiB），省略时明确提示。
- **`write`**：直接创建或覆盖完整正文，不要求也不返回锚点；相同正文返回无变化。目录 `write` 可创建根内缺失的父目录。`toModel` 成功只返回简短确认与少量统计，不回传 diff、正文或锚点。
- **限额与原子替换**：文件文本操作限于 8 MiB UTF-8，笔记限于 100,000 UTF-16 code units；差异由 `diff`（jsdiff）按计算预算生成。文件修改按真实路径串行，读取用固定句柄，写入先暂存再复核根、父目录、目标身份及完整当前正文，最后原子替换（新建采用排他提交，防止覆盖并发创建的目标；无法确认最终提交时返回 `unknown`）。真实路径复核处理符号链接越界，但并非操作系统级沙箱。
- **笔记状态边界**：笔记保存只更新会话数据（`session_data`）中该对象的 `atelier.builtin/note.content` 并通知视图，不追加时间线事件或维护历史版本；回溯后的卡片与实时 inspect/read 均读取最新当前内容。GUI 的 120 行预览预算与 Pierre Diffs 代码着色见 [界面设计系统](design-system.md#对话过程视图)。
