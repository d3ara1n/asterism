# 运行时、上下文与授权

## 执行轮次

一个执行轮次指代理开始处理输入，经过零次或多次模型与工具调用，直到交还控制权、进入等待、完成或失败。

它不是一次模型 API 请求，也不一定与主代理的一条消息一一对应。

每轮 `turn_started` 固定：

- `rules_version`
- `binding_version`
- `tool_catalog_version`
- 输入与历史位置

本轮工具执行只认这次冻结的绑定与授权。固定授权不等于固定资源内容。外部文件在执行期间仍可能被其他进程改变。

## 对话记录与模型输入

transcript 以同级条目平铺记录用户的 `message` 与模型的 `thinking`、`toolcall`、`text`，并支持扩展类型；不存在包含后三类的模型消息父容器。工具结果与错误属于执行事实，通过调用身份关联。轮次、模型请求、工具批次和调用身份提供关联，不形成 UI 分组层级。

能力层负责组织规则、历史、资源事件、工具目录与结果，再由适配层生成目标协议要求的输入；transcript 不等于某次模型请求的原始消息数组。界面通过查询与订阅查看记录、状态和实际模型输入，通过操作接口提交意图，不以组件结构定义执行语义。详细字段、统一流事件、错误与恢复契约见 [模型接入计划](../plans/todo-2026-10-01-model-protocol-storage.md)。

## 工具调用批次

同一批次的工具调用共同收束后，才将该批次的结果统一交给模型并发起后续请求。批次内可以逐项记录与展示进度，但不能因某个工具先完成就提前让模型继续。

成功、失败与授权拒绝都要保留对应调用结果；等待批次收束不等于要求所有调用成功。取消或结果未知时，不伪造成功或自动重放副作用，是否继续由执行状态决定。批次身份关联平铺的 `toolcall` 条目和执行结果，不形成 transcript 父子容器。具体并发度、调用启动时机与取消策略由能力契约明确。

## 资源绑定变化

普通 attach/detach 记为 `binding_requested`，在执行轮次交界处记 `bindings_applied`。

1. 发起变化，追加 `binding_requested`。
2. 目标代理有在途轮次时，该请求为 pending，连线半透明；本轮仍使用 `turn_started` 冻结的 `binding_version`。
3. 目标代理空闲时，`binding_requested` 与 `bindings_applied` 同一次提交。
4. 在途轮次 `turn_ended` 之后，按请求顺序追加 `bindings_applied`，得到新的 `binding_version`。
5. 下一轮 `turn_started` 带上新版本；模型上下文看到已生效的变化事件，执行层按新授权校验。

一个代理的普通解绑不应被暗中解释为全任务权限撤销。全任务解绑需要追踪所有受影响的在途执行；其详细交互尚待确认。

立即停止或紧急撤销与普通 detach 是不同操作，不承诺任意正在运行的副作用可以撤销。

## 稳定工具目录

初版策略：在选定能力集合内保持工具定义稳定，可全量暴露，不随资源实例 attach/detach 增删 schema。

- 工具按类型共享，调用携带显式 resource_id。
- 目标不存在、已解绑或不支持该操作时，执行层返回结构化错误。
- 模型知道一种工具存在，不代表当前拥有可调用的目标资源。
- Workspace 的目录不构成默认文件工具授权。
- 新增能力实现、修改 schema 或改变工具目录属于工具目录版本变化，可以引起缓存失配。

原生调用优先考虑“操作名 + resource_id + 参数”。统一 resource_call 分发协议是备选方案，尚未采纳；不得仅为缓存而静默替换成任意参数的万能调用。

## 模型上下文

模型选择由提供商模型、模型角色、agent 配置和本次明确覆盖共同解析，约定见 [模型与代理配置](model-configuration.md)。模型角色的空值继承发起调用的对话；新对话缺少继承来源时要求明确选择。角色与配置只提供引用和默认值，执行记录保存实际解析结果及配置版本。

模型输入是任务历史和当前执行状态的投影，不是任务的唯一数据库。

基础规则保持稳定；资源附加、移除等变化作为有序事件放入 messages，不把动态资源列表反复写入顶层 system。

事件应足够让模型理解：目标是谁、何时生效、当前有哪些能力和约束。例如 detach 表达“今后不可访问”，不要求抹去之前的知识。

- 保留历史操作、工具结果与来源关系。
- 不通过删除旧消息来模拟 detach。
- 用户资源的正文是数据，不因加入资源就提升为高优先级系统指令。
- 工具调用与结果在 provider 投影中保持合法配对。
- 记录每次模型请求所依据的历史位置、规则版本、工具目录版本和资源绑定版本。
- 完整请求留存、敏感信息处理和保留期限需另行确定，不默认永久保存全部原始内容。

长上下文压缩必须保留可定位的摘要来源及当前有效绑定状态，不能把已解绑资源总结成仍可用。压缩改变前缀的成本与审计要求需在实现阶段验证。

## 执行授权

工具调度器在调用时按本轮的有效授权验证：

1. agent 配置的工具策略是否允许调用；委派还需检查目标 agent 是否被允许。
2. 资源身份能否解析。
3. 本轮是否具有相应绑定与权限。
4. 资源是否提供请求的操作。
5. 参数是否符合契约与访问范围。
6. 对可变内容执行写操作时，所依据版本是否仍满足前置条件。

目录工具需考虑路径穿越、绝对路径、符号链接以及检查与使用之间的竞争，不能只比较字符串前缀。

资源 ID 校验不构成任意宿主 shell 的沙箱。通用命令执行需要单独设计权限与隔离，初版验证闭环不依赖无限制 shell。

## 多代理

Task 可以同时拥有多个 LLM 对话和执行轮次。任务记录确定的事件顺序，每个执行记录自己实际消费的上下文位置，不能把任务中已产生的所有事件都说成代理已经看到。

子代理输出何时交给父代理，是一项显式事件。历史分支不得自动获得分叉后才到达的子代理结果。

主代理与子代理共用 agent 配置和授权检查。只读代理不能委派可写代理以扩大权限；本次模型覆盖仅改变模型选择，不改变工具、委派或资源授权。资源传递策略和多层委派的权限校验细节在运行时计划中收敛。

## 错误语义

资源不可用、授权不足、内容版本不匹配与工具内部失败应区分。代理可以等待用户、重新读取或改用其他资源，不因资源变化无限猜路径或重试。

缓存机制见 [MCP 延迟加载与缓存](mcp-caching.md)。
