# 运行时、上下文与授权

## 执行轮次

一个执行轮次指代理开始处理输入，经过零次或多次模型与工具调用，直到交还控制权、完成、失败或取消。它不是一次模型 API 请求。

每次模型请求开始时，代理控制器一起取得消息路径、当前配置与已链接资源，组装本次环境。模型请求及该响应的工具批次使用同一份环境；期间发生的配置和资源变化留待下一次请求取用，一个执行轮次内也可以生效。固定授权不等于固定资源内容，外部文件在执行期间仍可能被改变。

整个会话 settled（所有被捕获的资源都已收束）时才允许回溯会话游标，见 [会话树](timeline.md)。这包括代理的模型流与工具执行，也包括其他会向时间轴写入事件的资源活动；外部状态的持续运行不计入。正常事件追加仍推进游标，不触发回溯。

## 代理控制器

代理是一级对象，同时可作为资源。对话能力属于代理对象，而非软件或工作台本身：

- 控制器读取当前 agent 配置、模型选择与本代理已链接的资源，组装系统提示词与工具目录。
- 控制器从会话树按本代理的可见性投影上下文，驱动模型与工具循环。
- 控制器对资源的使用（例如读取已链接目录中的 AGENTS.md）不经过模型，也不走 `resource_call`。
- 代理产生的 message、thinking、text、toolcall 节点平铺在会话树上，按 `agent_id` 归属。

## 环境与系统提示词

系统提示词属于环境，不属于会话，每次请求即时构建，不进入会话树：

- harness：软件环境、工作机制与前置知识，例如资源链接通知的含义。
- agent：解析后的代理职责与工作要求。
- context：已链接目录中的 AGENTS.md，每次构建时读取当前内容；目录断开即不再出现。
- skill：技能路径与描述，随增删即时反映（待接入）。

用户修改提示词、AGENTS.md 或技能导致缓存失效，属于预期。回溯会改变链接状态，因此继续后系统提示词反映回溯位置的链接与当前文件内容。

系统指令由有序结构化提示块组装，统一渲染为 XML-like 分段，例如：

```xml
<system from="weft">环境描述与运行机制。</system>
<agent role="worker">代理职责。</agent>
<context file="…/AGENTS.md">…</context>
```

标签是文本分段约定，不建立新的指令权限。实现入口为 `src/model/system-prompt.ts`。

## 工具匹配与 Weft 操作入口

Weft 操作入口是软件提供的外围接口，仅在 provider 协议中表示为顶层 tools：

- `resource_list` / `resource_inspect`：列出已链接资源，查看资源的实时状态与可用工具及 schema。
- `resource_call(resource_id, tool, target?, args)`：以工具操作已链接资源或其内部目标。省略 target 等价于 null，是否接受由实现声明。

资源与工具独立定义：资源契约描述类型与状态；共享工具契约只规定工具名称与 args schema。后端的工具实现声明自己支持的资源类型、target schema、result schema、读写副作用和调度策略，并提供 handler。一个 read 契约可以对应笔记、目录等多个实现，不在公共 read 函数中集中判断资源类型。资源实例不保存工具列表或白名单。

target 是 `resource_call` 的定位参数，由选中的实现直接解释，不要求使用 path，也不引入通用目标解析层。笔记 read 接受 null；目录 read 接受 `{path}`，表示目录内的文件；游戏工具可接受 `{piece}`。args 始终遵循共享工具契约，target 与 result 随实现变化。注册器拒绝同名工具的 args 冲突，以及同一资源类型、工具名的多个当前实现。

每次请求先取得已链接资源，再由工具目录匹配支持关系，最后应用 agent.tools/excludeTools 等外部策略。支持关系回答“工具能否操作这个资源”，外部策略回答“当前代理是否被允许使用”；两者独立。链接通知、inspect 和实际调用共用这份能力视图及同一工具定义，避免维护另一份名称或 schema。

Weft 入口集合由软件维护，外部工具策略只检查 `resource_call` 内的工具名，不检查一级入口。插件可扩展资源和工具实现，不能注册或替换一级入口。实际工具不加入顶层 tools，attach/detach 不改变协议工具前缀；链接通知与 inspect 提供同一实现的 args、target、result schema。调用可靠性需实测，但不通过混合两个目录改变架构边界。创建资源的外围操作尚未开放，具体接口另行设计。

## 链接与授权

- 链接（attach/detach）是会话树上的 event 节点；手动链接与回溯恢复都由节点表达，执行层授权按当前路径折叠的链接状态判定。
- 链接通知投影给对应代理，告知授权结果，减少频繁查询；通知本身不构成授权。
- 未链接、只存在于工作台的资源对模型不可见。
- 请求期间发生的链接变化即时记录到会话树，不改变在途请求或该响应工具批次的环境；下次模型投影把它们放到该响应与工具结果之后，再采用新授权。事件的存储时序与消费者看到的顺序分别由会话树和投影负责。
- 外部变化（文件被删、内容改变）不通知模型，由 `resource_inspect` 返回实时状态。

## 工具调用批次

同一响应的工具调用共同收束后，才统一把结果交给模型发起下一次请求。工具声明并行或顺序，含顺序工具的批次按原顺序执行。输出截断、无终态流与不完整参数不启动工具。

工具结局为 succeeded / rejected / failed / cancelled / partial / unknown；工具一旦开始必有结局，用户打断记 cancelled，写操作抛错且无法判断影响时记 unknown。已选定实现的结局保存其 ID 与版本。成功或部分结果经该实现的 result schema 校验，保存 `data` 与当次模型投影 `model`；实现可提供 `toModel`，默认使用结构化结果。工具结果随 toolcall 节点内联保存，不另设产物实体。

前端按保存的实现 ID/版本选取结果组件，只消费当次保存的数据；不重新解析当前资源或执行工具。找不到对应版本或数据不合契约时显示原始数据。视图与执行代码在同一功能模块内维护，通过纯契约关联，见 [资源扩展契约](architecture.md#资源扩展契约)。

## 执行授权

调度器在调用时验证：

1. agent 配置等外部工具策略是否允许二级工具。
2. 资源身份能否解析，资源当前是否链接到本代理。
3. 工具是否支持该资源，权限是否满足。
4. args 是否符合工具契约，target 是否符合实现契约与访问范围。
5. 对可变内容的写操作，依据的版本是否仍满足前置条件。

目录工具需处理路径穿越、绝对路径、符号链接与检查/使用竞争。资源 ID 校验不构成宿主 shell 沙箱。

## 多代理

会话中可以有任意数量的代理，也可以一个都没有。代理之间不分主子：“子代理”是被另一个代理通过 `resource_create` 创建并消费的代理资源，由 skill 组合 `resource_create`、`send`、`wait`、`agent_read` 等代理间通信工具实现。只读代理不能通过创建可写代理扩大权限。通信工具的具体设计待定。

## 错误语义

资源不可用、授权不足、版本不匹配与工具内部失败分别返回。请求在产生任何块前失败时，代理发出错误级通知节点。

缓存机制见 [MCP 延迟加载与缓存](mcp-caching.md)。
