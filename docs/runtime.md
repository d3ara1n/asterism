# 运行时、上下文与授权

## 执行轮次

执行轮次（turn，回合）由某代理的一条用户消息与其后、该代理下一条用户消息之前的相关助手产出组成。回合是 Agent 的对话投影，停止、取消、失败、达到预算或自然停止后的显式继续都不新增回合；本次执行收束表示暂时没有工作继续写入，不表示回合永久结束。

| 层级 | Agent 领域含义 |
| --- | --- |
| block | 思考、正文、工具调用等输出块，是组织与渲染单位；delta 只是增量展示，不构成执行轮次 |
| request | 一次实际模型请求，可产生多个 block；工具结果反馈进入后续请求 |
| turn | 用户与助手的一个回合，可包含多次 request 和多次执行启停 |

provider 的 `stop_reason=end_turn` 等终态只表示 request 的协议结局。`models.run` 完成一次请求及其工具批次，Agent loop 决定是否继续下一请求。公共会话 API 只提供记录与观察，消费者持 Agent 领域契约解释上述含义，不增加独立 turn 实体或生命周期钩子。

每次模型请求开始时，代理控制器一起取得消息路径、当前配置与已链接资源，组装本次环境。模型请求及该响应的工具批次使用同一份环境；期间发生的配置和资源变化留待下一次请求取用，一个执行轮次内也可以生效。固定授权不等于固定资源内容，外部文件在执行期间仍可能被改变。

整个会话 settled（所有被捕获的资源都已收束）时才允许回溯会话游标，见 [会话树](timeline.md)。这包括代理的模型流与工具执行，也包括其他会向时间线写入事件的资源活动；外部状态的持续运行不计入。正常事件追加仍推进游标，不触发回溯。

用户输入中的文件以不可变内容引用进入时间线。每次请求按当次对象与消息路径固定内容资格和独立占用，事务外读取字节，再由适配器编码；涉及的内容不随当前数据替换或草稿关闭而提前回收。模型取消和输入草稿分别收束。能力、限额与失败规则见 [模型输入](conversation-core.md#用户输入与文件)；工具目录中的文件读取仍遵守资源授权，不因文件部件接通而隐式获得媒体产出能力。

## 代理控制器

代理是一级对象，同时可作为资源。对话能力属于代理对象，而非软件或工作台本身：

- 控制器读取当前 agent 配置、模型选择与本代理已链接的资源，组装系统提示词与工具目录。
- 控制器从当前时间线按本代理的可见性投影上下文，驱动模型与工具循环。
- 控制器对资源的使用（例如读取已链接目录中的 AGENTS.md）不经过模型，也不走 `resource_call`。
- 代理产生的 message、thinking、text、toolcall 节点平铺在会话树上，来源为该代理资源（`source.resource`）。

事件以 `model: string | null` 显式提供模型正文：为 null 时不进入模型上下文；非空时仅投影该正文，不直接发送事件类型或 data。接收代理由事件契约在载荷中声明（如链接事件的 `agentId`），不复用记录来源；未声明接收者时向所有代理投影，仍须满足 model 非空。资源创建与对象移除事件的 model 为 null；链接与解绑通知只发给受影响的代理。

## 环境与系统提示词

系统提示词属于环境，不属于会话，每次请求即时构建，不进入会话树：

- harness：从模型视角说明可操作的已链接资源、工具使用方式、链接与解绑通知，以及环境变化后的处理方式；界面概念、内部授权检查与开发原则不作为模型指令。
- agent：解析后的代理职责与工作要求。
- context：已链接目录中的 AGENTS.md，每次构建时读取当前内容；目录断开即不再出现。
- skill：技能路径与描述，随增删即时反映（待接入）。

用户修改提示词、AGENTS.md 或技能导致缓存失效，属于预期。回溯会改变链接状态，因此继续后系统提示词反映回溯位置的链接与当前文件内容。

系统指令由有序结构化提示块组装，统一渲染为 XML-like 分段，例如：

```xml
<system from="core">环境描述与运行机制。</system>
<agent role="worker">代理职责。</agent>
<context file="…/AGENTS.md">…</context>
```

标签是文本分段约定，不建立新的指令权限。实现入口为 `src/modules/agent/system-prompt.ts`。

## 工具匹配与 宿主操作入口

宿主操作入口是软件提供的外围接口，仅在 provider 协议中表示为顶层 tools：

- `resource_list` / `resource_inspect`：列出已链接资源，查看资源的实时状态与可用工具及 schema。
- `resource_call(resource_id, tool, target?, args)`：以工具操作已链接资源或其内部目标。省略 target 等价于 null，是否接受由实现声明。

上述三个固定入口称一级工具，是协议 `tools` 中的工具，代表 Atelier 与工作台的操作界面；经 `resource_call` 使用的动态资源工具称二级工具，是模型完成实际任务的主要工具。层级描述调用关系，不表示产品中的重要性；可管理、可扩展的核心工具目录属于资源工具。一级视图由 Atelier 内置，resource_list/inspect 显示资源列表与详情，resource_call 的视图适配将摘要、正文和图标转交选定的二级工具。外壳显示实际工具的一层视图，不嵌套展示外围调用。

资源与工具独立定义：资源契约描述类型与状态；工具契约统一规定 id、name、description、guidelines 与 args schema。id 是稳定标识，name 用于模型调用；description 说明能力和适用场景，guidelines 说明选定后的使用规则，参数 schema 说明字段语义，不另设 snippet。后端的工具实现声明自己支持的资源类型、target schema、result schema、读写副作用和调度策略，并提供 handler；实现不重复或覆写工具的 description/guidelines。同一工具可对应多个实现，用法与行为含义保持一致，资源实例不保存工具列表或白名单。

target 是 `resource_call` 的定位参数，由选中的实现直接解释，不要求使用 path，也不引入通用目标解析层。定位可包含资源内部对象与内容范围：目录 list 接受 null 或 `{path}`，文件 read 接受 `{path, offset?, limit?}`，笔记 read 接受 null，游戏工具可接受 `{piece}`。不要求所有文本资源都采用行定位。args 始终遵循共享工具契约，target 与 result 随实现变化。三种 schema 都须有整体 description，字段说明随 schema 提供；target/result 的描述由实现解释定位规则与返回含义。工具实现引用同一个实际声明对象，公共模块加载保证实例共享，不以相同 ID 合并独立副本；同名异契约先按插件装配顺序消解。注册器拒绝未消解的同名契约，以及同一资源类型、工具名的多个当前实现。不同声明占用同一 ID 明确报错，不同用法或行为应另定义工具。

入口指导与 schema 描述明确要求直接传递符合 schema 的 JSON 值：对象保持为对象，null 保持为 null，不先编码成字符串。一级入口提供通用传参规则，共享工具定义提供操作用法，资源实现通过 target/result schema 提供定位与结果说明。

一级入口与二级工具使用同一个 ToolContract、defineTool 和定义投影；层级由装配与执行位置决定。一级入口将 guidelines 合入协议工具的 description，二级工具在链接通知与 inspect 中提供结构化 description、guidelines 与 args schema，再附加实现的 target/result schema。模型适配器中的 ToolDeclaration 只是 provider 传输投影，不是另一份工具定义。插件可以声明工具或共享纯契约库，无需将工具加入 Atelier 的内置声明文件。

每次请求先取得已链接资源，再由工具目录匹配支持关系，最后应用 agent.tools/excludeTools 等外部策略。支持关系回答“工具能否操作这个资源”，外部策略回答“当前代理是否被允许使用”；两者独立。链接通知、inspect 和实际调用共用这份能力视图及同一工具定义，避免维护另一份名称或 schema。

宿主入口集合由软件维护，外部工具策略只检查 `resource_call` 内的工具名，不检查一级入口。插件可扩展资源和工具实现，不能注册或替换一级入口。实际工具不加入顶层 tools，attach/detach 不改变协议工具前缀；链接通知与 inspect 提供同一实现的 args、target、result schema。调用可靠性需实测，但不通过混合两个目录改变架构边界。创建资源的外围操作尚未开放，具体接口另行设计。

### 原生正文工具

笔记与目录内文件共用 read/edit/write 的操作契约。read 的 args 只有 `anchored?`，默认 true；当前两类实现采用 `LINE#HASH│正文`，false 返回行号与正文而不提供哈希。文件的 offset/limit 属于 target，使用完整文件的绝对行号；笔记以 null 选择完整当前正文。文件读取返回最多指定行数与 64 KiB 完整行文本，nextOffset 指向首个未返回行；无法容纳的一整行明确报错，不将截断内容标成可编辑行。

edit 以 `{line, hash}` 引用当前正文；replace/delete 的范围首尾含端点，只有被引用的端点接受哈希检查，未引用的内部行不具有独立变化保护。insert_before/after 保留引用行，append/prepend 无需锚点。整批基于同一份当前正文校验，任一锚点或范围失败都不写入。位移恢复仅提供重试候选，不自动移动目标。成功结果的 data 保存实际 unified diff 与受影响行的新锚点，保留原有换行及末尾换行状态；模型反馈包含成功摘要、diff 与新锚点，模型可据此继续编辑，未提供锚点的行按需重新 read。短哈希用于编辑校验，不构成版本身份或授权凭证。

write 直接创建或覆盖完整正文，不要求锚点，也不返回新锚点；相同正文成功返回无变化。目录 write 可创建根内缺失的父目录。文件操作限于 8 MiB UTF-8 文本，笔记限于 100,000 UTF-16 代码单元。差异由 diff 库生成，超出计算预算时在保存前拒绝；工具历史保存完整 diff。

内置 edit 的成功 `toModel` 返回摘要、最多 64 KiB 的按完整行截取的 diff，以及最多 40 行、16 KiB 的新锚点；省略时分别明确提示，完整 diff 留在结果记录中。模型可直接使用新锚点继续编辑。write 成功只返回一句确认，带路径、创建状态或增删数量等少量信息，不回传 diff、正文或锚点；无变化时简述未修改。失败保留具体原因、出错操作／锚点和修正提示。read/list 等取材工具仍返回模型完成工作所需的内容，按各工具自身的读取／输出契约处理，不套用用户正文预览的 120 行预算。GUI 的 diff、代码着色、行预算与原始详情属于用户展示，模型投影独立定义。

文件修改按真实路径串行，读取使用固定句柄，写入先暂存，再复核根、父目录、目标身份及完整当前正文，最后提交替换。创建新文件采用排他提交，防止覆盖期间由其他进程创建的目标；无法确认最终提交时返回 unknown。真实路径复核处理常规变化与符号链接越界，但并非操作系统级目录沙箱；外部进程仍可能在最后复核与文件系统提交之间改变路径或内容。

笔记保存只更新会话数据中该对象的当前正文并使视图失效，不追加正文事件、资源日志或历史版本，不移动会话游标。回溯后的笔记卡片与实时 inspect/read 都显示当前内容；代理工具结果保留当次数据，不重新读当前正文。

## 链接与授权

- 链接（attach/detach）是会话树上的 event 节点；手动链接与回溯恢复都由节点表达，执行层授权按当前路径折叠的链接状态判定。
- 链接通知投影给对应代理，告知授权结果，减少频繁查询；通知本身不构成授权。
- 未链接、只存在于工作台的资源对模型不可见。
- 请求期间发生的链接变化即时记录到会话树，不改变在途请求或该响应工具批次的环境；下次模型投影把它们放到该响应与工具结果之后，再采用新授权。事件的存储时序与消费者看到的顺序分别由会话树和投影负责。
- 外部变化（文件被删、内容改变）不通知模型，由 `resource_inspect` 返回实时状态。

## 工具调用批次

同一响应的工具调用共同收束后，才统一把结果交给模型发起下一次请求。工具声明并行或顺序，含顺序工具的批次按原顺序执行。输出截断、无终态流与不完整参数不启动工具。

工具调用经历参数填充、执行与终结；参数完整后等待批次调度不算已开始执行。填充期间宽容解析部分 JSON，仅供工具可选的动态视图展示；预览身份取自请求固定的能力目录，不准备或执行工具，修复后的参数不进入执行与历史。执行仍等待完整响应与正式参数校验。执行器可通过 `publish(data)` 持续发布当前产出；每次发布是完整快照，通过实现的 result schema 校验后替换最近的合法产出，经会话进度通道供界面使用。过程态与终结态共用一个 data 契约，不将所有字段变为可选；尚未确定的字段由工具显式声明。null 表示没有产出。

工具结局为 succeeded / rejected / failed / cancelled / partial / unknown。每种结局均保存 `data` 与当次模型投影 `model`；终结不等于成功。工具显式返回最终结局，失败等分支省略 data 时保留最近合法产出，显式 null 则清空。执行中的只读操作抛出中止记 cancelled；写操作抛错或中止且无法确认影响时记 unknown，不宣称撤销副作用。开始前取消没有开始时间；正常返回的已知结局不被晚到的取消信号覆盖。终结后忽略迟到 publish。

实现可提供 `toModel(data)`，只在终结时调用，返回字符串或 `text | file` 部件（与用户输入同一形状）；未声明时 data 以 JSON 文本交给模型，文字只序列化一次。文件只随成功与部分成功交付，引用执行期 `object.content.stage` 暂存的不可变内容：执行结束时暂存内容交接给本次请求的占用，结果记录与内容根在同一事务登记，未提交时随请求回收。非成功结局的模型投影为文字，包含结局、说明与有效产出。投影出错保留已知执行结局，向模型报告输出不可用，不绕过自定义投影发送原始数据。结局保存实际实现的 ID、当次资源的身份/类型/名称及开始/结束时间，随 toolcall 节点内联保存。中间更新不追加历史，不触发下一次模型请求；内存产出不承诺进程崩溃后的恢复。

前端按保存的实现 ID选取调用视图。headerRenderer 与 bodyRenderer 分别可选，消费同一份调用信息与结果，各自回退默认摘要或原始数据正文。历史只消费当次保存的数据与身份，不重新访问资源或执行工具。找不到实现或数据不能由当前 schema 解码时使用默认视图。视图与执行代码在同一功能模块内维护，通过纯契约关联，见 [资源扩展契约](architecture.md#资源扩展契约)。

## 执行授权

调度器在调用时验证：

1. agent 配置等外部工具策略是否允许二级工具。
2. 资源身份能否解析，资源当前是否链接到本代理。
3. 工具是否支持该资源，权限是否满足。
4. args 是否符合工具契约，target 是否符合实现契约与访问范围。
5. 对可变内容的写操作，依据的版本是否仍满足前置条件。

目录工具需处理路径穿越、绝对路径、符号链接与检查/使用竞争。资源 ID 校验不构成宿主 shell 沙箱。

## 多代理

会话中可以有任意数量的代理，也可以一个都没有。代理之间不分主子：“子代理”是被另一个代理通过 `resource_create` 创建并消费的代理资源，由 skill 组合 `resource_create`、`send`、`wait`、`agent_read` 等代理间通信工具实现。只读代理不能通过创建可写代理扩大权限。通信工具的具体设计待定。

## 错误语义

资源不可用、授权不足、版本不匹配与工具内部失败分别返回。请求在产生任何块前失败时，代理发出错误级通知节点。

工具错误是模型修正调用的反馈：参数校验返回具体字段及校验原因；执行失败说明可区分的原因、稳定错误码与可执行的下一步。需要用户干预或原因未知时明确说明，不承诺所有失败都能自动恢复。错误随工具结局持久化并交给模型，用户视图可独立渲染。新增或修改工具遵循[模块开发指南的调用说明与错误自愈准则](../src/modules/README.md#调用说明与错误自愈)。

缓存机制见 [MCP 延迟加载与缓存](mcp-caching.md)。
