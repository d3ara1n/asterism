# 公共 i18n 机制

本文规定宿主与插件的界面本地化契约。SDK、目录加载、语言设置与文案迁移已完成，自动检查通过，用户已确认 GUI 验收无问题；实施与验证记录见 [已归档 i18n 计划](../plans/archived/todo-2026-10-12-i18n.md)。插件装配和公共模块规则见 [插件 SDK](plugin-sdk.md)。

## 原则与选型

普通字符串始终是合法的界面文案，原样显示。插件可以只使用一种语言、没有翻译目录，也不初始化翻译引擎；本地化是可选增强。宿主与内置插件面向普通用户的文案提供英文、简体中文两套，外部插件不承担双语准入要求。

消息使用 FormatJS 支持的 ICU MessageFormat。宿主以 `@formatjs/intl` 提供非 React 格式化，React 接入使用 `react-intl`，语言匹配使用 `@formatjs/intl-localematcher`，抽取与语法检查复用 `@formatjs/cli` 和 FormatJS 的 ICU parser。SDK 负责纯数据声明、插件归属和宿主展示接口，不另造消息解析、复数规则、翻译编译器或通用依赖容器。

UI 语言不隐式改变模型工具名称与说明、模型提示词、运行时日志、用户正文、模型输出和已保存标题。界面的事件说明可以按当前语言显示，历史事实和原始记录不改写。需要生成指定语言报告等业务输出时，调用方显式提供输出语言。

## 消费者与本地化范围

本地化按内容服务的对象判定，唯一消费者是普通用户，尤其是不熟悉英语的用户。给普通用户看的操作与说明需要本地化；给开发者或模型看的内容不进入翻译目录。这个判定贯穿声明、插件贡献、错误链和抽取检查，不按文件目录、所在进程、技术术语多少或是否显示在窗口中推断。

开发者与模型也可能受益于多语言内容，但维护多套诊断、协议与提示的成本过高，因此不扩展本地化消费者。开发文档的写作语言仍遵循项目约定；不为开发文档或开发工具接入动态本地化。

| 内容的消费者 | 范围指导 |
| --- | --- |
| 普通用户 | 导航、操作入口、设置说明、配置表单标签、ARIA／tooltip、进度与状态、面向用户的错误解释和恢复建议使用 UiText；主进程已有用户弹窗也在此范围 |
| 开发者 | 日志、异常栈、原始诊断、代码与 schema、API／IPC／消息 ID、开发者组件展示和仅开发模式操作保持原文，不增加翻译声明 |
| 模型 | 系统提示、模型工具名称与说明、参数和结果协议保持稳定英文定义；UI 语言不参与这些内容的生成或改写 |
| 用户或模型产生的业务内容 | 用户输入、文件和笔记正文、模型输出、保存的名称与历史原始记录保留原文；业务显式要求的输出语言独立于界面本地化 |

同一界面可同时包含不同消费者的内容。错误的 code 与英文 message 服务程序和开发诊断，display 服务普通用户；工具视图的状态与外壳说明可以翻译，展开的工具名、JSON、原始结果和异常保持原文。普通用户可以查看技术细节，这不把技术载荷变成翻译对象。配置模型与代理是普通用户操作，因此表单说明需要本地化；表单中的提示词、协议值和用户填写的名称不随之翻译。

新增文案先明确它服务谁，再决定是否声明消息。普通用户文案按宿主／插件能力逐步增加目录；开发者与模型内容使用普通字符串，不因抽取或覆盖率检查而被迫加入目录。

## 消息声明

`@atelier/sdk/contracts` 提供纯类型、Zod 校验和声明 helper，不依赖 React、Node、可变语言状态或宿主目录。

```ts
interface SourceMessage {
  readonly id: string;
  readonly defaultMessage: string;
  readonly description?: string;
}
type MessageValues = Readonly<Record<string, string | number | boolean>>;
interface UiMessage extends SourceMessage {
  readonly kind: "message";
  readonly owner: string;
  readonly sourceLocale: string;
  readonly values?: MessageValues;
}
type UiText = string | UiMessage;
```

`defaultMessage` 必须存在且非空。`description` 是供译者理解语境的说明，不是界面正文。插值数值必须有限；日期／时间作为 epoch 毫秒数传入并在 ICU 中明确使用 date／time 格式，不跨 IPC 传 Date、函数或 React 节点。`values` 仅保存声明式标量，不参与消息身份。

`defineMessages` 保留 FormatJS 标准的 `id / defaultMessage / description` 对象形状和静态字面量。`PluginNamespace.messages(sourceLocale, definitions)` 为每条消息绑定 namespace 的插件身份与规范化来源语言；消息模块按功能组织，消费者使用语义化引用名。源码属性名与文件位置可以整理，目录寻址仍使用稳定的 owner/id。SDK 不通过全局注册才能创建描述。

```ts
import { defineMessages, pluginNamespace, withValues, type UiText } from "@atelier/sdk/contracts";

const ns = pluginNamespace("example.counter");
export const messages = ns.messages("en", defineMessages({
  title: { id: "counter.title", defaultMessage: "Counter" },
  items: {
    id: "counter.items",
    defaultMessage: "{count, plural, one {# item} other {# items}}",
    description: "Number of items in the counter",
  },
}));

const fixedLabel: UiText = "Counter";
const translatedLabel: UiText = messages.title;
const summary: UiText = withValues(messages.items, { count: 3 });
```

`withValues` 返回新的纯数据描述，不改变共享声明。静态标签通常直接引用描述，动态内容在格式化调用时传参。`UiText` 中的 string 永远不是翻译键；内容即使形似某个 ID 也不得自动查询词典。

消息身份为 `(owner, id)`。`id` 是插件内部的稳定局部键，不自动随英文措辞变化；不得把插值后的字符串用作 ID。来源语言和默认文案在声明中是唯一真值，不在清单或另一个源语言目录重复手填。语义不变的措辞调整可以保留 ID；语义或参数契约不兼容时须换 ID。默认不使用内容哈希自动生成 ID。

开发检查报告同一源码集合中不一致的消息声明；运行时遇到不同默认文案只作诊断，不凭文案相等性判断身份，也不使插件失败。目录仍按 owner/id 寻址，译文是否能使用由语法与参数兼容性决定；源文案变化不能自动证明旧译文仍语义正确，语义兼容由作者负责。

文案身份不采用资源／工具契约的实例唯一性规则：同一消息的纯数据描述可以经 IPC 复制，绑定参数不产生新身份。插件通过公共模块导出消息时保留原 owner/sourceLocale；消费者不会把它重新绑定到自己的目录。使用公共模块仍须遵守插件依赖与启用规则；格式化本身不隐式安装、启用或执行缺失插件。

## 包目录与加载

插件清单的 `atelier.i18n` 可省略；它只登记翻译目录，不定义源文案或默认语言。以下仅展示该字段片段，完整清单仍须声明插件身份、SDK API 与所需入口：

```json
{
  "atelier": {
    "i18n": {
      "catalogs": {
        "zh-Hans": "./locales/zh-Hans.json"
      }
    }
  }
}
```

消息声明无需有对应翻译目录，因此也可以只有 `ns.messages(...)` 而省略 i18n 清单。完整包声明的最低 SDK 版本须覆盖这些作者接口。

每个目录为局部消息 ID 到 ICU 字符串的 JSON 对象，例如 `{ "counter.title": "计数器", "counter.items": "{count} 项" }`。目录可只包含部分消息，不复制默认文案。语言标签规范化后不可重复；文件路径必须位于包根内，规则覆盖规范化路径和符号链接，读取不执行插件代码。不扫描任意目录，也不通过路径模板发现语言。

宿主根据已登记启用的包装载静态目录，包括没有 renderer 或只有公共入口的包。无效 JSON、无法读取的目录、无效 ICU 条目单独诊断并回退，不使无关业务贡献失败；清单结构错误仍按包清单校验规则处理。损坏译文或缺词不是插件禁用原因。

目录与代码共用安装、启用、升级和重启生效的生命周期；语言切换不重新 setup 或构建插件。目录文件内容参与其分发产物与缓存的内容身份，即使代码没有变化，重启后也不能复用旧翻译。开发热更新不是此契约的前提。

目录经宿主受控通道或已有只读插件产物协议交付 renderer，按 owner 和版本关联；插件没有前端入口不影响交付。目录缺失时描述自身仍提供默认文案与来源语言。宿主只使用当前可用目录，不因读取消息而加载禁用插件。

## 语言环境与回退

主进程持有用户语言偏好 `system | BCP47`，保存于应用数据根的 `language.json`，通过 electron-store 与逐项 schema 校验管理；不存在或无效时取 system。它是用户设置，不属于插件配置、界面记忆或会话数据库。当前宿主提供 `en` 与 `zh-Hans`；语言标签与 SDK 不封闭为这两个值。

system 使用系统首选语言列表，按偏好顺序逐项寻找宿主支持项，全部不匹配才退英文；例如 `[zh-Hant-TW, zh-Hans-CN, en]` 应选简体中文。启动和应用返回前台时重新取系统语言，用户明确改变偏好时立即重新解析；不依赖持续轮询。显式选择则只消费该选择。请求与目录标签先规范化，借助 `Intl.Locale.maximize()` 推导 language/script 后筛选相容候选，再由成熟匹配器选择；不能用字符串前缀替代。`zh`、`zh-SG` 归入 Hans，`zh-TW`、`zh-HK`、`zh-MO` 归入 Hant；未支持繁体时不把它宣称为简体匹配，也不隐式转换。

宿主确定有效界面语言，并在相容时保留请求的地区信息，例如 en-GB 可使用英文界面和英国地区格式。独立数字／日期格式化使用这一地区语言；本期不提供独立的地区设置。插件目录跟随宿主选定语言，不绕过宿主选择自行追逐系统列表中的另一个语言。

一条消息按下列次序解析：

1. 按 owner 取得当前可用目录；在有效界面语言下选取相同语言、相容脚本的最佳目录，优先精确标签，其次相容的一般语言／脚本目录。无相容目录则直接使用默认文案。
2. 该目录含对应 ID 且格式化成功时使用译文；单条缺失、语法无效或参数不适用时使用默认文案。不向其他插件、宿主公共词典或不相容语言目录查同名键。
3. 默认文案按照描述的 sourceLocale 格式化；译文按照实际所用目录语言格式化。整条 ICU 消息的复数、select、嵌套数字／日期遵循同一消息语言，不在引擎内部拼接两套 locale。
4. 默认文案也不能格式化时显示原始 defaultMessage 并记录诊断；绝不以内部 ID 代替可读回退。源文案缺陷应由开发检查阻止交付，运行时仍保证展示不崩溃。

这是逐条消息的回退，不因部分缺词把整个插件切成默认语言。独立格式化 API 与消息内格式化的 locale 责任不同；业务若需固定单位、时区或特定地区，应显式提供相应标准选项。

语言状态与已装载目录组成可订阅的展示环境。主进程广播偏好解析结果，renderer 更新 context／formatter 缓存；缓存键包含 owner、消息语言和目录内容身份。Provider 不以 locale 作为组件 key，视图注册表不保存已翻译字符串。依赖文案的派生列表、搜索和 memo 随语言修订更新，业务对象、草稿、卡片位置、输入焦点和在途任务保持原生命周期。

## SDK 展示接口

`@atelier/sdk/renderer` 提供 `useI18n()`，由宿主应用级 provider 注入，不要求存在卡片对象；创建入口、配置页和普通插件组件均可使用。

- `text(value: UiText): string`：原样返回普通字符串，或格式化具归属描述。
- `formatMessage(message: UiMessage, values?: MessageValues): string`：调用参数覆盖描述中同名参数，仍使用描述原有 owner/sourceLocale。
- 只读的有效语言信息，以及标准数字、日期格式化接口。

宿主代绘的 ResourceDescription.label、ToolView.label、CreationEntry.label／description 等统一消费 UiText，ARIA、tooltip、菜单与搜索也从实际显示值派生。组件在 render 中消费 formatter，不在模块求值时读取当前语言。

React 富文本消息只在 renderer 的专门组件入口处理：复用 react-intl 的富文本能力，组件映射由调用方传入，不进入 UiText 或 IPC；普通 label 仍是纯文本，不把翻译串作为 HTML 注入。具体组件命名由实现决定，不能因自定义包装失去官方消息抽取能力。

插件不取得可变的全局 Intl 实例、任意写目录能力或语言设置 setter。宿主在每个进程维护所需 formatter；跨进程不宣称共享实例。React 与翻译 context 必须由宿主共享，SDK adapter 不能把另一份 react-intl context 打入插件私有 bundle。纯 contracts 的 defineMessages 是保持标准形状的声明 helper，不为声明消息加载 React。

## 配置展示

`plugin.config(schema, defaults, options?)` 保留一插件一配置。可选 `options.presentation.fields` 以配置值路径的 JSON Pointer 定位字段；根为 `""`，嵌套字段如 `/limits/max`，`~` 与 `/` 遵循 JSON Pointer 转义，不用点分隔猜测属性名。

```ts
interface ConfigurationFieldPresentation {
  title?: UiText;
  description?: UiText;
  enumLabels?: readonly { value: string | number | boolean | null; label: UiText }[];
}
interface ConfigurationPresentation {
  fields: Readonly<Record<string, ConfigurationFieldPresentation>>;
}
```

显式展示描述优先；未提供时保留 JSON Schema 的 title／description 字符串及现有字段名回退。枚举显示按原始标量值和类型匹配，不用字符串化键混同 `1` 与 `"1"`；没有标签则显示原值。展示映射不增加可选枚举值，不改变 required、默认值、转换或后台原始 Zod 校验。不存在的字段路径和重复枚举映射应报告开发诊断。

示例：`plugin.config(schema, defaults, { presentation: { fields: { "/limit": { title: messages.limit } } } })`。普通单语言 schema 无需这个参数。映射只覆盖现有表单可达的根与固定对象字段；数组元素、动态 record 键及不能投影的联合／引用内部不提供路径标注，不发明通配段。这些复杂值保留整体标题与说明，并继续回退完整 JSON 编辑；不可达路径诊断后忽略，不影响业务配置校验。

配置 IPC 增加纯数据 presentation。renderer 在显示时翻译；主进程或 runtime 不提前将 schema 改写为某种语言，语言切换不重取配置、不重置草稿、不重建 schema。纯后台插件的目录由包加载机制交付，因此没有 renderer 也能使用本机制。

## 用户提示与错误

程序分支继续消费稳定 code，日志继续消费正式英文诊断 message；可选 `display: UiText` 用于用户提示。Preparation.reject、PluginApiError、命令回执及配置错误边界须在同一操作链上保留 display，不通过猜测 message 文本恢复错误码。

```ts
{
  action: "reject",
  code: "limit_exceeded",
  message: "The requested count exceeds the configured limit.",
  display: withValues(messages.limitExceeded, { limit: 20 }),
}
```

display 含消息描述时保留 owner/sourceLocale/defaultMessage/values，renderer 按当前语言格式化。未提供 display 时，宿主认识的标准错误码映射为宿主文案；插件自定义错误保留原 message 回退。外部库原始错误不得作为翻译键。字段校验中的公共提示可按已知校验 code 与结构化参数本地化，插件自定义提示按同一机制显式提供；不根据自然语言诊断反推规则。

展示信息不改变模型工具结果协议，不能把翻译后的 display 回填模型上下文。本次不为了 UI 翻译改写已有历史或引入历史消息迁移；以后有持久化展示描述的具体需求时，仍须保留原始事实及无插件可读回退。

## 开发工作流与验收

作者可以依次采用普通字符串、带默认文案的消息声明、部分语言目录、完整翻译；每一步都可运行。官方抽取处理 `ns.messages(..., defineMessages({...}))` 内的标准静态描述；SDK 实施必须用实际作者代码验证这一点，并提供统一抽取／检查命令，不能仅假设自定义包装可被识别。

`npm run i18n:extract` 将宿主与内置插件的官方抽取结果写入被 Git 忽略的 `.i18n/`；`npm run i18n:check` 检查默认文案、ID 冲突、ICU、译文参数和内置中英覆盖，并实际抽取 SDK 作者示例。两条命令都可以在 `--` 后传插件包根；插件模式只报告覆盖率，不要求翻译齐全。抽取结果服务于翻译工作，代码声明仍是默认文案真值。作者接口与当前版本见 [SDK 作者说明](../packages/sdk/README.md)。

检查源消息的 ID 冲突、默认文案、ICU 语法和参数契约；检查译文的语法、参数及与源文案的兼容性。翻译覆盖报告不使外部插件的未翻译条目失败；宿主与内置插件的普通用户消息声明执行中英覆盖要求，不以源码字符串总数推导翻译义务。默认文案是可靠交付物，不为体积优化将其从最终产物全部删除。

自动验证以纯格式化、目录与包加载、配置／命令 IPC 和现有状态边界为主：缺词与坏译文、语言／脚本匹配、来源保持、参数与复数、仅后台插件配置、翻译缓存变更，以及切换不重建业务状态。GUI、应用自有菜单和焦点／草稿的真实交互由用户验收，不用启动、等待、杀掉式自动冒烟替代。当前 Electron 默认菜单不在接管或动态本地化范围。
