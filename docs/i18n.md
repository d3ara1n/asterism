# 公共 i18n 机制

本文规定宿主与插件的界面本地化契约。插件装配和公共模块规则见 [插件 SDK](plugin-sdk.md)。

## 原则与选型

普通字符串始终是合法的界面文案，原样显示。插件可以只使用一种语言、没有翻译目录，也不初始化翻译引擎；本地化是可选增强。宿主与内置插件面向普通用户的文案提供英文、简体中文两套，外部插件不承担双语准入要求。

消息使用 FormatJS 支持的 ICU MessageFormat。宿主以 `@formatjs/intl` 提供非 React 格式化，React 接入使用 `react-intl`，语言匹配使用 `@formatjs/intl-localematcher`，抽取与语法检查复用 `@formatjs/cli` 和 FormatJS 的 ICU parser。SDK 负责纯数据声明、插件归属和宿主展示接口，不另造消息解析或翻译编译器。

UI 语言不隐式改变模型工具名称与说明、模型提示词、运行时日志、用户正文、模型输出和已保存标题。界面的事件说明可以按当前语言显示，历史事实和原始记录不改写。

## 消费者与本地化范围

本地化按内容服务的对象判定，唯一消费者是普通用户。给普通用户看的操作与说明需要本地化；给开发者或模型看的内容不进入翻译目录。

| 内容的消费者 | 范围指导 |
| --- | --- |
| 普通用户 | 导航、操作入口、设置说明、配置表单标签、ARIA／tooltip、进度与状态、面向用户的错误解释和恢复建议使用 `UiText`；主进程已有用户弹窗也在此范围 |
| 开发者 | 日志、异常栈、原始诊断、代码与 schema、API／IPC／消息 ID、开发者组件展示和仅开发模式操作保持原文，不增加翻译声明 |
| 模型 | 系统提示、模型工具名称与说明、参数和结果协议保持稳定英文定义；UI 语言不参与这些内容的生成或改写 |
| 业务内容 | 用户输入、文件和笔记正文、模型输出、保存的名称与历史原始记录保留原文 |

同一界面可同时包含不同消费者的内容：错误的 `code` 与英文 `message` 服务程序和开发诊断，`display` 服务普通用户；工具视图的状态与外壳说明可以翻译，展开的工具名、JSON、原始结果和异常保持原文；配置表单说明需要本地化，其中的提示词、协议值和用户填写的名称不随之翻译。

## 消息声明

`@atelier/sdk/contracts` 提供纯类型、Zod 校验和声明 helper，不依赖 React、Node、可变语言状态或宿主目录：

```ts
import { defineMessages, pluginNamespace, withValues, type UiText } from "@atelier/sdk/contracts";

const ns = pluginNamespace("example.counter");
export const messages = ns.messages("en", defineMessages({
  title: { id: "counter.title", defaultMessage: "Counter" },
  items: {
    id: "counter.items",
    defaultMessage: "{count, plural, one {# item} other {# items}}",
    description: "Number of items in the counter",
  },
}));

const fixedLabel: UiText = "Counter";
const translatedLabel: UiText = messages.title;
const summary: UiText = withValues(messages.items, { count: 3 });
```

- `defaultMessage` 必须非空；插值数值必须有限，日期／时间作为 epoch 毫秒数传入并在 ICU 中使用 date／time 格式，不跨 IPC 传 Date、函数或 React 节点。
- `UiText` 中的普通 `string` 永远不是翻译键。
- 消息身份为 `(owner, id)`。来源语言和默认文案在声明中是唯一真值，不在清单或源语言目录重复手填。插件通过公共模块导出消息时保留原 `owner / sourceLocale`。

## 包目录与加载

插件清单的 `atelier.i18n` 可省略；它只登记翻译目录，不定义源文案或默认语言：

```json
{
  "atelier": {
    "i18n": {
      "catalogs": {
        "zh-Hans": "./locales/zh-Hans.json"
      }
    }
  }
}
```

每个目录为局部消息 ID 到 ICU 字符串的 JSON 对象，可只包含部分消息。文件路径必须位于包根内，读取不执行插件代码。宿主根据已登记启用的包装载静态目录（包括无 renderer 或只有公共入口的包），无效 JSON 或无效 ICU 条目单独诊断并回退，不使业务贡献失败。目录内容参与分发产物与缓存身份。

## 语言环境与回退

主进程持有用户语言偏好 `system | BCP47`，保存于应用数据根的 `language.json`。当前宿主提供 `en` 与 `zh-Hans`。`system` 使用系统首选语言列表，借助 `Intl.Locale.maximize()` 推导 language/script 后由匹配器选择（`zh / zh-SG` 归入 Hans，`zh-TW / zh-HK / zh-MO` 归入 Hant，未支持繁体时不隐式当作简体匹配），全部不匹配才退英文。启动、应用返回前台或用户修改偏好时重新解析。

单条消息按下列次序逐条回退（不因部分缺词把整个插件切成默认语言）：
1. 按 `owner` 取得当前可用目录，在有效界面语言下选取相同语言、相容脚本的最佳目录；无相容目录则直接使用默认文案。
2. 目录含对应 ID 且格式化成功时使用译文；单条缺失、语法无效或参数不适用时使用默认文案。
3. 默认文案按描述的 `sourceLocale` 格式化，译文按实际目录语言格式化；不在同一条 ICU 消息内拼接两套 locale。
4. 默认文案也不能格式化时显示原始 `defaultMessage` 并记录诊断，绝不以内部 ID 代替可读回退。

语言切换只更新展示 context／formatter 缓存，不以 locale 作为业务组件 key，不重置业务对象、草稿、卡片位置、输入焦点和在途任务。

## SDK 展示、配置与错误接口

- **`useI18n()`（`@atelier/sdk/renderer`）**：提供 `text(value: UiText): string`、`formatMessage(message, values?): string`、有效语言信息及标准数字／日期格式化；富文本使用专门的 `UiFormattedMessage` 组件入口。宿主代绘的 `ResourceDescription.label`、`ToolView.label`、`CreationEntry.label / description` 等统一消费 `UiText`。
- **插件设置展示**：配置页面使用 `useI18n()` 格式化插件自己的字段标题、说明与选项。布局和文案不进入托管配置契约；页面与存储职责见 [插件配置](plugin-sdk.md#插件配置与界面本地化)。
- **用户错误提示（`display: UiText`）**：程序分支消费稳定 `code`，日志消费正式英文 `message`；`Preparation.reject`、`PluginApiError` 与命令回执可携带 `display: UiText` 供界面按当前语言格式化，不回填模型上下文。
- **开发工作流**：`npm run i18n:extract` 将官方抽取结果写入 `.i18n/`；`npm run i18n:check` 检查 ID 冲突、默认文案、ICU 语法、译文参数及宿主与内置插件的中英覆盖（支持在 `--` 后传外部插件包根）。
