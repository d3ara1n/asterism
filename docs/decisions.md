# 决策与开放问题

## 已确定的产品原则

| 主题 | 约定 |
| --- | --- |
| 名称 | 中文“工坊”，英文 Atelier，包与仓库名 atelier；品牌名称集中于 `src/shared/application.ts`。现存同名软件已知，商标粗查不构成名称可用性的保证 |
| 品牌表达 | 与代理一起做事的个人工坊；资源是工作材料，代理在明确授权下操作，工作台呈现对象及关系，会话承接工作过程。README、产品定义和应用文案围绕此表达维护 |
| 应用标识与数据 | 正式 bundle ID 与 Windows AppUserModelID 固定为 `dev.dearain.atelier`；主进程显式以此身份生成发布目录与带 `-development` 后缀的开发目录，不依赖 Electron 按显示名称推导路径 |
| 内部身份 | 内置插件的资源、状态、记录、工具实现与展示契约用 `atelier.core/<name>`；宿主内部 ID 用 `core.*`，IPC 通道用 `core:*`，桌面桥固定为 `window.host`。身份与品牌显示名解耦，不随品牌变动。模型协议的固定入口仍为 resource_list/inspect/call |
| 代理即资源 | 代理是普通资源对象，以 `resource_created { type: "agent" }` 创建，可被移除，也可作为链接起点授权给另一个代理；链接终点只能是代理。所有代理平级，可在同一会话并行运行 |
| 授权连线方向 | 箭头从资源指向接收授权的代理，以拖动起点、终点决定；卡片四边均可使用，端点按相对位置与连线数量动态分散，卡片位置与布线不决定授权方向 |
| 双向连线 | 同一对象对的反向链接合并显示为一条双箭头线，共用一组动态端点；Delete 解除两个方向，单独解除一个方向后显示剩余单箭头；底层有向链接与历史事件分别保留 |
| 资源控制器 | 资源卡片的行为（代理的提交、继续、配置、取消）由该资源模块的控制器执行，经 `resource.command` 路由；会话只负责会话树、对象与链接事件、布局和通知。资源私有可变数据（如代理的模型选择）存于资源状态，不进会话树 |
| 资源收束 | 所有被捕获的资源（活动事件进入会话树）均 settled 才能回溯游标；外部状态的持续运行不计入。移除对象要求该对象 settled，未收束时明确拒绝；移除同时解除全部入向、出向链接 |
| 时间轴写入 | 资源控制器持有未成型的流与活动状态，成型记录提交给 Session；时间轴追加、终态、续接位置与回溯由 Session 管理。提交事务同步串行，模型流与资源准备可并行，不在写入区间异步等待 |
| 定位 | 比 coding agent 更宽的个人工作台，包含日常事务、研究、维护与编程 |
| 展示 | 对象卡片与关系线；工具调用默认收纳在代理流 |
| 卡片尺寸 | 所有对象卡片共用自由调整宽高的机制；选中且展开时使用右下角缩放柄，标题栏与字号保持稳定。模块声明默认和最小尺寸，用户覆盖随视图保存；折叠保留展开尺寸，菜单提供尺寸预设和恢复默认。尺寸不进入任务历史或模型上下文 |
| 画布放置与聚焦 | 画布统一提供最近空位与任意对象集合聚焦接口；无落点创建按新卡片默认尺寸在当前视口中心附近找空位，保留已有位置，拖入使用鼠标落点。创建后共同聚焦原选中对象与新对象，无选择时聚焦新对象；普通缩放下限为 5%，远距离全图按范围动态降低并保留概览余量 |
| Session | 一段工作的持续过程；唯一会话树，可含任意数量代理，代理不分主子 |
| 会话命名 | 用户消息提交触发两级自动命名，由 `utility` 异步生成名称并只追加命名事件；助手输出只作为材料。执行游标变化后，命名模块按当前路径最新命名事件独立同步标题，无命名时从当前分支首条输入重建截断标题，不另存初始标题。用户命名保护限于包含它的路径，旧事件保留且不进入模型输入。规则见 [自动会话命名](session-naming.md)，标题不作为身份或创建前置条件 |
| Workspace | 持久归属和配置集合，可以有稳定目录，但不隐式授予文件能力 |
| 资源 | 携带状态、视图与操作能力，可以是完全虚拟的对象 |
| 资源身份 | 新资源及代理资源使用 Nano ID 默认字符集的 16 位随机句柄；存储与模型调用共用同一身份，创建后稳定。句柄不在 GUI 展示，模型向用户描述资源时使用 title |
| 资源展示描述 | 资源类型模块声明静态图标与本地化类型名，独立于正文渲染；对象目录、历史、授权和卡片共用，不在 UI 散布按类型判断的名称／图标逻辑 |
| 对象面板 | 采用紧凑平铺列表快速识别和定位；不展开内容，不按代理归属组织，不把多对多或成环链接改造成列表层级 |
| 历史面板 | 按真实追加顺序逐节点显示，两行呈现原文片段／标准事件文本与来源；会话事件和资源事件可区分，不按 response 或执行段聚合，不用生成摘要代替节点落点 |
| 分支导航 | 顶部 Tab 显示共享起点与独有后续；原路径不变，共享节点之后的独立导航行在父子 Tab 间双向定位，并随该节点筛选。身份与编号按追加顺序稳定推导；浏览与执行位置独立，查询成功后随协调视图发布 Tab |
| 历史视图 | 支持全部、工作台事件、全部资源记录与具体资源来源，按身份而非名称或工具目标筛选；仅有创建／链接记录的静态资源不占来源选项，筛选不改变查看位置 |
| 授权面板 | 右侧浮岛提供按代理／资源查看有向链接和就地状态反馈；保存以真实投影确认为准。请求环境未完整暴露时，只说明请求生效边界，不推断单条链接的精确 pending |
| 工具目标 | 调用明确携带资源身份，不依赖隐式“当前资源” |
| 历史能力 | 历史查看与状态恢复分开，按资源实现声明支持范围 |
| 解绑 | 保留历史知识与操作记录，撤销后续访问而非删除记忆 |
| 环境生效边界 | 每次模型请求固定环境及其工具批次授权；期间变化即时记录，下一次模型请求取用 |
| context 真值 | context 从当前有效的时间轴事件投影，时间轴是唯一真值。Agent 可持选择、轮数、预算和活动等非 context 状态，不保留独立消息／context 历史；run 不保留跨调用上下文。每次请求显式传入投影，流缓冲和进度只在调用期间存在；上下文管理在时间轴上表达，不直接改写旧事件 |
| 工具边界 | 资源与工具平级，工具声明支持关系；链接资源激活匹配工具，agent.tools 等外部策略另行筛选。宿主一级操作入口固定，不受工具名单约束，不向插件开放注册或替换 |
| 工具定义 | 两层工具共用 ToolContract 与 defineTool：id、name、description、guidelines、argsSchema；id 用于稳定寻址，name 用于调用，description 用于选择，guidelines 用于使用，不另设 snippet。相同工具复用完整定义，不同用法或行为另定义工具 |
| 工具实现 | 后端实现规定 target、result 的 schema 与描述，并提供 handler 和执行信息，不覆写工具用法。三种 schema 均有整体描述；共享工具引用实际同一声明，独立声明占用同一身份报错。target 由实现解释，不建立通用目标解析层 |
| 正文定位与锚点 | 笔记与文件共享 read/edit/write；内容范围由实现的 target 定义，文件行范围不推广为所有资源的必备参数。anchored 是 read 的行为参数，默认 true；当前笔记与文件使用 hashline，write 不要求也不返回锚点 |
| 笔记当前内容 | 笔记是未捕获的自有对象，只持有最新可变正文；正文用 `NoteContent` 声明，契约身份为 `atelier.core/note.content`，通过对象提交保存并由宿主通知视图变化。工作数据格式为 16，仅支持当前格式。保存不追加资源时间轴、内容日志或历史版本，查看任何历史位置都显示当前正文。代理工具结果按统一审计契约保存，不构成笔记恢复能力 |
| 工具错误反馈 | 首次调用说明明确参数类型与用法；失败返回具体校验问题或可区分原因及下一步，支持模型自愈。约定见 [运行时错误语义](runtime.md#错误语义)，开发准则见 [模块指南](../src/modules/README.md#调用说明与错误自愈) |
| 功能模块 | 纯契约、后台实现和前端视图同目录维护、分入口编译；以契约 ID关联，通过 IPC 传数据。`setup` 是贡献装配入口，业务模块以普通函数、闭包或对象显式组合，只接收所需接口；保持事务和生命周期的整体语义，不引入通用服务查找或动态依赖容器。细则见 [插件 SDK](plugin-sdk.md) |
| 插件 | 插件是安装、身份与管理单位，用户只启用或禁用；模块是插件内部的贡献单位，不在界面展示。资源能力以资源及其工具、视图、控制器提供，会话观察与进入前拦截通过专门的会话扩展面提供，不注册全局工具或设置项式能力。插件完全信任、与宿主同进程，不设权限与隔离。插件只有一种形态：带 Atelier 清单的包；来源可以是 npm 安装或用户添加的本地包路径（只认包根，不扫描目录），管理、启用／禁用与装配不按来源区分 |
| 插件 API | 宿主按插件身份构造 plugin api，便于插件消费而非安全边界：包装内部接口、校验参数并返回稳定错误码，内部重构由适配层吸收。插件级 context 提供私有数据目录、命名空间配置（Zod schema 驱动）、凭据与带身份日志；按会话与对象绑定的 context 提供资源状态与受控的当前会话（读取路径与链接、追加本插件事件、通知变化）。不承诺可序列化，不暴露宿主注册表或其他插件贡献；processor、modifier 等改写类能力另行设计 |
| 插件 SDK | 独立、版本化、可发布的包定义宿主与插件共用的类型、服务接口、贡献接口与作者侧声明。宿主实现服务接口，插件调用服务；插件实现模块与功能贡献，宿主消费贡献。双方依赖同一个 SDK，SDK 不依赖宿主源码 |
| 应用组合与宿主机制 | 应用组合层可以依赖宿主接口、内置插件公开领域接口与 SDK，负责组成产品入口；通用宿主机制和插件分别依赖 SDK，领域规则留在插件。公开导入不授予插件写入身份，内置插件仍遵守统一校验与生命周期。人工命名只追加命名事件，标题沿既有路径重建规则同步；详见 [分层约定](architecture.md#应用组合与宿主机制) |
| SDK 对象调用 | 普通对象动作按对象排队，由领域实现检查幂等与执行冲突；首页创建、代理与输入整体原子提交。资源快照固定在调用边界，已授权工具在该次执行期间可提交被捕获对象的数据，普通对象写入仍要求当前路径有效。续接后重新检查对象位于路径，失败回滚游标与数据 |
| 插件基础 | SDK 的基础能力围绕工作台、会话、时间轴事件与资源；插件通过通用记录契约读取事实并提交自己的事件与状态。对话依赖时间轴，内置 Agent 是功能消费者，不决定所有插件的接口或生命周期；大部分插件无须认识 Agent |
| 未知记录 | 同一时间轴承载不同插件的记录。通用信封与 JSON 载荷先按公共结构读取，领域数据按持有的契约解码；不匹配返回 null，匹配且可解码返回 known，数据不支持返回 unknown 并保留原始记录。不认识载荷不妨碍基础查看与路径导航，也不自动加载来源插件 |
| 具名扩展入口 | 生命周期钩子、观察、拦截与功能贡献均通过具体接口、具名成员或可导入的具型契约声明；扩展某项能力须持有其接口或契约。不以 `on("start")` 这类字符串事件名开放泛用扩展；接口明确参数、结果与生效时点，具体声明形式沿插件计划收尾 |
| 具型插件契约 | 资源、记录、创建与动作通过可导入契约推导类型。创建和动作声明稳定身份、关联资源与输入 schema，前端持契约调用，宿主按自己的声明验证并路由；动作实现由资源内联组合，外部准备者绑定具体动作。持久契约识别与运行时共享实例分别设计 |
| 契约共享 | 同一运行环境内，共享契约须引用公共模块实际导出的同一声明对象；提供方自身与消费者一致。宿主通过模块解析与加载保证，不将相同 ID 的独立声明合并，不要求开发者为实例共享维护对象版本。稳定标识只负责寻址、持久化与跨进程关联；声明身份冲突明确报错 |
| 数据兼容 | 先按所属资源／记录／实现的稳定 ID 找到消费方，再由 schema 判断能否解码；兼容旧数据继续读，失败保留原始数据并明确不可用或 unknown。插件负责兼容与迁移，不要求每份数据维护 version，也不以插件发行版本作为统一读取门禁；宿主 SDK／IPC／数据库格式版本独立维护 |
| SDK 读取与执行 | 资源投影、检查、环境读取、链接说明和动作准备只取得 `ObjectReader / SessionReader`；创建、动作和授权工具执行取得 `ObjectExecutor / SessionExecutor`。读取门面的会话也只读；快照固定、当前数据实时读取，修改保留事务与捕获授权的有效期。这是职责接口，不是插件沙箱 |
| 创建与动作校验 | schema 支持默认值与转换，输入与解析结果分别推导类型且均为 JSON；宿主解析每份新输入一次，准备与执行消费解析结果。创建与动作准备均返回接受／替换／拒绝；接受沿用结果，替换提供新原始输入并按所有者契约解析，执行不重复解析。准备不能替换动作身份或通过读取门面写入 |
| 插件运行生命周期 | 任务、资源动作和模型调用组合使用宿主内部的活动登记、取消与收束机制；分别保留去重／超时、对象队列、请求互斥／授权批次。取消不等于结束，回溯与移除依据真实收束；不新增插件侧通用活动服务 |
| Agent 功能组合 | 选择与策略解析、输入受理、执行循环、资源装配分别负责领域职责。去重、续接有效性与输入／状态保存封装为一次原子受理；链接说明和模型请求使用同一套工具策略规则；每次请求从时间轴投影 |
| 前端功能组合 | 基础对象接口提供读取、具型调用、流订阅、视图及通用运行状态；模型进度、工具展示和配置目录按需取得。草稿与提交协调归交互模块并按会话／对象保留，导航显式注入；对话由展示、跟随、输入、配置选择与交互协调组合，共用宿主状态源 |
| 领域知识 | 通用记录信封只支持保存、定位与转交；解释载荷须持有对应领域契约，纯事件消费者也一样。SDK 不包含 AgentResource、AgentConfiguration 或用户消息／命名规则；core 的资源与事件契约须抽成普通领域共识包，这是确定延后实施的任务。会话命名读取首条用户输入即依赖 core Agent 领域契约；相关插件显式引入领域包，无须取得 core 实现或实例。插件自己的领域也可用普通包共享 |
| 公共模块 | 插件通过 package.json 的 `exports["./public"]` 声明公共入口，消费者以 `<包名>/public` 导入；插件正常导出契约、配置访问接口、服务和状态，其他插件通过普通 import 取得真实导出。宿主统一解析来源与依赖、避免重复内联并保证每个运行环境只加载一份；提供方自身也使用同一模块实例。共享内容由插件决定，无须逐对象登记或自建 globalThis 通道。前后台分别加载，跨进程通信独立设计；实施进度见插件计划 |
| 跨插件协作 | 公共模块及真实实例共享属于插件装配基础；通用跨插件命令与跨进程通信仍按需求推进。插件可通过公共导出的对象和函数在同一运行环境协作；调用不自动成为会话历史或资源授权 |
| 内置插件 | 全部内置模块与功能由随软件分发的 `atelier.core` 插件提供。与外部插件消费同一个 SDK，仅经 SDK 契约调用宿主能力；随软件分发不赋予内部接口特权。core 自行实现领域功能，不作为其他插件的必需基础 |
| 插件数据 | 当前会话与对象数据属于会话，按作用域与具型契约保存到 `session_data`，与插件私有数据、时间轴事件分开；纯数据保存不追加历史，查看与分叉不恢复当前值。事件不可变，用于重建历史；插件数据位于 `<data>/extensions/<pluginId>/`，插件可自由写入，其中 `.atelier/` 由宿主托管配置与数据库，凭据明文仍走 secrets 机制。卸载时可选择一并删除插件目录与凭据，会话数据保留 |
| 不可变内容 | 宿主统一暂存、封存与保留字节。`ContentRef` 是严格单键 JSON 保留值，最终持久写入自动登记依赖，作者不另填清单或提取函数。资格随输入／运行作用域传递，引用不授权；对象内容按对象归属与可见记录校验。当前数据替换其依赖，历史记录保留其依赖；字节先封存，JSON 与依赖再同步提交。草稿、尝试和读取各自占用，取消等待真实结束；跨对象共享另案。见 [内容契约](content.md) |
| 模型内容输入 | 用户输入以有序 parts 保存到时间轴后再投影，纯文件也是 message。parts 只有 text 与 file，文件复用不可变 ContentRef、如实识别的 mediaType 与可选 filename；stream/validate 显式接收已有 content，run 按对象和路径取用。宿主独立保留请求内容，适配器统一按文件部件编码。客户端不建模输入模态、不按格式拦截，接受与否由服务端反馈；模型能力仅 reasoning 与 tools |
| 工具结果内容 | 工具结果的模型投影复用 text \| file 部件，toModel 返回字符串或部件；未声明时 data 以 JSON 文本作为文字，只序列化一次。文件只随成功与部分成功，执行期暂存内容交接给请求占用并与结果记录同事务登记根。适配层如实交出：Responses／Anthropic 走 SDK content 输出，协议不支持的类型由协议边界决定；Chat Completions 的 tool 消息只放文字并注明附件，文件随后一条 user 消息发送。首个消费方为目录 see 工具，按文件头识别图片 |
| 插件配置 | 插件在纯契约中以 `ns.config(schema, defaults, { presentation })` 声明唯一一份配置契约，前后台共享；后台 `plugin.config(contract)` 返回 `get / update / subscribe`，前端 `useRendererConfig(contract)` 读取当前值；宿主负责存储、校验、设置页与前后台变更通知。偏好（上次选择等）不属于配置；保存于 `.atelier/config.json`；向业务模块注入各自所需的当前值读取和更新接口，更新基于最新完整配置。设置页由 schema 驱动，保存仍以原始 Zod 校验；独立 IPC 不加载会话，恢复默认先改草稿，损坏文件保留，保存不要求重启 |
| 插件装配 | 启动时装配并冻结，安装、启用、禁用、升级重启生效；不兼容或失败插件被禁用并通知，不阻止应用启动。成功 setup 的清理责任立即登记，后续失败取消托管工作并逆序清理，等待结束再释放存储；setup 返回前失败自行清理尚未交付的设施 |
| 插件编译 | 宿主在启动时打包插件 runtime 与 renderer 入口并缓存产物；宿主共享模块与插件公共模块保留统一加载引用，私有依赖进入插件 bundle。公共模块的解析同时覆盖提供方与消费者，不能仅按包名或手填版本推断来源相同。静态资源经 `atelier-plugin://` 协议提供，高频二进制经按对象的流通道传输，不进入会话记录 |
| 插件命名空间 | 插件只在 definePlugin 声明一次 id；资源 kind、实现、事件与视图契约以短名声明，宿主装配时补为 `<pluginId>/<name>`。工具契约是全局知识，模型看到短名，按 name 全局唯一 |
| 工具契约覆盖 | 工具名称覆盖与契约共享分别处理：不同身份的同名契约按插件装配顺序（`atelier.core` 最先，外部插件按用户列表）取最后定义者生效；实现绑定实际声明对象，共享该对象的实现保留，被覆盖契约的实现下线。不同声明占用同一身份报错，不当作共享；同一插件内同名异契约、同一资源类型与工具名的多个当前实现仍属冲突 |
| 插件缺席 | 资源类型、实现、事件与视图契约 ID 均带插件命名空间；插件禁用或卸载后历史与对象保留，视图回退默认渲染与原始数据，资源显示为实现缺失，不删除或改写记录 |
| 模型引用 | 提供商与模型以可读 slug 引用：提供商 ID 不含 `/`，模型 ID 即服务端模型名；模型表达式 `<provider>/<model>` 必定成对，不含思考等级。ID 可随时编辑，引用失效时请求明确失败，不级联改写。随机记录 ID 不对外引用 |
| 模型目标 | 请求以 `{ role, model?, thinking? }` 选择模型：覆盖字段优先，其余沿用角色，不支持 reasoning 时思考归 off；不可用以稳定错误码失败 |
| 插件模型 API | 模型与角色目录、stream 和 run 属于按需消费的模型分支。stream 是一次补全；run 是无跨调用状态的一次补全及完整资源工具批次，每次显式输入并交付具型事件／结果，由调用方写入时间轴。宿主保证真实授权、批次和取消收束；插件自己的 Agent 推动多次调用并管理轮数、预算和继续规则，不使用 request／next 策略让宿主驱动循环。共识载荷由 SDK 提供，记录身份由消费者声明；接口不依赖内置 Agent 配置或对话类型。现有模型、代理配置与注册机制保留；内置 Agent 通过具型只读目录读取配置，选择与提交去重保存于对象数据 |
| 工具产出 | 过程态与终结态共用一个 data schema；工具以 publish 发布当前完整产出，运行时替换最近的合法快照。只有终结结果持久化并交给模型；失败、取消与未知结局同样保留有效产出，终结后忽略迟到更新 |
| 结果展示 | 保存实际实现的 ID、当次资源身份、执行时间与 data/model；input/execution/result 三态同级，各自的 headerRenderer 和 bodyRenderer 独立可选，共享阶段数据。相同组件可跨阶段复用；缺失阶段独立回退，不隐式借用。历史使用保存的数据，组件缺失或不兼容时使用默认视图 |
| 工具三态视图 | 填充、执行与结果是工具自身的三态视图；动态填充可选，未提供时使用静态准备提示。填充视图消费未完成参数，不能触发执行；内置工具提供动态摘要，write/edit 提供正文尾部预览。外观设置分别控制填充时展开、填充结束或中断时折叠，默认开启；等待、执行、结束不重复自动折叠 |
| 工具展示连续性 | 三态尽可能逐步增加内容，保留已显示的目标、数量和相同元素的样式，避免阶段切换清空摘要或改变布局。视图可按内容需要切换正文形态，如 write 从生成中的尾部预览切换成功写入后的代码正文；外壳不限高，body 提供方自行控制局部高度、滚动与渲染量 |
| 内置工具正文预算 | `atelier.core` 工具正文每次调用最多展示 120 个逻辑行，read/write 与列表按顺序截取；edit 按实际编辑点展示带增删颜色和前后行号的 diff，远处编辑点之间省略未改内容，所有片段的上下文、删除与新增行共用总预算。read/write 支持代码语法着色，edit 不要求语法着色；原始详情、持久记录与模型输出不受该预算限制，外部插件由自身决定展示策略 |
| 内置正文模型反馈 | edit 成功时 `toModel` 返回摘要、实际 diff 与可继续编辑的新锚点；diff 和锚点按各自大小预算截取并提示省略。write 成功只给一句确认，带路径、创建状态或增删数量等少量信息，不回传 diff、正文与锚点。报错保留详细原因与修正信息。read/list 仍返回取材结果；120 行预算与着色只用于用户正文展示 |
| 内置正文渲染 | edit/read/write 统一使用 Pierre Diffs 1.5.2；edit 为 stacked（API 的 unified）差异视图，read/write 为原生 File 代码视图。语法识别采用库自身的文件名与扩展名机制，未知语言或没有文件名时使用普通文本，不按内容猜测。使用 Pierre 亮暗主题与 JavaScript 着色引擎，字体字号沿用公共 token；紧凑行号、增删颜色与分隔由组件提供 |
| 工具原始详情 | 调用详情与结果详情共用默认不选中的单选切换，点击当前项收起。结果详情显示完整 JSON，含文件或没有有效产出的结果隐藏入口；详情局部滚动不限制工具正文 |
| Header 设计 | 所有 block 的 header 按单行摘要设计以保持视觉高度一致；由 renderer 自行安排内容与省略，外壳不设高度上限或强制裁切。工具标题推荐名称与路径在中间区域收缩、数量与类型等摘要保留右侧，正文渲染独立，详见设计系统 |
| 思考展示 | 独立 header/body：生成时摘要显示思考中及运行时块起点计时，正文为固定高度的尾部窗口；结束或中断后正文切换全文。外观设置分别控制生成时自动展开、结束时自动折叠，默认均开启，增量不覆盖手动开合。历史默认折叠，空思考不显示；未保存的历史耗时不补造 |
| 工具层级 | 一级是协议 tools 中的三个固定宿主入口 resource_list/inspect/call，二级是经 resource_call 使用的动态资源工具。三类入口的视图由 Atelier 内置；resource_call 自己将展示转交二级工具，外壳只显示实际工具的一层视图。模块提供资源工具视图，不能替换固定入口 |
| 上下文 | 资源变化进入 messages 事件，不反复修改顶层动态资源声明 |
| 权限 | 执行层验证，工具可见性和 UI 连线均不是权限机制 |
| 历史 | 查看与恢复分开，外部不可恢复资源不假装回滚；所有入树记录均以当前游标为父并原子推进游标，均可查看与继续，无隐藏审计节点 |
| 终态元数据 | 块数据准备齐全后一次提交：正文等待响应终态，工具调用等待结局；终态随响应最高序号的实际块保存。不设 completion 记录、迟到字段后补或读取合并机制，审计信息属于块自身 |
| 请求起点 | 每个块记录请求取用的路径末端；模型投影据此安排响应和期间事件，保留实际发送前缀 |
| 选择审计 | 历史选择写独立追加日志，与当前游标原子提交，不进入模型上下文；宿主不吸附继续位置 |
| 历史派生状态 | `committed` 只通知新增记录；独立的 `cursorChanged` 将正常追加、回溯和分叉选择统一为变化后的固定路径，一次外层事务只通知最终位置。领域模块在提交后按当前路径重建派生当前值，直接覆盖；失败只记日志。只读查看、相同位置选择及纯数据／标题写入不触发游标观察，Agent 上下文继续即时投影 |
| 会话视图所有权 | 查看位置、工作台与对话读取由同一会话模块管理；应用层只持有导航和列表，异步列表刷新不能覆盖会话内容 |
| 命令与展示 | 会话命令返回受理结果，查询返回指定位置的协调视图；布局与领域变化分别处理，历史查看不禁止布局操作 |
| 进度与块身份 | 流增量独立于持久视图订阅，以持久修订协调落库衔接；同一块在生成、执行和保存后保持展示身份 |
| 平台 | 测试以 macOS 为主；发布覆盖 macOS、Windows、Linux |

## 初版技术基线

本地桌面、单用户起步。Electron 外壳，React + TypeScript + Vite；shadcn/ui + Tailwind CSS 作为组件与样式体系，组件源码纳入仓库，不并行维护另一套组件样式体系。@xyflow/react 作为卡片与连线画布，Monaco 按需用于文件与 diff。结构化持久化为 SQLite（`node:sqlite`，运行时不可用或能力不足时改用 better-sqlite3），大内容为本地对象存储，校验为 Zod。独立 Node.js 任务运行时。包管理器为 npm，不使用 bun 或 pnpm。代码构建为 electron-vite，打包分发为 Electron Forge。

应用数据在 `app.getPath('userData')` 下分目录存放：`db/`、`objects/`、`content/`、`logs/`、`credentials/`。凭据与任务日志、事件记录分离；Chromium 会话数据使用独立 `sessionData`。

模型接入为 Vercel AI SDK，MCP 接入为官方 TypeScript SDK。运行时拥有任务历史与授权，接入层不拥有会话真值；不以完整 agent 框架替代工坊的历史、资源和授权内核。

模型接入的上层封装须支持继续扩展协议，首批围绕 OpenAI 与 Anthropic 协议。每个 Session 有唯一的只追加扁平会话树，节点是带来源的通用记录与工作台事件。平台职责：模型调用（run／stream／validate）、工具目录与 `resource_*` 入口、工具批次执行、链接与授权、provider 适配与续接资料校验；第三方执行体插件把自行投影的上下文交给 run 即可使用平台工具。执行体是插件定义的资源，其消息、输出块、通知等记录完全归插件：内置代理按响应归组、延后响应期间的事件、截取不完整或以 thinking 结尾的上下文，都只在其投影内完成。会话所有被捕获的资源 settled 才可回溯，宿主可从任何历史节点继续。首页发起对话是唯一指名内置代理的宿主入口：经正规创建接口创建 `atelier.core/agent` 并经公共消息契约提交。具体契约见 [会话树](timeline.md) 与 [会话与代理能力](conversation-core.md)。

模型与端点的协议差异由可组合的兼容包集中处理请求编码、响应解码与历史续接，避免在通用路径散布品牌、域名或模型名称条件链。提供商连接可设置默认组合及选项，具体模型继承并覆盖；内置目录提供推荐，用户可为自定义与中转端点显式选择。同一请求使用统一解析后的组合，不同格式策略可跨模型复用。该方向已确认，本次不实施；配置、组合契约与现有 DeepSeek 专用分支的迁移见 [模型兼容计划](../plans/todo-2026-10-10-model-compatibility.md)。

同一批次工具调用共同收束后统一向模型交付结果，再开始后续模型请求；单个工具完成可更新进度，但不触发提前续轮。批次身份是执行关联，不是 transcript 容器。

全局设置与工作数据分开持久化：提供商、具体模型、模型角色与 agent 配置保存在 `configuration.json`，外观与全局界面状态分别保存在 `appearance.json`、`ui-state.json`。SQLite 保存工作区身份、累计会话记录、资源当前状态及会话视图，不承担应用配置存储。配置修改按完整文档原子保存，只在文件不存在时初始化，损坏配置明确报错并保留原文件；重建工作数据库不重置全局设置。单实例内由对应进程独占各文件写入，不引入文件锁或跨实例同步。

提供商连接为本机应用级配置，首批覆盖 OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages。普通配置和凭据引用保存于 `configuration.json`；API key 由 Electron safeStorage 加密，密文独立保存在应用数据目录 credentials/，加密不可用时不回退明文。能力层提供配置管理与异步连接测试，界面消费接口。具体实施状态见 [模型接入计划](../plans/todo-2026-10-01-model-protocol-storage.md)。

设置分为提供商、角色、代理：提供商管理连接与具体模型的能力、生成参数；角色管理 `heavy/fast/default/utility/smart` 及自定义模型角色；代理管理所有代理共用的 agent 配置。内置模型角色不能删除，其余设置可编辑；`utility` 默认隐藏，内部功能仍可引用。模型角色是配置参考，不是工作台对象。

配置按取用时读取、消费时校验处理，不建跨配置引用约束，不级联清空已选身份。删除不因其他配置持有其 ID 而受阻；非空失效 ID 不降级为继承。模型角色与 agent 配置由内置原始定义和用户局部覆盖解析出最终视图；用户未提供字段表示未覆盖，提示词留空恢复继承。自定义模型角色以内置原始 default 为基准，自定义 agent 以内置原始 worker 为基准，不依赖其他项的最终视图。编辑器可用 placeholder 展示继承值，不将其回存为用户覆盖。已有对话每次模型请求按当前选择重新解析配置，允许中途切换 agent、模型与思考等级，下一次模型请求生效。内置 agent 为 worker、explorer、reviewer、researcher、advisor，worker 默认，advisor 使用 smart；初始内容来自指定 pi 配置。具体语义见 [模型与代理配置](model-configuration.md)，实施状态见模型接入计划。

系统指令从有序的结构化提示块统一渲染，使用 XML-like 分段表达 harness、agent、context 及后续 skill 的来源与边界。harness 从模型视角解释可操作的已链接资源、工具入口与环境变化的处理方式，不传授界面概念、内部授权检查或开发原则；执行层独立检查实际资源链接与工具策略。动态资源状态只通过消息节点追加；工具定义由独立协议通道传递，不重复拼入系统指令。已链接目录中的 AGENTS.md 作为 context 注入；提示块追加与拦截替换的插件扩展面以及 skills 待接入。相同配置下提示块与工具定义的内容及顺序保持稳定；标签不改变协议指令层级或执行授权。详细约定见 [运行时与上下文](runtime.md)。

只有对话 messages 从历史重建，harness、角色提示词、模型参数与工具目录均从当前代码和应用配置即时解析。对话历史不保存环境正文或完整请求；模型输出块仅保留协议续接所需来源及执行引用。当前选中的配置 ID、模型 ID 与思考等级属于可修改会话设置，独立于追加历史；设置编辑与角色切换不改写消息。在途请求及其工具批次保持已取用环境一致，下一次模型请求采用新配置。执行记录只保存计算结果（模型表达式、计量等），不记录 agent 配置或模型角色身份。

对话创建选择 agent 与具体模型，agent 的模型角色提供默认参考，用户可覆盖；无继承来源且模型未定义时要求明确选择。对话期间可切换 agent 配置、模型和思考等级，下一次模型请求生效；委派也可覆盖模型。只读 agent 不因被委派或被其他代理链接而获得写权限。完整规则见 [模型与代理配置](model-configuration.md)。

目录与虚拟资源作为验证：目录验证外部授权与 diff；具备捕获能力的虚拟资源验证状态历史与恢复。笔记不承担历史恢复验证。文本差异采用 diff 9.0.0（BSD-3-Clause），其标准 unified patch、结构化行差异、换行保留与计算预算匹配后端需求；diff-match-patch 的自有补丁格式与 fast-diff 的字符差异不适用于这次按行补丁生成。

## 初版缓存取舍

provider tools 只暴露固定宿主操作入口；动态资源实例通过消息事件表达，工具 schema 通过链接通知或 inspect 提供。所有工具管理与 resource_call 共享工具及实现目录，匹配目标资源后再应用外部允许/排除策略。同一个工具可有多个后端实现，资源实例不携带工具目录或工具白名单。

这优先保证工具前缀稳定，不声称几百个工具必然廉价，也不声称前缀稳定必然命中缓存。provider 原生搜索和延迟加载的机制见 [调研记录](mcp-caching.md)。

## 正式应用框架约定

- 窗口采用系统材质底座：左上标题/任务区、右上快捷操作区，下方为主体工作台，部件之间与窗口四周留出材质间隙。macOS 原生红黄绿位于左上标题区；辅助面板按需打开。
- 应用启动永远进入独立首页，不自动打开会话。左侧可隐藏侧栏与右侧首页/工作台同属主屏；设置为独立屏，切换时包含侧栏的主屏整体移动。工作台不是唯一主视图。首次发送才创建带生成 ID 的会话、第一个代理资源与首条输入，utility 异步命名，不要求预先命名。一次性原型只保留于 feat/ux-prototype，正式分支可参考其侧栏职责但不继承演示状态模型。
- 侧栏只保留「首页」入口，不另设同样返回首页的「新会话」按钮；首页状态下入口高亮且不可点击，切入工作台后恢复可点击。
- 首页与工作台双向切换时，两边独立的进退场动画同时播放，应用首次显示首页不播放入场。会话导航立即切换到工作台，不等待首份内容、不显示独立加载画面；读取期间呈现工作台底板与当前外观纹理，内容就绪后填入，页面过渡保持连续。读取失败保留错误与重试入口。
- Electron 44.5.1、electron-vite 5.0.0、Forge 8.0.1；Vite 7.3.6 满足构建器 peer 范围。shadcn/ui 采用 Radix 底层，React Flow 承担真实画布交互。
- 本地单工作区，每个会话一棵会话树。工作台的笔记和可添加资源种类用于基础能力验证，不构成最终资源目录；代理卡片内部已接入真实对话，对象、历史与授权面板沿已确定的正式交互维护。资源身份与执行层授权的原则独立于验证用的资源类型。
- 当前代理、笔记与目录的创建对话框共用布局与提交状态，名称为首个字段，统一标签且无名称占位符；笔记提交时要求非空名称，代理与目录空名称分别采用 agent 配置名与目录 basename。三个添加菜单项均带省略号；目录路径有效性由后台校验，笔记编辑继续延后。具体交互见 [工作台](workbench.md)。
- 会话树、查询索引和视图分开；宿主正文存 `objects/<hash>`，插件不可变内容存 `content/` 并随记录或当前数据登记依赖，自包含可变内容（笔记）另行存储；细节见 `docs/architecture.md`。
- 开发与发布数据隔离。关闭最后一个窗口退出应用与任务进程；进程中断后不自动重放命令。
- macOS 使用原生 vibrancy，Windows 11 22H2+ 使用系统 Acrylic；较旧 Windows/Linux 和减少透明度/高对比度场景采用实色回退。不引入自绘标题栏库，原生窗口按钮和缩放能力保留。
- 窗口层次为 Window { Titlebar, Space { 屏[] { 浮岛[] } } }；屏带左浅右深，由菜单切换。屏内采用浮岛编织：放得下时分栏，放不下时溢出跟随焦点。
- 本地化按内容服务的对象判定，唯一消费者是普通用户，尤其是不熟悉英语的用户；开发者诊断、代码／协议标识和模型提示／工具协议不进入翻译目录，避免扩大维护成本。普通用户界面按系统语言或用户明确选择单语显示，不并排双语；宿主与内置插件提供英文和简体中文，外部插件可长期仅用普通字符串。公共 i18n 采用 FormatJS／ICU，宿主管理语言与目录，消息在声明时绑定插件身份和来源语言，静态贡献及跨进程用户提示在显示时解析；语言切换不重建业务状态，不改变模型上下文与历史原文。具体范围、契约与回退见 [公共 i18n](i18n.md)，已完成的实施与验收记录见 [归档计划](../plans/archived/todo-2026-10-12-i18n.md)。
- 代理正文与思考使用 Streamdown 2.7.0 渲染，包含 GFM 与流式未闭合语法处理；不自建 Markdown 解析器。HTML 不作为可执行内容，网页链接经协议检查后由系统浏览器打开；远程图片首批显示为明确打开的链接。
- 图标统一为 lucide-react，动画统一为 Motion，控件统一为 shadcn/ui 实现；通用问题优先采用成熟库。


## 界面控件与主题

- 控件只使用 shadcn 官方 registry 源码，外观只通过主题 token 定制；不手改组件、不在业务代码另写控件皮肤。
- 对话框描述聚焦当前操作，不在各资源创建表单重复说明资源与授权的通用性质；同类表单的文案语气与结构统一，约定见 [设计系统](design-system.md)。
- 配色、圆角、密度（紧凑/标准/宽松）与画布纹理属于用户可选主题；密度以 token 统一缩放，不在调用处写死尺寸。亮暗模式（跟随系统/浅色/深色）、主题色与灰色为独立设置，色值取自 `@radix-ui/colors` 的亮暗 12 级色阶；命名调色板只是主题色 + 灰色的推荐组合，选择时写入两项，不进存储、无选中态。切换任何一项只改变 token 的值，不改变 token 名。
- 字体设置分界面字体与代码字体两项，存家族名，`null` 为系统默认；候选来自 Chromium Local Font Access API（`queryLocalFonts`），主进程仅对受信主框架放行 `local-fonts` 权限，其余权限一律拒绝。选择控件为 shadcn Popover + Command（依赖 `cmdk`）组合的 `FontPicker`；代码字体默认只列经 canvas 测宽判定的等宽字体，可切换显示全部。界面字号由密度决定，不另设；代码字号单独可选（11–18px 或跟随）。
- 外观设置为非敏感应用设置，由主进程经 electron-store 存于 userData 下的 `appearance.json`，读出后以 Zod 逐项回退默认值；renderer 经 IPC 读写并把 token 写到 `:root`。
- 持久化的本地数据分三类：设置（用户可见可改，如外观）、界面状态（应用顺手记录、不出现在设置页，如窗口尺寸与位置、侧栏宽度、「不再提示」）、任务视图状态（视口与卡片位置、尺寸，独立于任务历史，存 SQLite）。界面状态统一存于 userData 下的 `ui-state.json`，键与 schema 在 `src/shared/ui-state.ts` 登记，单项损坏回退默认、不做迁移；由主进程读写。renderer 只能经受控 IPC 读写 `preferences` 容器，键限于宿主路由记忆 `creation-route/` 与按插件隔离的 `plugin/<pluginId>/` 前缀。
- 资源创建入口由插件在 renderer 声明（菜单与拖放同一原语），宿主仲裁候选并持有跨插件路由记忆；插件不拦截拖放事件，也不取得可写会话。详见插件 SDK。
