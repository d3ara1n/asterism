# 决策归档与开放问题

> **阅读说明**：本文档是**历史决策归档（ADR）与未决问题清单**，不是当前功能的规格真值。它按演进时间记录过去为什么做出某项关键架构取舍、排除了什么替代方案，防止后续迭代重新讨论已否决路径。当前生效的详细契约请查阅 `AGENTS.md` 文档地图中的各领域真值文档。

## 历史决策记录（按演进时间排序）

### 2026-09：基础定位、桌面基线与对象边界

- **产品定位与对象边界（2026-09-17）**
  - **决策**：面向比 coding agent 更宽的个人工作台；以对象卡片与有向连线呈现工作，但工具调用默认收纳在代理对话流中；Workspace 存储目录、UI 可见性与连线均不构成隐式授权，所有资源操作在运行时执行层凭显式 `resource_id` 与有效绑定验证。
  - **理由**：把每条消息与工具调用都铺到画布上会迫使用户持续整理布局；将 UI 视图或工作区目录等同于权限会导致不可控的越权副作用。
- **桌面与存储技术栈（2026-09-18）**
  - **决策**：采用 Electron + React + TypeScript、`@xyflow/react`、SQLite（`node:sqlite`）与本地对象文件存储、Zod，以及独立 Node.js 任务进程（`utilityProcess`）；构建用 `electron-vite`，打包用 `Electron Forge`，包管理器固定 `npm`。模型接入采用 Vercel AI SDK 做无状态单步协议适配。
  - **理由**：复杂画布需要统一的 Chromium 与本地 Node 接入；独立任务进程避免模型流与大文件操作阻塞窗口或受 React 组件生命周期影响；任务历史与授权必须由工坊自持，不托付给第三方聊天或 agent 框架的会话存储。
- **两层工具目录与稳定前缀（2026-09-18）**
  - **决策**：对 provider 协议顶层 `tools` 只暴露三个固定宿主入口（`resource_list` / `resource_inspect` / `resource_call`），可管理与扩展的动态资源工具作为二级工具经 `resource_call` 调用，其 schema 通过链接通知或 `inspect` 在消息历史后部提供。
  - **理由**：动态增删顶层 `tools` 会频繁破坏 provider 提示缓存前缀；将资源变化投影为后续消息事件可保持请求前缀稳定（调研依据见 [MCP 延迟加载与提示缓存](mcp-caching.md)）。
- **请求边界固定环境（2026-09-19）**
  - **决策**：每次模型请求开始时固定消息路径、代理配置与已链接资源授权，连同该响应的工具批次使用到底；期间发生的配置或链接变化按真实顺序落入时间线，留待下一次模型请求取用。
  - **理由**：保证单次响应与工具批次内的权限、能力视图与消息前缀自洽，不因执行中途解绑而破坏在途响应的协议配对。

### 2026-10 上旬：窗口视觉、扁平会话树与资源平级

- **原生材质窗口、浮岛编织与官方控件（2026-10-01 ～ 10-07）**
  - **决策**：窗口采用平台原生材质底座（macOS vibrancy / Windows 11 Acrylic），不使用全屏 CSS `backdrop-filter` 或自绘窗口按钮；窗口层次固定为 `Window → Titlebar / Space → Screen → Island`，屏内浮岛放得下分栏、放不下溢出跟随焦点；`shared/ui/` 仅维护 shadcn 官方 registry 源码，通过 Radix Colors 12 级色阶映射语义 token；本地持久化拆分为设置（`appearance.json` / `language.json`）、顺手记录的界面状态（`ui-state.json`）与会话视图布局（SQLite）。
  - **理由**：避免自绘皮肤与手写坐标动画带来的高昂维护成本，让视觉与交互规则集中在一处纯模型中。
- **独立首页与按需加载会话（2026-10-02 / 10-10）**
  - **决策**：启动永远进入无会话身份的独立首页，只读取列表摘要；首次发送被接受时才原子创建 Session、首个代理与首条消息，不预先创建空会话或强制先命名；侧栏只保留「首页」作为新会话唯一入口。
  - **理由**：消除大量空白废弃会话，让用户直接从具体工作意图开始。
- **模型角色、代理配置与局部覆盖继承（2026-10-08）**
  - **决策**：全局配置拆分为提供商、模型角色（`default / heavy / fast / smart / utility`）与代理配置（`worker / explorer / reviewer / researcher / advisor`），保存在独立于会话数据库的 `configuration.json`；角色与代理只持久化用户的局部覆盖字段，运行时与内置原始定义合并（自定义项分别以原始 `default` 与 `worker` 为基准，不互相链式继承）；配置按需读取、消费时校验，不建跨配置外键或级联清空。
  - **理由**：保证内置提示词或默认参数随版本升级时未覆盖字段自动受益，同时避免修改默认项意外污染自定义项，重建会话数据库也不丢失全局配置。
- **会话级扁平树与代理资源化（2026-10-08 ～ 10-09）**
  - **决策**：废除单代理专属消息表，每个 Session 拥有唯一一棵只追加的扁平会话树（`session_nodes`）；代理作为普通一级资源创建与移除，不分主子，输出块平铺在树上，对话从当前时间线即时投影；所有被捕获资源均 `settled` 时才允许回溯游标。
  - **理由**：支持多代理与工作台事件按真实发生次序交错记录，使分支回溯能用同一套重放逻辑重建所有对象与授权关系。
- **正文工具、Hashline 锚点与 Pierre Diffs（2026-10-10）**
  - **决策**：目录与笔记共享 `read / edit / write` 契约；`edit` 采用 `LINE#HASH` 锚点整批校验，后端用 `diff`（jsdiff）生成标准 unified diff；前端弃用重量级 Monaco Editor，统一采用 `@pierre/diffs` 渲染 stacked diff 与代码着色，内置工具正文限制每次调用最多 120 个逻辑行预览预算；笔记定义为未捕获的自有对象，只保存当前正文，回溯不恢复笔记内容。
  - **理由**：在对话流高频展开多个工具块时，Monaco 实例开销过大；Pierre Diffs 轻量且契合只读代码／差异预览，120 行预算防止大文件撑爆 DOM。
- **品牌定名 Atelier 与固定应用身份（2026-10-10）**
  - **决策**：中文定名“工坊”，英文定名 Atelier；应用标识固定为 `dev.dearain.atelier`，显式决定数据目录，内部契约与通道固定使用 `atelier.core/*`、`core.*` 与 `window.host`，与显示名称解耦。
  - **理由**：防止品牌或目录改名导致用户本地数据库、凭据与持久契约身份断裂。

### 2026-10 中旬：插件 SDK、领域收回与多模态/多语言/模型兼容

- **完全信任的插件 SDK、公共模块与领域收回（2026-10-10 ～ 10-13）**
  - **决策**：内置功能全部收敛为随软件分发的 `atelier.core` 插件，与外部插件消费同一个独立版本化的 `@atelier/sdk`；插件采用包形态，启动时编译冻结，完全信任、同进程运行，不设沙箱或配额；通过 `exports["./public"]` 由宿主 ESM 图保证同运行环境共享真实声明实例；宿主只认识通用记录信封（带宿主打戳的 `source: { plugin, resource } | null`）与无状态单步 `models.run / stream / validate`，Agent 消息块、回合循环、终态随最高序号块保存、执行状态投影与命名规则全部收回 `atelier.core` 领域模块。
  - **理由**：插件由用户主动安装，防御式沙箱与字符串事件总线只会增加抽象税而无法提供真正的安全；将 Agent 领域知识移出宿主内核，才能让非对话类资源插件在不依赖 Agent 概念的前提下干净扩展。
- **时间线按需观察快照与双观察入口（2026-10-12 ～ 10-13）**
  - **决策**：区分线性 `timeline` 与全树 `session` 查询范围；快照改为只捕获末端、追加上界与标题的轻量观察柄，按需读取；会话观察拆分为 `committed`（仅新增记录）与 `cursorChanged`（追加、回溯、分叉统一通知最终游标位置），彻底移除工作台历史只读预览模式，工作台始终对应持久执行游标并由全量重放重建。
  - **理由**：消除历史预览模式带来的「当前查看位置 vs 真实执行位置」双轨状态复杂度，让会话标题等历史派生值在任何游标移动后都沿唯一规则同步。
- **公共 i18n 仅服务普通用户（2026-10-12）**
  - **决策**：基于 FormatJS / ICU MessageFormat 建立可选本地化机制，唯一消费者是普通用户；日志、开发诊断、schema 与模型提示／工具协议保持稳定英文，不进入翻译目录；普通字符串始终合法，消息描述绑定 `(owner, id)` 与 `sourceLocale`，逐条回退。
  - **理由**：避免为开发者诊断或模型协议维护多语言目录带来的高昂成本与上下文污染。
- **不可变内容引用 `ContentRef` 与统一文件部件（2026-10-12）**
  - **决策**：宿主统一管理字节暂存、封存与回收，业务 JSON 通过严格单键 `{ "$atelier.content": "<uuid>" }` 引用内容，写入时自动扫描登记持久依赖根；模型输入与工具结果统一收敛为 `text | file` 部件，移除客户端对模型输入模态与 MIME 白名单的配置拦截，按实际 `mediaType` 交由服务端判定。
  - **理由**：避免将大体积二进制转为 base64 塞入 SQLite JSON，同时消除客户端因模型模态元数据滞后而误拦合法文件输入的问题。
- **全局具型瞬态事件总线与资源状态徽标（2026-10-13 ～ 10-14）**
  - **决策**：提供跨进程的全局具型事件总线，区分 `occurrence`（逐条 `all`）与 `snapshot`（可选 `latest` 合并），发布不参与事务、断连不补发；侧栏会话列表以 `latest` 订阅 `ResourceStatusChanged`，展示 `running / failed / awaiting / completed` 徽标与可选进度，进入会话即消费终态。
  - **理由**：让未打开的后台会话能轻量推送运行与待操作状态，而不必频繁查询完整会话正文或把瞬态 UI 提示写进不可变历史树。
- **可组合模型兼容包、跨模型续接与自动压缩（2026-10-14 ～ 10-15）**
  - **决策**：
    1. 协议差异通过预定义的五项兼容包（显式添加到提供商或模型，请求时按 id 整项覆盖合并）表达，不在执行循环中写死品牌或域名分支；思考明文、摘要与签名/密文续接作为协议基线原生支持，跨模型切换时只过滤不匹配来源作用域的原生续接资料，保留公共正文与思考。
    2. 提供商预设作为一次性草稿生成器，不持久化预设身份；参数获取通过 `@opencode-ai/models` 按剥离路由前缀后的模型名精确匹配并直接覆盖可映射字段；移除执行层费用预算字段（`maxCost`）。
    3. 长对话压缩由内置 Agent 在请求之间按固定预留预算触发，使用同模型、独立系统提示、无工具生成结构化交接摘要，以普通记录保存摘要与 `keptFrom` 保留边界，不改写旧历史节点。
  - **理由**：兼顾聚合中转站（OpenRouter、OpenCode、Kimi、智谱等）的协议微调需求与多模型切换时的上下文连续性，同时保持历史树的纯粹不可变。

- **模型参考价格与派生费用（2026-10-15）**
  - **决策**：模型配置保存工坊自有的 API 参考价格结构，币种统一、按模态组织，各计费项分别持有金额、计价单位与基数；由 models.dev 导入边界转换并支持手动编辑。计费不进入上游 usage，费用以已有请求历史和当前价格即时推导，不另存消费账本与历史价格快照。
  - **理由**：现有时间线已保存响应模型和用量，参考费用不需要引入第二套事实存储；同一模态的输入和输出可能按不同单位收费，不能把外部目录的百万 token 单价作为通用结构的限制。分档与字段规则见 [模型配置](model-configuration.md#api-参考价格)。

- **卡片辅助面板与资源内视图（2026-10-15）**
  - **决策**：辅助面板作为卡片公共呈现能力，由资源声明具体内容；agent 的诊断与上下文分别作为独立面板。宽卡片并排、窄卡片覆盖，面板开关保留主体挂载；会话级对象、授权与历史继续使用工作台浮岛。
  - **理由**：诊断、资源授权详情、Git 等旁信息需要一致的入口与局部归属，统一容器可以复用布局和焦点管理，同时把领域数据与操作留在资源模块；避免资源各自实现模态窗并打断主体阅读。

- **卡片缩放手势归属（2026-10-15）**
  - **决策**：缩放默认交给画布，内部缩放组件只在自身交互区域声明接管；普通滚动留在卡片内容区。交互规则见 [画布与对象卡片](workbench.md#画布与对象卡片)。
  - **理由**：整张卡片屏蔽 wheel 会同时阻断画布缩放；组件是否需要缩放无法从可滚动性或 DOM 外观可靠推断。复用 React Flow 的局部声明机制，避免按组件类型猜测或另写画布缩放算法。

## 待确认或待验证的开放问题

以下事项尚未最终定案或需在实际接入后验证（跨会话推进的具体任务见 `plans/`）：

### 工作台与多代理交互
- **画布自动布局引擎**：优先验证 ELK，需结合动态卡片尺寸、手动位置保留与折叠端点验证（见 `plans/todo-2026-09-18-workbench-layout.md`）。
- **快捷绑定与单次输入**：拖入资源时默认仅加入工作台还是支持快捷绑定到目标代理；连线到“下一次输入区”与“持续绑定区”的细化交互。
- **子代理委派与通信工具**：代理创建代理时的默认授权继承方式，以及 `resource_create`、`send`、`wait`、`agent_read` 等代理间通信工具的契约设计。

### 运行时、存储与扩展
- **虚拟资源与检查点格式**：支持状态恢复的虚拟资源检查点（checkpoint）存储格式、恢复原实例与创建隔离实例的操作流。
- **无引用对象回收与崩溃对账**：`objects/<sha256>` 的孤儿文件回收与跨介质崩溃对账；完整模型请求留存与敏感内容保留期限。
- **核心领域共识包拆分**：将 `atelier.core` 的资源与事件纯契约抽成普通领域共识包供外部插件直接引用，以及按需设计跨插件通用 RPC 调用（`plugin.ipc.calls`）。
- **价格与费用计量**：模型调用成本统计与展示（见 `plans/todo-2026-10-14-model-costs.md`）。

### 规模与实测边界
- **工具目录规模与 MCP 接入**：工具数量增长后 `resource_call` 内层 schema 的调用准确率，以及是否需要引入 provider 原生工具搜索或延迟发现。
- **长历史与大画布性能**：大量历史节点、多分支导航密度与多卡片同时挂载时的虚拟化与渲染性能。
