# 决策归档与开放问题

> **阅读说明**：本文档是**历史决策归档（ADR）与未决问题清单**，不是当前功能的规格真值。它按演进时间记录过去为什么做出某项关键架构取舍、排除了什么替代方案，防止后续迭代重新讨论已否决路径。当前生效的详细契约请查阅 `AGENTS.md` 文档地图中的各领域真值文档。

## 历史决策记录（按演进时间排序）

### 2026-09：基础定位、桌面基线与对象边界

- **产品定位与对象边界（2026-09-17）**
  - **决策**：面向比 coding agent 更宽的个人工作台；以对象卡片与有向连线呈现工作，但工具调用默认收纳在代理对话流中；Workspace 存储目录、UI 可见性与连线均不构成隐式授权，所有资源操作在运行时执行层凭显式 `resource_id` 与有效绑定验证。
  - **理由**：把每条消息与工具调用都铺到画布上会迫使用户持续整理布局；将 UI 视图或工作区目录等同于权限会导致不可控的越权副作用。
- **桌面与存储技术栈（2026-09-18）**
  - **决策**：采用 Electron + React + TypeScript、`@xyflow/react`、SQLite（`node:sqlite`）与本地对象文件存储、Zod，以及独立 Node.js 任务进程（`utilityProcess`）；构建用 `electron-vite`，打包用 `Electron Forge`，包管理器固定 `npm`。模型接入采用 Vercel AI SDK 做无状态单步协议适配。
  - **理由**：复杂画布需要统一的 Chromium 与本地 Node 接入；独立任务进程避免模型流与大文件操作阻塞窗口或受 React 组件生命周期影响；任务历史与授权必须由工坊自持，不托付给第三方聊天或 agent 框架的会话存储。
- **两层工具目录与稳定前缀（2026-09-18）**
  - **决策**：动态资源工具作为二级工具经 `resource_call` 调用，其 schema 通过链接通知或 `inspect` 在消息历史后部提供。当时提供的顶层工具为 `resource_list / resource_inspect / resource_call`，这是实现现状，不是顶层工具数量或插件扩展的限制。当前工具契约见 [运行时](runtime.md#工具匹配与宿主操作入口)。
  - **理由**：资源链接变化若直接增删顶层 `tools`，会频繁破坏 provider 提示缓存前缀；将资源变化投影为后续消息事件可保持请求前缀稳定。插件在装配时静态注册的顶层工具不随链接变化，不与此目标冲突（调研依据见 [MCP 延迟加载与提示缓存](mcp-caching.md)）。
- **请求边界固定环境（2026-09-19）**
  - **决策**：每次模型请求开始时固定消息路径、代理配置与已链接资源授权，连同该响应的工具批次使用到底；期间发生的配置或链接变化按真实顺序落入时间线，留待下一次模型请求取用。
  - **理由**：保证单次响应与工具批次内的权限、能力视图与消息前缀自洽，不因执行中途解绑而破坏在途响应的协议配对。

### 2026-10 上旬：窗口视觉、扁平会话树与资源平级

- **原生材质窗口、浮岛编织与官方控件（2026-10-01 ～ 10-07）**
  - **决策**：窗口采用平台原生材质底座（macOS vibrancy / Windows 11 Acrylic），不使用全屏 CSS `backdrop-filter` 或自绘窗口按钮；窗口层次固定为 `Window → Titlebar / Space → Screen → Island`，屏内浮岛放得下分栏、放不下溢出跟随焦点；`shared/ui/` 仅维护 shadcn 官方 registry 源码，通过 Radix Colors 12 级色阶映射语义 token；本地持久化拆分为设置（`appearance.json` / `language.json`）、顺手记录的界面状态（`ui-state.json`）与会话视图布局（SQLite）。
  - **理由**：避免自绘皮肤与手写坐标动画带来的高昂维护成本，让视觉与交互规则集中在一处纯模型中。
- **独立首页与按需加载会话（2026-10-02 / 10-10）**
  - **决策**：启动永远进入无会话身份的独立首页，只读取列表摘要；首次发送被接受时才原子创建 Session、首个代理与首条消息，不预先创建空会话或强制先命名；侧栏只保留「首页」作为新会话唯一入口。
  - **理由**：消除大量空白废弃会话，让用户直接从具体工作意图开始。
- **模型角色、代理配置与局部覆盖继承（2026-10-08）**
  - **决策**：全局配置拆分为提供商、模型角色（`default / heavy / fast / smart / utility`）与代理配置（`worker / explorer / reviewer / researcher / advisor`），保存在独立于会话数据库的 `configuration.json`；角色与代理只持久化用户的局部覆盖字段，运行时与内置原始定义合并（自定义项分别以原始 `default` 与 `worker` 为基准，不互相链式继承）；配置按需读取、消费时校验，不建跨配置外键或级联清空。
  - **理由**：保证内置提示词或默认参数随版本升级时未覆盖字段自动受益，同时避免修改默认项意外污染自定义项，重建会话数据库也不丢失全局配置。
- **会话级扁平树与代理资源化（2026-10-08 ～ 10-09）**
  - **决策**：废除单代理专属消息表，每个 Session 拥有唯一一棵只追加的扁平会话树（`session_nodes`）；代理作为普通一级资源创建与移除，不分主子，输出块平铺在树上，对话从当前时间线即时投影；所有被捕获资源均 `settled` 时才允许回溯游标。
  - **理由**：支持多代理与工作台事件按真实发生次序交错记录，使分支回溯能用同一套重放逻辑重建所有对象与授权关系。
- **正文工具、Hashline 锚点与 Pierre Diffs（2026-10-10）**
  - **决策**：目录与笔记共享 `read / edit / write` 契约；`edit` 采用 `LINE#HASH` 锚点整批校验，后端用 `diff`（jsdiff）生成标准 unified diff；前端弃用重量级 Monaco Editor，统一采用 `@pierre/diffs` 渲染 stacked diff 与代码着色，内置工具正文限制每次调用最多 120 个逻辑行预览预算；笔记定义为未捕获的自有对象，只保存当前正文，回溯不恢复笔记内容。
  - **理由**：在对话流高频展开多个工具块时，Monaco 实例开销过大；Pierre Diffs 轻量且契合只读代码／差异预览，120 行预算防止大文件撑爆 DOM。
- **品牌定名 Atelier 与固定应用身份（2026-10-10）**
  - **决策**：中文定名“工坊”，英文定名 Atelier；应用标识固定为 `dev.dearain.atelier`，显式决定数据目录，内部契约与通道固定使用 `atelier.core/*`、`core.*` 与 `window.host`，与显示名称解耦。
  - **理由**：防止品牌或目录改名导致用户本地数据库、凭据与持久契约身份断裂。

### 2026-10 中旬：插件 SDK、领域收回与多模态/多语言/模型兼容

- **完全信任的插件 SDK、公共模块与领域收回（2026-10-10 ～ 10-13）**
  - **决策**：内置功能全部收敛为随软件分发的 `atelier.core` 插件，与外部插件消费同一个独立版本化的 `@atelier/sdk`；插件采用包形态，启动时编译冻结，完全信任、同进程运行，不设沙箱或配额；通过 `exports["./public"]` 由宿主 ESM 图保证同运行环境共享真实声明实例；宿主只认识通用记录信封（带宿主打戳的 `source: { plugin, resource } | null`）与无状态单步 `models.run / stream / validate`，Agent 消息块、回合循环、终态随最高序号块保存、执行状态投影与命名规则全部收回 `atelier.core` 领域模块。
  - **理由**：插件由用户主动安装，防御式沙箱与字符串事件总线只会增加抽象税而无法提供真正的安全；将 Agent 领域知识移出宿主内核，才能让非对话类资源插件在不依赖 Agent 概念的前提下干净扩展。
- **时间线按需观察快照与双观察入口（2026-10-12 ～ 10-13）**
  - **决策**：区分线性 `timeline` 与全树 `session` 查询范围；快照改为只捕获末端、追加上界与标题的轻量观察柄，按需读取；会话观察拆分为 `committed`（仅新增记录）与 `cursorChanged`（追加、回溯、分叉统一通知最终游标位置），彻底移除工作台历史只读预览模式，工作台始终对应持久执行游标并由全量重放重建。
  - **理由**：消除历史预览模式带来的「当前查看位置 vs 真实执行位置」双轨状态复杂度，让会话标题等历史派生值在任何游标移动后都沿唯一规则同步。
- **公共 i18n 仅服务普通用户（2026-10-12）**
  - **决策**：基于 FormatJS / ICU MessageFormat 建立可选本地化机制，唯一消费者是普通用户；日志、开发诊断、schema 与模型提示／工具协议保持稳定英文，不进入翻译目录；普通字符串始终合法，消息描述绑定 `(owner, id)` 与 `sourceLocale`，逐条回退。
  - **理由**：避免为开发者诊断或模型协议维护多语言目录带来的高昂成本与上下文污染。
- **不可变内容引用 `ContentRef` 与统一文件部件（2026-10-12）**
  - **决策**：宿主统一管理字节暂存、封存与回收，业务 JSON 通过严格单键 `{ "$atelier.content": "<uuid>" }` 引用内容，写入时自动扫描登记持久依赖根；模型输入与工具结果统一收敛为 `text | file` 部件，移除客户端对模型输入模态与 MIME 白名单的配置拦截，按实际 `mediaType` 交由服务端判定。
  - **理由**：避免将大体积二进制转为 base64 塞入 SQLite JSON，同时消除客户端因模型模态元数据滞后而误拦合法文件输入的问题。
- **全局具型瞬态事件总线与资源状态徽标（2026-10-13 ～ 10-14）**
  - **决策**：提供跨进程的全局具型事件总线，区分 `occurrence`（逐条 `all`）与 `snapshot`（可选 `latest` 合并），发布不参与事务、断连不补发；侧栏会话列表以 `latest` 订阅 `ResourceStatusChanged`，展示 `running / failed / awaiting / completed` 徽标与可选进度，进入会话即消费终态。
  - **理由**：让未打开的后台会话能轻量推送运行与待操作状态，而不必频繁查询完整会话正文或把瞬态 UI 提示写进不可变历史树。
- **可组合模型兼容包、跨模型续接与自动压缩（2026-10-14 ～ 10-15）**
  - **决策**：
    1. 协议差异通过预定义的五项兼容包（显式添加到提供商或模型，请求时按 id 整项覆盖合并）表达，不在执行循环中写死品牌或域名分支；思考明文、摘要与签名/密文续接作为协议基线原生支持，跨模型切换时只过滤不匹配来源作用域的原生续接资料，保留公共正文与思考。
    2. 提供商预设作为一次性草稿生成器，不持久化预设身份；参数获取通过 `@opencode-ai/models` 按剥离路由前缀后的模型名精确匹配并直接覆盖可映射字段；移除执行层费用预算字段（`maxCost`）。
    3. 长对话压缩由内置 Agent 在请求之间按固定预留预算触发，使用同模型、独立系统提示、无工具生成结构化交接摘要，以普通记录保存摘要与 `keptFrom` 保留边界，不改写旧历史节点。
  - **理由**：兼顾聚合中转站（OpenRouter、OpenCode、Kimi、智谱等）的协议微调需求与多模型切换时的上下文连续性，同时保持历史树的纯粹不可变。

- **模型参考价格与派生费用（2026-10-15）**
  - **决策**：模型配置保存工坊自有的 API 参考价格结构，币种统一、按模态组织，各计费项分别持有金额、计价单位与基数；由 models.dev 导入边界转换并支持手动编辑。计费不进入上游 usage，费用以已有请求历史和当前价格即时推导，不另存消费账本与历史价格快照。
  - **理由**：现有时间线已保存响应模型和用量，参考费用不需要引入第二套事实存储；同一模态的输入和输出可能按不同单位收费，不能把外部目录的百万 token 单价作为通用结构的限制。分档与字段规则见 [模型配置](model-configuration.md#api-参考价格)。

- **卡片辅助面板与资源内视图（2026-10-15）**
  - **决策**：辅助面板作为卡片公共呈现能力，由资源声明具体内容；agent 的诊断与上下文分别作为独立面板。宽卡片并排、窄卡片覆盖，面板开关保留主体挂载；会话级对象、授权与历史继续使用工作台浮岛。
  - **理由**：诊断、资源授权详情、Git 等旁信息需要一致的入口与局部归属，统一容器可以复用布局和焦点管理，同时把领域数据与操作留在资源模块；避免资源各自实现模态窗并打断主体阅读。

- **请求诊断与上下文洞察（2026-10-15）**
  - **决策**：`models.run` 结果附带按分区组织的请求诊断（系统提示块的种类、来源与字数，声明的工具名称），不含正文；内置代理将其保存为请求诊断记录。上下文面板的窗口占用只用 provider 实报 input，对话与系统构成只用发送文本的精确字数，两种单位不互相换算；缓存命中、压缩历史与增长趋势归诊断面板。
  - **理由**：provider usage 只回报输入总量，任何分项 token 都需要估算；Claude 3 以后与 Gemini 的分词器未公开，本地分词器只要存在不准确的情况就不可信，官方计数接口覆盖不全且需额外请求。系统提示与工具声明由宿主在请求时组装，前端无法取得，只有请求时测量才能还原现场；保存正文既无洞察价值，也会重复写入 AGENTS.md 全文。被排除：本地分词器、按字数比例分摊实报 token、计数 API 差分、渲染端按当前配置预估系统提示。
- **卡片缩放手势归属（2026-10-15）**
  - **决策**：缩放默认交给画布，内部缩放组件只在自身交互区域声明接管；普通滚动留在卡片内容区。交互规则见 [画布与对象卡片](workbench.md#画布与对象卡片)。
  - **理由**：整张卡片屏蔽 wheel 会同时阻断画布缩放；组件是否需要缩放无法从可滚动性或 DOM 外观可靠推断。复用 React Flow 的局部声明机制，避免按组件类型猜测或另写画布缩放算法。

- **插件顶层工具与内置插件公共扩展（2026-10-15）**
  - **决策**：插件模块可以直接声明并注册顶层工具；定义与 handler 一体提供，运行时通过上下文取得当前执行对象和会话，不为资源工具增加自身访问例外。内置插件分为实现包和独立公共契约／API 包，内置实现与外部插件共同消费公共包以扩展现有 Agent，其领域插槽契约不进入通用 SDK。工具边界见 [运行时](runtime.md#工具匹配与宿主操作入口)，公共边界见 [插件 SDK](plugin-sdk.md#公共模块与契约身份)；接口实施与验收见 [归档记录](../plans/archived/todo-2026-10-15-plugin-tools-ui.md)。
  - **理由**：此前三个顶层入口只是实现现状，静态注册的插件工具同样能保持前缀稳定。ask_user 需要调用上下文与用户交互，未来 todo 需要独立存在的面板；强制通过 Agent 资源工具或要求插件重写 Agent 会混淆工具寻址与界面扩展。通用机制先于具体消费者，首批以 ask_user 验收。

- **内置插件物理分包与公共提供方**
  - **决策**：实现为 `@atelier/builtin`，公共声明为独立 `@atelier/builtin-api`，基础控件为内部 `@atelier/ui`；插件身份同步改为 `atelier.builtin`。孵化期开发数据不保留，不建立旧身份兼容或迁移。
  - **取舍**：保留内置静态构建，以应用组合登记公共提供方、注入真实导出；公共包不伪造插件身份，不将内置业务加入免校验白名单。用 semver 校验公共包依赖，SDK API 与领域包版本各自管理。应用信息显式注入，通用模型序列化与 Agent 提示组合分离。
  - **依据**：外部插件须能扩展已有 Agent，并与内置实现取得同一声明对象。当前规则见 [插件 SDK](plugin-sdk.md#公共模块与契约身份)；工具与 UI 能力实施见 [归档记录](../plans/archived/todo-2026-10-15-plugin-tools-ui.md)。

- **Agent 自有的覆盖界面与模态窗**
  - **决策**：界面登记、overlay／modal 呈现及 `hideComposer` 均由内置 Agent 提供，经 `@atelier/builtin-api/renderer` 暴露，内置组件与第三方同等消费；不在 SDK 建立跨资源的通用 UI 槽位。`hideComposer` 隐藏并禁用整个输入区，包括唯一的停止入口，不另设退出按钮；多个请求只组合隐藏条件，不合并业务状态。
  - **理由**：资源形态各异，Agent 的历史阅读与输入区组合才是当前扩展对象。ask_user 可以要求完成面板后返回工具结果，todo 可以长期展示；界面生命周期与工具的具体关联由插件掌握。允许插件长期占用或强制交互，宿主不替作者加入时限或自动解锁。当前规则见 [Agent 扩展界面](workbench.md#agent-扩展界面)。

- **内置问答与无限期用户等待**
  - **决策**：以内置插件的 `ask_user` 作为顶层工具、通用调用和 Agent UI 的首个完整消费者；用户等待不受执行或通信计时器自动终止，运行时退出不承诺恢复未完成调用。当前规则见 [等待用户回答](runtime.md#等待用户回答)。
  - **理由**：工具执行时模型响应已经结束，用户可以离开任意长时间再回答，后台等待无需保持模型连接。将用户思考时间纳入执行超时会使待回答界面无故消失；无限期内存等待也不要求引入持久化工作流或跨重启恢复。

- **Agent 循环不设时间期限**
  - **决策**：移除 Agent `timeout` 配置及整次执行计时，托管任务缺省不设置期限；保留显式取消与模型请求次数上限。网络错误由传输与模型适配层反馈，不另加 Agent 计时器。当前规则见 [执行轮次与循环](runtime.md#执行轮次与循环)。
  - **理由**：循环是等待状态转换的本地状态机，静置本身无需设限；为人机等待暂停并恢复整轮计时会引入不必要的机制。ask_user 只作为首个验收消费者，先提供单题文本回答，不扩展完整问卷产品。

- **Agent overlay 统一悬浮外壳**
  - **决策**：由内置 Agent 提供各位置面板的留白与悬浮表面，插件负责内部内容，不开放插件分别定制外壳；视觉规则见 [对象卡片尺寸](design-system.md#对象卡片尺寸)。
  - **理由**：底部面板隐藏 composer 后应自然承接输入区，保留与卡片边框的距离和阴影。统一外壳使后续插件直接获得一致外观，避免每个插件重复处理容器留白。

- **结构化问答与 GUI 作答面板（2026-10-16）**
  - **决策**：`ask_user` 提供单选、多选、文本及整组结构化答案；底部面板保留对话阅读，多题统一复核，用户主动放大。模型声明问题语义，布局由插件决定；自定义答案、针对选择的限制与整体补充分别保留。
  - **取舍**：沿用已验证的顶层工具、具型调用及内存等待机制；保留 pi-ask-user 的自由表达和提交前修改能力，去掉 TUI 编辑模式切换与必填题阻止导航的限制。草稿跨组件卸载保留，但不引入持久化工作流或跨重启恢复。当前规则见 [等待用户回答](runtime.md#等待用户回答) 与 [结构化问答](workbench.md#结构化问答)。

- **作答选项与补充入口收敛（2026-10-16）**
  - **决策**：单选与多选的自定义项均直接在选项行内编辑、独立勾选；移除逐题补充说明，只保留整组说明。可选题留空在复核与结果中明确表示为跳过。
  - **理由**：自定义回答与逐题说明同时出现在列表下方形成重复编辑框，增加作答负担；可选题要求另点跳过不符合留空即可继续的预期。导航不应隐式触发提交或阻止进入复核。

- **Agent UI 统一滚动区（2026-10-16）**
  - **决策**：overlay 与 modal 内的局部滚动通过公共 `AgentScrollArea` 交给内置 Agent，插件只声明滚动范围和尺寸。
  - **理由**：焦点光圈必须在实际滚动裁切边界内预留空间，单纯扩大 overlay 外边距不能修复任意后代的裁切；标准视口避免各插件重复维护 padding 与对齐补偿，也不强行改写插件任意后代的样式。视觉规则见 [对象卡片尺寸](design-system.md#对象卡片尺寸)。

- **输入框内的统一草稿附件（2026-10-16）**
  - **决策**：首页与 Agent 卡片共用紧凑文件名附件，放在输入框底栏并单行横向滚动；图片预览按悬停／聚焦浮出。当前规则见 [工作台交互](workbench.md#应用首页与导航)。
  - **理由**：附件属于本次待发送输入，独立缩略图区域与多行排列会随文件类型、数量及卡片宽度挤占对话阅读空间。统一条目使输入区高度稳定，同时保留按需辨认图片的能力。

- **会话列表操作按需占位（2026-10-16）**
  - **决策**：会话与历史条目共用完整行表面和整行命中机制，行内操作独立响应；会话状态入口与 more 按钮显示时按实际宽度压缩标题，收起时释放宽度。
  - **理由**：浮在标题上的状态图标影响可读性，固定预留宽度也无法准确覆盖不同状态数量；由布局分配剩余空间可同时保留标题宽度与独立操作入口。当前规则见 [会话列表状态与资源通知](workbench.md#会话列表状态与资源通知)。

- **代理对话的紧凑配置入口（2026-10-16）**
  - **决策**：代理卡片以机器人图标、解析后的模型与思考等级组成单一摘要按钮；局部浮层采用配置行与同层二级选择，首页保留展开选择。当前规则见 [对话配置选择](workbench.md#对话配置选择)。
  - **理由**：对话期间切换配置频率低，三个常驻选择器占用工具栏宽度。逐行入口比三列并排面板更适合以后扩展配置项；同一浮层切换避免画布边缘的多层侧向菜单。摘要提供实际结果，二级选项保留继承意图；图标采用机器人／芯片／大脑，沿用公共视觉语言。

- **模型按提供商浏览与参数预览（2026-10-16）**
  - **决策**：模型入口先选提供商，再在该提供商内搜索模型；列表旁预览当前候选的已有参数与参考价格，浏览与提交分开。当前规则见 [对话配置选择](workbench.md#对话配置选择)。
  - **理由**：聚合提供商的数百个模型不应淹没其他连接；在选择时直接查看上下文、输出配置与参考价能减少跳转设置页。只使用已有目录资料，不编造智能／速度评分；局部加宽的预览仍属于同一个配置浮层。

- **只读文本计量统一缩写（2026-10-16）**
  - **决策**：token 与字数的只读展示统一采用 `k / M / G / T`，单位使用 `toks / chars`；以原生 `Intl.NumberFormat` 处理量级与舍入，保留完整编辑值和原始数据。规范见 [文字、图标与控件](design-system.md#文字图标与控件)。
  - **理由**：百万级逗号分组数字占据过多空间，本地化为「万／亿」又使不同语言的展示尺度不一致。共享格式化入口覆盖配置提示、模型参数、诊断、上下文与工具摘要，避免各处重复计算。

- **公共对象卡片采用单行标题栏（2026-10-16）**
  - **决策**：代理及其他资源统一由公共 `ObjectCard` 提供类型与名称并排的紧凑标题栏。视觉规范见 [对象卡片尺寸](design-system.md#对象卡片尺寸)。
  - **理由**：上下两行文字配合较大留白，使标题栏与右侧紧凑按钮比例失衡，也挤占正文空间；统一外壳可让各类资源保持相同的标题层级与密度。

- **对象面板集中管理卡片显隐（2026-10-16）**
  - **决策**：公共卡片移除标题栏的隐藏 X；对象面板保留整行定位，以嵌在条目内的睁眼／闭眼按钮表达当前状态并切换显隐。交互规范见 [对象面板](workbench.md#辅助浮岛面板对象授权与历史)。
  - **理由**：X 容易与关闭、移除或停止混淆，也容易误点。隐藏与恢复入口放在同一目录便于找回对象，整行表面与独立行内操作兼顾快速定位和紧凑布局。

- **请求计时与诊断速率（2026-10-17）**
  - **决策**：请求起止日期时间和单调时钟测得的耗时、输出偏移与 usage 一起归入响应终态计量；工具调用响应终态就是本次模型请求的计时终点。未取得终态的失败保留实际测得的计时现场，旧记录不补造。诊断计时与计速的展示口径见 [代理诊断](workbench.md#代理诊断)。
  - **理由**：诊断需要恢复当时的有意义现场，保存原始计量和结构概要即可；TPS 与汇总是查看时的计算结果，不另存次级数据。日期时间便于定位但会受系统校时影响，耗时需独立使用单调时钟。流式增量不等于 token，隐藏思考和摘要也不等于完整输出，不能据此宣称精确生成速率。

- **对话按轮次保留计量概要（2026-10-17）**
  - **决策**：逐请求 token 行改为各个已收束 turn 末尾的计量概要，历史轮次保留以便回顾比较，当前执行轮暂不显示。输入区只有上下文占用，缓存与吞吐归入轮次概要；只读详情沿用悬停／键盘聚焦触发。统计沿用用户输入界定的 turn，继续执行不另起统计，整体时间线与逐请求分析留在诊断。规则见 [对话计量](workbench.md#对话计量)。
  - **理由**：工具续轮会产生多个模型请求，逐请求计量行打断阅读；用户更关心一轮对话的整体用量与性能，也需要与之前轮次比较。输入区重复显示缓存与吞吐没有必要，只读数据也不需要点击操作。以总量比值汇总可以避免简单平均请求百分比或 TPS 的偏差。

- **轮尾复制最终回复（2026-10-17）**
  - **决策**：轮尾采用左侧计量、右侧操作，只复制最终回复的 Markdown 正文，不导出执行过程，也不提供分享入口。具体范围与反馈见 [对话计量](workbench.md#对话计量)。
  - **理由**：直接复制最终产出已满足内容转用需求；整轮导出需要额外定义工具摘要表达，系统分享还引入平台差异，当前无需承担这些扩展。

- **对象聚焦移入左侧浮岛（2026-10-17）**
  - **决策**：卡片内容可移到工作台左侧的聚焦浮岛，作为受控前置浮岛与侧栏、工作台共同编织；所有资源统一由宿主提供入口，不新增 SDK 声明。内容从卡片卸载后在浮岛重新挂载，聚焦对象身份按会话保存在应用内存中，不持久化。卡片隐藏不结束聚焦，对象离开当前投影才结束。规则见 [对象聚焦](workbench.md#对象聚焦)。
  - **理由**：用户大部分时间只关注主要代理，资源链接不需频繁调整；把内容移出画布而不是覆盖工作台，两者可并排使用，因此不叫「最大化」。会话前端本来就随切换卸载、切回按需加载，只保留一个对象身份即可恢复聚焦，无需扩展存储格式。保持同一组件实例需要引入 portal 类依赖并改变卡片内容的生命周期，而重新挂载的代价（滚动位置等局部状态）与切换会话一致，按对象保留的草稿不受影响。隐藏卡片是工作台布局选择，聚焦内容已不在工作台中，二者不重叠。

- **会话视图生命周期统一为两层（2026-10-17）**
  - **决策**：前端按会话持有的状态分为视图态与保留状态。视图态（控制器投影与进度、工作台环境出口等）跟随会话可见性：最后一个连接断开且没有在途命令时释放，同步重连不触发，再次进入重新读取。保留状态（草稿、提交身份、聚焦身份）由宿主对象保留表按对象持有，每份就绪投影发布后释放不在其中的对象；SDK 经 `RendererObjectContext.retained` 暴露 `get / discard`，内置 Agent 草稿与聚焦都迁移到这张表。规则见 [会话视图生命周期](workbench.md#会话视图生命周期)。
  - **理由**：资源只是数据，任务在后台运行，界面不需要常驻未展示会话的投影；全局只保留轻量的用户意图，其余按需加载。原先各模块自建 Map、释放规则各异，草稿在对象移除后永不关闭，其内容占用还会阻止回收；统一由宿主持有生命周期，插件只声明创建与释放，不会遗漏清理。释放条件取「不在当前投影」而非仅 `object.remove`，与聚焦一致，代价是跳到对象出现之前时草稿丢失。替代方案「宿主广播对象释放事件、插件自行清理」要求每个插件都记得订阅，未采用。在途命令收束前保留同一控制器，使命令与其后读取仍按会话串行。

- **主题色进入激活状态、默认灰改为中性（2026-10-17）**
  - **决策**：默认灰色由 sage 改为 gray；`secondary`（当前项与标签）改为主题色 3 级浅底配 AA 文字，`ListRow` 选中态随之使用 `secondary`；亮色边框退一级；亮色 `background` 改回白色，工作台等画布区域改用新增的 `canvas` token。主色保持亮色 11 级、暗色 9 级。字号层级与表面无阴影的约定不变。规则见 [已确认的视觉](design-system.md#已确认的视觉)。
  - **理由**：原界面「老气」来自带色相的灰把整体染成灰绿，且主题色只出现在主按钮与焦点环，激活状态全是灰色。中性灰让主题色成为唯一色相，激活状态带色后界面更有层次。shadcn 组件把 `background` 当作页面白底，原先取灰阶 3 级使对话框、白卡片上的 outline 按钮变灰，激活 tab 与 `muted` 列表同色难以分辨；画布灰底因此单独成 token。试验过的候选未采用：主色亮色改取 9 级时白字对比度仅约 3:1，改配深色字虽达 AA，但 `text-primary` 作链接文字仍不达标，且活力主要来自激活状态而非主按钮明度；放大页面与区块标题会降低内容密度；按钮按压缩放观感提升有限，且需要在官方控件外写全局样式；表面阴影违背内容面无阴影的约定。

- **扩充主题色与调色板，新增石墨无彩模式（2026-10-17）**
  - **决策**：主题色从 8 个扩为按色相环排列的 12 个（新增 cyan、grass、tomato、plum），另加 `graphite` 以灰阶作主色；灰色新增 olive。调色板整理为 12 组，默认组合 jade + gray 即「苔原」，其余多数配中性灰，暖色与紫色系配同调灰。存储 enum 只追加值，旧配置照常读取。规则见 [已确认的视觉](design-system.md#已确认的视觉)。
  - **理由**：原预设缺少默认组合，苔原仍是被弃用的 jade + sage；色相集中在冷色，暖色与大地色不足。石墨提供 Codex 式的克制外观；当前项若沿用 `secondary` 浅底会与 `muted`、hover 同色，因此取比 hover 深一级的灰阶作底，保留选中可分辨。

- **工作台连线风格作为全局外观偏好（2026-10-17）**
  - **决策**：在外观设置的画布区域提供曲线、直角折线与圆角折线，使用 React Flow 内置路径与拖线预览能力。当前规则见 [连线与授权交互](workbench.md#连线与授权交互)。
  - **理由**：用户需要在平滑曲线与横平竖直的连线间选择；统一外观偏好便于跨会话保持一致，无需为每条链接存储样式或引入布线依赖。保留曲线默认值使旧配置继续保持原有外观。

- **Agent 输入工具栏统一使用贡献机制（2026-10-17）**
  - **决策**：沿用 Agent UI 的登记和生命周期，增加工具栏呈现入口；内置模型选择器与上下文占用也作为普通工具栏贡献。提供关联 Agent 当前模型选择的只读接口，界面共同消费同一解析结果。规则见 [Agent 扩展界面](workbench.md#agent-扩展界面)与 [前端视图与扩展入口](plugin-sdk.md#前端视图与扩展入口)。
  - **理由**：常驻状态需要紧凑的输入区位置，现有 overlay 外壳面向独立面板。现有贡献登记与 React Portal 足以支持新位置，无需另一套插件框架或跨资源槽位；内置两个真实组件可直接验证机制，避免为验证扩展而编造插件需求。UI 常驻不等于业务数据持久化，具体额度查询及认证仍属于未来业务插件。

- **插件工具按用户顺序覆盖（2026-10-17）**
  - **决策**：顶层工具允许外部插件以同名完整声明替换内置或其他插件工具；资源工具同时支持共享契约下的按资源类型替换实现，以及同名新契约的全局替换。覆盖依据用户列表，公共依赖初始化顺序不影响优先级，旧契约的后续引用不恢复已被替换的 schema。当前规则见 [工具匹配与宿主操作入口](runtime.md#工具匹配与宿主操作入口)。
  - **理由**：内置 `ask_user` 的问答体验和 `read / edit` 的 hashline 机制都应允许插件作者改进，不为随软件分发的工具保留覆盖特权。保留共享契约时可局部替换资源实现；改变 schema 时必须让旧实现整体下线，避免模型参数与 handler 不一致。稳定 ID 继续区分实现和历史展示，宿主资源路由入口继续承担授权与分发职责。

### 2026-10-18：配色语义归位

- **普通标签与持续选中态分离（2026-10-18）**
  - **决策**：按控件含义分配配色，普通标签与次级操作恢复中性，持续选中态单独使用 `selected`；徽章区分主题强调、中性与成功／警告／错误，进行中与就绪使用不同语义。当前规则见 [已确认的视觉](design-system.md#已确认的视觉)与 [状态与反馈](design-system.md#状态与反馈)。
  - **理由**：此前为扩大主题色应用，把当前项与普通徽章共同映射到 `secondary`，使内置、归属等没有强调含义的标签也被染色。将持续选中态拆开，可以保留导航的主题色反馈，同时恢复普通标签的中性语义；实色填充与文字色分别映射，避免暗色强调文字及写死白字造成对比度不足。

### 2026-10-18：对话阅读导航

- **代理对话采用贴边短柱导航（2026-10-18）**
  - **决策**：按用户确定的形式，以每条用户消息为锚点，在阅读区左边缘悬浮显示短柱；悬停使用相邻波形与有界文本预览，点击定位消息。交互真值见 [对话导航](workbench.md#对话导航)。
  - **理由**：长对话需要按提问快速回看，贴边浮层保留卡片正文宽度；限制预览字数与行数，避免粘贴代码撑满屏幕。参考 [Vivid Layer Chat Minimap](https://www.vivid-layer.com/components/chat-minimap) 的邻项放大形式，以现有 Button / Tooltip 组合并接入本地消息 ID 和滚动跟随机制，不引入另一套消息滚动容器。

### 2026-10-18：工作台状态反馈归属

- **工作台只提示阻塞与读取异常（2026-10-18）**
  - **决策**：移除常驻的工作台就绪徽章，将操作进度、视图同步、读取失败和后台不可用分别表达；读取异常由工作台统一承接。当前规则见 [工作台状态反馈](workbench.md#工作台状态反馈)。
  - **理由**：“本地工作台”不能说明用户当前能做什么，“保存中”又混合了操作、读取及错误状态；多个卡片和全局通知重复呈现同一读取失败会制造噪声。明确反馈归属后，正常画布保持安静，等待与失败各有准确文案，恢复入口紧邻问题说明。

### 2026-10-18：流式 Markdown 与富内容渲染

- **使用 LobeHub Streamdown 的原生平滑输出与渐入**
  - **决策**：使用独立的 `@lobehub/streamdown`，保留原生动画；图片、Pierre 代码着色、KaTeX 公式与 Mermaid 图形经公开组件和插件接口接入，不 patch 库或覆盖动画时序。当前渲染规则见[代理卡片与工具调用视图](workbench.md#代理卡片与工具调用视图)。
  - **理由**：Vercel 2.7.0 的旧字符归零时长机制会提前结束高频更新中的渐入，按空白分词也不适合中文。LobeHub 将输出节奏、块队列与文字动画生命周期交给渲染引擎统一维护。独立包不要求引入完整 UI 体系；取舍是跨块引用存在限制，原生组件不附带工具栏，应用仅提供代码语言名与源码复制。

### 2026-10-18：Mermaid 与工坊视觉统一

- **使用公共 token 配置 Mermaid 官方基础主题**
  - **决策**：图形默认外观通过 `base + themeVariables` 和图类配置接入工坊设计系统，规则见[对话过程视图](design-system.md#对话过程视图)。
  - **理由**：官方默认主题的配色、字体与间距独立于应用，容易使嵌入图形显得突兀；消费公共 token 可以跟随用户外观设置，保留 Mermaid 自身的布局与渲染能力，无需维护 SVG 后处理。

### 2026-10-18：插件作用域与自定义设置页

- **插件拥有设置与共享服务，模块承担功能组合**
  - **决策**：设置总览上下展示带 header 的应用区与插件信息卡片区；插件提供自己的设置页面，宿主提供统一承载与打开入口。插件具有自身的装配、共享服务与清理责任，模块继续通过显式依赖组合。配置托管为可选服务，与页面登记独立；复杂业务可自管数据。具型调用在同一机制内区分插件级与对象级作用域。最终契约见 [插件 SDK](plugin-sdk.md#模块与装配)与 [设置总览与插件管理](workbench.md#设置总览与插件管理)。
  - **理由**：自动表单无法充分表达分组、账号登录、连接测试及复杂业务交互；继续增加布局描述会扩大表单机制的职责。现有配置、凭据与按需数据库仍可减少插件作者的基础工作，无须因开放页面定制而移除。插件共享服务也不应被迫寄存在占位模块中；全局设置操作不应要求虚构资源引用。市场入口属于插件列表工具区，其位置不要求同时建设市场服务。

### 2026-10-18：跨平台标题栏与全屏避让

- **窗口层统一管理标题栏模式和控件安全区**
  - **决策**：macOS 保留原生红黄绿；Windows/Linux 通过 Electron 官方覆盖式标题栏绘制窗口控件，Linux 保留系统装饰启动选项。布局与状态契约见 [原生窗口与 Web 内容](design-system.md#原生窗口与-web-内容)。
  - **理由**：按钮隐藏后的固定留白和右侧菜单重叠应由窗口层共同解决。使用官方全屏事件与覆盖区域几何，兼顾系统缩放、Linux 按钮位置和全屏内刷新；避免应用维护窗口按钮交互或通过窗口尺寸猜测全屏。

### 2026-10-19：模型目录格式独立识别

- **模型列表与消息协议解耦**
  - **决策**：模型发现根据响应结构识别目录格式，解析器不接收提供商或消息协议；请求地址与鉴权继续沿用连接约定。支持范围与解析边界见 [模型发现与添加](model-configuration.md#模型发现与添加)。
  - **理由**：同一提供商可提供多种推理协议并共用模型目录；智谱 Responses 入口实测返回 Codex 风格的 `models / slug`，绑定 OpenAI 的 `data / id` 会把正常响应判为错误。采用已知结构识别，无需用户维护第二套协议设置；未知或损坏结构明确失败，避免宽松字段猜测把错误响应当成成功目录。

### 2026-10-19：思考等级与预算映射

- **协议默认能力与用户自定义映射分离**
  - **决策**：协议适配内置等级与手动预算映射，分别由 `customThinkingLevels`、`customThinkingBudgets` 覆盖；预算包不承担思考模式切换，公共等级和历史不变。规则见[思考等级与预算映射](model-configuration.md#思考等级与预算映射)。
  - **理由**：Anthropic 的预算思考应能在没有兼容包时直接使用，只有用户要调整数值时才需要兼容包。effort、adaptive 和预算是不同维度；SDK 的枚举校验、自动等级降级和预算叠加不能代替宿主的显式配置，因此在最终协议编码处维护有限字段的确定行为。

### 2026-10-19：兼容配置选择边界

- **预设提供已核实配置，自定义连接由用户配置**
  - **决策**：取消模型专属兼容资料与推荐入口的延后事项；配置选择边界见[提供商预设](model-configuration.md#提供商预设)。
  - **理由**：提供商预设已经承担已知连接的配置引导。使用自定义提供商意味着用户了解其上游需求并自行选择设置，无需再建设模型级兼容推荐机制。

### 2026-10-19：会话资源操作与 Agent 创建入口

- **通用创建契约与模型创建通路分层**
  - **决策**：SDK 提供会话枚举及会话内具型创建、链接、解除链接、移除；内置公共 API 提供 Agent 创建入口声明，内置工具按入口创建并自动链接。最终契约见 [插件 SDK](plugin-sdk.md#会话目录与资源操作api-91) 与 [Agent 创建与移除](runtime.md#agent-创建与移除)。
  - **理由**：调用方应组装公开输入，由资源提供方初始化私有状态。模型输入可能比前端或插件输入更窄，单一 `agentCreatable` 标记不能表达转换和领域条件；另建具型领域入口能复用宿主创建管线。schema 的获知方式不限，不把 inspect 当授权握手，也不把签名知识当权限凭证。
- **统一移除，不设资源继承权**
  - **决策**：移除由一个通用工具消费宿主能力，用户和插件共用收束检查；资源不继承创建者的链接或访问权限。生命周期语义见 [对象模型](object-model.md#resource可被操作的对象)。
  - **理由**：已有对象的身份、存在性、链接和忙碌状态可由宿主统一判断，逐类型声明销毁入口只会重复生命周期规则。移除工作台对象不等于删除外部实体。子代理通信与 skill 组织仍按实际需求单独设计。

### 2026-10-20：预设组合连接与编辑体验

- **编辑规则随连接保存，不引入提供商类型身份**
  - **决策**：预设一次性组合普通连接配置与 `fixedFields`；通用编辑器按规则隐藏固定项，保存边界保留固定值，执行端继续只消费协议、认证和兼容包。当前契约见[提供商预设](model-configuration.md#提供商预设)。
  - **理由**：预设用户需要简洁的凭据配置体验，自定义连接仍需自由组合。定制编辑体验本身可以由有限字段规则表达，无需持久化 `kind`、反推 endpoint 身份或在 UI／模型执行端维护厂商品牌分支。保留预设的一次性复制语义，目录调整不接管已有连接。
  - **范围**：本轮实现连接编辑规则与 UI；账户用量查询和 OAuth 认证另行推进，后续事项见[账户用量与认证计划](../plans/todo-2026-10-20-provider-usage-auth.md)。

- **预设与用量查询均由插件提供，展示独立消费**
  - **决策**：SDK 定义预设新增／修改、查询提供方及账户用量消费接口；内置插件是首个预设与智谱查询提供方，其独立 toolbar 模块是首个消费者。目录引用、结果类型与 UI 规则分别见[账户用量](model-configuration.md#账户用量)、[提供商贡献](plugin-sdk.md#提供商与用量目录api-100)和[工具栏交互](workbench.md#账户用量工具栏)。
  - **理由**：预设只是连接组合，查询实现与展示可以由不同插件提供；同名预设／查询 ID 方便关联但不恢复持久提供商类型。统一结果列表可同时表达 balance 与 quota，避免以提供方类型互斥、两套缓存或假 token 分母限制后续扩展。toolbar 选最短周期余量，全部窗口在 tooltip 中展开。

- **用量来源与结果类别分离，响应头被动更新**
  - **决策**：同一用量目录支持主动 query 与被动 headers；消费者将模型响应交给所选提供方归一化。限流结果明确标注类别与请求模型，原始 header 不进入历史。契约见[账户用量](model-configuration.md#账户用量)。
  - **理由**：OpenAI、Anthropic、xAI 的限流余量随响应交付，不适合定时探测。被动来源无需凭据读取或额外模型请求；观察失败不能破坏正文流，重置字段也不能被解释为套餐余额或客户端自动补满额度。

- **提供目录，消费策略归插件**
  - **决策**：提供商与用量沿用模型服务的边界。宿主交付 `providers / usages` 目录、显式凭据读取；响应元信息随 `run` 返回结果与 `stream` 结束事件交给调用者，不另设响应回调。内置插件拥有自己的缓存、轮询、事件和 toolbar，其他消费者独立取用目录。SDK API 升至 10.0，移除宿主统一查询状态与前端 hook。契约见[提供商目录](plugin-sdk.md#提供商与用量目录api-100)。
  - **理由**：目录注册不意味着宿主代为消费。把用量状态归入配置服务、由模型执行直接接入用量缓存，会耦合原本独立的提供方和消费者，并限制 dashboard、其他 Agent 对连接、刷新和展示范围的选择。公共接口表达原始能力，组合策略留给调用插件。

### 2026-10-21：模型选择说明与使用指导

- **按选择与使用组织模型可见信息**
  - **决策**：明确 description 与 guidelines 的职责及列表发现边界，见[工具说明契约](runtime.md#工具匹配与宿主操作入口)。本阶段保留已有运行行为，提示内容的全面收敛随能力补齐推进，见[运行时计划](../plans/todo-2026-10-01-runtime-capabilities.md#模型说明与指导收敛)。
  - **理由**：列表需要用途描述帮助模型选择，详情需要选定后的使用指导，两者不能按字面重复一概删除。当前委派、工具目录等仍在建设中，不能将开发中间态直接判断为最终描述错误，也不应靠反复强调内部环境规则补偿尚未完成的操作能力。

- **Harness 原语、代理发现与显式初始资源链接（2026-10-21）**
  - **决策**：harness 文本以陈述表达原语与基础设施规则，工作流由用户组合；清理否定指令及用临时能力缺口定义行为边界的提示。代理发现采用选择字段白名单，创建可附带调用者请求范围内的资源列表。当前契约见 [运行时](runtime.md#代理控制器与请求环境)、[代理配置](model-configuration.md#代理配置) 与 [创建入口](runtime.md#agent-创建与移除)。
  - **理由**：调用方需要选择依据，被选代理的工作方式由其自身提示词承载。将“尚未实现”写成禁止事项或规定工具调用顺序，会把开发阶段状态固化为 workflow。显式资源列表使授权范围可审查，宿主事务保证创建与全部初始链接整体生效。

- **精简代理选择信息（2026-10-21）**
  - **决策**：代理定义以描述和任务示例承载选择依据，移除独立选择条件及其配置界面。公开列表与领域定义同步精简，见 [代理配置](model-configuration.md#代理配置)。
  - **理由**：描述表达适用场景，示例将其具体化；额外的条件字段重复同一语义，增加维护负担，并容易夹带调用流程。

- **创建领域参数归入口（2026-10-21）**
  - **决策**：通用模型创建工具只传递入口 ID 与入口输入；Agent 的初始资源列表由自身入口声明和适配，宿主保留通用初始链接的授权校验与原子提交。契约见 [创建入口](runtime.md#agent-创建与移除)。
  - **理由**：将代理专用参数放在公共工具外层，会让笔记等资源暴露无意义的输入并延迟到执行时失败。入口负责领域参数，宿主负责基础机制，两者独立演进。

- **创建工具围绕资源展示（2026-10-21）**
  - **决策**：公开资源类型展示目录与模型创建入口到类型的查询；工具标题使用本地化类型标签，创建成功后显示通用创建结果中的实例标题。当前契约见 [前端视图接口](plugin-sdk.md#前端视图与扩展入口) 与 [创建工具视图](workbench.md#工具调用三态视图)。
  - **理由**：用户关心资源类型和具体资源，入口 ID 服务寻址。类型名复用资源提供方的本地化声明，避免按内置资源硬编码；最终标题由资源创建实现决定，读取通用结果可覆盖无标题输入的资源，并保留不依赖当前对象状态的历史摘要。

- **Agent 记录调查与流式报告（2026-10-21）**
  - **决策**：peek 作为 Agent 的只读资源工具，目标身份沿用授权资源引用；自己将时间线投影为记录快照，通过 utility 的独立 stream 请求执行检索并输出报告。动态状态留在 header，body 使用思考式报告预览，开合偏好归内置插件设置。契约见 [运行时](runtime.md#agent-记录调查peek) 与 [工具视图](workbench.md#工具调用三态视图)。
  - **理由**：工坊拥有原始会话树和动态工具标题，能够查询压缩前证据并持续展示检索进度，无需依赖目标代理的模型上下文、跨实例传输或额外工作台代理。报告随调用方工具结局保存，保持目标历史与调查执行的职责清晰。

- **操作失败归发起入口（2026-10-21）**
  - **决策**：会话控制器仅保存读取异常，操作失败随回执交给发起入口；代理对话不汇总通用错误。当前规则见 [工作台状态反馈](workbench.md#工作台状态反馈)。
  - **理由**：共享操作错误会丢失发起对象与操作的归属，使其他卡片和面板显示无关错误；入口直接消费回执可以保留表单反馈和即时通知的边界。

- **请求资料随终态、无输出反馈瞬态化（2026-10-21）**
  - **决策**：公共 completion 提供具型领域扩展，Agent 请求资料与 usage 随最高序号实际块一次保存；无块失败、取消与空响应仅即时提示。契约见 [请求诊断](runtime.md#请求诊断) 与 [时间线](timeline.md#不完整内容与异常收束)。
  - **理由**：独立诊断节点会在游标回到终态块时切断同一请求的资料，使上下文混用不同请求。领域数据由引入方声明和消费，公共层保留未知扩展，避免把 Agent 面板模型固化进 SDK。没有输出时保留用户输入就足以表达历史，不为计量或界面补造响应。

- **孵化期直接采用当前契约（2026-10-21）**
  - **决策**：首发前不维护旧接口、旧存储载荷或旧行为的向后兼容，删除旧分支与兼容测试，不为开发历史引入迁移。项目操作边界见 [项目规范](../AGENTS.md#决策操作与提交约定)。

### 2026-10-22：共享交互终端与资源存在性

- **决策**：用户与模型操作同一 PTY 和后台终端状态；模型通过文字／图片观察屏幕并发送字符或按键，shell 集成只提供就绪和执行边界。运行实例不跨软件重启恢复。
- **理由**：shell 拥有待编辑命令，终端流本身不提供可靠的输入区或命令输出归属。保留真实交互能覆盖普通运维、服务器和文本应用，避免维护独立命令编辑器；最小集成满足关闭确认与等待需求。
- **决策**：资源生命周期表达当前集合中的出现／消失，涵盖普通提交和回溯；初始化策略归资源模块，消失后的清理异步跟随，插件退出等待清理。终端领域状态不充当宿主时间线 busy。
- **理由**：视图挂载和历史动作都不能完整表达外部实例寿命；统一存在性通知能清理回溯移除的对象，同时允许模拟器与终端采用不同初始化规则。
- **实现取舍**：采用 node-pty 与 xterm 系列库；公共层只提供存在性观察、结束提示和模块级前端调用，终端协议、屏幕与进程管理留在内置模块。当前契约见 [对象模型](object-model.md)、[插件 SDK](plugin-sdk.md) 与 [终端资源](runtime.md#终端资源)。

### 2026-10-22：renderer 与任务进程直连、对象通道与终端实例模型

- **决策**：renderer 与任务进程经主进程交接的 MessagePort 直连，所有任务进程业务流量（命令、会话推送、事件、调用、对象通道）多路复用于一条连接；主进程只保留窗口、系统能力、凭据、任务进程监护与退出确认。
- **理由**：此前每条消息经 renderer → main → utility 两跳转发，main 与 preload 各做一次 Zod 解析，main 事件循环繁忙会拖慢所有通道；终端逐键往返与流式正文都受此影响。直连后来源校验在交接端口时完成一次，领域命令结构仍由任务进程入口解析。
- **排除**：保留主进程转发、仅为终端加专用通道——高频问题不限于终端，两套传输会长期并存。
- **决策**：`session.progress` 的流式块按块 ID 增量交付，追加文本只发尾部。
- **理由**：原实现每 32ms 重发全部累积正文，长回复传输量为 O(n²)；与传输方式无关。
- **决策**：输入阶段的工具调用块只传 `argumentsText`，预览参数由宿主前端以 `partial-json` 宽容解析推导，后台同一实现只用于调用身份；进入 ready 后下发一次完整参数。SDK 块类型不变。
- **理由**：原文与预览是同一份模型输出的两种形态，整字段替换的预览使写大文件等工具传输量为 O(n²)。
- **决策**：流式块增量按 JSON 路径生成，工具执行中的 `result` 同样只传变化部分；持久化工具调用记录的 `argumentsText` 只在没有解析参数时保留，已解析时为 null。
- **理由**：执行中结果（如命令输出尾部）随进度整值重发同样是平方级；解析成功时原文与 `arguments` 重复，执行与上下文投影均以 `arguments` 为准，原文只在参数缺失时用于展示与排查。
- **决策**：renderer 直连请求不设单次期限，任务进程卡死由主进程心跳检测（5 秒间隔、15 秒期限）后结束进程并广播 unavailable。
- **理由**：会话命令与插件调用可合法地长时间运行，按请求设期限会误杀正常操作；存活是进程级事实，由监护方判定一次即可结算所有在途请求。
- **排除**：按 JSON 路径的结构化补丁——同一信息仍传两遍并需第二套补丁协议；渲染端引入 AI SDK `parsePartialJson`——会把 provider 栈与 `undici` 带入 renderer。
- **决策**：新增 SDK 对象级双工通道（API 15.0），删除 `streams.publish / onStream`；资源结束提示改为确认时查询，不进入工作台投影。
- **理由**：单向字节流无法承载输入、确认与流控；状态写入投影会让每次状态变化重投影并刷新会话列表。
- **决策**：终端资源对象只是实例入口：仅新建时自动开启，回溯恢复与软件重启后为未开启；卡片关闭结束实例保留资源，shell 退出后可重新开启；模型输入不自动重启已退出的 shell。实例状态经终端通道交付，会话列表只标记开启失败。
- **理由**：回溯恢复自动开启会在用户不知情时启动进程；已退出后自动重启会让模型在环境不同的新 shell 中继续执行。交互 shell 的每条命令或常驻服务器不适合作为会话完成／运行标记。
- **实现取舍**：shell 集成改用 OSC 133/633 语义并带实例 nonce，脚本固定写入插件目录共用；macOS 默认登录 shell，Bash 登录模式由脚本模拟。输出 5ms 合批并以前端确认字符数做水位流控；前端 xterm 使用 `@xterm/addon-webgl` 0.19.0（与 xterm 6.0.0 同批发布），上下文丢失回退 DOM。结束实例先 SIGHUP，宽限后对后代进程 SIGKILL。

### 2026-10-22：资源工具共享声明进入公共 API

- **决策**：`list / read / edit / write / see` 与新增的 `wait` 声明移入 `@atelier/builtin-api`，说明文字与资源无关；target 与结果由各资源实现。终端改为实现 `read / see / wait`，读取选择（屏幕、缓冲、原始输出）移入 target；代理实现 `wait`，等待被链接代理收束。
- **理由**：工具声明只定义参数与语义，同一语义只要参数一致就应复用，资源差异由 target 与结果表达；声明在内置实现包内时第三方资源无法实现。`wait` 统一"等待资源静止"，静止含义由资源定义。
- **排除**：`terminal_input` 并入 `write` 或改名为公共 `append`——两者表示写入并成为目标内容的一部分，终端输入由前台程序消费、不保证留在屏幕上，按键名称也只适用于终端，因此保留为实现包私有工具。

### 共用 Shell 配置发现

- **决策**：内置 Shell 模块提供 `shell_profile_list` 顶层查询，供目录 `exec` 与终端创建发现配置、默认选择和可执行文件可用性；查询与执行复用解析规则。当前契约见 [Shell 配置与进程](runtime.md#shell-配置与进程)。
- **理由**：终端创建需要在资源出现前取得 profile ID，目录命令也需要了解默认 Shell；以共享模块提供静态工具能覆盖两种用途。动态配置留在工具结果中，避免嵌入创建 schema 改变工具描述；已配置与本机可用分别表达。

### 2026-10-23：终端输入后的短时状态观察

- **决策**：模型终端输入采用固定 250ms 的反馈收集窗口，再返回已解析的状态；工具说明陈述观察时机与 idle 的含义。当前契约见 [终端资源](runtime.md#终端资源)。
- **理由**：输入写入后立即读取的状态通常早于 shell 的执行反馈，容易产生短命令也追加一次等待的调用。短时观察让模型依据实际状态选择后续操作，同时保持输入成功与命令完成的独立语义。
- **排除**：仅说明短命令通常很快完成——说明不能补足返回时尚未观察到的执行反馈。

### 2026-10-23：MCP 模块内的工具发现与连接策略

- **决策**：MCP Host 资源作为共享服务器集合的授权入口，远端工具目录、搜索与分发全部由内置 MCP 模块拥有，宿主只注册固定资源工具。当前契约见 [MCP 模块](mcp.md)。
- **理由**：远端工具和说明可能很多，模型通过搜索与 inspect 分段取得信息；将每项远端工具纳入宿主能力目录会扩大机制与上下文成本。模块独立装配和释放，宿主无需新增动态工具注册能力。
- **决策**：服务器由工坊可视化自管，不做外部清单导入／引用；仅支持 stdio 与 Streamable HTTP。eager/lazy 只决定连接时机：两种模式启动时都读取持久目录，lazy 按需连接并按 TTL 回收。
- **理由**：保持单一配置真值和两个明确的连接模式，避免外部格式适配与连接策略组合。未索引服务器随搜索第一页交付，使首次 lazy 发现可以通过 connect 继续完成。
- **决策**：每台服务器全应用一个共享会话，多个会话、多个 MCP Host 对象共用同一连接与进程；连接、授权等待与断开串行过渡，调用遇到连接中或等待授权时阻塞等待，不另起连接。
- **理由**：MCP 服务器是外部状态，按会话隔离连接与实际用法相悖；有状态服务器的共享后果由服务器自身承担，宿主不兜底。等待授权与等待用户回答同属用户操作等待，代理循环是静态机制，阻塞不影响模型。
- **决策**：`tool_id` 采用 `server_id/tool_name`，服务器 ID 为创建时确定的可读 slug。
- **理由**：JSON 元组或 UUID 句柄要求模型在字符串参数中书写转义结构，审计时也难以辨认；slug 不含 `/`，按第一个 `/` 切分即可无歧义还原，远端工具名自带的前缀照常保留。
- **实现取舍**：使用官方 MCP 客户端 SDK，目录缓存、凭据适配和内容转换留在模块；五个二级工具沿用宿主授权、结局与历史。stdio 继承任务进程完整环境，与 shell 一致。

### 2026-10-23：授权控制上下文，工坊不设权限模型

- **决策**：资源链接与执行层授权只决定模型可见、可操作的对象集合，用于控制上下文规模与引用精度；工坊不提供权限模型，不审计代理行为，shell、终端与 MCP 以当前系统用户能力运行。用户以链接、工具策略和模块设置（如停用服务器）决定可用能力。当前表述见 [安全边界](architecture.md#安全边界与非目标)。
- **理由**：工坊已提供全能终端，再为 MCP 服务器或单个远端工具叠加授权层不能形成真实边界，只增加配置负担；前沿模型的行为安全由模型自身承担。
- **排除**：按服务器划分 MCP Host 的访问范围、按远端工具读写注解动态区分执行策略。只读代理的工具范围仍作为一致性规则保留。

### 2026-10-23：启动时读取登录 shell 环境

- **决策**：主进程在 fork 任务进程前以 `shell-env` 读取登录 shell 环境并写回 `process.env`，所有子进程统一继承。
- **理由**：从 Finder／Dock 启动的应用只有 launchd 的最小 PATH，非登录 shell 执行与直接 spawn 的 MCP 服务器都找不到用户安装的命令。在宿主层修正一次，插件无需各自解析，SDK 不增加环境工具接口。
- **排除**：在 SDK 暴露环境解析 helper——插件看到的 `process.env` 已经正确；自行实现超时与回退——当前启动耗时可以接受。

### 2026-10-23：插件设置页开放浮岛接口

- **决策**：SDK 新增插件浮岛接口（打开、关闭、子浮岛身份、关闭守卫）与宿主注入的面板外框 `IslandPanel`，内置 Shell 与 MCP 设置改为在右侧浮岛中编辑，标题栏「保存」后保持打开、由关闭按钮关闭，未保存修改由外框确认放弃。最终契约见 [插件 SDK](plugin-sdk.md#插件配置与界面本地化)与 [设置总览与插件管理](workbench.md#设置总览与插件管理)。
- **理由**：提供商等宿主设置已用浮岛编辑，插件设置只能行内展开，交互不一致。SDK 的 renderer 入口已以 peer 依赖使用 React，只声明契约与 hooks、由宿主注入实现，不给插件增加视觉依赖；宽度、外框与放弃确认由宿主统一，插件之间视觉与时机一致，同时可自由组织浮岛内容与多层浮岛。
- **排除**：把浮岛编织（`Screen`）移入共享 UI 包——插件可自行建屏排岛，绕开宿主的布局与焦点管理；只暴露按场景的「设置编辑器」契约——保存与守卫时机更固定，但限制插件组织详情、选择器等其他浮岛内容，按需再在浮岛之上叠加场景契约。

### 2026-10-23：MCP 服务器去掉用途说明字段

- **决策**：服务器配置只保留 ID、名称、启用状态、连接模式与传输参数；未索引服务器在搜索中只按名称排序，发现前所需的信息通过连接建立目录获得。字段格式提示统一改为控件 placeholder。当前契约见 [MCP 模块](mcp.md#配置与认证)与 [设计系统](design-system.md)。
- **理由**：用户基本不填写用途说明；实际使用中由用户指明要用的服务器，或预先连接建立缓存，连接后有服务器指示与工具目录。缺信息时去连接，而不是额外维护一个配置负担字段。
- **排除**：连接后以服务器指示回填空的用途说明——仍保留一个多数时候为空的字段及其回退规则。
