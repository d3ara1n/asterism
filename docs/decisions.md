# 决策与开放问题

## 已确定的产品原则

| 主题 | 约定 |
| --- | --- |
| 名称 | 中文“织台”，英文 Weft，仓库 weft |
| 应用标识 | 正式 bundle ID 与 Windows AppUserModelID 为 `dev.dearain.weft`；应用数据目录独立于该标识 |
| 代理即资源 | 代理是普通资源对象，以 `resource_created { type: "agent" }` 创建，可被移除，也可作为链接起点授权给另一个代理；链接终点只能是代理。所有代理平级，可在同一会话并行运行 |
| 授权连线方向 | 箭头从资源指向接收授权的代理，以拖动起点、终点决定；卡片四边均可使用，端点按相对位置与连线数量动态分散，卡片位置与布线不决定授权方向 |
| 双向连线 | 同一对象对的反向链接合并显示为一条双箭头线，共用一组动态端点；Delete 解除两个方向，单独解除一个方向后显示剩余单箭头；底层有向链接与历史事件分别保留 |
| 资源控制器 | 资源卡片的行为（代理的提交、继续、配置、取消）由该资源模块的控制器执行，经 `resource.command` 路由；会话只负责会话树、对象与链接事件、布局和通知。资源私有可变数据（如代理的模型选择）存于资源状态，不进会话树 |
| 资源收束 | 所有被捕获的资源（活动事件进入会话树）均 settled 才能回溯游标；外部状态的持续运行不计入。移除对象要求该对象 settled，未收束时明确拒绝；移除同时解除全部入向、出向链接 |
| 时间轴写入 | 资源控制器持有未成型的流与活动状态，成型记录提交给 Session；时间轴追加、终态、续接位置与回溯由 Session 管理。提交事务同步串行，模型流与资源准备可并行，不在写入区间异步等待 |
| 定位 | 比 coding agent 更宽的个人工作台，包含日常事务、研究、维护与编程 |
| 展示 | 对象卡片与关系线；工具调用默认收纳在代理流 |
| Session | 一段工作的持续过程；唯一会话树，可含任意数量代理，代理不分主子 |
| Workspace | 持久归属和配置集合，可以有稳定目录，但不隐式授予文件能力 |
| 资源 | 携带状态、视图与操作能力，可以是完全虚拟的对象 |
| 资源身份 | 新资源及代理资源使用 Nano ID 默认字符集的 16 位随机句柄；存储与模型调用共用同一身份，创建后稳定。句柄不在 GUI 展示，模型向用户描述资源时使用 title |
| 资源展示描述 | 资源类型模块声明静态图标与本地化类型名，独立于正文渲染；对象目录、历史、授权和卡片共用，不在 UI 散布按类型判断的名称／图标逻辑 |
| 对象面板 | 采用紧凑平铺列表快速识别和定位；不展开内容，不按代理归属组织，不把多对多或成环链接改造成列表层级 |
| 历史面板 | 按真实追加顺序逐节点显示，两行呈现原文片段／标准事件文本与来源；会话事件和资源事件可区分，不按 response 或执行段聚合，不用生成摘要代替节点落点 |
| 分支导航 | 顶部 Tab 显示共享起点与独有后续；原路径不变，共享节点之后的独立导航行在父子 Tab 间双向定位，并随该节点筛选。身份与编号按追加顺序稳定推导；浏览与执行位置独立，查询成功后随协调视图发布 Tab |
| 历史视图 | 支持全部、工作台事件、全部资源记录与具体资源来源，按身份而非名称或工具目标筛选；仅有创建／链接记录的静态资源不占来源选项，筛选不改变查看位置 |
| 授权面板 | 右侧浮岛提供按代理／资源查看有向链接和就地状态反馈；保存以真实投影确认为准。请求环境未完整暴露时，只说明请求生效边界，不推断单条链接的精确 pending |
| 工具目标 | 调用明确携带资源身份，不依赖隐式“当前资源” |
| 历史能力 | 历史查看与状态恢复分开，按资源实现声明支持范围 |
| 解绑 | 保留历史知识与操作记录，撤销后续访问而非删除记忆 |
| 环境生效边界 | 每次模型请求固定环境及其工具批次授权；期间变化即时记录，下一次模型请求取用 |
| 工具边界 | 资源与工具平级，工具声明支持关系；链接资源激活匹配工具，agent.tools 等外部策略另行筛选。Weft 一级操作入口固定，不受工具名单约束，不向插件开放注册或替换 |
| 工具定义 | 两层工具共用 ToolContract 与 defineTool：name、description、guidelines、argsSchema；description 用于选择，guidelines 用于使用，不另设 snippet。相同工具复用完整定义，不同用法或行为另定义工具 |
| 工具实现 | 后端实现规定 target、result 的 schema 与描述，并提供 handler、版本和执行信息，不覆写工具用法。三种 schema 均有整体描述；同名工具的描述、指导、args 契约与读写属性须一致。target 由实现解释，不建立通用目标解析层 |
| 工具错误反馈 | 首次调用说明明确参数类型与用法；失败返回具体校验问题或可区分原因及下一步，支持模型自愈。约定见 [运行时错误语义](runtime.md#错误语义)，开发准则见 [模块指南](../src/modules/README.md#调用说明与错误自愈) |
| 功能模块 | 纯契约、后台实现和前端视图同目录维护、分入口编译；以契约 ID/版本关联，通过 IPC 传数据，不传函数或组件 |
| 工具产出 | 过程态与终结态共用一个 data schema；工具以 publish 发布当前完整产出，运行时替换最近的合法快照。只有终结结果持久化并交给模型；失败、取消与未知结局同样保留有效产出，终结后忽略迟到更新 |
| 结果展示 | 保存实际实现的 ID/版本、当次资源身份、执行时间与 data/model；headerRenderer 和 bodyRenderer 独立可选，消费同一份结果。用户视图使用保存的数据，组件缺失或不兼容时使用默认视图 |
| 思考展示 | 独立 header/body：生成时摘要显示思考中及运行时块起点计时，正文为固定高度的尾部窗口；结束或中断后正文切换全文。外观设置分别控制生成时自动展开、结束时自动折叠，默认均开启，增量不覆盖手动开合。历史默认折叠，空思考不显示；未保存的历史耗时不补造 |
| 工具层级 | 一级是协议 tools 中的三个固定 Weft 入口 resource_list/inspect/call，二级是经 resource_call 使用的动态资源工具。三类入口的视图由 Weft 内置；resource_call 自己将展示转交二级工具，外壳只显示实际工具的一层视图。模块提供资源工具视图，不能替换固定入口 |
| 上下文 | 资源变化进入 messages 事件，不反复修改顶层动态资源声明 |
| 权限 | 执行层验证，工具可见性和 UI 连线均不是权限机制 |
| 历史 | 查看与恢复分开，外部不可恢复资源不假装回滚 |
| 终态元数据 | 块正文完成即追加；迟到计量只追加一次并绑定响应最高序号的实际块，查询时合并，不改写原始节点或另设计量节点 |
| 请求起点 | 每个块记录请求取用的路径末端；模型投影据此安排响应和期间事件，保留实际发送前缀 |
| 选择审计 | 历史选择及继续前吸附写独立追加日志，与当前游标原子提交，不进入模型上下文 |
| 会话视图所有权 | 查看位置、工作台与对话读取由同一会话模块管理；应用层只持有导航和列表，异步列表刷新不能覆盖会话内容 |
| 命令与展示 | 会话命令返回受理结果，查询返回指定位置的协调视图；布局与领域变化分别处理，历史查看不禁止布局操作 |
| 进度与块身份 | 流增量独立于持久视图订阅，以持久修订协调落库衔接；同一块在生成、执行和保存后保持展示身份 |
| 平台 | 测试以 macOS 为主；发布覆盖 macOS、Windows、Linux |

## 初版技术基线

本地桌面、单用户起步。Electron 外壳，React + TypeScript + Vite；shadcn/ui + Tailwind CSS 作为组件与样式体系，组件源码纳入仓库，不并行维护另一套组件样式体系。@xyflow/react 作为卡片与连线画布，Monaco 按需用于文件与 diff。结构化持久化为 SQLite（`node:sqlite`，运行时不可用或能力不足时改用 better-sqlite3），大内容为本地对象存储，校验为 Zod。独立 Node.js 任务运行时。包管理器为 npm，不使用 bun 或 pnpm。代码构建为 electron-vite，打包分发为 Electron Forge。

应用数据在 `app.getPath('userData')` 下分目录存放：`db/`、`objects/`、`logs/`、`credentials/`。凭据与任务日志、事件记录分离；Chromium 会话数据使用独立 `sessionData`。

模型接入为 Vercel AI SDK，MCP 接入为官方 TypeScript SDK。运行时拥有任务历史与授权，接入层不拥有会话真值；不以完整 agent 框架替代织台的历史、资源和授权内核。

模型接入的上层封装须支持继续扩展协议，首批围绕 OpenAI 与 Anthropic 协议。每个 Session 有唯一的只追加扁平会话树：message、thinking、text、toolcall（带结果）、event、notice 平级节点；代理块带 agent_id 与 response_id，不完整块以 complete=false 落库但不发给模型。对话是代理从树上的即时投影，不单独存储；模型投影按响应归组并把响应期间的事件延后。会话所有被捕获的资源 settled 才可回溯，继续点不得使投影以 thinking 结尾。具体契约见 [会话树](timeline.md) 与 [会话与代理能力](conversation-core.md)。

模型与端点的协议差异由可组合的兼容包集中处理请求编码、响应解码与历史续接，避免在通用路径散布品牌、域名或模型名称条件链。提供商连接可设置默认组合及选项，具体模型继承并覆盖；内置目录提供推荐，用户可为自定义与中转端点显式选择。同一请求使用统一解析后的组合，不同格式策略可跨模型复用。该方向已确认，本次不实施；配置、组合契约与现有 DeepSeek 专用分支的迁移见 [模型兼容计划](../plans/todo-2026-10-10-model-compatibility.md)。

同一批次工具调用共同收束后统一向模型交付结果，再开始后续模型请求；单个工具完成可更新进度，但不触发提前续轮。批次身份是执行关联，不是 transcript 容器。

提供商连接为本机应用级配置，首批覆盖 OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages。普通配置和凭据引用保存于 SQLite；API key 由 Electron safeStorage 加密，密文独立保存在应用数据目录 credentials/，加密不可用时不回退明文。能力层提供配置管理与异步连接测试，界面消费接口。具体实施状态见 [模型接入计划](../plans/todo-2026-10-01-model-protocol-storage.md)。

设置分为提供商、角色、代理：提供商管理连接与具体模型的能力、生成参数；角色管理 `heavy/fast/default/utility/smart` 及自定义模型角色；代理管理所有代理共用的 agent 配置。内置模型角色不能删除，其余设置可编辑；`utility` 默认隐藏，内部功能仍可引用。模型角色是配置参考，不是工作台对象。

配置按取用时读取、消费时校验处理，不建跨配置引用约束，不级联清空已选身份。删除不因其他配置持有其 ID 而受阻；非空失效 ID 不降级为继承。模型角色与 agent 配置由内置原始定义和用户局部覆盖解析出最终视图；用户未提供字段表示未覆盖，提示词留空恢复继承。自定义模型角色以内置原始 default 为基准，自定义 agent 以内置原始 worker 为基准，不依赖其他项的最终视图。编辑器可用 placeholder 展示继承值，不将其回存为用户覆盖。已有对话每次模型请求按当前选择重新解析配置，允许中途切换 agent、模型与思考等级，下一次模型请求生效。内置 agent 为 worker、explorer、reviewer、researcher、advisor，worker 默认，advisor 使用 smart；初始内容来自指定 pi 配置。具体语义见 [模型与代理配置](model-configuration.md)，实施状态见模型接入计划。

系统指令从有序的结构化提示块统一渲染，使用 XML-like 分段表达 harness、agent 及后续 context、skill 的来源与边界。harness 解释环境和运行机制，动态资源状态只通过消息节点追加；工具定义由独立协议通道传递，不重复拼入系统指令。插件扩展面允许追加及拦截替换结构化提示块，插件接入、AGENTS.md 指令注入与 skills 暂缓实现。相同配置下提示块与工具定义的内容及顺序保持稳定；标签不改变协议指令层级或执行授权。详细约定见 [运行时与上下文](runtime.md)。

只有对话 messages 从历史重建，harness、角色提示词、模型参数与工具目录均从当前代码和应用配置即时解析。对话历史不保存环境正文或完整请求；模型输出块仅保留协议续接所需来源及执行引用。当前选中的配置 ID、模型 ID 与思考等级属于可修改会话设置，独立于追加历史；设置编辑与角色切换不改写消息。在途请求及其工具批次保持已取用环境一致，下一次模型请求采用新配置。执行记录只保存计算结果（模型表达式、计量等），不记录 agent 配置或模型角色身份。

对话创建选择 agent 与具体模型，agent 的模型角色提供默认参考，用户可覆盖；无继承来源且模型未定义时要求明确选择。对话期间可切换 agent 配置、模型和思考等级，下一次模型请求生效；委派也可覆盖模型。只读 agent 不因被委派或被其他代理链接而获得写权限。完整规则见 [模型与代理配置](model-configuration.md)。

目录与虚拟资源作为验证：目录验证外部授权与 diff；虚拟资源验证完整状态的历史查看与恢复。

## 初版缓存取舍

provider tools 只暴露固定 Weft 操作入口；动态资源实例通过消息事件表达，工具 schema 通过链接通知或 inspect 提供。所有工具管理与 resource_call 共享工具及实现目录，匹配目标资源后再应用外部允许/排除策略。同一个工具可有多个后端实现，资源实例不携带工具目录或工具白名单。

这优先保证工具前缀稳定，不声称几百个工具必然廉价，也不声称前缀稳定必然命中缓存。provider 原生搜索和延迟加载的机制见 [调研记录](mcp-caching.md)。

## 待确认或验证

### 实现开始前

- 首次真实验证使用的服务端点与模型，由用户配置；首批三种协议与提供商保存方案已确定。
- 动态资源工具（`resource_call` 内层 schema 在链接通知或 inspect 中提供）的调用可靠性需实测。
- 只截掉末尾 toolcall 的投影是否被各 provider 接受，需实测。
- 检查点格式与迁移。事件表见 `docs/architecture.md`。
- 尚未接入模块的依赖版本；桌面 GUI 与跨平台产物按 [工程工具立案](../plans/todo-2026-09-18-desktop-tooling.md) 验证。
- 完整请求留存与敏感内容保留期限。
- 模型角色与 agent 配置的真实执行消费、模型切换的协议兼容与生效边界见模型接入计划；配置字段、按需读取和删除规则已定。

### 工作台迭代中

- 自动布局引擎与布局策略：优先验证 ELK，尚未选定依赖；验证动态卡片尺寸、手动位置保留与折叠端点，见 [布局验证立案](../plans/todo-2026-09-18-workbench-layout.md)。
- 拖入资源时默认加入任务还是同时请求绑定代理。
- 单次输入与持续绑定的快捷操作。
- 代理创建代理时的授权默认继承方式与代理间通信工具。
- 全任务解绑和多个在途执行的状态展示。
- 历史长列表性能与大量分支的导航密度；导航粒度固定为单个可查看节点。

### 实测之后

- 工具目录规模与模型选择工具的可靠性。
- 是否需要 provider 专属工具搜索及通用延迟发现。
- 模型上下文压缩与缓存策略。
- 大画布、长消息及大量 Monaco 实例的性能。
- 后台持续运行、终端资源、隔离执行与第三方插件。

## 当前授权范围

首页、侧栏、基础工作台、设置壳子与三类真实配置已实现；提供商连接测试在后台运行，首页已接入 agent/模型选择，单代理能力层已实现，会话树、模型适配、工具执行与 IPC 已接通；首页发送与代理对话视图已消费该接口，支持流式阅读、停止、继续和历史分支。GUI 与真实系统凭据/端点验收由 UI 和 [模型接入计划](../plans/todo-2026-10-01-model-protocol-storage.md) 跟踪。提交、push 与 PR 仍分别授权；正式工具协议、目录 IO 与发布 CI 继续由各自立案跟踪。

## 正式应用框架约定

- 窗口采用系统材质底座：左上标题/任务区、右上快捷操作区，下方为主体工作台，部件之间与窗口四周留出材质间隙。macOS 原生红黄绿位于左上标题区；辅助面板按需打开。
- 应用启动永远进入独立首页，不自动打开会话。左侧可隐藏侧栏与右侧首页/工作台同属主屏；设置为独立屏，切换时包含侧栏的主屏整体移动。工作台不是唯一主视图。首次发送才创建带生成 ID 的会话、第一个代理资源与首条输入，utility 异步命名，不要求预先命名。一次性原型只保留于 feat/ux-prototype，正式分支可参考其侧栏职责但不继承演示状态模型。
- 侧栏只保留「首页」入口，不另设同样返回首页的「新会话」按钮；首页状态下入口高亮且不可点击，切入工作台后恢复可点击。
- Electron 44.5.1、electron-vite 5.0.0、Forge 8.0.1；Vite 7.3.6 满足构建器 peer 范围。shadcn/ui 采用 Radix 底层，React Flow 承担真实画布交互。
- 本地单工作区，每个会话一棵会话树。工作台的笔记和可添加资源种类用于基础能力验证，不构成最终资源目录；代理卡片内部已接入真实对话，对象、历史与授权面板沿已确定的正式交互维护。资源身份与执行层授权的原则独立于验证用的资源类型。
- 当前代理、笔记与目录的创建对话框共用布局与提交状态，名称为首个字段，统一标签且无名称占位符；笔记提交时要求非空名称，代理与目录空名称分别采用 agent 配置名与目录 basename。三个添加菜单项均带省略号；目录路径有效性由后台校验，笔记编辑继续延后。具体交互见 [工作台](workbench.md)。
- 会话树、查询索引和视图分开；织台捕获的不可变大内容存 `objects/<hash>`，自包含可变内容（笔记）另行存储；细节见 `docs/architecture.md`。
- 开发与发布数据隔离。关闭最后一个窗口退出应用与任务进程；进程中断后不自动重放命令。
- macOS 使用原生 vibrancy，Windows 11 22H2+ 使用系统 Acrylic；较旧 Windows/Linux 和减少透明度/高对比度场景采用实色回退。不引入自绘标题栏库，原生窗口按钮和缩放能力保留。
- 窗口层次为 Window { Titlebar, Space { 屏[] { 浮岛[] } } }；屏带左浅右深，由菜单切换。屏内采用浮岛编织：放得下时分栏，放不下时溢出跟随焦点。
- 界面按系统语言单语显示，不并排双语；对外文案仍提供中英两套。
- 代理正文与思考使用 Streamdown 2.7.0 渲染，包含 GFM 与流式未闭合语法处理；不自建 Markdown 解析器。HTML 不作为可执行内容，网页链接经协议检查后由系统浏览器打开；远程图片首批显示为明确打开的链接。
- 图标统一为 lucide-react，动画统一为 Motion，控件统一为 shadcn/ui 实现；通用问题优先采用成熟库。


## 界面控件与主题

- 控件只使用 shadcn 官方 registry 源码，外观只通过主题 token 定制；不手改组件、不在业务代码另写控件皮肤。
- 对话框描述聚焦当前操作，不在各资源创建表单重复说明资源与授权的通用性质；同类表单的文案语气与结构统一，约定见 [设计系统](design-system.md)。
- 配色、圆角、密度（紧凑/标准/宽松）与画布纹理属于用户可选主题；密度以 token 统一缩放，不在调用处写死尺寸。亮暗模式（跟随系统/浅色/深色）、主题色与灰色为独立设置，色值取自 `@radix-ui/colors` 的亮暗 12 级色阶；命名调色板只是主题色 + 灰色的推荐组合，选择时写入两项，不进存储、无选中态。切换任何一项只改变 token 的值，不改变 token 名。
- 字体设置分界面字体与代码字体两项，存家族名，`null` 为系统默认；候选来自 Chromium Local Font Access API（`queryLocalFonts`），主进程仅对受信主框架放行 `local-fonts` 权限，其余权限一律拒绝。选择控件为 shadcn Popover + Command（依赖 `cmdk`）组合的 `FontPicker`；代码字体默认只列经 canvas 测宽判定的等宽字体，可切换显示全部。界面字号由密度决定，不另设；代码字号单独可选（11–18px 或跟随）。
- 外观设置为非敏感应用设置，由主进程经 electron-store 存于 userData 下的 `appearance.json`，读出后以 Zod 逐项回退默认值；renderer 经 IPC 读写并把 token 写到 `:root`。
- 持久化的本地数据分三类：设置（用户可见可改，如外观）、界面状态（应用顺手记录、不出现在设置页，如窗口尺寸与位置、侧栏宽度、「不再提示」）、任务视图状态（视口与卡片位置，属于任务视图事件，存 SQLite）。界面状态统一存于 userData 下的 `ui-state.json`，键与 schema 在 `src/shared/ui-state.ts` 登记，单项损坏回退默认、不做迁移；由主进程读写，renderer 首次需要时再开放仅限登记键的 IPC。
