# 决策与开放问题

## 已确定的产品原则

| 主题 | 约定 |
| --- | --- |
| 名称 | 中文“织台”，英文 Weft，仓库 weft |
| 应用标识 | 正式 bundle ID 与 Windows AppUserModelID 为 `dev.dearain.weft`；应用数据目录独立于该标识 |
| 定位 | 比 coding agent 更宽的个人工作台，包含日常事务、研究、维护与编程 |
| 展示 | 对象卡片与关系线；工具调用默认收纳在代理流 |
| Task | 代表一件工作的过程，可以含多个 LLM 对话 |
| Workspace | 持久归属和配置集合，可以有稳定目录，但不隐式授予文件能力 |
| 资源 | 携带状态、视图与操作能力，可以是完全虚拟的对象 |
| 工具目标 | 调用明确携带资源身份，不依赖隐式“当前资源” |
| 历史能力 | 历史查看与状态恢复分开，按资源实现声明支持范围 |
| 解绑 | 保留历史知识与操作记录，撤销后续访问而非删除记忆 |
| Pending | 普通绑定变化在执行轮次交界生效，运行期间半透明表示待生效 |
| 上下文 | 资源变化进入 messages 事件，不反复修改顶层动态资源声明 |
| 权限 | 执行层验证，工具可见性和 UI 连线均不是权限机制 |
| 历史 | 查看与恢复分开，外部不可恢复资源不假装回滚 |
| 平台 | 测试以 macOS 为主；发布覆盖 macOS、Windows、Linux |

## 初版技术基线

本地桌面、单用户起步。Electron 外壳，React + TypeScript + Vite；shadcn/ui + Tailwind CSS 作为组件与样式体系，组件源码纳入仓库，不并行维护另一套组件样式体系。@xyflow/react 作为卡片与连线画布，Monaco 按需用于文件与 diff。结构化持久化为 SQLite（`node:sqlite`，运行时不可用或能力不足时改用 better-sqlite3），大内容为本地对象存储，校验为 Zod。独立 Node.js 任务运行时。包管理器为 npm，不使用 bun 或 pnpm。代码构建为 electron-vite，打包分发为 Electron Forge。

应用数据在 `app.getPath('userData')` 下分目录存放：`db/`、`objects/`、`logs/`、`credentials/`。凭据与任务日志、事件记录分离；Chromium 会话数据使用独立 `sessionData`。

模型接入为 Vercel AI SDK，MCP 接入为官方 TypeScript SDK。运行时拥有任务历史与授权，接入层不拥有会话真值；不以完整 agent 框架替代织台的历史、资源和授权内核。

模型接入的上层封装须支持继续扩展协议，首批围绕 OpenAI 与 Anthropic 协议。织台拥有独立、可扩展的会话节点树（transcript）：输入、模型、压缩和扩展节点通过父节点组织历史；一个模型节点对应一次模型调用及响应，内部有序保存思考、正文和聚合调用/结果的工具单元，用量归属该节点，不另建 response 实体。底层事实只追加；工具单元不能拆为续接位置。压缩不删除历史，可从压缩前完整节点另起路径。扩展可对模型和用户都不可见；模型与 GUI 独立投影，工具结果使用多态结局，不以 isError 作为领域契约。具体契约见 [会话与单代理能力](conversation-core.md)。工具执行结果、错误与实际模型输入由能力层管理并提供明确接口，不按界面组件反推能力模型。界面消费这些接口，自行组织、分组和折叠；当前默认聚合连续思考与工具过程、完整显示模型正文。具体字段、协议接口与持久化格式按模型协议立案确认。

同一批次工具调用共同收束后统一向模型交付结果，再开始后续模型请求；单个工具完成可更新进度，但不触发提前续轮。批次身份是执行关联，不是 transcript 容器。

提供商连接为本机应用级配置，首批覆盖 OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages。普通配置和凭据引用保存于 SQLite；API key 由 Electron safeStorage 加密，密文独立保存在应用数据目录 credentials/，加密不可用时不回退明文。能力层提供配置管理与异步连接测试，界面消费接口。具体实施状态见 [模型接入计划](../plans/todo-2026-10-01-model-protocol-storage.md)。

设置分为提供商、模型、代理：提供商管理连接与具体模型的能力、生成参数；模型管理 `heavy/fast/default/utility/smart` 及自定义模型角色；代理管理主代理与子代理共用的 agent 配置。内置模型角色不能删除，其余设置可编辑；`utility` 默认隐藏，内部功能仍可引用。模型角色是配置参考，不是工作台对象。

配置按取用时读取、消费时校验处理，不建跨配置引用约束，不级联刷新会话或已选项。删除不因其他配置持有其 ID 而受阻；非空失效 ID 不降级为继承。选择 agent 时取得默认配置，已有会话不随配置编辑刷新。内置 agent 为 worker、explorer、reviewer、researcher、advisor，worker 默认，advisor 使用 smart；默认内容来自指定 pi 配置，首次初始化后不重置用户编辑。

对话创建选择 agent 与具体模型，agent 的模型角色提供默认参考，用户可覆盖；无继承来源且模型未定义时要求明确选择。对话开始后 agent 固定、模型可切换，委派也可覆盖模型。只读 agent 不因作为主代理或委派而获得写权限。完整规则见 [模型与代理配置](model-configuration.md)。

目录与虚拟资源作为验证：目录验证外部授权与 diff；虚拟资源验证完整状态的历史查看与恢复。

## 初版缓存取舍

在选定能力集合内全量暴露稳定工具目录；动态资源实例通过消息事件表达。资源类型共享工具定义，不按实例复制 schema。

这优先保证工具前缀稳定，不声称几百个工具必然廉价，也不声称前缀稳定必然命中缓存。provider 原生搜索和延迟加载的机制见 [调研记录](mcp-caching.md)。

## 正式应用框架约定

- 窗口采用系统材质底座：左上标题/任务区、右上快捷操作区，下方为主体工作台，部件之间与窗口四周留出材质间隙。macOS 原生红黄绿位于左上标题区；辅助面板按需打开。
- 应用启动永远进入独立首页，不自动打开会话。左侧可隐藏侧栏与右侧首页/工作台同属主屏；设置为独立屏，切换时包含侧栏的主屏整体移动。工作台不是唯一主视图。首次发送才创建带生成 ID 的会话、主代理与首条输入，utility 异步命名，不要求预先命名。一次性原型只保留于 feat/ux-prototype，正式分支可参考其侧栏职责但不继承演示状态模型。
- Electron 44.5.1、electron-vite 5.0.0、Forge 8.0.1；Vite 7.3.6 满足构建器 peer 范围。shadcn/ui 采用 Radix 底层，React Flow 承担真实画布交互。
- 本地单工作区、每个任务一个初始分支。现有工作台内部的添加笔记、Access 授权面板与对象/历史面板属于框架验证占位，不构成最终产品交互或资源目录；主代理卡片内部已接入真实对话，可添加资源需要重新设计。已有笔记持久化和读取授权仅用于验证基础能力，不要求正式产品保留笔记类型或当前授权操作形式。资源身份与执行层授权的原则独立于这些占位界面。
- IPC 协议与应用 SQLite 迁移起始版本均为 1。任务事件、查询索引和视图分开，笔记正文采用 hash 引用的不可变对象存储；细节见 `docs/architecture.md`。
- 开发与发布数据隔离。关闭最后一个窗口退出应用与任务进程；进程中断后不自动重放命令。
- macOS 使用原生 vibrancy，Windows 11 22H2+ 使用系统 Acrylic；较旧 Windows/Linux 和减少透明度/高对比度场景采用实色回退。不引入自绘标题栏库，原生窗口按钮和缩放能力保留。
- 窗口层次为 Window { Titlebar, Space { 屏[] { 浮岛[] } } }；屏带左浅右深，由菜单切换。屏内采用浮岛编织：放得下时分栏，放不下时溢出跟随焦点。
- 界面按系统语言单语显示，不并排双语；对外文案仍提供中英两套。
- 主代理正文与思考使用 Streamdown 2.7.0 渲染，包含 GFM 与流式未闭合语法处理；不自建 Markdown 解析器。HTML 不作为可执行内容，网页链接经协议检查后由系统浏览器打开；远程图片首批显示为明确打开的链接。
- 图标统一为 lucide-react，动画统一为 Motion，控件统一为 shadcn/ui 实现；通用问题优先采用成熟库。


## 界面控件与主题

- 控件只使用 shadcn 官方 registry 源码，外观只通过主题 token 定制；不手改组件、不在业务代码另写控件皮肤。
- 配色、圆角、密度（紧凑/标准/宽松）与画布纹理属于用户可选主题；密度以 token 统一缩放，不在调用处写死尺寸。亮暗模式（跟随系统/浅色/深色）、主题色与灰色为独立设置，色值取自 `@radix-ui/colors` 的亮暗 12 级色阶；命名调色板只是主题色 + 灰色的推荐组合，选择时写入两项，不进存储、无选中态。切换任何一项只改变 token 的值，不改变 token 名。
- 外观设置为非敏感应用设置，由主进程经 electron-store 存于 userData 下的 `appearance.json`，读出后以 Zod 逐项回退默认值；renderer 经 IPC 读写并把 token 写到 `:root`。
- 持久化的本地数据分三类：设置（用户可见可改，如外观）、界面状态（应用顺手记录、不出现在设置页，如窗口尺寸与位置、侧栏宽度、「不再提示」）、任务视图状态（视口与卡片位置，属于任务视图事件，存 SQLite）。界面状态统一存于 userData 下的 `ui-state.json`，键与 schema 在 `src/shared/ui-state.ts` 登记，单项损坏回退默认、不做迁移；由主进程读写，renderer 首次需要时再开放仅限登记键的 IPC。
