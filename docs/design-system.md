# 界面设计系统

## 已确认的视觉

窗口作为系统材质底座，独立内容表面铺在其上。默认跟随系统亮暗，主题色 jade、灰色 gray；亮暗、主题色、灰色、圆角、密度与画布纹理由用户在设置的「外观」中选择。画布区域同时提供带示意图的连线风格选择，交互规则见 [连线与授权交互](workbench.md#连线与授权交互)。

主题色用于主操作、明确强调、进行中与持续选中态；普通标签、次级操作与静止常态使用所选灰阶。颜色 token 按用途命名，组件消费语义 token，不根据主题色相自行决定用途。

| token | 语义与取色 |
| --- | --- |
| `primary / primary-foreground` | 主操作与强调徽章的实色表面；亮色取主题色 11 级、暗色取 9 级，前景在白与深灰之间取对比度更高者 |
| `primary-text` | 普通表面上的主题色文字与状态图标；亮色取主题色 12 级、暗色取 11 级，在内容表面与中性次级表面上均达到 AA |
| `secondary / secondary-foreground` | 中性次级表面与普通标签；所选灰阶 3 级底、12 级字，不随主题色变化 |
| `selected / selected-foreground` | 导航、列表与已打开面板入口的持续选中态；主题色 3 级底，亮色 12 级字、暗色 11 级字 |
| `muted / muted-foreground` | 弱化区域与辅助文字；所选灰阶 3 级底、11 级字 |
| `external-message / external-message-foreground` | 外部代理输入与待发送条目；固定 violet 3 级底、12 级字，随亮暗切换，不随主题色变化 |
| `accent / accent-foreground` | 悬停与菜单键盘高亮等临时交互反馈；所选灰阶 4 级底、12 级字。这里的 `accent` 是控件 token，与外观设置中选择主题色相的 `appearance.accent` 含义不同 |
| `success / success-foreground`、`warning / warning-foreground`、`destructive / destructive-foreground` | 成功、警告与错误／破坏性操作；分别取固定 green、amber、red 的 11 级，不随主题色变化，实色表面搭配各自前景色 |

带底色的控件成对使用表面与对应 `*-foreground`，不写死白字；无底色的主题强调文字使用 `primary-text`，状态文字与图标使用对应状态色。主操作、选中态与徽章的文字配对达到 AA。正文与边框取所选灰阶；亮色边框取 5 级，暗色取 6 级。焦点环与文字选区取主题色对应浅级；`selection` 仅用于文字选区，与持续选中态 `selected` 分开。

主题色按色相环排列，另有无彩的石墨（`graphite`）：`primary` 与 `primary-text` 以所选灰阶 12 级（近黑／近白）取色，`selected` 取比 hover 深一级的灰阶 5 级底配正文色，焦点环与选区同样取灰阶。调色板只是主题色与灰色的快捷组合：多数配中性灰，暖色与紫色系配 Radix 推荐的同调灰（slate、olive、sand、mauve）。

底色分两层：`background` 遵循 shadcn 约定作页面与控件底色（亮色白、暗色灰阶 1 级），对话框、outline 按钮、激活 tab 等官方组件直接使用；`canvas` 是工坊扩展，只用于工作台底板、带底板的屏、React Flow 画布与外观预览等画布区域（亮色灰阶 3 级、暗色灰阶 1 级）。

- 左上是应用导航与当前视图标题，macOS 原生红黄绿置于该区域。
- 右上是紧凑快捷操作，Windows/Linux 覆盖式窗口控件通过统一标题栏安全区避让。
- 下方是左侧可隐藏的应用侧栏与右侧主内容两个浮岛。启动主内容为无背景首页，不加载会话；选择已有会话或首次发送创建后才显示工作台。工作台是主屏根浮岛；对象、历史、授权与以后的对象预览/编辑器在其右侧以更深浮岛打开，由编织机制压缩与转移焦点。
- 侧栏以「首页」作为返回首页与准备新会话的唯一入口，不另设「新会话」按钮；处于首页时，入口保持完整高亮并禁用点击，不使用普通禁用按钮的淡化效果。
- 窗口外沿与部件之间均留 6px 间隙，让系统材质可见。顶部表面高 32px。控件尺寸使用 shadcn 官方尺寸档；界面密度作为主题项统一缩放，不在调用处写死像素。
- 状态、画布控制和内容都处于对应表面内，外部间隙保持空白。

## 原生窗口与 Web 内容

| 平台 | 原生窗口 | 内容留白 |
| --- | --- | --- |
| macOS | hidden 标题栏 + 原生红黄绿 + under-window vibrancy | 普通窗口中按按钮组宽度对称留白，全屏时恢复导航的普通内边距 |
| Windows 11 22H2+ | hidden 标题栏 + titleBarOverlay + Acrylic | 使用 Window Controls Overlay 的环境变量避开窗口控件 |
| 较旧 Windows | 原生控件覆盖 + 实色背景 | 与现代 Windows 使用相同内容布局 |
| Linux（默认） | hidden 标题栏 + titleBarOverlay + 实色背景 | 与 Windows 共用覆盖区域避让，按钮由 Electron 绘制 |
| Linux（系统标题栏） | 桌面环境窗口装饰 + 实色背景 | 系统按钮在 Web 内容之外，应用标题栏不额外留白 |

主进程通过 nativeTheme 响应减少透明度/高对比度设置，必要时禁用材质。亮暗模式经 `nativeTheme.themeSource` 下发，系统材质、renderer 的 `prefers-color-scheme` 与实色回退同源。

系统材质使用 Electron 原生 API，不使用全窗口 CSS backdrop-filter 模拟桌面模糊，不开启 transparent 窗口模式。HTML、body、root 与 Window 无不透明全屏底色。卡片与内容表面保留实色，确保文字可读。

macOS 覆盖区域高为顶部表面高度加两倍窗口边距。原生按钮位置在 `windowGeometry.macControlsPosition` 集中配置（当前为 `{ x: 20, y: 15 }` DIP）；普通窗口中 renderer 按 `macControlsPosition` 与 `macControlsWidth` 计算左侧留白，使按钮组两侧到部件边缘等距；不使用 `titlebar-area-x`。

窗口层统一消费主进程确定的标题栏模式与原生全屏状态。主进程通过 Electron 的 `enter-full-screen` / `leave-full-screen` 事件发布状态，renderer 首帧前先订阅再读取当前状态，此后直接采用每次收到的状态；全屏内刷新同样取得真实状态。全屏时收回窗口控件专用留白，退出后恢复；最大化仍保留按钮避让。

Windows/Linux 覆盖模式使用 `titlebar-area-x` / `titlebar-area-width` 提供的可用区域计算标题栏左右安全区，控件与菜单之间保留标准部件间隙。右侧工作台菜单随标题栏整体布局避让；Linux 桌面将按钮放在左侧时也遵循实际区域。覆盖区域随系统缩放与窗口尺寸更新，不以固定按钮宽度限制安全区；环境变量尚未就绪时暂按右侧 138px 预留。窗口按钮的绘制、点击与系统行为由 Electron 负责。

Linux 默认使用覆盖式标题栏；桌面环境兼容性不佳或用户偏好系统装饰时，可用 `--native-titlebar` 启动，开发命令为 `npm run dev -- -- --native-titlebar`。标题栏模式在创建窗口时确定，修改启动参数需退出并重启；此选项不改变 macOS/Windows 的标题栏策略。

窗口底座可拖动，包括外沿与部件之间露出的空白；标题区、操作区和工作台均完整排除拖动，保留给交互。根节点声明 `drag`，部件边界声明 `no-drag`；所有后代直接使用 `window-drag: initial` 重置，避免 Electron 的继承语义使画布变换后的后代生成超出可见边界的排除区域（不可用显式 `none` 代替 `initial`）。弹窗和遮罩另行排除底座拖动。

## 窗口层次

```
Window          平台差异、拖动区域、窗口几何变量
├─ Titlebar     全局，不随屏平移
└─ Space        受管空间，负责窗口留白与整屏切换
   ├─ 设置屏 / Screen / Island[]
   └─ 主屏 / Screen
      ├─ Island 应用侧栏，可隐藏的受控前置浮岛
      ├─ Island 聚焦浮岛，会话有聚焦对象时出现的受控前置浮岛
      └─ Island 首页或会话工作台
```

- 屏与浮岛只相对所在层定位，不感知标题栏。全屏、浮动标题栏等变化只改 Window 中 Titlebar 与 Space 的排布。
- 屏带方向固定：左浅右深。设置为主屏左侧的独立 Screen；侧栏与首页/工作台属于同一个主屏，切到设置时整体平移离场，返回时一起移回。屏间切换只由导航等明确操作触发，不设快捷键，不接管触控板手势。视口外的屏保持挂载并设为 `inert`，焦点转移使用 `preventScroll`，视口用 `overflow: clip`。
- 首页与设置无页面底板，内容直接位于窗口材质上；首页输入框有独立表面，工作台有底板。

## 浮岛编织

- 浮岛是屏内一列独立的表面，彼此留 6px 间隙。每个浮岛声明 `min`、`grow`、可选 `max`。
- 所有 `min` 放得下时按 `grow` 分配并居中，屏内静止；放不下时退到 `min` 并溢出，视口跟随焦点：完整可见不动，越界贴边。被挤出的浮岛变淡，点击露出部分移回；溢出时底部留白显示分段导航：每段对应一个浮岛、按其在带中的位置与宽度排布，视口内可见的段加深、焦点浮岛最深；点击或键盘激活某段即把焦点移入该浮岛，视口随之跟随，完全被挤出视口的浮岛（如侧栏）也由此找回。各段是带浮岛名称提示与无障碍名称的按钮，不可拖动，不作为滚动条；触控板横向滚动只在浮岛之间的缝隙生效。
- 浮岛在其父浮岛右侧打开，替换父浮岛右侧原有的更深浮岛；Esc 由最深的屏先处理，关闭焦点浮岛，焦点回到打开它的元素。屏内有多个浮岛时，焦点浮岛显示 1px 高光。
- 业务代码只调用 `useIsland().open/close/closeChild`，不写坐标与动画。布局规则是 `shared/weave/model.ts` 的纯函数。
- 带底板的浮岛由宿主统一绘制边框与焦点高光；内容区内缩一个边框宽度并按内圆角裁切，内容（含铺满的背景、直角子元素）不会盖住边框或从圆角露出。浮岛内容不自绘外层圆角或边框。
- 应用侧栏通过 `Screen.leading` 声明为受控前置浮岛，参与同一宽度与焦点布局，不参与主内容的父子打开/关闭栈。
- 聚焦浮岛同样通过 `Screen.leading` 声明，位于侧栏与工作台之间，宽度分配权重大于工作台；浮岛身份固定，切换会话或聚焦对象时只交替淡入内容，没有聚焦对象时退场。内容使用与卡片相同的对象外壳（`ObjectSurface`），不加卡片边框，直接位于浮岛底板上。交互见 [对象聚焦](workbench.md#对象聚焦)。
- 设置屏：根浮岛按上下两个带 header 的区块呈现应用分类卡片与插件信息卡片，以间距和分隔形成层次；插件区 header 容纳列表工具，窄窗口允许换行。打开分类或插件时卡片底板共享布局放大为详情，其余卡片与区块 header 淡出；详情内容可在右侧打开更深浮岛（如提供商详情）。入口与内容规则见 [设置总览与插件管理](workbench.md#设置总览与插件管理)。

## 动效

- 动画使用 Motion：进退场随存在性由 `AnimatePresence` 自动播放，替换时 `mode="popLayout"` 让退场者脱离布局流，位移由 `layout` 自动补位；共享元素用 `layoutId`。不手写测量、关键帧或动画状态机。
- 流式 Markdown 采用 LobeHub Streamdown 原生的 balanced 节奏与按词渐入；排版接入公共 token，不覆盖库的动画时序。系统减少动态时使用静态渲染。
- 时长：短动效 200ms（`--motion-fast`），屏间平移 380ms（`--motion-page`），浮岛 420ms；曲线统一 `--ease-out`。`MotionConfig reducedMotion="user"` 与 CSS 媒体查询共同遵循减少动态。
- 首页与工作台切换时，两边独立的进退场动画同时播放，复用浮岛过渡参数：进入会话时首页放大淡出、工作台放大淡入；返回首页时工作台缩小淡出、首页缩小淡入。应用首次显示首页不播放入场。会话导航立即切换，不等待首份内容读取；工作台先呈现底板与当前外观纹理，内容就绪后填入同一过渡容器，不显示独立的会话加载画面。

## 对象卡片尺寸

卡片默认宽高与最小尺寸由资源模块声明；用户可通过选中且展开卡片的右下角缩放柄自由调整宽高。缩放控件使用 React Flow 原生机制与公共主题 token，不与四边连线端点共用命中区；字号和按钮不随卡片尺寸缩放。正文占据剩余空间，滚动与媒体适配由模块内容视图负责。交互与持久化语义见 [工作台](workbench.md#画布与对象卡片)。

所有对象卡片（含代理）共用 `ObjectCard` 的紧凑单行标题栏（标题栏与辅助面板由卡片与聚焦浮岛共用的 `ObjectSurface` 提供）：左侧依次为 `size-4` 图标、弱化的类型与主要层级的名称，类型与名称按文字基线对齐；右侧操作垂直居中，使用既有紧凑按钮尺寸。标题栏采用 `px-3 py-2` 留白；类型最多占文字区域的三分之一，名称使用剩余空间，超长文字省略并通过悬停显示完整内容，操作区不被挤压。

辅助面板使用卡片本身的宽度决定布局，不随窗口宽度或画布缩放改变展示模式：宽卡片的主体与右侧面板以单条竖分隔线划分，窄卡片的面板覆盖内容区。面板复用卡片表面，不新增浮岛阴影；面板标题与关闭入口固定，正文独立滚动。标题图标由外壳统一约束为 `size-4`，不得因资源声明的 SVG 默认尺寸撑高标题栏；入口使用多面板图标。完整交互见 [卡片辅助面板](workbench.md#卡片辅助面板)。

Agent overlay 的外壳由内置 Agent 统一提供，插件只组织内部内容。三个位置均使用 `surface-floating` 的圆角、边框、表面与阴影；呈现区域四周使用与 composer 外层一致的 `p-3` 留白，多个面板之间使用 `gap-3`，为阴影保留空间。外壳不额外建立滚动裁切边界；overlay 与 modal 的局部滚动统一使用 `AgentScrollArea`，由内置 Agent 的同一个实现提供滚动视口、四边焦点光圈留白及对齐补偿。插件只指定滚动轴和尺寸，不重复编写留白；自行增加嵌套裁切容器时，外层留白不保证其内部光圈可见。底部面板在隐藏 composer 后仍保留侧边与底部留白，视觉上承接输入区，不贴住卡片边框。位置与输入区控制见 [Agent 扩展界面](workbench.md#agent-扩展界面)。

结构化问答复用该外壳，内部以问题、选项和说明的字号层级组织，不叠加浮动卡片。普通选项与自定义项共用官方 FieldLabel／Field／FieldContent 的外框、内边距、选择控件列和文字列；自定义项通过 FieldLabel 的 `asChild` 组合 InputGroup 与无独立边框的编辑器，保留统一选中外观及编辑焦点反馈，不使用 addon 的按钮偏移。题目区和横向导航使用 `AgentScrollArea`，操作区保持可见；底部呈现保留上方历史阅读空间，主动放大使用宽版 Agent modal（`size: wide`），详情分栏按作答容器宽度决定。交互见 [结构化问答](workbench.md#结构化问答)。

## 连线外观

工作台连线统一使用 `primary`：常态 60% 不透明、1.5px，悬停提高不透明度，选中时实色加粗到 2.25px，变化沿用 `--motion-fast / --ease-out`。线身下垫一层 `canvas` 色光晕，把连线与画布纹理、交叉线分开；线端与转角为圆头。两端都落在卡片边缘的端点上：起点由端点圆点覆盖线头，终点箭头尖端贴住端点圆点外沿；双向连线两端均为箭头且不画中段箭头与流动效果。选中时的流动以 `canvas` 色缺口沿线身移动，不另起颜色。方向语义见 [连线与授权交互](workbench.md#连线与授权交互)。

连线端点是 7px 主题色圆点，带 `card` 色描边，跨在卡片边缘上；常态位于卡片之下，只露出外侧半圆，悬停或拖线经过时浮到卡片之上，放大并出现主题色浅光圈。透明命中区为 20px，常态只有卡片外侧部分可命中。端点定位盒同为 7px，连线锚点不随悬停放大与命中区变化。

## 对话过程视图

输入消息气泡限制在阅读区宽度内并留出侧边空间，用户消息靠右、使用中性底色，外部代理消息靠左、使用 `external-message / external-message-foreground`。发送者标签与对应气泡对齐，正文保持左对齐；外部代理标签同时包含 Bot 图标和名字，不单独依赖颜色区分。草稿箱沿用相同的发送者标识与底色。交互规则见 [代理卡片](workbench.md#代理卡片与工具调用视图)。

思考块和工具调用共用折叠外壳，外层无内边距，标题按钮铺满点击区域。标题与正文分别拥有留白，展开正文四周使用相同内边距。

- **单行 Header 规范**：所有 block 的 header 按单行摘要设计，使不同内容块的标题视觉高度一致。由各 renderer 决定内容、排列、收缩与省略，外壳不设置高度上限或裁切规则。工具 header 推荐按“操作名—资源名称或路径—右侧摘要”安排（复用 `shared/tool-header.tsx`）：名称与路径占可收缩的中间区域，末尾省略；行数、目录项数、资源数、资源类型和增删统计保留在右侧，不换行，数值使用等宽数字。
- **三态连续性原则**：填充、执行与结果的 header/body 应尽可能逐步增加信息，保留已出现的路径、输入数量与相同元素的排版，避免阶段切换清空摘要；同时允许按内容语义切换正文形态（如 write 从生成中的 8rem 尾部预览切换为成功写入后的代码正文）。
- **公共流式预览**：思考、工具参数填充、调查报告与命令输出统一使用 `@atelier/ui/streaming-preview` 的 `StreamingPreview`。组件拥有 8rem 固定高度、底部对齐、顶部渐隐与裁切，内容随排版自然上移；预览标记为 inert 并从辅助技术中隐藏。调用方只提供 Markdown、代码或纯文本正文；终结后的正文由各工具按内容语义展示。开合行为见 [工具调用三态视图](workbench.md#工具调用三态视图)。
- **创建工具类型标签**：操作名后紧接资源类型标签，复用 `Badge secondary`、小号文字与资源图标；成功后的实例标题占据其后可收缩的主体区域。类型标签限宽并省略，悬停显示完整本地化名称。显示阶段见 [工具调用三态视图](workbench.md#工具调用三态视图)。
- **局部高度与原始详情**：工具外壳不限制正文高度，也不为整个展开区建立滚动容器；body 提供方自行决定局部高度、滚动与截取。仅在工具终结后提供调用详情与结果详情，使用可取消选中的单选切换，共用下方详情区域（结果含 file 或无非 null data 时隐藏结果详情），原始详情不受正文行预算影响。
- **命令输入与输出**：`exec` 的命令与输出均使用代码字体，默认 `text-xs`，比对话正文 `text-sm` 小一档；显式代码字号设置继续生效。分区标签与执行信息使用次要文字层级，资源标题沿用普通标题字体。输出保持纯文本，截断说明与文件入口独立排在输出文本之外，分区与滚动行为见 [工具调用三态视图](workbench.md#工具调用三态视图)。
- **内置 120 行预算与 Pierre Diffs 着色**：内置插件 `atelier.builtin` 的代码、差异与列表工具正文遵循每次调用最多 120 个逻辑行的展示预算（不是 SDK 对外部插件的强制限制）。`read` 的返回行、`write` 的正文、目录列表与 `edit` 的所有 diff 片段（上下文、删除行、新增行合计）各自在一次调用内共用该预算，超出时提示省略行数。差异与代码展示统一复用 Pierre Diffs（`@pierre/diffs`）：`edit` 使用竖向堆叠的 stacked（`unified`）差异视图，显示修改前后绝对行号、原生增删颜色与片段分隔，不显示补丁头；`read / write` 使用原生 `File` 代码视图，按库自身的文件名与扩展名机制识别语法，未知语言按普通文本展示。两类视图使用 Pierre 亮暗主题与公共代码字体 token。调查报告复用思考块的尾部预览与完整 Markdown，交互见 [工具调用三态视图](workbench.md#工具调用三态视图)。
- **Markdown 富内容**：代码块同样复用 Pierre `File`、亮暗主题和代码字体，不显示行号；紧凑标题栏左侧为语言名，右侧为源码复制。数学公式使用 KaTeX 原生排版，宽公式在自身区域横向滚动。内容行为见[代理卡片与工具调用视图](workbench.md#代理卡片与工具调用视图)。
- **Mermaid 主题**：以官方 `base + themeVariables` 映射公共 token：图形底板用 `card`，普通节点用中性表面、正文色和轻边框，连线用 `muted-foreground`，活动状态使用主题色与选中表面；饼图和坐标图使用 `chart-*` 分类色。默认无渐变、无阴影；字体继承对话正文，节点和连线间距随字号缩放。亮暗、主题色、灰阶、字体、密度与圆角变化后重绘，等待期间保留旧图；不改写 SVG，源码显式指定的图形样式仍由 Mermaid 处理。

## 文字、图标与控件

- 面向普通用户的界面按用户选择或系统语言单语显示，不并排双语；宿主与内置插件提供英文、简体中文，规则见 [公共 i18n](i18n.md)。窄窗口时顶栏按钮只留图标。
- 对话框描述只提供当前操作的填写引导或特有行为说明，不重复资源创建与授权等通用性质；同类表单使用一致的语气与结构。
- 字号五级：`type-page`、`type-section`、`type-body`、`type-caption`、`type-label`。
- 只读 token 与字数统一采用十进制工程缩写：不足千保留普通数字，较大值使用 `k / M / G / T`，最多一位小数；单位固定为 `toks / chars`，不随界面语言切换成「万／亿」。选择器、悬停提示、诊断、上下文面板、图表与工具摘要共用 `@atelier/ui/format-count`，量级与舍入由 `Intl.NumberFormat` 处理。可编辑数值字段及原始数据展示保留完整值，存储与计算不使用缩写。
- 字体只有两个 token：`--font-sans`（界面）与 `--font-mono`（代码）。用户在外观设置选择的本机字体（通过 Chromium `queryLocalFonts` 获取，代码字体默认筛选等宽）置于默认回退栈之前；界面字号即密度；代码另有字号 `--code-font-size`（11–18px，未设置时跟随所在文字），代码文字统一用 `type-code`。
- 图标统一使用 `lucide-react`，不使用 Unicode 符号；界面标识为 `brand-mark.tsx` 的经纬线框。
- `packages/ui/src/ui/` 以 shadcn（new-york-v4）官方 registry 源码为基础，保持官方结构、尺寸与交互；公共语义扩展集中在此维护：Button 的 `selected`、Badge 的 `success / warning`、实色表面前景配对与链接文字 token。升级时保留这些语义映射，不在业务调用处覆盖配色。主题绑定的 `src/renderer/shared/ui/sonner.tsx` 留在应用组合侧：主题取自 `useScheme()` 而不引入 `next-themes`，状态图标按状态 token 着色。官方没有的组合（如 `PageState`、`StatusBadge`、`IconButton`、`ListRow`）放在 `packages/ui/src/ui/` 内，复用公共组件与 token。
- 业务代码只用官方组件与公共组合，不使用裸 button/select 等控件，不写控件颜色、阴影或圆角。可点击的卡片用 `Item variant="outline" asChild` 包裹 button。
- 表面只有两种：`surface`（边框 + 卡片底，无阴影，用于浮岛、顶栏部件、卡片、画布）与 `surface-floating`（加阴影，用于悬浮面板、浮条、通知）；对话框、菜单、下拉由官方组件提供浮层外观。

## 按钮层级

按钮变体只表达所在区域内的强调层级与角色，不区分操作是否改写数据。

| 变体 | 用途 | 示例 |
| --- | --- | --- |
| `default` | 区域主操作，每个表单、浮岛或对话框至多一个；列表区块标题处的新建入口 | 保存、创建、添加所选、添加提供商 |
| `outline` | 区块与编辑器内的辅助操作；错误状态中的恢复操作；对话框与表单页脚中与主操作成组的取消、放弃 | 获取模型、获取参数、测试连接、重试、取消 |
| `ghost` | 顶栏与导航、列表行内操作、折叠区块标题、浮条内的操作、仅图标按钮 | 行内测试、参数（折叠）、关闭 |
| `secondary` | 中性底色的次级操作，不表示当前选中 | 浏览目录、停止执行 |
| `selected` | 导航与列表中的当前项、已打开面板入口，按交互配合 `aria-current` 或 `aria-pressed` | 侧栏当前会话、历史当前条目 |
| `destructive` | 确认对话框中的不可逆确认按钮 | 删除、放弃修改 |
| `link` | 文字行内的附属操作 | 移除已保存的密钥 |

- 删除等不可逆操作的入口用 `ghost` 加 `text-destructive`，经 `AlertDialog` 确认后执行。
- 区块与编辑器中带文字的辅助操作使用语义前导图标，进行中以 `Spinner` 替换该图标；错误恢复与页脚取消、放弃不带图标。
- 设置页与浮岛内使用 `sm`，对话框页脚沿用默认尺寸，紧凑行内使用 `xs`。仅图标按钮使用 `IconButton`（Button + Tooltip）。

### 对话配置摘要与浮层

输入工具栏沿用输入区表面，内置项与第三方项使用相同的紧凑行内布局和间距，不额外包覆悬浮卡片。工具栏项的排列与显隐见 [Agent 扩展界面](workbench.md#agent-扩展界面)。

对话配置摘要使用一个紧凑 `ghost / xs` 按钮：`Bot` 图标、模型名、短竖分隔线、弱化的思考等级、唯一展开箭头。模型名允许省略，等级保持可见；思考等级前不再放图标。机器人图标与浮层「代理」选择行呼应；悬停／聚焦提示使用「所选代理名 · 模型名 · 思考等级 · 上下文容量」的紧凑单行摘要，不显示字段标签或单位，例如 `worker · deepseek-flash · 中 · 1M`；窗口缺失时显示未知。

配置浮层复用官方 Popover 表面，贴近按钮展开并避让窗口边缘。第一层是三行配置，图标固定为 `Bot / Cpu / Brain`；右侧当前值弱化。普通选择页和提供商列表保持紧凑宽度；进入提供商的模型列表时加宽为列表与参数预览两栏，以单条分隔线划分同一表面，不嵌套卡片。可用宽度不足时预览排到列表下方，两区分别滚动。返回与标题固定；模型搜索使用局部 Command 列表，不打开全局命令面板或模态框。完整行为见 [对话配置选择](workbench.md#对话配置选择)。

账户用量项沿用紧凑计量布局，以短 Progress 与等宽余量百分比展示；纯余额显示金额。Tooltip 列出各窗口的余量与重置时间，错误、过期与任一窗口耗尽通过状态提示表达，不把未知量绘制为零额度。交互见 [账户用量工具栏](workbench.md#账户用量工具栏)。

### 对话导航

对话导航的柱列贴阅读区左边缘、垂直居中，不增加背景面、边框或正文留白。短柱使用低透明度的 `muted-foreground`，统一左对齐；预览项以长度和明度共同突出，邻项连续衰减。尺寸使用 rem 随密度缩放：短态长度 `0.3125rem`，展开基础长度 `0.5rem`，预览项最长 `1.375rem`，条目节距 `0.5rem`。交互命中区覆盖整行，宽于短柱本身；键盘焦点使用公共焦点环。

宽度与透明度变化沿用 `--motion-fast / --ease-out`，减少动态时立即切换。预览复用官方 Tooltip，优先向右展开，使用界面字体与有界的多行纯文本。公共组合位于 `packages/ui/src/ui/chat-minimap.tsx`，内容与定位语义见 [对话导航](workbench.md#对话导航)。

### 对话计量概要

配置选择器后只放只读的上下文占用圆环与等宽百分比，保持紧凑留白。轮次底栏左侧使用弱化计量概要，紧凑排列缓存 `DatabaseZap`、吞吐 `Gauge` 的关键数值与耗时，空间不足时在左侧顺序换行；右侧操作靠右、与计量首行居中对齐，复制使用 `ghost / icon-xs` 的公共 `IconButton`。只读计量不呈现为点击按钮；详情复用官方 Tooltip，向上展开并避让窗口边缘，按标题、主要数值与两列明细组织，以 Separator 分区，不嵌套卡片。位置、展示时机、内容与统计范围见 [对话计量](workbench.md#对话计量)。

## 状态与反馈

状态分五类，每类固定图标与颜色；业务代码经 `packages/ui/src/ui/status.tsx` 的 `StatusIcon`、`StatusBadge`、`StatusText` 表达，不直接写状态颜色。颜色不单独表达含义，始终与图标和文字同时出现。

| 状态 | token | 图标 | 示例 |
| --- | --- | --- | --- |
| 成功 | `success`（green 11） | CircleCheck | 已连接、测试通过、插件已加载、资源已完成 |
| 警告 | `warning`（amber 11） | TriangleAlert | 缺少密钥、需要重启、配置已改需重测、等待处理 |
| 错误 | `destructive`（red 11） | CircleAlert | 测试失败、插件无效、引用失效 |
| 进行中 | `primary-text`（图标）／`primary`（徽章表面） | Spinner | 测试中、运行中 |
| 中性 | `muted-foreground`（图标）／`secondary`（徽章表面） | Circle | 就绪、已停用、未测试、无模型 |

| 场景 | 通道 |
| --- | --- |
| 字段校验与失效引用 | 控件 `aria-invalid`，说明用 `FieldError` |
| 字段格式与默认值提示 | 控件 `placeholder`，标签保持字段名；不在字段下方另加说明小字 |
| 用户发起的操作进行中 | 发起处的按钮／面板反馈，防止重复提交 |
| 工作台等待视图同步 | 顶部紧凑 `surface` + `StatusText`，不使用状态徽章、不遮挡画布交互；显示时机见 [工作台状态反馈](workbench.md#工作台状态反馈) |
| 工作台读取失败或后台不可用 | 有旧内容时使用顶部 `Alert`，首份内容缺失时使用 `PageState`；恢复操作与说明放在同一处 |
| 区块内持续存在的状态（读取失败、需要重启、加密不可用、获取参数的逐项结果） | 区块内 `Alert` |
| 瞬时操作反馈（复制成功／失败、创建失败、模型已添加）与没有就地承接的全局错误 | Sonner 通知（窗口底部居中，状态驱动通知用 `useStateToast`，随对应状态撤下） |

- Badge 变体按含义选择：`default` 对应 `primary`，仅用于明确强调；`secondary` 表示普通标签与归属（内置、默认、已添加、使用方）；`success / warning / destructive` 分别表示成功、警告、错误；`outline` 是中性描边标签。不得仅为增加主题色使用范围而把普通标签设为 `default`。
- 需要徽章形式的状态统一使用 `StatusBadge`：进行中映射 `default`，中性映射 `secondary`，其余映射对应语义变体；图标与文字使用该表面的前景色，避免把状态文字色叠在同色底上。持续异常与需要恢复操作的说明使用上表对应通道。

## 数据图表

图表表达数量构成与占比，配合文字明细使用，不单独承载含义。图表用 CSS 与内联 SVG 由业务组合，不引入图表库；动效遵循上文 Motion 规范与减少动态。

- **分类色板**：`chart-1` 至 `chart-8` 取 Radix Colors 第 9 级（blue、teal、amber、violet、crimson、orange、cyan、plum），亮暗分别取对应色阶，不随主题色与灰色变化。只用于图形填充（分段、瓷砖、图例色块），不用作文字、边框或状态色；同一视图内类别按固定顺序取色，跨视图的同一类别不要求同色。
- **非数据区域**：空闲与背景用 `muted`，预留等需与空闲区分的保留区用 `border` 色斜纹，不新增 token。
- **图例与明细**：每个色块都有可见文字标签与数值；颜色不是唯一区分手段，悬停或聚焦图例与图形双向高亮，键盘可聚焦图例项。数值使用等宽数字。
