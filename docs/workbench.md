# 应用与工作台交互

## 应用首页与导航

启动永远显示左侧应用侧边栏与右侧首页，不自动打开已有会话。侧栏负责首页、新会话、已有会话和设置入口，可以隐藏以专注主内容，并能从顶栏恢复。启动可读取列表摘要，用户明确选择会话后才加载其正文、历史与工作台。

首页是独立的创建入口，没有会话身份；其输入是应用草稿，不预先生成任务或代理。首页本身无背景，标识、标题与输入区直接位于窗口材质上，只有输入框等控件形成自己的表面。首页与侧栏是相邻浮岛。

侧栏与首页/工作台共同属于主屏。设置是另一独立屏，切入时侧栏随整个主屏一起移走，返回时一起移回；设置不嵌入右侧主内容。

用户输入内容并选择 agent、具体模型，首次发送被接受后才创建会话、第一个代理资源及首条输入，右侧主内容转为工作台。会话使用生成的 ID，不要求先命名；utility 异步生成标题，标题失败不改变身份或阻止对话。创建失败保留草稿；发送与创建的原子性、去重和失败处理在模型接入计划落实。

首页与代理对话输入框支持文件选择、图片粘贴和拖入文件，允许纯文件发送；草稿中可移除文件或取消上传，受理失败保留可重试。文件随用户消息进入时间轴，图片显示缩略图，其他文件显示文件名；不因此创建资源卡片或建立资源链接。首页的内容尝试随 start 参与会话、代理和首条消息的原子提交。

首页不是空工作台，也不是某个会话的初始状态。工作台是应用可承载的主视图之一，设置及未来主视图不依附于它。首页到工作台的连接动画让背景表面展开、内容过渡，不放大文字，也不等待标题命名完成。

## 对象化，不是把所有内容铺开

默认画布展示代理及用户关心的资源。工具调用在代理流中是一行状态，按需展开为独立卡片。

卡片共有身份、类型、标题、展开/定位等外壳，但不强制共有“目标、输入、进度”等内部结构。代理、文件、网页与工具操作使用适合自身的内容视图。

## 代理卡片

创建对话时选择 agent 与具体模型。选中 agent 后，按它引用的模型角色填入已定义的默认模型，用户可以覆盖；缺少可解析模型时要求明确选择。对话期间可切换 agent 配置、模型和思考等级，下一次模型请求生效；消息历史与代理对象身份保持不变。模型角色在设置中维护，普通对话界面不要求用户额外操作角色对象；完整配置语义见 [模型与代理配置](model-configuration.md)。

内部保留可连续阅读的执行流，以执行段组织用户输入、模型回复、工具过程、输入与产物，而不强制拆成一地消息节点。

对话记录底层为内置代理的普通插件记录，思考、正文与带结果的工具调用平铺保存，由代理按响应归组。代理流在 UI 中聚合并默认折叠连续的思考与工具过程，按需展开；助手输出正文默认完整显示。工具单元可紧邻展示调用和结果，模型投影仍保持完整响应在前、工具结果在后。执行段与过程分组是视图组织，展开、折叠不改变历史。

- 当前资源区：查看有效绑定和 pending 变化，支持折叠。
- 执行段：有稳定定位点，可展开该段的输入、调用与输出。
- 下一次输入区：接受指示与拖入的资源。
- 当前状态：运行、等待用户、受阻、失败、完成，避免混为一类。

所有代理平级，使用相同外壳；一个代理不因创建或链接另一个代理而获得其上下文，只能经授权与该代理资源的工具交互。

思考块与工具调用使用一致的折叠外壳：标题点击区域铺满边框内部，留白位于标题按钮和正文各自内部，外壳不另加内边距。离开阅读区底部时，“最新内容”按钮悬浮在阅读区底部中央，不占据输入托盘布局，不挤动代理、模型与思考等级栏；悬浮层只有按钮区域接收指针事件。

思考块从首个可见内容开始显示。header 在生成期间显示运行图标、“思考中”与计时器，计时起点来自运行时收到的思考块开始事件，切换页面不重新起算；结束后切换为静态思考图标并冻结本次可见计时，中断另有标识。历史未保存起点时不显示耗时。

思考 body 在生成期间使用固定高度、底部对齐的尾部窗口，新内容从下方进入，旧内容从上方移出；预览中的控件不参与键盘焦点。全文不被裁剪或改写，结束或中断后切换为完整 Markdown。内置代理插件的偏好提供“思考时自动展开”和“思考结束后自动折叠”，默认都开启；关闭结束折叠时保留当前开合状态。手动选择在当前阶段持续有效，增量和设置变化不反复开合已经显示的块；开合偏好不改变 body 的过程态/终结态渲染。重新打开历史时默认折叠。

### 工具调用视图

工具调用共用外壳，填充、执行和结果由工具自己的视图表达。模块通过同级的 input、execution、result 声明三态，每个阶段均可独立提供 `headerRenderer`（摘要）和 `bodyRenderer`（正文），相同组件可直接复用。填充视图接收未完成的 JSON 参数；等待调度和执行共用 execution，接收完整参数及运行产出；result 接收当次终结结局。未提供动态填充视图时使用静态准备提示，执行与结果缺失的部分独立回退。摘要不嵌套操作控件；生命周期、异常状态和展开交互由外壳负责。作者接口见 [插件 SDK](plugin-sdk.md#工具视图)。

| 阶段 | 外壳 | 内容与展开 |
| --- | --- | --- |
| 参数填充 | 虚线边框、轻微脉动的输入图标 | 可选动态 header/body，字段与字符串前缀逐步出现；提供正文视图时可展开 |
| 等待执行 | 虚线边框、静态等待图标 | 保留调用摘要，可手动展开输入与调用详情 |
| 执行中 | 实线边框、旋转运行图标 | 保留目标和输入数量，摘要与正文随产出补充；可手动展开 |
| 已终结 | 实线边框、工具静态图标 | 使用保存的终结结果；失败、拒绝、取消、部分完成、未知结局明确标识 |

core 插件偏好提供“工具填充时自动展开”和“工具填充结束后自动折叠”，默认均开启。后者在参数生成完成或中断时作用一次，等待、执行、结束与落库不会重复自动折叠。手动开合在当前阶段持续有效，增量和偏好更新不覆盖当前选择；关闭自动折叠则保留开合状态。历史初次打开默认折叠。瞬态工具不人为延长状态。终结结果可以没有内容，展开显示空结果或原因；不完整且未执行的请求显示“未执行”，可查看已收到的原始参数。减少动态效果时停用图标动画。

`resource_list` 的摘要显示可用资源及数量，正文为资源图标、名称与类型列表；`resource_inspect` 的摘要显示操作及资源类型/名称，正文展示状态字段和可用工具，用法与 schema 进一步展开。两个入口的视图由 Atelier 内置。`resource_call` 自己将展示转交实际二级工具，不增加外围折叠层；填充参数足以匹配本次请求捕获的资源与工具时即可转交预览，尚不能匹配时使用准备提示。展示身份不构成执行授权。

三态应尽可能逐步增加内容，保持已有目标、数量与相同元素的样式连续，具体原则见 [设计系统](design-system.md#对话过程视图)。内置 write 填充时逐步显示路径、正文字符数及自动跟随的正文尾部，字数在执行与完成后保留；成功写入后展示代码正文，read 同样支持代码语法着色。edit 预览操作与新正文，结果按实际编辑点分段展示有增删颜色和前后行号的 diff，远处编辑点之间省略未改内容。工具外壳不限高，body 自行决定局部限制；内置插件正文共用每次调用最多 120 个逻辑行的预算，超出时提示省略，不改变完整记录或模型输出。

正常正文直接展示产出，原始调用参数与结果 JSON 置于次级“调用详情／结果详情”，通过默认不选中的单选控件切换；点击当前项收起，两项共用详情区。结果含 file 或没有有效 data 时隐藏结果详情，原始详情不受内置正文行预算限制。工具错误说明由外壳显示，不会被自定义正文覆盖。历史视图仅使用保存的结果、实现身份和当次资源身份，不以当前资源补写过去，也不为展示历史重新执行。

## 连线端点

- 连到下一次输入区：作为下一次执行输入。
- 连到资源区：请求建立持续绑定。
- 连到已结束的执行段：不得静默改写过去，需进入从该位置分叉的流程。
- 展开历史执行段：可显示实际使用/产出关系。

底层关系定位具体对象与执行端点；卡片折叠时，线可以汇总到卡片边缘。连线布局不决定模型上下文，明确的绑定/输入操作才决定。

## 文件编辑示例

1. 代理流显示一行 edit 调用状态。
2. 用户双击或选择展开，显示该操作卡片。
3. 操作卡片连接来源执行段、目标文件，以及实际变更的 diff 视图。
4. 用户从 diff 视图打开来源操作，定位同一操作对象，不复制记录。
5. 用户选择继续编辑，则针对当前文件创建新操作，不修改旧 diff。

文件对象的当前视图与某次操作的历史 diff 可以同时存在，并显示不同版本语义。

## 资源与上下文查看

资源描述、当前绑定以及实际提供给某次执行的上下文可以查看和折叠。无需单独强迫用户使用一个复杂“上下文管理器”。

拖入资源不应产生不透明副作用：文件/目录接入与向哪个代理授权是不同动作，具体快捷交互可合并，但需要显示结果。

## 对象面板

对象面板是紧凑的快速导航列表。每个对象只出现一次，用资源类型图标、名称和必要的类型／可见状态帮助识别。支持查找与定位；定位已隐藏的卡片时先打开视图，再移动画布。

点击条目直接定位，不在面板中展开正文、详情或操作区。对象之间可以多对多链接并形成环，列表不按代理归属组织，也不展开关系树。内容阅读留在对象卡片或专用视图中，关系由画布表达。

## 授权面板

授权交互突出接收访问能力的代理、被访问资源、访问方向与当前状态；提供代理与资源的选择、资源查找和就地变更反馈。执行期间的变化区分已记录与下一次请求生效，不把链接开关直接解释为完整的工具权限。

授权面板与对象、历史共用右侧浮岛。按代理或资源查看有向链接，以搜索选择器应对对象数量增长。开关提交后显示保存中，等待受理之后的读取结束，再显示实际链接；若后续继续或分叉已覆盖状态，也结束等待并提示路径已改变。失败在对应行提示，读取失败需重试，历史位置只读。

当前会话进度不完整暴露每个在途请求的授权环境，界面显示请求边界说明，不推断单条链接的「已生效／待生效」。能力文案依据实际链接、工具支持与外部策略，不从资源种类猜测可用工具。资源种类与后续运行时能力变化时，交互沿这些原则适配。

## 时间导航与透明度

- 历史面板使用紧凑历史列表，按会话节点真实追加顺序逐条显示；所查看路径内保持相同顺序。时间戳可辅助阅读，不以时间戳重排会话树的追加次序。
- 每条记录的摘要、图标与行样式由提供该记录的模块声明（见 [插件 SDK](plugin-sdk.md#历史记录视图)）；用户消息、思考与模型输出以各自样式区分，不依赖文字前缀。面板只负责定位、分支、筛选与来源分类。
- 每条历史记录对应一个可查看的节点，不按 response、代理、执行段或任务摘要聚合。多代理与工作台事件穿插时，保留各条实际位置；分支导航和筛选不合并节点或改变相对次序。
- 顶部以线形 Tab 切换分支，横向溢出时滚动。首条路径为「主分支」，同一父节点最先追加的后代延续原分支，之后的兄弟后代各开启「分支 1、分支 2……」；编号按出现顺序固定，不随游标、过滤或后续追加改变。实际追加兄弟节点后才出现新 Tab，不把仅移动执行游标当成已经产生分支。
- 每个 Tab 展示共享起点与该分支独有的连续后续。例如原分支 `A → C → B` 保留不变，新分支显示 `C → D`；C 仍是同一个历史节点。分叉入口位于 C 之后、下一事件之前的独立轻量导航行：原分支跳到新 Tab 的 C，新分支返回原 Tab 的 C。导航行不属于历史事件，不占事件操作区；仅在存在分支关系时出现，与所属 C 一起参与筛选，避免落在无关事件之间。同一点的多个分支合入带数量的菜单。嵌套分支逐层返回，更多共同历史在上级 Tab 中查看。会话起点也支持相同往返；不完整块同样作为导航落点，完整性由块自身标识。
- 面板打开期间记住各 Tab 最近查看的节点，首次切换定位其最后一个可查看节点。分叉点按钮始终定位共同起点，并清除会隐藏落点的搜索与来源筛选。切换只改变查看位置；等待查询期间维持原 Tab 和完整画面，成功后随工作台／对话投影一起切换，失败保留原视图。当前执行分支与执行位置使用单独标记，查看位置使用条目选中态与查看图标。
- 历史视图可在所选分支内选择全部记录、会话事件、全部资源事件或某个具体资源的记录，并与文本搜索组合。分类只读记录来源 `source.resource`：为空是会话事件（工作台事件、自动命名等），否则是该资源的记录；工具目标和工作台链接的相关对象不视为记录来源。代理视图包括它提交的用户输入以及其思考、正文、调用和通知。来源选择器可搜索，只列出整份历史中存在可查看资源记录的对象，保留已移除或其他分支的来源。来源筛选与搜索不移动查看位置或执行游标。
- 条目左侧为图标，右侧固定两行：第一行是记录提供方声明的摘要。第二行弱化显示来源：资源记录为「资源类型 · 资源 title」，会话事件为「会话」。宿主只按来源字段区分，不按记录种类写条件分支。
- 选中不展开、不增加行高；正文与详细过程在对应对象视图中阅读。当前查看位置与执行游标分别标识，返回当前与继续操作放在稳定位置。
- 历史位置包含所选节点。查看某条之前定位其真实父节点，不能用筛选列表的上一行代替；会话起点可独立定位。会话收束后可从任意历史节点原样继续，模型上下文的截取由执行体负责。
- 过去尚不存在的对象不显示；已结束绑定按所查看时刻判断。
- 半透明用于 pending attach/detach，不用于含糊表达“可能过时”。
- 历史模式有明确标识和返回当前入口。
- 工作台与代理对话一起切换到同一查看位置；后台执行和列表刷新不会改变历史查看位置。生成中的块与保存后的块保持同一展示身份，保存不会重置展开状态。
- 查看历史与执行恢复是不同按钮/流程。

## 布局原则

- 窗口层次与浮岛编织见 `docs/design-system.md`：应用屏承载侧栏与主内容；工作台在选中会话后占据主内容。对象、历史与授权面板以工作台右侧的更深浮岛打开，复用 `IslandPanel`；双击预览、编辑器等扩展视图同样走浮岛机制。以后的工作台分屏（聚焦对象、代理手稿区）接入同一浮岛编织机制。
- 窗口以系统材质为底座，左上导航区、右上当前视图操作区及下方内容彼此留出间隙。侧栏是应用导航，不属于工作台；隐藏时将空间让给主内容。工作台操作只在工作台中出现，画布控制和对象、历史面板位于工作台内。尺寸与主题见 `docs/design-system.md`。
- 默认自动布局，用户移动过的卡片不随意被重新摆放。
- 代理对话中的高频工具过程可以收纳或聚合；历史导航始终保留独立节点落点。
- 提供聚焦某张卡片的方式，不要求用户始终操作整个画布。
- 大量历史按需加载，长文本与列表需虚拟化。
- 视图布局与工作事件分开持久化；布局同步和历史布局恢复不属于初版核心能力。

## 当前应用框架

工作台内的笔记和可添加资源种类仍用于基础能力验证，不构成最终资源目录。对象、历史与授权使用上述正式交互，数据来自真实会话控制器。

首页选择 agent、模型与思考等级后发送；接受成功后首页放大淡出，工作台放大淡入，第一个代理卡片随会话一同建立视图位置。失败保留草稿，相同输入重试复用提交身份。切换会话或设置不取消正在运行的模型请求。

所有卡片使用 `ObjectCard` 控件：官方 Card 外壳、拖动柄标题栏、折叠/关闭视图与不触发画布的内容区。宽高使用画布单位，不随浮岛宽度自动变化。资源模块声明默认尺寸和可选最小尺寸；未声明下限时使用公共下限。选中且展开时显示右下角缩放柄，宽高可独立调整，标题栏高度、字号与操作控件不随卡片尺寸变化。内容使用剩余空间，溢出由模块内部滚动或适配；该机制适用于所有卡片，不依赖资源类型。

拖动过程中连续更新本地尺寸，松手后通过 `view.set` 保存宽高覆盖；旧投影不覆盖正在拖动或尚未确认的尺寸。折叠时只呈现标题栏，保留展开尺寸，再次展开恢复；关闭再定位、重开会话和查看历史也使用当前布局尺寸。更多菜单的「卡片尺寸」提供按默认宽高 1.5 倍与 2 倍设置的「大」「特大」，以及清除覆盖的「恢复默认尺寸」，这些入口可用键盘操作。尺寸与位置同属视图布局，不追加任务历史，不影响资源授权和模型上下文。

代理卡片内部连续显示输入、正文、思考与工具过程，底部为输入区，标题栏提供状态与对象操作；增加高度主要扩展阅读区，增加宽度使正文重新排版。历史由工作台统一入口进入。正文由 Streamdown 渲染。

React Flow 提供平移、缩放、卡片移动和尺寸调整、关系展示与定位选中对象。工作台画布统一提供寻找放置空位与聚焦对象集合两个接口，创建、对象面板及画布工具栏共用这些入口；节点测量、视口动画与保存由画布管理。

没有指定落点的新卡片在创建提交时，按自身默认尺寸和已有可见卡片的实际测量边界寻找空位；卡片中心离当前视口中心越近越优先，保持卡片间距，不重排已有卡片。资源类型的创建尺寸与卡片 renderer 共用声明。创建成功后，视口共同容纳提交前选中的对象和新对象；没有选中对象时只聚焦新对象。共同聚焦只调整视口，不扩大选中集合。拖入资源使用鼠标落点，多项拖入按偏移错开。

聚焦接口接受任意数量的对象身份，显示目标的完整边界并留少量边距，最高以 100% 显示；空集合或含失效身份的请求不移动视图。隐藏对象先打开视图，再等待所有目标的投影与节点测量就绪；对象面板定位同时选中目标，其他聚焦默认保留选择。新聚焦意图与导航变化取消旧意图，完成后的普通窗口尺寸变化不重复执行旧定位。

缩放上限为 400%。普通画布的交互缩放下限为 5%；可见对象分散得更远时，下限随全图边界与画布尺寸降低，保留全图适配缩放之外约 20% 的余量，以便概览寻找对象。持久化契约允许更小的合法缩放，重开会话保留保存的视口。放大与缩小按钮之间提供「重置缩放至 100%」，保持当前画布中心并保存视口。画布的「适配所有对象」使用四角图标，「定位选中对象」使用准星图标。

关闭卡片只保存隐藏状态，通过对象面板定位时重新打开。移除对象位于卡片更多菜单，确认后执行，要求对象已收束，并同时解除全部入向与出向链接；键盘 Delete 只解除明确选中的连线。

标题栏「添加」下拉统一添加代理与资源，三个菜单项均带省略号并打开创建对话框。名称统一为首个字段，标签为「名称」，不使用可选标记或名称占位符。提交时去除名称首尾空白：笔记名称为空时显示字段错误；代理名称为空时采用所选 agent 配置名；目录名称为空时采用目录 basename，根目录以完整路径作为回落值。代理需显式选择 agent 配置、模型与思考等级；笔记正文在创建表单填写，当前卡片只读；目录可填写绝对路径或调用系统选择窗口，路径为空、非绝对路径或目录不存在时由后台校验拒绝。提交期间锁定字段和关闭操作，创建失败保留输入并在对话框内提示，会话读取失败可在原表单内重试；正文与弹窗均限制高度，超出时滚动。文件夹也可直接拖入画布成为目录资源。

从任意对象的端点拖到代理端点即请求授权，箭头从拖动起点对象指向接收授权的代理；卡片位置不决定授权方向。选中连线后按 Delete 解除；代理之间连线表示起点代理作为资源授权给终点代理。历史查看时不可连线或删线。授权面板同时提供键盘与读屏可用的操作入口。

同一对代理的两个反向链接合并显示为一条双箭头线，两端各占一个自动分布端点。选中双箭头线后按 Delete 解除两个方向；通过授权面板单独解除一个方向时，连线变回剩余方向的单箭头。合并只影响显示，底层仍保留两条独立有向链接及各自的建立、解除事件。

卡片上、下、左、右四边都可拖线。已建立的连线按两端卡片的相对位置与尺寸选择相向的边；同一边的多条连线按对方卡片坐标排序，每条线分配独立端点并沿该边均匀分散。没有连线的边保留一个中心端点，有连线的端点也可继续拖线。移动、调整尺寸、展开或折叠卡片会重新计算端点，隐藏任一端卡片时收起该连线。端点由可见布局投影，不单独持久化，不改变授权或工作历史。

历史列表以标准事件文本和原文片段定位独立节点；历史模式禁用业务修改并提供返回当前入口。隐藏、展开、折叠、位置、尺寸与视口仍可保存，它们不改变查看位置或历史内容。查看旧节点不改变执行游标，空闲时可从任意历史节点明确继续。初始标题取首条输入前 72 字符；utility 执行两级自动命名，失败时保留当前标题，来源通过不可变事件记录，规则见 [自动会话命名](session-naming.md)。查看历史不恢复会话标题。
