# 应用与工作台交互

## 应用首页与导航

启动永远显示左侧应用侧边栏与右侧首页，不自动打开已有会话。侧栏负责首页、新会话、已有会话和设置入口，可以隐藏以专注主内容，并能从顶栏恢复。启动可读取列表摘要，用户明确选择会话后才加载其正文、历史与工作台。

首页是独立的创建入口，没有会话身份；其输入是应用草稿，不预先生成任务或代理。首页本身无背景，标识、标题与输入区直接位于窗口材质上，只有输入框等控件形成自己的表面。首页与侧栏是相邻浮岛。

侧栏与首页/工作台共同属于主屏。设置是另一独立屏，切入时侧栏随整个主屏一起移走，返回时一起移回；设置不嵌入右侧主内容。

用户输入内容并选择 agent、具体模型，首次发送被接受后才创建会话、主代理及首条输入，右侧主内容转为工作台。会话使用生成的 ID，不要求先命名；utility 异步生成标题，标题失败不改变身份或阻止对话。创建失败保留草稿；发送与创建的原子性、去重和失败处理在模型接入计划落实。

首页不是空工作台，也不是某个会话的初始状态。工作台是应用可承载的主视图之一，设置及未来主视图不依附于它。首页到工作台的连接动画让背景表面展开、内容过渡，不放大文字，也不等待标题命名完成。

## 对象化，不是把所有内容铺开

默认画布展示代理及用户关心的资源。工具调用在代理流中是一行状态，按需展开为独立卡片。

卡片共有身份、类型、标题、展开/定位等外壳，但不强制共有“目标、输入、进度”等内部结构。代理、文件、网页与工具操作使用适合自身的内容视图。

## 代理卡片

创建对话时选择 agent 与具体模型。选中 agent 后，按它引用的模型角色填入已定义的默认模型，用户可以覆盖；缺少可解析模型时要求明确选择。对话开始后 agent 固定，模型仍可切换。模型角色在设置中维护，普通对话界面不要求用户额外操作角色对象；完整配置语义见 [模型与代理配置](model-configuration.md)。

内部保留可连续阅读的执行流，以执行段组织用户输入、模型回复、工具过程、输入与产物，而不强制拆成一地消息节点。

对话记录底层为会话节点树，模型节点内包含有序内容块和工具单元。代理流在 UI 中聚合并默认折叠连续的思考与工具过程，按需展开；助手输出正文默认完整显示。工具单元可紧邻展示调用和结果，模型投影仍保持完整响应在前、工具结果在后。执行段与过程分组是视图组织，展开、折叠不改变历史。

- 当前资源区：查看有效绑定和 pending 变化，支持折叠。
- 执行段：有稳定定位点，可展开该段的输入、调用与输出。
- 下一次输入区：接受指示与拖入的资源。
- 当前状态：运行、等待用户、受阻、失败、完成，避免混为一类。

子代理使用相同外壳，通常独立呈现；主代理不自动拥有所有子代理上下文。

## 连线端点

- 连到下一次输入区：作为下一次执行输入。
- 连到资源区：请求建立持续绑定。
- 连到已结束的执行段：不得静默改写过去，需进入从该位置分叉的流程。
- 展开历史执行段：可显示实际使用/产出关系。

底层关系定位具体对象与执行端点；卡片折叠时，线可以汇总到卡片边缘。连线布局不决定模型上下文，明确的绑定/输入操作才决定。

## 文件编辑示例

1. 代理流显示一行 edit 调用状态。
2. 用户双击或选择展开，显示该操作卡片。
3. 操作卡片连接来源执行段、目标文件，以及实际变更的 diff 视图。
4. 用户从 diff 视图打开来源操作，定位同一操作对象，不复制记录。
5. 用户选择继续编辑，则针对当前文件创建新操作，不修改旧 diff。

文件对象的当前视图与某次操作的历史 diff 可以同时存在，并显示不同版本语义。

## 资源与上下文查看

资源描述、当前绑定以及实际提供给某次执行的上下文可以查看和折叠。无需单独强迫用户使用一个复杂“上下文管理器”。

拖入资源不应产生不透明副作用：文件/目录接入与向哪个代理授权是不同动作，具体快捷交互可合并，但需要显示结果。

## 时间导航与透明度

- 使用执行 summary list 定位历史，不先实现 3D 画布。
- 过去尚不存在的对象不显示；已结束绑定按所查看时刻判断。
- 半透明用于 pending attach/detach，不用于含糊表达“可能过时”。
- 历史模式有明确标识和返回当前入口。
- 查看历史与执行恢复是不同按钮/流程。

## 布局原则

- 窗口层次与浮岛编织见 `docs/design-system.md`：应用屏承载侧栏与主内容；工作台在选中会话后占据主内容。对象与历史辅助面板是工作台内的浮层。以后的工作台分屏（聚焦对象、主代理手稿区）接入同一浮岛编织机制。
- 窗口以系统材质为底座，左上导航区、右上当前视图操作区及下方内容彼此留出间隙。侧栏是应用导航，不属于工作台；隐藏时将空间让给主内容。工作台操作只在工作台中出现，画布控制和对象、历史面板位于工作台内。尺寸与主题见 `docs/design-system.md`。
- 默认自动布局，用户移动过的卡片不随意被重新摆放。
- 高频工具过程收纳或聚合，完成的分支可折叠。
- 提供聚焦某张卡片的方式，不要求用户始终操作整个画布。
- 大量历史按需加载，长文本与列表需虚拟化。
- 视图布局与工作事件分开持久化；布局同步和历史布局恢复不属于初版核心能力。

## 当前主代理界面

首页选择 agent、模型与思考等级后可以发送，接受成功进入工作台并呈现主代理卡片；失败保留草稿，相同输入重试复用提交身份。启动只读列表摘要，选择已有会话后才读取正文。切换会话或设置不取消正在运行的模型请求。

主内容浮岛承载 React Flow 工作台；主代理作为具有稳定对象身份的可移动卡片，内部连续显示用户输入、模型正文、可折叠思考与工具过程。输入区稳定置于底部，支持 Enter 发送、Shift+Enter 换行；执行中可写草稿并停止当前执行。正文、思考与摘要使用 Streamdown 渲染 Markdown；工具单元展开后显示参数和用户结果。用量按响应展示，不拆分伪造内容块计量。

历史菜单可查看旧节点，观察行为不改变当前游标或运行。空闲时可从完整节点明确继续，旧分支仍保留。不完整节点仅可查看，提供从前一完整位置另起分支重试的入口，不承诺撤销工具影响。关闭并重开后读取保存的内容和中断状态。

工作台按对象身份投影卡片，已有资源对象仍可查看，已有绑定关系显示为连线。对象菜单可隐藏和重新打开卡片；现有笔记创建与显式绑定入口保留，作为已有资源能力使用，不据此固定最终资源目录；卡片位置和画布视口独立保存，隐藏不删除对象。主代理标题栏可拖动，正文和输入区独立处理滚动、选择及输入，不触发画布移动。画布支持平移、缩放、适应全部对象和定位主代理。早期没有真实对话记录的代理显示说明，不伪造消息。正式资源种类、添加方式和授权操作的完善另行收敛，不改变对象与关系的工作台形态。

当前标题取首条输入的前 72 字符，utility 异步命名仍待接入。主代理具体布局、真实模型输出与交互需用户在 Electron 中验收；自动化检查不代替视觉验收。
