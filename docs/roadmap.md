## 1. 无模型的任务历史骨架

用手动事件验证任务、对象、关系、执行轮次与视图：

- 能持久化并重建指定历史位置。
- 请求期间的环境变化不影响在途请求及其工具批次，下一次请求按新状态执行。
- 打开卡片不创建重复业务对象。
- 回看不改变现实资源。

上述历史内核契约已由自动化测试覆盖。应用服务另验证重开存储、事务回滚、跨任务对象隔离与视图/事件分离。

### 进入真实执行前：设置配置能力

1. 应用级设置入口、页面承载与公共控件已实现；收尾既有壳子交互验收，保留现有视觉风格。
2. 提供商添加、具体模型管理、加密保存、重开读取和连接测试已实现，真实系统凭据/端点与 GUI 待用户验收。
3. 模型角色与所有代理共用的 agent 配置已实现；配置职责与选择语义见 [模型与代理配置](model-configuration.md)。
4. 会话树、模型输入投影、请求边界配置取用、工具批次、目录和笔记正文操作已实现；后续收尾真实执行与专项边界验收。

首次真实执行从首页发送开始：原子创建生成 ID 的会话、第一个代理资源和首条输入，不要求预先命名或创建空任务。core `naming` 模块经提交后观察，调用配置了模型的 `utility` 角色依据首条消息异步命名；用户确认命名实现无故障。

配置字段、模型协议与存储工作按 [专项计划](../plans/todo-2026-10-01-model-protocol-storage.md) 跟踪；配置管理与真实执行分别交付和验收。

## 2. 目录资源与单代理

接入一个 provider，提供带 resource_id 的最小文件操作；只通过明确绑定获得目录能力。

验收流程：

1. Workspace 存在目录，但未绑定目录资源，文件调用被拒绝。
2. 绑定 a.txt 所在目录，代理读取并成功编辑。
3. 保存实际变更，流中显示一行 edit；展开后能定位操作与 diff。
4. 模型请求期间 detach，按真实顺序记录事件，该请求及其工具批次按原授权完成。
5. 同一执行轮次的下一次模型请求看到投影至响应之后的 detach 事件，旧资源调用被拒绝，历史记录仍可查看。
6. 从编辑前分叉，识别现实文件已经改变，不把旧内容默默写回。


## 3. 虚拟资源与历史恢复

实现一个工坊持有完整状态的虚拟资源，验证历史查看与状态恢复：

- 可以查看已记录历史位置的状态。
- 完整状态能够恢复；固定操作序列下可验证状态转移。
- 浏览历史不自动恢复当前实例。
- 当前实例与历史观察有明确区分。
- 恢复原实例与创建隔离实例需要明确选择，不覆盖其他工作而不提示。

不以细粒度时间轴 UI 为第一项要求；先验证状态记录与恢复正确性。

## 4. 完整工作台与多代理

- 代理、资源和操作卡片，以及具体执行端点与关系线。
- 验证自动布局、动态卡片尺寸、手动位置保留与折叠端点，见 [布局验证立案](../plans/todo-2026-09-18-workbench-layout.md)；布局引擎不接管业务对象与历史。
- 逐节点紧凑历史导航、对象定位与按需加载；代理流内的折叠不改变历史落点。
- 子代理委派、结果交付事件及显式资源授权。
- 多代理在途执行期间的解绑状态、分支和晚到结果处理。

## 5. MCP 与缓存实测

- 先接入少量工具，区分延迟连接、工具发现与模型可调用集合。
- 测量稳定工具目录与动态发现的输入量、延迟、缓存 token 和调用正确率。
- 在确有收益时采用 provider 工具搜索或稳定分发入口，保持资源授权和历史语义不变。
- 不根据“工具数量”单独推断成本；记录 schema 大小与模型实际表现。

## 必测边界

- 资源不存在、已解绑、权限不足、路径越界和符号链接。
- 工具失败、部分成功、进程崩溃与副作用结果未知。
- 模型尝试按旧消息调用已解绑资源。
- 文件在读取与写入之间被外部修改。
- 历史缺乏完整内容、恢复不受支持、当前授权已撤销。
- 两个代理共享资源，以及分叉后的共享可变状态。
- 工具调用和结果在 provider 消息中合法配对。
- 冷启动保留工作记录，但始终显示首页；用户选择后读取会话，不自动重放非幂等副作用。
