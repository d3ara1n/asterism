# 实施路线与验收边界

本文定义工坊从基础内核到完整多代理工作台的阶段划分、验收场景与必测边界。具体跨会话待办任务由 `plans/` 跟踪。

## 阶段 1：任务历史内核与桌面底座（已完成）

建立不依赖第三方 agent 框架的持久历史树、三进程桌面底座与基础工作台：
- 会话级扁平节点树（`session_nodes`）、执行游标与当前时间线追加，游标跳转后全量重放重建工作台对象与有向链接。
- 请求期间的环境与链接变化按序记录，不影响在途请求及其工具批次，下一次请求按新状态执行。
- 原生材质窗口、浮岛编织（`Window / Space / Screen / Island`）、独立首页、侧栏会话列表及外观／语言设置。
- 插件 SDK（`@atelier/sdk`）主干、内置 `atelier.builtin` 插件装配、具型创建／动作准备管线、不可变字节内容存储（`ContentRef`）、公共 i18n 与全局具型瞬态事件总线。

## 阶段 2：模型配置、单代理执行与原生正文工具（已完成主体，专项收尾中）

接通真实模型协议、全局配置体系与首批验证资源（目录、笔记）：
- **提供商与模型配置**：OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages 三协议接入与异步连接测试；提供商预设目录、端点模型发现、从 `models.dev` 获取参考参数、可组合模型兼容包，以及模型角色与代理配置的内置继承和局部覆盖。
- **代理对话与上下文管理**：首页原子创建会话并发送、流式 Markdown 与思考渲染、工具填充／执行／结果三态视图、执行状态投影（停止／继续）、两级自动会话命名與人工重命名、跨模型思考续接投影，以及长对话上下文自动压缩。
- **目录与笔记工具**：共享 `read / edit / write` 正文契约（`LINE#HASH` 锚点整批编辑与 unified diff）、目录 `list` 与图片查看 `see`、Pierre Diffs 代码与差异预览。

插件扩展的分包、公共提供方、顶层工具、对象关联调用与 Agent 界面扩展已完成；内置 `ask_user` 作为首个消费者贯通工具等待、面板输入与结果续轮。实施与验收边界见 [归档记录](../plans/archived/todo-2026-10-15-plugin-tools-ui.md)。插件分发和后续能力分别由 [插件系统计划](../plans/todo-2026-10-12-plugin-system.md) 与 [运行时能力计划](../plans/todo-2026-10-01-runtime-capabilities.md) 跟踪。

### 核心验收流程
1. Workspace 存在目录，但未绑定目录资源时，文件调用被拒绝。
2. 绑定目标目录后，代理读取并成功编辑文件，对话流显示 `edit` 状态，展开可查看实际 diff。
3. 模型请求期间执行 detach，按真实顺序记录事件，在途请求及其工具批次按原授权完成。
4. 同一执行轮次的下一次模型请求看到投影至响应之后的 detach 事件，旧资源调用被拒绝，历史记录仍可查看。
5. 从编辑前的位置分叉继续，系统识别现实文件已经改变，不把旧内容静默写回。

## 阶段 3：虚拟资源与状态恢复（待推进）

实现由工坊持有完整状态的捕获型虚拟资源，验证历史重建与状态恢复：
- 资源可按执行游标重建已记录的状态；固定操作序列下可验证状态转移。
- 历史面板候选选择不改变当前实例，明确点击「从这里继续」跳转后才重建。
- 状态恢复作为独立操作：明确区分“恢复原实例”与“从快照创建隔离实例”，不静默覆盖其他分支工作。

## 阶段 5：MCP 接入与缓存实测（待推进）

- 接入官方 MCP TypeScript SDK，区分延迟连接、工具发现与模型可调用集合。

- 在确有收益时接入 provider 工具搜索或延迟发现，保持资源执行层授权与历史语义不变。

## 必测边界

- 资源不存在、已解绑、权限不足、路径越界、符号链接及读写竞争。
- 工具失败、部分成功、取消及写操作影响未知（`unknown`）。
- 模型尝试按旧消息调用已解绑资源，或跨模型切换时的思考／工具 ID 兼容投影。
- 历史缺乏完整内容、恢复不受支持或当前授权已撤销。
- 两个代理共享同一可写资源，以及分叉后的共享可变状态。
- 冷启动保留工作记录但始终显示首页；用户选择后读取会话，不自动重放非幂等副作用。
