## 1. 无模型的任务历史骨架

用手动事件验证任务、对象、关系、执行轮次与视图：

- 能持久化并重建指定历史位置。
- pending 变化不会提前进入有效绑定。
- 打开卡片不创建重复业务对象。
- 回看不改变现实资源。

上述历史内核契约已由自动化测试覆盖。应用服务另验证重开存储、事务回滚、跨任务对象隔离与视图/事件分离。

### 进入真实执行前：UI 壳子与提供商配置

1. 补齐应用级设置入口、页面承载、公共控件与已有壳子交互，完成用户验收；保留现有视觉风格。
2. 接入已确认的提供商配置与保存方案，在设置界面完成添加连接、添加模型、保存、重开读取和连接测试。
3. 收敛 transcript、模型实际输入、错误恢复与工具批次契约，再进入目录资源与单代理阶段。

模型协议与存储工作按 [专项计划](../plans/todo-2026-10-01-model-protocol-storage.md) 跟踪；UI 前置阶段不安装模型 SDK 或提前迁移配置存储。

## 2. 目录资源与单代理

接入一个 provider，提供带 resource_id 的最小文件操作；只通过明确绑定获得目录能力。

验收流程：

1. Workspace 存在目录，但未绑定目录资源，文件调用被拒绝。
2. 绑定 a.txt 所在目录，代理读取并成功编辑。
3. 保存实际变更，流中显示一行 edit；展开后能定位操作与 diff。
4. 执行中请求 detach，显示 pending，本轮按原授权完成。
5. 下一轮看到 detach 生效事件，旧资源调用被拒绝，历史记录仍可查看。
6. 从编辑前分叉，识别现实文件已经改变，不把旧内容默默写回。


## 3. 虚拟资源与历史恢复

实现一个织台持有完整状态的虚拟资源，验证历史查看与状态恢复：

- 可以查看已记录历史位置的状态。
- 完整状态能够恢复；固定操作序列下可验证状态转移。
- 浏览历史不自动恢复当前实例。
- 当前实例与历史观察有明确区分。
- 恢复原实例与创建隔离实例需要明确选择，不覆盖其他工作而不提示。

不以细粒度时间轴 UI 为第一项要求；先验证状态记录与恢复正确性。

## 4. 完整工作台与多代理

- 代理、资源和操作卡片，以及具体执行端点与关系线。
- 验证自动布局、动态卡片尺寸、手动位置保留与折叠端点，见 [布局验证立案](../plans/todo-2026-09-18-workbench-layout.md)；布局引擎不接管业务对象与历史。
- summary list 历史导航、聚焦、折叠与按需加载。
- 子代理委派、结果交付事件及显式资源授权。
- 多代理在途执行期间的解绑状态、分支和晚到结果处理。

## 5. MCP 与缓存实测

- 先接入少量工具，区分延迟连接、工具发现与模型可调用集合。
- 测量稳定工具目录与动态发现的输入量、延迟、缓存 token 和调用正确率。
- 在确有收益时采用 provider 工具搜索或稳定分发入口，保持资源授权和历史语义不变。
- 不根据“工具数量”单独推断成本；记录 schema 大小与模型实际表现。

## 必测边界

- 资源不存在、已解绑、权限不足、路径越界和符号链接。
- 工具失败、部分成功、进程崩溃与副作用结果未知。
- 模型尝试按旧消息调用已解绑资源。
- 文件在读取与写入之间被外部修改。
- 历史缺乏完整内容、恢复不受支持、当前授权已撤销。
- 两个代理共享资源，以及分叉后的共享可变状态。
- 工具调用和结果在 provider 消息中合法配对。
- 冷启动能恢复工作记录，但不自动重放非幂等副作用。
