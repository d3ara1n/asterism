# 自动会话命名

会话命名由内置插件 `atelier.builtin` 的 `naming` 模块提供。模块理解同一插件的 Agent 记录契约，通过记录提交观察生成名称，通过执行游标变化观察重建当前标题；回合含义见 [运行时](runtime.md#执行轮次与循环)，公共会话 API 不解释 Agent 的 block／request／turn 或命名事件。

## 触发与材料

命名只在用户消息提交时检查条件，异步请求配置了模型的 `utility` 角色，不阻塞对话。助手输出、工具结果、停止和显式继续仅增加对话材料，不触发命名。

用户消息指 `AgentInputMessage.sender.kind === "user"`；代理通信不触发命名、不计入用户消息检查点，也不作为初始标题回退材料。由代理消息独立开启的回合，其回复不归入上一用户回合；当前用户回合中的代理插话不改写用户发言。

| 层级 | 触发条件 | 材料 |
| --- | --- | --- |
| 一级 | 本批新增记录包含全会话第一条用户消息 | 该消息的少量文本 |
| 二级 | 本批包含当前路径最新用户消息，路径内用户消息数量为 5、10、20、50、100 | 当前路径的用户输入与相关助手正文，包括尚无回复的新输入 |

计数包括本次新输入，跨代理累计当前路径上的用户消息；每个代理的输入与回复按代理身份、请求起点关联。停止后继续仍属原回合，模型请求、工具批次与执行启停均不增加回合数。兄弟分支不进入材料或路径计数。

一级与二级共用命名规则：用用户的自然语言概括工作，结合助手回复中的实际发现与结果，保留有辨识度的对象、文件或模块名。标题上限为 50 个 Unicode 字符，模型输出只取正文，清理前缀、标签与引号；错误、截断、缺少正常终态或空结果保留当前标题。

材料固定在触发提交的快照。每回合按输入边界聚合其全部用户消息和最后一次有完整正文的模型回复；同一回复的多个正文块按序合并，思考、工具载荷与未完成正文排除。最多取 8 回合；超出时取前 4 与后 4，并注明中间省略。每回合用户文本预算为 200、助手为 400 个 UTF-16 code units，分别保留头尾、合并空白，保持角色结构。

## 标题来源与不可变事件

`SessionNamed`（`atelier.builtin/session.named`）是会话级记录（经 `session.commit` 写入，来源 `resource` 为 null），记录每次命名的 `{ title, source, auto? }`：

| source | 含义 | 自动更新 |
| --- | --- | --- |
| `user` | 用户明确设置 | 跳过 |
| `auto` | 自动命名；`auto` 携带 `{ level: initial \| refined, messageId, model }` | 可被后续自动命名替换 |

`messageId` 是触发本次命名的用户消息，`model` 是 utility 实际解析出的模型引用。命名只有这一种记录，不另记安排或尝试。

执行游标变化后，命名模块读取当前祖先路径上的最后一条 `SessionNamed`，将其标题同步到宿主的 `session.title`。正常追加、从历史位置继续与切回已有路径使用同一规则。历史面板选中条目不移动执行游标，也不改变标题。用户命名保护只作用于包含该命名事件的路径，旁支不继承保护。

路径上没有命名事件时，从当前路径第一条用户消息重建初始标题：文本取去除首尾空白后的摘要，纯文件输入使用文件名或媒体类型摘要，再截断到 72 个 UTF-16 code units。初始标题只是规则推导的概念，不另存也不提供读取；游标回到首条输入之前时路径上两者都没有，标题保持不变。最新命名事件无法解码，或没有可解码的首条输入时，保留当前标题，不跳过未知记录猜测旧名。

观察到新增用户消息后，先查询当前路径最新命名事件。若 source 为 `user` 或记录无法解码，立即退出，不进行回合计数、材料采样、提示构造、角色检查、任务启动或模型请求；若其 `auto.messageId` 已是本次输入，同样不再命名。

命名生成只追加 `SessionNamed`；用户命名的写入方同样只需追加 `source: user` 的命名事件。每次命名都追加新事件，包括文字相同但来源不同的命名；旧事件保留，不修改或删除。标题由 `cursorChanged` 观察者在原提交后以 `title.set` 直接覆盖。标题同步不追加记录、不移动游标，回溯也不追加恢复命名事件。

观察者失败记录日志，下一次执行游标变化重新按路径同步。

失败、取消或过时的结果不追加任何记录；输入不会因重开自动补做，下一个检查点可以再次命名。命名事件 `model: null`，不进入 Agent 模型输入，也不触发命名。

## 人工命名入口

会话列表每行通过 more 按钮打开操作菜单，当前提供「重命名会话」。按钮在鼠标悬停、键盘焦点进入该行或菜单打开时可见；点击操作不切换当前会话。命名对话框以该会话标题初始化草稿，草稿不随自动命名或列表刷新覆盖。当前打开的会话视图未就绪时禁用其重命名；其他会话可直接从列表命名。保存相同文字仍表达一次人工命名。输入最多 160 个 UTF-16 code units，空白标题拒绝；命名模块合并连续空白并去除首尾空白后保存。

应用的 `rename` 会话命令调用 `NamingApi.nameByUser`，只追加 `source: user` 的 `SessionNamed`。`createNamingModule` 在真实 `setup(plugin)` 中创建捕获插件 context 的函数，经显式连接交给应用组合层；`createModules` 每次装配持有独立接口，在 core 装配成功后开放调用，装配失败或关闭开始后拒绝调用。模块清理时断开连接，不使用模块级单例，也不公开整个 context。来源由 SDK 写入通道打戳，应用不另行设置标题。

应用组合层为对话框提供提交接口：当前会话沿已有会话控制器提交并等待重读；其他会话直接提交 `rename`，不加载正文或改变导航。标题与列表沿已有会话变化通知重读；命令失败保留草稿，成功后关闭对话框，焦点回到对应行的 more 按钮。不增加模型工具、通用服务查找或 SDK 命名接口。

## 异步结果保护

托管任务按会话与输入身份去重，超时为 10 秒。模型请求开始前、结果追加的同步事务内均检查当前路径最新命名事件身份与最新用户消息。较新的命名、用户命名（即使文字相同）、新输入或不再包含该输入的路径变化均使旧任务失效；请求尚未开始时直接退出，已发送请求的旧结果不追加。标题当前值与观察者调用先后不参与判断，后续助手输出不改变本次固定材料。

`utility` 不可用时保留当前标题，不回退到对话模型。请求错误由托管任务日志记录，命名失败不影响 Agent 执行。
