# 技术架构

## 初版技术基线

| 领域 | 选择 | 说明 |
| --- | --- | --- |
| 桌面外壳 | Electron | 本地集成与统一 Chromium；测试以 macOS 为主，发布覆盖 macOS、Windows、Linux |
| 界面 | React + TypeScript + Vite | 交互面板与常规 Web 组件 |
| 对话渲染 | Streamdown 2.7.0 | Markdown、GFM 与流式未闭合语法，应用不自建解析器 |
| 设计系统 | shadcn/ui + Tailwind CSS | 组件源码纳入仓库；统一使用 Tailwind 与设计 token，不并行维护另一套组件样式体系 |
| 节点工作台 | @xyflow/react | DOM 卡片、端点与连线 |
| 文件编辑与 diff | Monaco Editor | 文件视图和差异视图，按需挂载 |
| 文本差异生成 | diff（jsdiff） | 后端按行生成标准 unified diff，保留换行差异并限制计算预算；与编辑器展示分工 |
| 结构化持久化 | SQLite（`node:sqlite`） | 对象元数据、事件、关系、检查点索引；运行时未提供该模块或能力不足时改用 better-sqlite3 |
| 校验 | Zod | 事件、工具参数与配置的运行时校验；与 Vercel AI SDK 对齐 |
| 代码构建 | electron-vite | 主进程、preload、renderer 与任务运行时的开发与构建 |
| 打包分发 | Electron Forge | 跨平台打包；不与 electron-vite 叠加承担同一构建职责 |
| 大内容 | 本地对象文件存储 | 图片、资源快照和大段内容，不都塞入 UI 状态 |
| 任务运行时 | 独立 Node.js 进程 + TypeScript | 执行不依赖 React 生命周期，不阻塞主进程 |
| 模型接入 | Vercel AI SDK | 无状态适配：流式、工具调用、多 provider；不拥有任务历史 |
| MCP 接入 | 官方 MCP TypeScript SDK | 一种能力接入方式，不作为产品核心对象模型 |
| 包管理器 | npm | 不使用 bun 或 pnpm |

已安装版本见 `package-lock.json`：Electron 44.5.1、electron-vite 5.0.0、Forge 8.0.1、React 19.3.0、React Flow 12.12.0、Tailwind 4.3.3。Vite 锁定 7.3.6 以符合 electron-vite 的 peer 范围。shadcn/ui 控件采用 Radix UI，源码位于 `src/renderer/shared/ui/`；配置入口为 `components.json`。Monaco、模型 SDK、MCP SDK 随模块接入。

## 选型边界

- Electron 提供随应用分发的 Chromium 与 Node.js，优先保证复杂工作台的渲染一致性和本地 TypeScript 接入，不以最小安装包为首要目标。独立任务进程不等于工具执行沙箱。
- shadcn/ui 用于常规控件与卡片外壳，可复用 React Flow 的可选 UI 组件；产品对象模型不依赖组件库。
- React Flow 只维护节点、端点和连线的视图投影，不拥有对象、授权或任务历史。其核心不提供自动布局算法，布局引擎与手动位置保留策略须单独验证，见 [布局验证立案](../plans/todo-2026-09-18-workbench-layout.md)。
- Monaco 只在需要编辑或查看 diff 时挂载，不为每张文件卡片常驻编辑器。流式内容更新应局限于相关视图，不因每个文本增量重算整张画布布局。
- Vercel AI SDK 用于模型请求、流式响应和工具协议适配。可复用执行辅助能力，但所有工具执行仍经过工坊的授权与事件记录；不引入另一套 agent 框架会话或检查点作为任务历史真值。
- 模型接入上层封装支持扩展协议；协议差异集中于适配边界。工坊 transcript 为会话级扁平节点树，thinking、text 和 toolcall 平铺保存，通过 response_id 关联；响应由消费者归组投影。能力层负责执行、错误、工具结果与实际模型输入，向界面提供查询、订阅和操作接口；界面独立决定展示与聚合。适配层构造目标协议要求的消息分组。具体契约见 [会话与代理能力](conversation-core.md)。
- electron-vite 负责代码构建，Electron Forge 负责打包分发；二者减少工程配置，不接管运行时职责。版本、进程入口与打包产物验证见 [工程工具立案](../plans/todo-2026-09-18-desktop-tooling.md)。

## 模型兼容边界

基础协议适配与可组合的兼容包在模型接入边界集中装配。兼容模块承担请求参数与消息编码、响应及流事件解码、历史续接投影；通用执行循环、会话存储与 renderer 只消费工坊契约，不按品牌或域名分支。SDK 的已覆盖能力继续复用，其缺口由兼容模块通过明确接口补充。

提供商默认选项与具体模型覆盖由统一解析入口生成本次生效组合，编码和解码使用同一份结果。包的适用协议、组合顺序、冲突和必要续接版本在装配边界处理，不将差异分散到各个消费者。该机制尚未实现，当前 DeepSeek Responses 仍为模型适配器内的端点专用分支；迁移与配置接入见 [模型兼容计划](../plans/todo-2026-10-10-model-compatibility.md)。

## 进程职责

### Renderer

卡片、连线、时间导航、编辑器、资源视图、输入与确认交互。通过受控 IPC 获取状态和发出意图，不直接访问任意文件或模型凭据。

### Electron 主进程

窗口、系统对话框、桌面集成、运行时进程生命周期与 IPC 路由，以及 Electron safeStorage 的凭据加解密。凭据服务通过进程间私有接口供运行时使用，不向 renderer 开放通用解密命令。避免承担模型循环和大规模资源操作。

### 任务运行时

任务事件、上下文构建、代理执行、资源与授权、工具调度、历史投影、恢复流程以及持久化。提供商配置、加密凭据文件与异步连接测试也由能力层管理；系统加解密由主进程提供。

系统提示词作为运行时对象从当前代码与最新 agent 配置构造，模型适配前统一投影；提示块、角色正文、模型参数、工具目录及完整请求投影均不落入会话历史。messages 从历史重建；当前选择身份与思考等级保存在可修改会话设置中，每轮据此重新解析环境。

独立进程不自动提供桌面应用退出后继续运行的能力。初版默认随应用关闭；持久后台服务需另行确认。

### 工程入口与生命周期

| 源码 | 构建产物 | 职责 |
| --- | --- | --- |
| `src/main/index.ts` | `dist/main/index.js` | 窗口、单实例锁、数据目录、IPC 信任检查 |
| `src/preload/index.ts` | `dist/preload/index.cjs` | 沙箱桥；仅暴露应用命令和状态订阅 |
| `src/runtime/index.ts` | `dist/main/runtime.js` | Electron utilityProcess 入口，拥有应用服务与数据库 |
| `src/renderer/main.tsx` | `dist/renderer/` | React 组合与工作台视图 |

main 与 runtime 使用 ESM；preload 使用独立 CJS bundle，第三方校验代码内联，适配 sandbox。运行时与主进程是同一 main 构建的两个入口，共享构建块保留相对路径。Forge 只打包 `dist/`、清单和生产依赖，不叠加 Vite 插件。包默认 ASAR，数据始终写到包外。

应用只接受同一窗口主 frame 的命令；禁止 renderer 任意 Node 调用、窗口跳转、webview 与新窗口。开发版仅为 Fast Refresh 的内联脚本放宽 CSP，发布版脚本只允许自身资源。preload、main、runtime 分别校验边界数据。

正式应用标识为 `dev.dearain.atelier`：Forge 配置 `appBundleId`，Windows 设置 AppUserModelID。品牌、固定系统身份与数据布局集中于 `src/shared/application.ts`；内部契约与通道通过 `src/shared/core.ts` 生成 `core.*` / `core:*` 身份，桌面桥固定为 `window.host`。开发启动仍运行 Electron.app；Electron 不按 bundle ID 自动选择数据库目录，主进程显式按固定应用身份设置路径。

窗口外观独立于任务运行时：`window-appearance.ts` 配置平台材质、回退和系统偏好监听，`app/Window.tsx` 只组合标题栏与受管空间。macOS 使用 vibrancy；Windows 11 22H2+ 使用 Acrylic 与原生窗口控件覆盖；旧版 Windows/Linux 使用实色。preload 额外暴露只读平台标签，不开放窗口通用控制 API。窗口几何由 `src/shared/desktop.ts` 统一；细节见 `docs/design-system.md`。

任务进程启动就绪后才创建窗口。请求带协议版本与关联 ID，只发送一次；超时/退出使在途请求失败，不自动重放。退出时先要求任务进程关闭数据库，再等待退出；超时终止进程。初版关闭最后一个窗口即退出应用。任务进程崩溃后要求重启应用，不把进程重启当作未完成操作的重试。

应用列表契约位于 `src/shared/contracts.ts`，协议版本为 4，只提供工作区身份与会话摘要。资源命令与工作台投影位于纯契约 `src/shared/workbench.ts`，通过 `src/shared/session.ts` 的版本 9 会话通道与提交、停止、续接统一处理。命令只返回受理结果；会话读取一次固定查看路径，提供工作台和对话共同使用的数据。配置能力通过独立版本 1 通道提供，配置读写不会重新载入工作台；连接测试完成通知只触发消费方重新查询，普通配置编辑不广播级联更新。资源操作仍经过运行时，不能在 renderer 中模拟执行或直写数据库。

renderer 的 `features/session/` 拥有会话查看位置、读取协调、历史面板和操作队列；应用层只拥有导航与列表。查看位置和持久执行游标分别管理，历史位置不会由异步命令结果覆盖。持久变化使用视图修订通知，内存进度独立发布并带对应持久修订；先于持久视图到达的进度暂存，避免块消失或重复。只订阅对象、关系与布局的画布不消费流增量。完整读取保留为初次打开和重连的恢复入口，不新增历史存储格式。

| 模块 | 外部职责 |
| --- | --- |
| 会话树 | 只追加的会话级扁平节点树与游标，提供路径折叠与投影 |
| 代理执行 | 执行轮次、请求环境快照、模型与工具循环、固定宿主操作入口 |
| 资源能力 | 资源身份、类型、生命周期、视图与历史能力；实例不持有工具名单 |
| 工具目录 | 与资源目录平级；共享工具契约、后端实现注册、支持关系与契约冲突检查 |
| 功能模块 | 共置纯契约、后台能力和前端视图，两个进程分别静态装配；不跨进程传递代码 |
| 工具调度 | 已链接资源与工具支持关系的匹配、外部策略与参数校验、授权检查、实际执行、结果和关系记录 |
| 模型接入 | 用 Vercel AI SDK 将内部上下文投影为 provider 请求及标准化响应 |
| 模型配置解析 | 接受模型角色、明确的对话继承来源与本次覆盖，统一解析实际模型、思考配置和非秘密版本信息 |
| 代理配置 | 管理所有代理共用的提示词、工具策略、委派范围和模型角色引用 |
| 工作台投影 | 为 UI 提供卡片与关系数据，不把坐标作为业务事实 |

这是职责划分，不要求提前拆成多个包、服务或插件系统。先由目录资源与虚拟资源验证接口，再决定公共扩展面。

## 数据与事务

- 事件和相应元数据提交应有清晰事务边界。
- 数据库与外部副作用不构成天然的原子事务；记录操作开始、结果和未知状态，恢复时对账，不盲目重试。
- 大内容记录稳定引用及完整性信息；文件落盘与数据库索引需处理崩溃中间态。
- 历史快照、资源状态、配置与上下文投影需要可迁移的版本标识。
- 当前视图状态与业务事件分开。
- `session_nodes` 保存 `seq`、`id`、`session_id`、`parent_id`、`kind` 与不可变 JSON `payload`；`response_id`、`ordinal` 为生成列并有响应内唯一序号约束。块载荷含请求起点、代理身份、正文、完成状态、时间与协议来源。检查点格式未定。
- `block_completions` 只追加一次终态元数据，外键绑定实际块，响应身份唯一；查询时合并，不更新节点。`session_blocks` 提供块与计量的 SQL 视图，`session_usage` 合并块计量及无内容块异常 notice 的计量，便于按会话/代理/模型筛选汇总。
- `cursor_selections` 追加历史选择审计，保存原位置、请求位置、实际位置、原因和时间；与 `sessions.cursor` 更新处于同一事务。选择日志不属于消息路径。
- 应用数据统一位于 Electron `app.getPath('userData')` 下：发布为 `appData/dev.dearain.atelier`，开发为 `appData/dev.dearain.atelier-development`。两个目录都在获取单实例锁前创建并显式设置，固定身份不随品牌显示名称变化；不写入源码仓库或安装目录。外观与窗口状态显式以同一根目录构造 electron-store，任务进程只接受主进程传入的数据根。
- Chromium 的 cookie、缓存等会话数据使用独立的 `sessionData` 路径，不与应用数据混放。
- 不把 API key 写入事件或模型请求记录。完整请求留存与保留期限未定，不默认永久保存全部原始内容。

### 存储归属

| 路径 | 内容 | 管理方 |
| --- | --- | --- |
| `configuration.json` | 全局提供商、具体模型、模型角色与代理配置，角色与代理只保存用户覆盖 | 运行时配置模块 |
| `appearance.json` | 外观与思考展示偏好 | 主进程，electron-store |
| `ui-state.json` | 窗口位置、尺寸等全局界面状态 | 主进程，electron-store |
| `credentials/` | 系统保护的密文；配置文件只保存引用 | 运行时凭据模块，主进程加解密 |
| `db/workspace.sqlite` | 工作区身份、累计会话记录、资源当前状态与会话视图 | 任务运行时 |
| `objects/` | 不可变正文与大内容 | 任务运行时 |
| `logs/` | 运行日志 | 任务运行时 |
| `chromium/` | cookie、缓存等 Chromium 会话数据 | Electron |

全局配置独立于工作数据生命周期，重建会话数据库不重置配置。资源当前状态和视图归属于具体会话，即使可修改或不进入历史，也随工作数据保存。

### 提供商配置

提供商连接属于本机应用级配置，可被不同任务引用；普通配置与凭据引用保存在 `configuration.json`，不依赖数据库。首批接入 OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages，协议适配可扩展。配置可见性不构成资源授权。

提供商下的具体模型保存能力与温度等生成参数；模型角色保存模型 ID、思考等级、启用、用途描述和隐藏；agent 配置保存提示词、工具与委派策略及模型角色 ID。三者通过独立能力接口消费，不建立跨配置外键或级联刷新；统一解析函数在需要时检查存在性与启用状态。语义见 [模型与代理配置](model-configuration.md)。

模型角色与 agent 配置的用户存储仅持有局部覆盖，能力层结合内置原始定义生成完整生效配置。自定义项分别以内置 default 与 worker 为基准；最终视图不互相继承。初始化只写内置身份与空覆盖，内置 agent 删除后不重新播种。可修改的代理选择（按代理对象）仅保存所选 agent 配置 ID、模型 ID、思考等级及选择修订号。配置 IPC 提供生效配置、原始基准和用户覆盖；会话 IPC 独立管理选择与消息。

配置文件格式版本为 1，按 providers、models、roles、agents 分组保存具名字段与修订号，角色与代理的用户字段位于 overrides。文件只在不存在时初始化；读取经 Zod 校验结构、身份唯一性与生效配置，损坏或版本不支持时明确报错并保留原文件。配置模块拥有文件格式和原子保存，修改先形成完整候选文档，经临时文件写入、刷新与重命名成功后才替换内存视图。删除提供商及其模型在同一次保存中完成，不维护跨配置引用图或级联清空其他选择。修订号标识测试和执行取用的配置版本，不用于配置编辑的冲突门槛。应用按单实例运行，配置命令在运行时内串行处理。

API key 由主进程调用 safeStorage 加密，运行时保存密文至 `credentials/`；renderer 只读取凭据状态。加密不可用或 Linux 仅提供 `basic_text` 时不保存明文 key；解密失败时保留非秘密配置并要求重新填写凭据。开发与发布数据保持隔离。

连接测试采用可取消的异步任务，通过状态与结果通知返回，不让外部网络请求占用普通命令的超时等待。普通配置保存不触发外部请求。运行时使用显式协议 SDK 实例，不从环境变量取凭据或经默认 Gateway；关闭 SDK 自动重试，仅返回固定错误分类，不输出 provider 原始错误正文。测试结果保存在运行时内存，应用退出时取消。

### 工作数据存储版本 11

`db/workspace.sqlite` 使用 WAL 与外键；开发前期只有当前格式，不提供旧数据兼容或迁移，已有数据库的 `user_version` 不为 11 时直接报错。工具实现与展示契约身份属于持久化格式的一部分，内置身份使用固定 `core.*` 命名空间。更名时清理旧应用数据，新目录中的提供商、凭据与偏好重新设置；以后格式变化时关闭应用，清理并重新初始化开发数据。任务进程独占工作数据库、模型配置文件和密文文件的写入；主进程管理外观与窗口状态，单实例锁阻止重复实例。

- 会话级节点表保存事件与各代理的 block。资源创建事件显式记录类型；工具调用保存 target 和 args，每种结局均保存选定实现的 ID/版本、当次资源身份与执行时间，以及模型/用户数据。
- `workspace` 保存本地工作区身份与名称；`sessions` 保存会话查询索引。
- `object_views` 保存当前卡片位置、隐藏、折叠和展开宽高覆盖；宽高同为 NULL 时使用资源模块的默认尺寸。`view.set` 的 size 未提供时保留覆盖，显式 null 清除覆盖；折叠、隐藏或位置更新不改写尺寸；`viewports` 保存每个会话当前视口。两者不追加工作事件，也不声称重建历史布局。
- 应用元数据与相应事件处于同一 SQLite 事务；历史内核用保存点嵌入外层事务。
- `objects/<sha256>` 保存不可变 UTF-8 正文。先通过临时文件写入、刷新与重命名完成内容，再提交事件引用；文件系统与数据库没有跨介质原子事务，失败可能留下无引用对象。读取校验 hash，丢失或不匹配时报告内容不可用。无引用对象回收与更强的崩溃对账见后续立案。

笔记是未捕获的自有对象，正文以 `resource_states` 的 `note.content {text}` 保存并覆盖当前值，创建事件不携带正文引用；保存不写内容日志或历史版本。卡片在任何历史位置都显示最新当前正文；read/edit/write 同样取用当前值，笔记不声明恢复能力。目录资源提供 list 与 UTF-8 文本 read/edit/write，文件副作用不随会话回溯恢复；写入冲突与未知结局见 [运行时正文工具](runtime.md#原生正文工具)。检查点仍待设计。两种构建的 `sessionData` 都在对应数据根的 `chromium/`，于 ready 前创建并设置。

## 资源扩展契约

功能模块位于 `src/modules/<name>/`，内置模块采用三个入口：

| 入口 | 内容 | 可依赖 |
| --- | --- | --- |
| `contract.ts` | 资源状态、工具实现的 target/result schema 及描述、卡片数据契约；共享工具统一定义 description、guidelines 与 args schema | Zod 与纯契约，不依赖 Node/React |
| `runtime.ts` | 资源 project/inspect/context，工具 handler、publish 与可选 toModel | 后台服务、Node API、纯契约 |
| `renderer.tsx` | 卡片内容、附加操作，工具图标与独立可选的 headerRenderer/bodyRenderer | React、公共控件、纯契约 |

两个进程各自通过构建期静态入口装配，不使用一个同时导入前后端的总入口。共享注册 helper 保留作者侧类型推导，在目录边界擦除具体类型并校验数据。新增内置模块可按入口约定加入；动态插件加载、第三方隔离与插件市场不在本次范围。

资源投影携带 `{contract: {id, version}, data}`，不再用一个 content 字符串容纳所有资源。工具通过 publish 发布完整产出快照，过程态与终结态共用 data schema；运行时校验并保留最近合法产出，通过 session.progress 更新 UI。终结结果保存实际实现的 `{id, version}`、当次资源身份与执行时间；失败、取消和未知结局同样保留有效产出。模型投影只在终结时生成并保存，进度不发给模型。

前端按精确实现身份读取调用视图，header/body 分别可选且消费同一份结果；缺失或数据不兼容时使用默认摘要或原始数据正文。旧版 renderer 可与新版并存。历史只用保存的数据，不调用当前资源后端。三个固定入口的视图在 Atelier 前端内置，resource_call 的适配器转交二级工具视图；公共外壳不依赖具体工具。

工作台统一拥有 ObjectCard 的框架、拖动与视图操作，模块提供内容与附加操作。前端注册目录在应用根部注入，卡片与对话消费目录接口，不反向导入模块总表。各资源共享生命周期与调用约定，不强求共享内部存储或恢复实现。编写入口见 [功能模块](../src/modules/README.md)。

不以通用 extractTool 字符串猜测替代可靠的对象关系信息。原生实现输出结构化关系；MCP 接入可补充适配，无法判断时明确未知。

## 安全边界

- Renderer 不开放通用 Node 执行，不接受任意 IPC 方法与参数。
- 网络内容与用户文件按不可信数据处理，不直接执行其中的脚本或指令。
- 资源引用不构成授权；授权在运行时工具执行层落实。
- 凭据与任务日志分离，不把 API key 序列化进事件或模型请求记录。
- 目录资源需要真实路径与文件访问约束；未来 shell 等能力另行设计隔离。
- 用户的运行数据不写入源码仓库。

## 非目标

不实现浏览器引擎、通用绘图引擎或插件市场；不把任务历史托付给聊天或 agent 框架；不为了统一而提前建立通用 DSL。
