# 技术架构

## 初版技术基线

| 领域 | 选择 | 说明 |
| --- | --- | --- |
| 桌面外壳 | Electron | 本地集成与统一 Chromium；测试以 macOS 为主，发布覆盖 macOS、Windows、Linux |
| 界面 | React + TypeScript + Vite | 交互面板与常规 Web 组件 |
| 对话渲染 | Streamdown 2.7.0 | Markdown、GFM 与流式未闭合语法，应用不自建解析器 |
| 设计系统 | shadcn/ui + Tailwind CSS | 组件源码纳入仓库；统一使用 Tailwind 与设计 token，不并行维护另一套组件样式体系 |
| 节点工作台 | @xyflow/react | DOM 卡片、端点与连线 |
| 文件编辑与 diff | Monaco Editor | 文件视图和差异视图，按需挂载 |
| 文本差异生成 | diff（jsdiff） | 后端按行生成标准 unified diff，保留换行差异并限制计算预算；与编辑器展示分工 |
| 结构化持久化 | SQLite（`node:sqlite`） | 对象元数据、事件、关系、检查点索引；运行时未提供该模块或能力不足时改用 better-sqlite3 |
| 校验 | Zod | 事件、工具参数与配置的运行时校验；与 Vercel AI SDK 对齐 |
| 代码构建 | electron-vite | 主进程、preload、renderer 与任务运行时的开发与构建 |
| 打包分发 | Electron Forge | 跨平台打包；不与 electron-vite 叠加承担同一构建职责 |
| 大内容 | 本地对象文件存储 | 图片、资源快照和大段内容，不都塞入 UI 状态 |
| 任务运行时 | 独立 Node.js 进程 + TypeScript | 执行不依赖 React 生命周期，不阻塞主进程 |
| 模型接入 | Vercel AI SDK | 无状态适配：流式、工具调用、多 provider；不拥有任务历史 |
| MCP 接入 | 官方 MCP TypeScript SDK | 一种能力接入方式，不作为产品核心对象模型 |
| 包管理器 | npm | 不使用 bun 或 pnpm |

已安装版本见 `package-lock.json`：Electron 44.5.1、electron-vite 5.0.0、Forge 8.0.1、React 19.3.0、React Flow 12.12.0、Tailwind 4.3.3。Vite 锁定 7.3.6 以符合 electron-vite 的 peer 范围。shadcn/ui 控件采用 Radix UI，源码位于 `src/renderer/shared/ui/`；配置入口为 `components.json`。Monaco、模型 SDK、MCP SDK 随模块接入。

## 选型边界

- Electron 提供随应用分发的 Chromium 与 Node.js，优先保证复杂工作台的渲染一致性和本地 TypeScript 接入，不以最小安装包为首要目标。独立任务进程不等于工具执行沙箱。
- shadcn/ui 用于常规控件与卡片外壳，可复用 React Flow 的可选 UI 组件；产品对象模型不依赖组件库。
- React Flow 只维护节点、端点和连线的视图投影，不拥有对象、授权或任务历史。其核心不提供自动布局算法，布局引擎与手动位置保留策略须单独验证，见 [布局验证立案](../plans/todo-2026-09-18-workbench-layout.md)。
- Monaco 只在需要编辑或查看 diff 时挂载，不为每张文件卡片常驻编辑器。流式内容更新应局限于相关视图，不因每个文本增量重算整张画布布局。
- Vercel AI SDK 用于模型请求、流式响应和工具协议适配。可复用执行辅助能力，但所有工具执行仍经过工坊的授权与事件记录；不引入另一套 agent 框架会话或检查点作为任务历史真值。
- 模型接入上层封装支持扩展协议；协议差异集中于适配边界。工坊 transcript 为会话级扁平的通用记录树；执行体插件（core 代理即其一）以自己的记录契约保存输出块，按自身规则归组与投影，宿主不认识块结构。能力层负责执行、错误、工具结果与实际模型输入，向界面提供查询、订阅和操作接口；界面独立决定展示与聚合。适配层构造目标协议要求的消息分组。具体契约见 [会话与代理能力](conversation-core.md)。
- electron-vite 负责代码构建，Electron Forge 负责打包分发；二者减少工程配置，不接管运行时职责。版本、进程入口与打包产物验证见 [工程工具立案](../plans/todo-2026-09-18-desktop-tooling.md)。

## 模型兼容边界

基础协议适配与可组合的兼容包在模型接入边界集中装配。兼容模块承担请求参数与消息编码、响应及流事件解码、历史续接投影；通用执行循环、会话存储与 renderer 只消费工坊契约，不按品牌或域名分支。SDK 的已覆盖能力继续复用，其缺口由兼容模块通过明确接口补充。

兼容包由应用预定义目录声明稳定 id、schema 与 `appliesTo`；名称、说明和参数编辑器取自 schema，appliesTo 中协议／端点只作展示参考。提供商与具体模型分别保存已添加的 `compatibility` 列表，同层 id 不重复。请求边界取用两层配置，统一按 id 合并，模型同名条目整项优先，不深合并参数；模型不能单独禁用提供商条目，合并结果不回写配置。配置边界校验身份与参数，协议投影代码按 id 消费认识的行为，不执行参考信息匹配或用户处理器。定义、存储、UI 与首批请求消费已接入，GUI 和真实端点待验收，见 [模型兼容计划](../plans/todo-2026-10-10-model-compatibility.md)。

兼容包与跨模型续接共用单次目标投影。时间线保存公共正文、思考与工具结果，以及带来源的原生附加资料；只有资料复用检查来源作用域与适配版本，公共内容不因来源不同而整段拒绝。不持久化第二份模型上下文，不改历史或伪造密文／签名。DeepSeek 明文 reasoning 输入经公开 SDK 中间件固定顺序，再在公开传输入口核对并补充序列化项；其他消息编码仍复用 SDK，不修改依赖源码。详见 [模型适配](conversation-core.md#模型适配)。

## 进程职责

### Renderer

卡片、连线、时间导航、编辑器、资源视图、输入与确认交互。通过受控 IPC 获取状态和发出意图，不直接访问任意文件或模型凭据。

### Electron 主进程

窗口、系统对话框、桌面集成、运行时进程生命周期与 IPC 路由，以及 Electron safeStorage 的凭据加解密。凭据服务通过进程间私有接口供运行时使用，不向 renderer 开放通用解密命令。避免承担模型循环和大规模资源操作。

### 任务运行时

任务事件、上下文构建、代理执行、资源与授权、工具调度、历史投影、恢复流程以及持久化。提供商配置、加密凭据文件与异步连接测试也由能力层管理；系统加解密由主进程提供。

系统提示词作为运行时对象从当前代码与最新 agent 配置构造，模型适配前统一投影；提示块、角色正文、模型参数、工具目录及完整请求投影均不落入会话历史。messages 从历史重建；当前选择身份与思考等级保存在可修改会话设置中，每轮据此重新解析环境。

独立进程不自动提供桌面应用退出后继续运行的能力。初版默认随应用关闭；持久后台服务需另行确认。

### 工程入口与生命周期

| 源码 | 构建产物 | 职责 |
| --- | --- | --- |
| `src/main/index.ts` | `dist/main/index.js` | 窗口、单实例锁、数据目录、IPC 信任检查 |
| `src/preload/index.ts` | `dist/preload/index.cjs` | 沙箱桥；仅暴露应用命令和状态订阅 |
| `src/runtime/index.ts` | `dist/main/runtime.js` | Electron utilityProcess 入口，拥有应用服务与数据库 |
| `src/renderer/main.tsx` | `dist/renderer/` | React 组合与工作台视图 |

main 与 runtime 使用 ESM；preload 使用独立 CJS bundle，第三方校验代码内联，适配 sandbox。运行时与主进程是同一 main 构建的两个入口，共享构建块保留相对路径。Forge 只打包 `dist/`、清单和生产依赖，不叠加 Vite 插件。包默认 ASAR，数据始终写到包外。

应用只接受同一窗口主 frame 的命令；禁止 renderer 任意 Node 调用、窗口跳转、webview 与新窗口。开发版仅为 Fast Refresh 的内联脚本放宽 CSP，发布版脚本只允许自身资源。preload、main、runtime 分别校验边界数据。

正式应用标识为 `dev.dearain.atelier`：Forge 配置 `appBundleId`，Windows 设置 AppUserModelID。品牌、固定系统身份与数据布局集中于 `src/shared/application.ts`；内部契约与通道通过 `src/shared/core.ts` 生成 `core.*` / `core:*` 身份，桌面桥固定为 `window.host`。开发启动仍运行 Electron.app；Electron 不按 bundle ID 自动选择数据库目录，主进程显式按固定应用身份设置路径。

窗口外观独立于任务运行时：`window-appearance.ts` 配置平台材质、回退和系统偏好监听，`app/Window.tsx` 只组合标题栏与受管空间。macOS 使用 vibrancy；Windows 11 22H2+ 使用 Acrylic 与原生窗口控件覆盖；旧版 Windows/Linux 使用实色。preload 额外暴露只读平台标签，不开放窗口通用控制 API。窗口几何由 `src/shared/desktop.ts` 统一；细节见 `docs/design-system.md`。

任务进程启动就绪后才创建窗口。请求带协议版本与关联 ID，只发送一次；超时/退出使在途请求失败，不自动重放。退出时先要求任务进程关闭数据库，再等待退出；超时终止进程。初版关闭最后一个窗口即退出应用。任务进程崩溃后要求重启应用，不把进程重启当作未完成操作的重试。

应用列表契约位于 `src/shared/contracts.ts`，协议版本为 5，提供工作区身份、会话摘要和启动时装载的插件静态翻译目录。资源命令与工作台投影位于纯契约 `src/shared/workbench.ts`，通过 `src/shared/session.ts` 的版本 19 会话通道与提交、停止、续接统一处理。命令只返回受理结果；会话读取一次固定执行游标，提供工作台和对话共同使用的数据。应用配置和插件配置分别使用独立版本 5 与版本 2 通道；插件配置携带纯数据展示映射，错误回执可携带 `display`。配置读写不会重新载入工作台，语言切换也不重取配置；连接测试完成通知只触发消费方重新查询，普通配置编辑不广播级联更新。资源操作仍经过运行时，不能在 renderer 中模拟执行或直写数据库。

renderer 的 `features/session/` 拥有当前会话的读取协调、历史面板和操作队列；应用层只拥有导航与列表。历史面板的候选选择不驱动工作台，明确继续才移动持久执行游标。工作台与代理对话始终读取当前游标。持久变化使用视图修订通知，内存进度独立发布并带对应持久修订；先于持久视图到达的进度暂存，避免块消失或重复。只订阅对象、关系与布局的画布不消费流增量。完整读取保留为初次打开和重连的恢复入口，不新增历史存储格式。

## 建议的核心模块

| 模块 | 外部职责 |
| --- | --- |
| 会话历史 | 会话树保存全部不可变节点；执行游标确定当前时间线，提供末端追加与时间线读取，领域消费者据此折叠与投影 |
| 代理执行 | 执行轮次、请求环境快照、模型与工具循环、固定宿主操作入口 |
| 资源能力 | 资源身份、类型、生命周期、视图与历史能力；实例不持有工具名单 |
| 工具目录 | 与资源目录平级；共享工具契约、后端实现注册、支持关系与契约冲突检查 |
| 功能模块 | 共置纯契约、后台能力和前端视图，两个进程分别静态装配；不跨进程传递代码 |
| 工具调度 | 已链接资源与工具支持关系的匹配、外部策略与参数校验、授权检查、实际执行、结果和关系记录 |
| 模型接入 | 用 Vercel AI SDK 将内部上下文投影为 provider 请求及标准化响应 |
| 模型配置解析 | 接受模型角色、明确的对话继承来源与本次覆盖，统一解析实际模型、思考配置和非秘密版本信息 |
| 代理配置 | 管理所有代理共用的提示词、工具策略、委派范围和模型角色引用 |
| 工作台投影 | 为 UI 提供卡片与关系数据，不把坐标作为业务事实 |

这是职责划分，不要求提前拆成多个包、服务或插件系统。先由目录资源与虚拟资源验证接口，再决定公共扩展面。

## 数据与事务

- 事件和相应元数据提交应有清晰事务边界。
- 数据库与外部副作用不构成天然的原子事务；记录操作开始、结果和未知状态，恢复时对账，不盲目重试。
- 大内容记录稳定引用及完整性信息；文件落盘与数据库索引需处理崩溃中间态。
- 宿主存储与协议格式独立版本化；插件领域数据由所属类型的 schema 判断兼容性，迁移归插件。
- 当前视图状态与业务事件分开。
- `session_nodes` 保存 `seq`、`id`、`session_id`、`parent_id` 与不可变 JSON `payload`，`contract` 为从载荷提取契约身份的虚拟生成列；载荷含记录来源 `source: { plugin, resource }`、契约身份与数据，工作台事件也按具名契约保存。宿主不为任何执行体的输出建列、约束或视图；响应分组、终态与用量由执行体插件在自己的记录中表达。检查点格式未定。
- `cursor_selections` 追加显式执行游标选择的审计，保存原位置、请求位置、实际位置、原因和时间；与 `sessions.cursor` 更新处于同一事务。历史面板候选选择不写日志；选择日志不属于会话树或时间线，也不进入模型上下文。
- 应用数据统一位于 Electron `app.getPath('userData')` 下：发布为 `appData/dev.dearain.atelier`，开发为 `appData/dev.dearain.atelier-development`。两个目录都在获取单实例锁前创建并显式设置，固定身份不随品牌显示名称变化；不写入源码仓库或安装目录。外观与窗口状态显式以同一根目录构造 electron-store，任务进程只接受主进程传入的数据根。
- Chromium 的 cookie、缓存等会话数据使用独立的 `sessionData` 路径，不与应用数据混放。
- 不把 API key 写入事件或模型请求记录。完整请求留存与保留期限未定，不默认永久保存全部原始内容。

### 存储归属

| 路径 | 内容 | 管理方 |
| --- | --- | --- |
| `configuration.json` | 全局提供商、具体模型、模型角色与代理配置，角色与代理只保存用户覆盖 | 运行时配置模块 |
| `appearance.json` | 外观与思考展示偏好 | 主进程，electron-store |
| `language.json` | 界面语言偏好 `preference`（system 或明确语言标签），见 [公共 i18n](i18n.md) | 主进程，electron-store |
| `ui-state.json` | 窗口位置、尺寸与受控偏好容器（创建路由记忆、插件偏好）等全局界面状态 | 主进程，electron-store |
| `credentials/` | 系统保护的密文；配置文件只保存引用 | 运行时凭据模块，主进程加解密 |
| `db/workspace.sqlite` | 工作区身份、累计会话记录、资源当前状态与会话视图 | 任务运行时 |
| `objects/` | 宿主不可变 UTF-8 正文 | 任务运行时 |
| `content/` | 插件不可变字节内容与临时上传；依赖索引在工作数据库 | 任务运行时 |
| `extensions/<pluginId>/` | 插件私有数据，`.atelier/` 托管插件配置与数据库 | 插件与运行时托管设施 |
| `logs/` | 运行日志 | 任务运行时 |
| `chromium/` | cookie、缓存等 Chromium 会话数据 | Electron |

全局配置独立于工作数据生命周期，重建会话数据库不重置配置。资源当前状态和视图归属于具体会话，即使可修改或不进入历史，也随工作数据保存。

### 提供商配置

提供商连接属于本机应用级配置，可被不同任务引用；普通配置与凭据引用保存在 `configuration.json`，不依赖数据库。首批接入 OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages，协议适配可扩展。配置可见性不构成资源授权。

提供商下的具体模型保存能力与温度等生成参数；模型角色保存模型 ID、思考等级、启用、用途描述和隐藏；agent 配置保存提示词、工具与委派策略及模型角色 ID。三者通过独立能力接口消费，不建立跨配置外键或级联刷新；统一解析函数在需要时检查存在性与启用状态。语义见 [模型与代理配置](model-configuration.md)。

模型角色与 agent 配置的用户存储仅持有局部覆盖，能力层结合内置原始定义生成完整生效配置。自定义项分别以内置 default 与 worker 为基准；最终视图不互相继承。初始化只写内置身份与空覆盖，内置 agent 删除后不重新播种。可修改的代理选择（按代理对象）仅保存所选 agent 配置 ID、模型 ID、思考等级及选择修订号。配置 IPC 提供生效配置、原始基准和用户覆盖；会话 IPC 独立管理选择与消息。

配置文件格式版本为 5，按 providers、models、roles、agents 分组保存具名字段与修订号，角色与代理的用户字段位于 overrides；提供商与模型的 compatibility 各自只保存显式添加的兼容条目，定义目录与合并结果不写入配置。文件只在不存在时初始化；读取经 Zod 校验结构、身份唯一性与生效配置，损坏或版本不支持时明确报错并保留原文件。配置模块拥有文件格式和原子保存，修改先形成完整候选文档，经临时文件写入、刷新与重命名成功后才替换内存视图。删除提供商及其模型在同一次保存中完成，不维护跨配置引用图或级联清空其他选择。修订号标识测试和执行取用的配置版本，不用于配置编辑的冲突门槛。应用按单实例运行，配置命令在运行时内串行处理。

API key 由主进程调用 safeStorage 加密，运行时保存密文至 `credentials/`；renderer 只读取凭据状态。加密不可用或 Linux 仅提供 `basic_text` 时不保存明文 key；解密失败时保留非秘密配置并要求重新填写凭据。开发与发布数据保持隔离。

连接测试采用可取消的异步任务，通过状态与结果通知返回，不让外部网络请求占用普通命令的超时等待。普通配置保存不触发外部请求。运行时使用显式协议 SDK 实例，不从环境变量取凭据或经默认 Gateway；关闭 SDK 自动重试，仅返回固定错误分类，不输出 provider 原始错误正文。测试结果保存在运行时内存，应用退出时取消。

### 工作数据存储版本 16

`db/workspace.sqlite` 使用 WAL 与外键；开发前期只有当前格式，不提供旧数据兼容或迁移，已有数据库的 `user_version` 不为 16 时直接报错。资源、工具实现、状态与展示契约身份属于持久化格式的一部分，内置契约位于固定的 `atelier.core/<name>` 命名空间。格式变化时关闭应用，清理并重新初始化开发数据；全局模型配置与凭据独立于会话数据库。任务进程独占工作数据库、模型配置文件和密文文件的写入；主进程管理外观与窗口状态，单实例锁阻止重复实例。

- 用户 message 的 parts 在节点载荷中保存文字与 ContentRef；依赖与记录同事务建立。原始字节保存在内容存储，请求边界临时解析，完整 provider 请求不持久化。
- 会话级节点表保存事件与各代理的 block。资源创建事件显式记录类型；工具调用保存 target 和 args，每种结局均保存选定实现的 ID、当次资源身份与执行时间，以及模型/用户数据。
- `workspace` 保存本地工作区身份与名称；`sessions` 保存会话查询索引。
- `session_data` 保存当前会话或对象数据，以会话 ID、对象作用域和契约 ID 定位，不维护领域契约版本。空对象 ID 表示会话作用域；同一契约在会话与对象中互不覆盖。读取按 schema 解码，兼容数据继续使用，不兼容时明确不可用并保留原值；插件负责旧形状兼容与迁移。数据可与事件同事务提交，纯数据保存只通知视图，不追加历史；会话删除级联清理，查看或分叉不恢复当前值。
- `contents` 保存不透明内容身份、摘要与长度，`content_roots` 保存记录或当前数据的依赖。SDK 保留引用值在实际持久写入时被识别并校验，与 JSON 同事务提交。字节在 `content/temporary/` 写完并封存到 `content/sealed/<id>` 后才可提交引用；草稿、运行和读取分别固定内容，根消失且没有占用时回收。规则见 [不可变内容](content.md)。
- `object_views` 保存当前卡片位置、隐藏、折叠和展开宽高覆盖；宽高同为 NULL 时使用资源模块的默认尺寸。`view.set` 的 size 未提供时保留覆盖，显式 null 清除覆盖；折叠、隐藏或位置更新不改写尺寸；`viewports` 保存每个会话当前视口。两者不追加工作事件，也不声称重建历史布局。
- 业务提交中的应用元数据与事件处于同一 SQLite 事务，历史内核用保存点嵌入外层事务；游标观察者重建的标题等派生当前值在原提交后另行写入。
- `objects/<sha256>` 保存不可变 UTF-8 正文。先通过临时文件写入、刷新与重命名完成内容，再提交事件引用；文件系统与数据库没有跨介质原子事务，失败可能留下无引用对象。读取校验 hash，丢失或不匹配时报告内容不可用。无引用对象回收与更强的崩溃对账见后续立案。

笔记是未捕获的自有对象，正文声明为 `NoteContent`，经绑定对象的同步提交保存到 `session_data` 对象作用域的 `atelier.core/note.content {text}` 并覆盖当前值。创建事件的数据为 `{}`，不携带正文引用；保存由宿主发布视图通知，不写内容日志、时间线事件或历史版本。缺失或损坏的正文显示为不可用，工具拒绝以空正文覆盖。卡片在任何历史位置都显示最新当前正文；read/edit/write 同样取用当前值，笔记不声明恢复能力。目录资源提供 list 与 UTF-8 文本 read/edit/write，文件副作用不随会话回溯恢复；写入冲突与未知结局见 [运行时正文工具](runtime.md#原生正文工具)。检查点仍待设计。两种构建的 `sessionData` 都在对应数据根的 `chromium/`，于 ready 前创建并设置。

## 资源扩展契约

功能模块位于 `src/modules/<name>/`，内置模块采用三个入口：

| 入口 | 内容 | 可依赖 |
| --- | --- | --- |
| `contract.ts` | 资源状态、工具实现的 target/result schema 及描述、卡片数据契约；共享工具统一定义 description、guidelines 与 args schema | Zod 与纯契约，不依赖 Node/React |
| `runtime.ts` | 资源 project/inspect/context，工具 handler、publish 与可选 toModel | 后台服务、Node API、纯契约 |
| `renderer.tsx` | 卡片内容、附加操作，工具图标与独立可选的 headerRenderer/bodyRenderer | React、公共控件、纯契约 |

两个进程各自通过构建期静态入口装配，不使用一个同时导入前后端的总入口。共享注册 helper 保留作者侧类型推导，在目录边界擦除具体类型并校验数据。新增内置模块可按入口约定加入。

### 插件

插件是安装、身份与管理单位，包含提供具体功能的模块；模块不单独出现在管理界面。内置功能由随软件分发的 `atelier.core` 插件提供，与外部插件使用同一个 SDK，仅通过公开契约消费宿主能力。宿主按插件身份提供 context，身份用于存储、命名空间与诊断。

SDK 的基础能力围绕工作台、会话、时间线事件与资源。插件可以只读取或追加事件、操作自己的状态、提供资源与视图，不必认识 Agent。对话从时间线记录构造，模型与代理相关能力是按需使用的分支；软件保留现有模型与代理配置、注册机制，支持插件提供自己的代理或资源。

#### 应用组合与宿主机制

Atelier 应用组合层负责将宿主能力与随软件分发的内置插件组成产品功能，可以显式依赖双方接口及插件的公开领域契约。首页创建 Agent 并提交首条输入、人工命名入口提交命名事件，都属于应用组合职责。通用宿主机制负责事务、记录存储、游标、路由、校验与生命周期，不解释 Agent 消息或命名来源等插件领域语义。

源码依赖方向为：应用组合层依赖宿主接口、内置插件公开领域接口与 SDK；通用宿主机制和插件分别依赖 SDK；SDK 不依赖任何一方实现。宿主经 SDK 调用插件贡献、插件经 SDK 调用宿主服务，是运行时协作，不改变源码依赖方向。应用组合与宿主机制按职责区分，不能仅以所在进程或 `runtime/` 目录归属判断。

应用组合层认识领域契约，不意味着它自动取得插件操作柄。记录的声明、校验与来源打戳仍由真实写入通道负责；领域接口的调用不改变插件身份与生命周期约束，内置插件不因随软件分发获得内部接口特权。

由时间线派生的当前值沿统一规则重建。人工命名与自动命名都以追加 `SessionNamed` 表达事实，由命名模块按当前路径同步标题；应用入口不另行覆盖标题或维护一份同步逻辑。具体规则见 [会话命名](session-naming.md)。

#### SDK 的双方职责

插件 SDK 定义双方共用的类型与接口，独立于宿主源码。服务与功能贡献有各自的实现方和消费方：

| 契约 | 实现方 | 消费方 |
| --- | --- | --- |
| 宿主服务接口 | 宿主实现会话、对象、模型与托管设施等服务 | 插件通过 SDK 调用服务 |
| 模块与功能贡献接口 | 插件实现资源、工具、视图及其他功能贡献 | 宿主通过 SDK 装配、调用与展示贡献 |
| 生命周期扩展接口 | 宿主定义并触发具体生命周期入口，插件实现对应处理器 | 宿主在约定时点调用处理器，插件通过服务接口开展操作 |

SDK 是独立、版本化、可发布的包，`@atelier/sdk` 提供 `contracts`（契约、记录信封与解码）、`runtime`（后台服务与贡献）、`renderer`（视图与具型对象调用）三个入口。接口职责、对象读取／执行、具型创建／动作、校验阶段、运行生命周期与业务组合统一见 [插件 SDK 与功能组合](plugin-sdk.md)，实现与验收进度见 [插件计划](../plans/todo-2026-10-12-plugin-system.md)。内置资源、Agent、命名与卡片消费公开 SDK；共享正文算法、Agent 系统提示和领域投影归 core，物理存储编码经明确的 core 存储适配模块由宿主承担。

#### 插件包与源码开发

插件只有一种形态：带 Atelier 清单的包。开发者可在 monorepo 中消费 SDK，添加本地包根作为来源，由宿主启动时打包；只认包根，不扫描目录。可用 Atelier 或外部编辑器开发，打开仓库不自动加载或启用其中代码。npm 安装与本地包登记采用同一清单和装配规则，安装、启用、禁用与升级重启后生效；npm 安装与升级流程尚未实现，见插件计划。

宿主打包 runtime 与 renderer 入口，按内容缓存于 `<data>/plugins/.cache`。Zod、React、SDK 等宿主共享模块与插件公共入口保留统一加载引用，私有依赖进入插件 bundle；提供方自身与消费者都经过相同的公共模块解析，避免实际对象被重复创建。公共模块加载的实施状态见插件计划。前端产物通过 `atelier-plugin://` 只读提供，每张卡片有独立错误边界；高频二进制经按对象的流通道传给视图，不进入记录。任务进程到 main、main 到 preload 共用 `shared/object-stream.ts` 的严格信封，包含会话、对象、带命名空间的通道与 `Uint8Array`。main 校验后原样转发，preload 再校验并筛选订阅；无效信封直接忽略，不转换二进制正文。

插件可在清单登记静态翻译目录，无需提供 renderer；目录内容参与缓存身份，由宿主交付界面。界面语言由主进程管理，格式化使用 FormatJS，SDK 消息描述携带插件归属、来源语言和默认文案；静态贡献、配置与用户错误提示在显示时解析。语言切换只更新展示环境，不重新装配插件、读取配置草稿或改变任务上下文。具体接口与进度见 [公共 i18n](i18n.md)。

#### 具名、具型的扩展入口

插件通过具体接口、具名成员或可导入的具型契约声明功能、生命周期、观察与拦截。创建与动作契约包含稳定身份、关联资源和输入 schema；资源内联组合对应实现，前端持同一契约调用，外部准备者绑定具体动作。进入前准备和资源读取只交付只读门面，执行取得修改接口；详见 [插件 SDK](plugin-sdk.md)。扩展入口不使用字符串事件总线。

瞬态事件通过宿主管理的全局具型通信机制传递，按契约与声明式来源条件路由，不依赖会话或模块的界面生命周期。发布路径不运行消费者代码，各订阅独立有界排队；发送端按契约语义合并并批量传输，跨进程消费额度限制发送、中转、在途和接收缓冲。领域拥有事件含义及当前状态恢复，宿主只负责校验、来源、路由、流控和清理。采用 KISS 边界，不为插件同步阻塞增加执行隔离；通用调用仅预留独立协议位置。完整契约见 [瞬态事件与插件调用](plugin-sdk.md#瞬态事件与插件调用)。

记录提交观察与执行游标变化观察是独立入口：`committed` 只交付新增记录，`cursorChanged` 将正常追加、回溯与分叉选择统一为变化后的固定路径。依赖历史的派生当前值由领域模块在游标变化后重建，Agent 上下文继续即时投影。观察者在原提交后同步排队执行，失败记录日志；队列清空后每个会话发布一次界面通知。

core `naming` 模块识别新增用户消息并读取固定路径材料，调用 `utility` 执行两级自动命名，只追加命名事件；游标观察者按当前路径最新命名同步标题，没有命名时从首条用户输入重建截断标题。规则见 [自动会话命名](session-naming.md)。宿主提供固定边界的记录观察柄、按需首尾查询、托管任务与通用提交能力，不解释用户回合或命名事件。命名与 Agent 领域知识属于 core，其他插件无须认识 Agent 或用户消息就能使用通用服务。

SDK 的会话、资源与记录接口通过具型契约提供查询、解码与写入能力，由宿主 adapter 承接内部存储。稳定身份与 schema 用于持久化与跨进程识别，不替代作者侧接口；不要求插件维护数据版本。记录的持久身份与运行时实例身份是不同约束。公开模型服务独立于 core 的 Agent 类型、配置、对话投影和会话写入规则。

同一时间线承载不同插件的记录，宿主先读取通用信封与 JSON 载荷，不要求认识所有领域。持有的契约不匹配记录时返回 null，匹配且可解码时返回 known，数据不支持时返回 unknown 并保留原始内容。未知载荷不妨碍基础查看与路径导航；持有公共模型记录契约即可读取模型事件，无须依赖内置 Agent。TypeScript 类型在运行时擦除，schema 校验与显式解码承担数据识别。

可选模型分支提供无状态的 `stream` 与 `run`。stream 只提供一次补全，会话命名等消费者直接使用它；run 在一次补全上增加真实资源授权、工具批次执行、响应聚合、缓存诊断和取消收束，完成该请求及其整批工具后返回，不隐式继续。输入每次显式提供，内含终态的具型块和诊断交付调用方，经时间线服务保存；run 不自行读写历史或维护另一份 context。SDK 提供共识载荷 schema，消费插件声明自己的记录契约，宿主 adapter 承接既有物理格式。

外层 Agent 属于插件，负责推动循环、轮数与预算、停止规则和时间线上的上下文管理。context 的唯一真值是时间线，每次请求从当前有效事件投影；Agent 可持配置选择、计数和活动等状态，不保留独立的消息／context 历史。请求投影、流缓冲与进度是临时数据。宿主保证每次调用的环境与链接授权固定到该响应及工具批次，不以扩展策略回调接管 Agent loop。基础会话／对象接口不包含模型执行或对话注入，具体接口见 [SDK 说明](../packages/sdk/README.md)。

#### 领域独立与未来的跨插件协作

core 自行实现 Agent、Note、Directory 等领域功能，资源与事件契约须抽成普通领域共识包，这是确定延后实施的任务。通用时间线接口只提供保存、定位与转交；消费者要理解资源、Agent 或其他插件的事件，仍须显式引入对应领域契约，纯事件插件也不例外。会话命名读取首条用户输入依赖 core Agent 的契约；领域包只提供共识类型与接口，不要求加载 core 实现或取得其运行时实例。具体功能扩展与跨插件运行时协作继续按真实需求设计，领域知识不扩大为所有插件必需的 SDK。

公共模块是插件装配基础：提供方通过公开入口导出契约、配置访问接口、服务和状态，消费者使用普通 import。宿主统一解析实际来源、保留共享依赖关系并保证同一运行环境只执行一份；缺失或冲突明确报错，不以相同 ID合并独立声明。公共入口使用 package.json 的 `exports["./public"]`，消费者导入 `<包名>/public`；源码包按完整 ESM 图构建，公共依赖驱动初始化与反向清理。前后台分别持有实例，跨进程通信与通用后台 RPC 继续独立设计。调用不自动追加历史或授予资源访问。

#### 设计方向

- 插件是管理单位，模块是贡献单位；资源能力以资源及其工具、视图、控制器提供，会话观察与拦截由专门的会话扩展面提供，不注册全局工具或设置项式能力。
- 完全信任、同进程，不做权限与隔离；身份用于命名空间、诊断与插件页，不用于授权。
- SDK／plugin api 为插件消费而设计：带身份、参数校验与稳定错误码，内部重构由宿主 adapter 吸收；内置插件与外部插件使用同一接口，不保留特权入口。
- 会话与对象绑定的 context 优先于手传 ID；会话数据随会话走，插件数据随插件目录走。生命周期依附会话与资源，不把 agent 的执行过程定义为所有插件的生命周期。
- 生命周期通知、宿主管理的异步工作与进入前拦截通过具名、具型接口分别声明；会话首条消息命名是其中一个消费者，接口不依赖命名规则或 Agent 领域。
- 插件不能改写宿主：一级入口 resource_list/inspect/call、会话树格式、授权判定与其他插件贡献不开放注册或替换；进入前拦截不能据此改写旧历史或已固定请求环境。
- 资源、记录与扩展入口的接口或契约值提供类型推导；稳定身份与 schema 负责历史和跨进程识别。运行时共享实例由公共模块加载保证；相同 ID 的独立声明报错，数据兼容由插件解码，不以插件发行版本作读取门禁。
- 启动时装配并冻结，不热加载；npm 和源码只是不同加载来源，安装、启用、禁用与升级重启后生效。
- 贡献身份由宿主按插件命名空间补全；插件缺席只回退展示，不删除或改写记录。

plugin api 是稳定包装层，不承诺可序列化，不向插件暴露宿主注册表。当前会话／对象数据与时间线事件分别保存，前者不随历史位置恢复，后者用于重建历史；插件目录为 `<data>/extensions/<pluginId>/`，其中 `.atelier/` 由宿主管理，凭据明文经 secrets 机制读取。

插件配置：插件在纯契约中以 `ns.config(schema, defaults, { presentation })` 声明唯一一份配置契约，前后台共享；后台 `plugin.config(contract)` 返回 `get / update / subscribe`，前端 `useRendererConfig(contract)` 读取当前值；宿主负责存储、校验、设置页与前后台变更通知。偏好（上次选择等）不属于配置，每个插件对应一份 `.atelier/config.json`。装配位置向业务模块注入各自所需的当前值读取和更新接口，更新基于最新完整配置。宿主保存原始 Zod schema 与配置对象，向设置页投影输入 JSON Schema、默认值、当前值与读取状态；凭据和插件数据库不进入配置响应。独立 `plugin-configuration` 通道按插件身份提供读取／保存／恢复，沿用可信 frame 检查和双向校验；恢复默认先改草稿再保存。

工具名称覆盖按用户插件列表顺序解析，绑定被覆盖声明的实现下线，同一声明对象的多个实现保留。公共依赖决定初始化与清理顺序，不改变覆盖顺序。声明冲突、越出命名空间的贡献或模块抛错使该插件装配失败，依赖它的插件不可用；成功 setup 的清理责任立即登记，后续失败取消该插件工作并逆序清理，等待收束后释放托管存储。任务、动作和模型调用共用宿主内部生命周期机制，各自保留去重、排队和请求授权规则。

插件缺席时对象与历史保留：资源投影为 `atelier.core/missing-resource`，携带来源插件、kind 与原始数据；inspect 与工具调用返回 implementation_missing，前端可查看原始数据。

资源投影携带 `{contract: {id}, data}`，不再用一个 content 字符串容纳所有资源。工具通过 publish 发布完整产出快照，过程态与终结态共用 data schema；运行时校验并保留最近合法产出，通过 session.progress 更新 UI。终结结果保存实际实现的 `{id}`、当次资源身份与执行时间；失败、取消和未知结局同样保留有效产出。模型投影只在终结时生成并保存，进度不发给模型。

前端按实现身份读取调用视图，header/body 分别可选且消费同一份结果；消费方 schema 负责兼容旧数据，缺失或不能解码时使用默认摘要或原始数据正文。历史只用保存的数据，不调用当前资源后端。三个固定入口的视图在 Atelier 前端内置，resource_call 的适配器转交二级工具视图；公共外壳不依赖具体工具。

工作台统一拥有 ObjectCard 的框架、拖动与视图操作，模块提供内容与附加操作。前端基础对象接口提供读取、具型调用、对象流和通用状态；模型进度、工具展示、配置目录按需取用，共享已有宿主状态源。草稿与提交身份归按会话／对象绑定的交互模块，导航显式注入。Agent 对话组合时间线、输出跟随、输入、配置选择与交互协调；目录在应用根部注入，内容不反向导入模块总表。编写入口见 [功能模块](../src/modules/README.md)。

不以通用 extractTool 字符串猜测替代可靠的对象关系信息。原生实现输出结构化关系；MCP 接入可补充适配，无法判断时明确未知。

## 安全边界

- Renderer 不开放通用 Node 执行，不接受任意 IPC 方法与参数。
- 网络内容与用户文件按不可信数据处理，不直接执行其中的脚本或指令。
- 资源引用不构成授权；授权在运行时工具执行层落实。
- 凭据与任务日志分离，不把 API key 序列化进事件或模型请求记录。
- 目录资源需要真实路径与文件访问约束；未来 shell 等能力另行设计隔离。
- 用户的运行数据不写入源码仓库。

## 非目标

不实现浏览器引擎、通用绘图引擎或插件市场；不把任务历史托付给聊天或 agent 框架；不为了统一而提前建立通用 DSL。
