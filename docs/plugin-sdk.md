# 插件 SDK 与功能组合

本文规定插件 SDK 的接口、组合方式与宿主职责。产品与授权原则见 [运行时](runtime.md)，实现进度和迁移验收见 [插件计划](../plans/todo-2026-10-12-plugin-system.md)。SDK 的 `contracts`、`runtime`、`renderer` 三个入口分别承担纯契约、后台接口和前端接口。

## 模块与装配

| 层次 | 职责 | 接口的消费方 |
| --- | --- | --- |
| SDK 契约 | 资源、创建、动作、记录、宿主服务与功能贡献的稳定接口 | 宿主与插件 |
| 宿主机制 | 路由、校验、事务、授权、运行生命周期、传输与存储编码 | SDK 的宿主实现 |
| 插件业务模块 | 配置选择、输入受理、执行循环、正文编辑与视图等领域功能 | 插件自己的装配入口和其他业务模块 |

`PluginModule.setup` 是贡献装配入口，接收完整 `PluginContext`，创建业务模块、连接依赖并返回 `ModuleContribution`。业务模块是普通函数、闭包或对象，只接收需要的具名接口；复用一个业务模块不要求将它注册为 `PluginModule`。聚合模块承担依赖连接与整体语义，不能要求调用方自行维护隐藏的调用顺序。

一项功能的纯契约、后台实现和前端视图共置、分入口编译。组合以显式导入和参数传递完成，不引入通用服务查找、动态依赖注入容器、字符串事件总线或任意生命周期 hook 集合。宿主仍在启动时装配并冻结贡献；业务组合不改变插件安装、启用和身份语义。

## 对象读取与执行

| 接口 | 能力 |
| --- | --- |
| `SessionReader` | 会话身份、固定快照、当前会话数据读取、标题读取 |
| `SessionExecutor` | 读取能力，以及同步提交、续接和标题比较更新 |
| `ObjectReader` | 资源身份、调用绑定的资源快照、当前对象数据读取、只读会话接口 |
| `ObjectExecutor` | 读取能力，以及对象同步提交、可执行会话接口、对象二进制流发布 |

资源 `project / inspect / context / links.tools`、动作准备与外部准备者只接收 `ObjectReader`。创建、动作执行和已授权工具执行接收 `ObjectExecutor`。只读门面的 `session` 也只暴露读取能力；宿主构造实际的窄门面，不只用 TypeScript 隐藏同一个可写对象的方法。

这些接口表达副作用职责，不构成插件沙箱。插件完全信任；宿主对显式修改仍检查身份、作用域与有效性。普通对象写入要求对象位于当前路径；创建门面加入宿主创建事务；已授权工具保留捕获对象快照和调用期间的修改能力，执行结束后该能力失效。

`snapshot()` 固定在该次调用或读取位置，`get()` 读取当前数据。固定资源快照不冻结当前对象数据；查看历史和分叉也不恢复当前数据。`commit` 的同步性、writer 有效期、嵌套事务回滚与提交后通知规则保持一致。

## 具型创建与动作

创建和动作属于资源行为；工具独立声明支持关系，支持关系和动作契约都不授予模型访问权限。

- `CreationContract<I>` 与 `ActionContract<I>` 具有稳定的 `id / version`、关联资源类型和输入 schema，位于插件的纯契约入口。
- `defineCreation(resource, { id, version, schema })` 与 `defineAction(resource, { id, version, schema })` 定义契约。身份使用声明插件的命名空间，版本是正整数。
- `implementCreation(contract, { prepare?, create })` 与 `implementAction(contract, { prepare?, execute })` 根据契约推导输入类型。创建同步返回资源标题与数据，动作异步执行并返回受理结果所需的完成状态，不在这一接口增加任意 RPC 返回值。
- `implementResource` 聚合一个可选的创建实现和一组动作实现，以及投影、检查、环境来源和记录声明。动作实现可以独立开发、组合；同一业务操作的参数分支可以继续使用联合类型。
- `CommandPreparer` 绑定具体动作契约，取得对应输入、只读对象与取消信号，返回接受、替换或拒绝。

前端调用 `object.invoke(ActionContract, input)` 和 `session.create(CreationContract, input, position)`。参数由契约推导；传输只包含契约身份、版本、目标和 JSON 输入，不发送 schema 或函数。宿主按已装配声明验证契约、版本与真实资源类型，拒绝未知或冲突的路由。宿主校验使用自己的声明，不信任调用者提供的契约对象。

资源类型拥有的动作保持内联装配，不另设全局动作目录。首页的首次提交仍由宿主协调会话、Agent 创建、首条输入与幂等身份的整体原子提交；领域动作负责输入受理，不能通过准备替换动作身份来绕过首次提交语义。准备者只能替换所绑定动作的输入。

以下为作者组合形态，具体领域契约由插件自己的纯契约文件导出：

```ts
const counter = implementResource(Counter, CounterView, {
  creation: implementCreation(CreateCounter, createCounter),
  actions: [
    implementAction(ChangeCount, changeCount),
    implementAction(ResetCount, resetCount),
  ],
  project: projectCounter,
  inspect: inspectCounter,
});

// 前端引用同一份纯契约。
object.invoke(ChangeCount, { amount: 1 });
session.create(CreateCounter, { title: "Counter" }, position);
```

## 校验与准备

公开创建和动作输入 schema 校验 JSON 业务值，不改变它。默认值补全、去空白、强制类型转换和其他规范化由显式准备逻辑承担；不能在输入 schema 中用 default、coerce、transform 或静默删除字段实现转换。对象输入优先使用严格对象 schema。约束只针对创建和动作输入，不改变插件配置、记录解码升级或其他已有 schema 的职责。

宿主命令模块拥有输入处理次序：

1. 按已注册契约检查原始输入与 JSON 值保持性。
2. 动作按装配顺序执行匹配的外部准备者；每次替换立即按同一契约检查。
3. 执行资源自身准备；拒绝终止处理，替换仍须符合该动作契约。
4. 将合法输入交给对象队列；执行前再次检查真实对象和当前路径等执行条件。
5. 创建在准备成功后进入宿主事务，创建资源及其初始数据和事件。

准备阶段只读取，不通过所交付门面提交数据。业务执行仍须在最终修改处检查冲突和幂等，不能将异步准备的检查结果视为永久有效。拒绝不会因为准备门面而留下会话数据或事件写入。

SDK helper 负责具型声明与实现包装，宿主命令模块负责命令校验、路由与准备的调度；相邻适配层不重复解析输入。准备结果若确实需要不同于公开输入的结构，须显式声明其类型和校验，并保持在对应创建或动作实现内部，不能复用原始输入 schema 猜测阶段。

## 宿主运行生命周期

任务、资源动作和模型调用组合使用同一个宿主内部运行生命周期模块。它负责关闭门禁、插件／会话／对象关联、取消传播、真实结束等待与活动汇总；不作为插件需要直接调用的新服务。

| 使用方 | 自己负责的规则 |
| --- | --- |
| 托管任务 | key 去重、超时、任务失败日志 |
| 资源动作 | 对象队列、具型动作调用、执行条件 |
| 模型调用 | 同对象请求互斥、请求环境与授权固定、工具批次和模型进度 |
| 运行生命周期 | 接受运行、活动登记、取消、等待收束和关闭状态 |

对象活动由尚未结束的工作汇总，同一工作通过组合进入多个层次时要明确关联；取消信号不等于已经结束。Agent 任务可以等待其模型调用，模型调用可以等待工具批次，关闭时先关闭入口并向相关工作传播取消，再等待依赖收束。会话回溯和资源移除继续依据真实收束状态。

每个成功返回的模块 `setup` 的清理责任立即由宿主登记。后续模块或贡献校验失败时，宿主取消该插件的托管工作，并按初始化逆序执行已取得的清理责任；等待结束后释放托管存储。正常关闭也遵守运行收束与设施释放的次序。某个 `setup` 在返回之前失败，须自行清理尚未交给宿主的设施。

## 插件配置与领域适配

一个插件保留一份配置声明和 `.atelier/config.json`。装配位置取得完整配置，向业务模块提供其负责部分的读取和更新接口；这些接口每次取当前值，更新基于最新完整配置，避免缓存覆盖其他分组。模块不需要知道其他模块的字段，也不重复声明完整配置。设置页、凭据和私有数据库的现有职责保持独立。

core 的用户输入、模型执行和通知与宿主物理会话格式的映射属于明确的 core 存储适配模块。通用插件门面不继续积累领域分支；物理存储不作为插件公开接口。core 领域共识包的发布与后台跨插件调用、共享实例、通信按各自计划推进，不由本次接口整理隐式实现。

## Agent 组合

| 业务模块 | 对外职责 |
| --- | --- |
| 选择与策略解析 | 从当前配置得到模型选择、提示所需配置及工具策略；链接说明和实际执行消费同一套策略规则 |
| 输入受理 | 去重、续接有效性、输入与状态的原子提交；调用方不自行编排事务内步骤 |
| 执行循环 | 每轮重新从时间轴投影消息、执行一次模型调用、处理预算及继续／停止规则 |
| 资源装配 | 组合创建、动作、投影、检查与上述业务模块，交给 SDK 装配 |

模型执行仍只完成一次补全及完整工具批次；Agent 持有非 context 状态，时间轴是 context 唯一真值。循环依赖明确的请求执行、领域投影和记录保存接口。命名模块继续按现有规模保持内聚，真实复用或独立变化出现时再拆分其内部业务模块。

## 前端组合

前端基础对象接口提供对象身份、视图状态、会话读取与刷新、具型创建／动作、对象流订阅和通用运行状态。模型块、工具展示、配置目录分别通过具名的专门接口按需取用，共享宿主已有状态源，不为拆分接口复制状态或订阅真值。

草稿与提交身份由交互模块管理，按会话和对象绑定并跨卡片重挂载保留；相同输入重试保留身份，受理成功后清除。导航通过显式界面依赖提供。普通资源无需取得模型、对话草稿或 Agent 提交知识。

Agent 对话由时间轴展示、输出跟随、消息输入、配置选择、Agent 交互协调组成。展示模块消费投影后的条目和明确的操作意图；交互协调负责受理结果、去重身份、发送后清理、继续与停止。只读对话与完整 Agent 对话复用同一套展示模块，差异在组合位置表达，不向单个组件累加控制全部功能的开关。

## 验证接口

- 作者用例直接导入公开 SDK，覆盖普通资源、具型创建／动作和自有 Agent；类型反例验证错误输入与读取门面上的写操作被拒绝。
- 命令测试验证输入校验不改变值、准备替换和拒绝、真实类型与版本检查、对象队列和最终冲突检查。
- 生命周期测试验证装配失败逆序清理、取消与真实收束、关闭门禁、被捕获工具的有效期和历史门禁。
- Agent 测试通过输入受理和执行循环接口验证原子性、幂等与停止语义，不按内部函数数量补测试。
- 复用源码插件加载测试验证完整作者路径；前端只做必要的类型检查、逻辑验证和构建，视觉与真实交互由用户验收。
