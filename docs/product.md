# 产品定义

## 定位

工坊（Atelier）是本地优先、单用户起步的个人 agent 工作台。用户与代理围绕一件具体的工作协作，在同一张工作台上组织材料、查看产出和掌握执行过程。

“工坊”强调在材料上开展工作的过程。目录、笔记等资源构成工作材料，代理凭明确授权调用工具。会话承接工作的持续过程，卡片与连线帮助用户看清对象及其关系；历史允许查看过去、继续推进或从完整位置另起分支。

信息收集、日常事务、文件维护、研究与编程都属于目标场景。产品面向由个人发起和掌握的一件件工作，当前通过私有仓库孵化，逐步验证桌面体验与真实执行能力。

## 核心体验

1. 启动进入首页，在输入框描述工作、选择 agent 与模型，发送后创建会话并进入工作台；不预先命名或加载已有会话。
2. 拖入文件、目录，或加入网页、服务等资源。
3. 将资源绑定给代理，或作为某次执行的输入。
4. 观察代理进度；工具调用默认只显示一行状态，各代理在自己的卡片中呈现对话与执行。
5. 展开重要操作，查看它涉及的对象、结果与历史变更。
6. 将已有结果作为后续工作的资源，或从某个检查点分叉探索。
7. 在时间线上查看过去；仅对明确支持恢复的资源执行状态恢复。

## 首批验证资源

### 目录

- 提供列举、读取、写入、编辑等操作。
- 操作必须限定于绑定目录的授权范围。
- 编辑产生可独立查看的实际 diff 记录。
- 普通目录资源不承诺整个目录的历史恢复或隔离分叉。

### 虚拟资源

- 状态由工坊持有，可完整快照。
- 提供观察与改变状态的操作。
- 历史查看不改变当前实例。
- 状态恢复是独立操作，范围与精度由实现声明。
- 恢复原实例与从快照创建隔离实例是不同操作。

目录验证外部可变世界与授权边界；虚拟资源验证历史查看与状态恢复机制。其他资源类型按同一对象模型接入。

## 产品边界

- 不把每条消息、每次调用都强制展开到画布上。
- 不以多代理数量作为能力指标；单代理也应当完整可用。
- 不把连线当作实际安全隔离，也不把 UI 隐藏当作权限撤销。
- 不把查看历史当作回滚现实，不承诺重新调用模型得到相同结果。
- 初版不做多人协作、插件市场、云端同步、通用 shell 沙箱和自动回滚任意系统操作。

## 成功标准

- 用户能分辨当前运行、等待、失败、完成以及 pending 的状态。
- 用户能看出代理当前可以访问什么，以及一次工具调用操作了什么。
- 同一对象的多个视图一致，关闭视图不影响对象生命周期。
- 从历史继续时，系统不会用旧授权或旧文件认知静默覆盖现实。
- 资源绑定变化不导致历史工具调用断链。
- 用户不必持续整理画布才能理解工作过程。
