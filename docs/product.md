# 产品定义

## 定位

织台是本地优先、单用户起步的个人 agent 工作台。用户围绕一件工作组织代理、资源与操作，而不必围绕聊天窗口组织全部信息。

核心表达：代理的能力随资源绑定而形成；代理的执行创建或改变对象；卡片与连线让用户理解、控制和复用这些对象。

编程是能力之一，不是产品边界。信息收集、日常事务、文件维护、研究、可交互的虚拟环境都属于目标场景。

## 核心体验

1. 创建一个工作任务，而非必须先打开代码仓库。
2. 拖入文件、目录，或加入网页、服务、游戏等资源。
3. 将资源绑定给代理，或作为某次执行的输入。
4. 观察代理进度；工具调用默认只显示一行状态，子代理可以独立成卡片。
5. 展开重要操作，查看它涉及的对象、结果与历史变更。
6. 将已有结果作为后续工作的资源，或从某个检查点分叉探索。
7. 在时间线上查看过去；仅对明确支持恢复的资源执行状态恢复。

## 首批验证资源

### 目录

- 提供列举、读取、写入、编辑等操作。
- 操作必须限定于绑定目录的授权范围。
- 编辑产生可独立查看的实际 diff 记录。
- 普通目录资源不承诺整个目录的历史恢复或隔离分叉。

### 内置俄罗斯方块

- 不是外部游戏机模拟器，而是织台控制状态的虚拟资源。
- 提供观察、输入、重置等操作，支持历史查看与状态恢复。
- 用于验证资源不必是文件或远端对象，以及时间线不必局限于文本消息。
- 精确恢复所需状态包括随机数、计时、棋盘和方块状态，而不只是画面。

这两个资源用于证明同一模型能容纳不可恢复的外部世界与可恢复的虚拟世界。

## 产品边界

- 不把每条消息、每次调用都强制展开到画布上。
- 不以多代理数量作为能力指标；单代理也应当完整可用。
- 不把连线当作实际安全隔离，也不把 UI 隐藏当作权限撤销。
- 不把查看历史当作回滚现实，不承诺重新调用模型得到相同结果。
- 初版不做多人协作、插件市场、云端同步、通用 shell 沙箱和自动回滚任意系统操作。

## 成功标准

- 用户能分辨当前运行、等待、失败、完成以及 pending 的状态。
- 用户能看出代理当前可以访问什么，以及一次工具调用操作了什么。
- 同一对象的多个视图一致，关闭视图不影响对象生命周期。
- 从历史继续时，系统不会用旧授权或旧文件认知静默覆盖现实。
- 资源绑定变化不导致历史工具调用断链。
- 用户不必持续整理画布才能理解工作过程。
