# 不可变内容与导入

宿主内容模块提供字节暂存、封存、读取与持久引用。来源适配取得字节，插件解释业务格式，视图和模型适配按各自契约消费内容。内容不是新的工作台对象；资源、当前数据与记录可以引用它。

## 内容身份与引用值

`ContentRef` 是 SDK 保留的 JSON 值，严格形状为 `{ "$atelier.content": "<opaque UUID>" }`。保留键所在对象只能具有这一字段；畸形保留值拒绝写入。普通字符串、路径、URL 与哈希不会被识别为内容引用。需要保存保留形状的字面文本时，将它编码为字符串。

SDK 导出 `contentRefSchema` 供业务 schema 组合。仅保留精确键 `$atelier.content`，不预占其他领域字段。将引用字符串化或写入插件私有目录不建立持久依赖；transform 若移除引用，宿主不再为移除的引用登记根。投影、系统提示与普通文本也不建立根。

宿主在最终校验过的持久 JSON 中识别保留引用值，验证其可用性与调用归属，自动生成依赖清单。清单与业务 JSON 在同一事务保存；不要求插件逐次填写清单、声明提取函数或暴露 schema 内部结构。schema 的默认值、联合和转换规则保持不变。插件缺席或数据无法解码时，已保存的依赖清单仍有效。

公开身份不暴露磁盘路径、哈希算法或物理存储布局，也不授予读取或保留权。宿主内部使用完整性摘要与长度校验内容，可对相同字节去重。文件名、MIME、用途等由消费契约表达，不属于字节身份；MIME 声明不能替代插件的实际格式检查。

## 临时占用与提交

输入草稿绑定具型创建或动作契约；创建草稿不要求已存在对象。草稿的宿主凭据仅在命令信封传递，业务输入只包含稳定引用值。一次提交尝试固定其取用的内容，后续新增草稿内容不隐式扩大该次尝试的资格。

草稿与尝试各自持有占用。准备拒绝或执行失败后，保留的草稿可以再次提交；结束一次尝试不消耗原始输入。关闭草稿禁止新上传和新尝试，已捕获的尝试仍按自身生命周期收束。取消是信号，清理须等待实际使用者结束，不能仅因 TTL 到期删除活动内容。

后台准备取得窄的内容上下文：资源自身准备可读取输入并产生受管的临时内容，外部准备者只能读取。准备不修改会话／对象数据，也不建立持久引用。prepare 的 replace 仍按所有者 schema 解析；替换为不属于本次作用域或已有合法归属的引用时拒绝受理。

后台执行可以在宿主管理的作用域内暂存生成内容。异步读取、写入和加工在同步事务之外完成。封存完成后字节不可修改；create 和 commit 只验证封存状态、保存 JSON 与依赖关系，不在事务内等待传输、复制大文件或计算摘要。

准备、排队、执行与提交必须使用覆盖整个尝试的内容占用，不能在 prepare 返回时释放。作用域关闭后不得再读取或认领其中仅临时存在的内容。重开应用后不恢复上传草稿，不自动重放未知结局的命令。

## 持久归属

| 归属 | 规则 |
| --- | --- |
| 当前数据 | 以会话、对象（可空）与契约为根；每次 set 同事务替换整组依赖 |
| 历史记录 | 以记录身份为根；资源创建事件也属于历史，引用随记录保留 |
| 输入草稿、提交尝试 | 临时根；由宿主随草稿与运行收束释放 |
| 活动读取 | 打开时固定内容，关闭后释放，避免读取期间被回收 |

当前数据不按历史分支复制，查看与分叉不恢复当前值。替换当前文件后，旧内容只有在其他当前数据或历史记录仍引用时才继续保留。原件若需留存，由插件把引用写入事件；宿主不会把全部输入自动保存为历史。

create 返回的 data 仅属于 `resource_created` 历史事件；创建中的 `writer.set` 属于对应当前数据槽，不自动双写。分叉仍在同一个 Session 的树内，不建立新会话。

对象移除、解绑、关闭卡片、切换分支或插件卸载不删除历史依赖。会话内容由宿主持有，插件私有目录用于插件自己的配置、数据库和缓存；删除插件目录不应破坏会话附件。

## 读取与授权

读取接口绑定输入、对象或会话的合法内容归属：对象门面只能使用本对象当前数据或所取用历史路径上的记录依赖；会话门面只使用会话级根，不能借此读取任意对象。当前尝试也可使用其捕获或生成的临时内容。宿主在异步读取前固定占用；分段读取同样受限域检查。已知内容 ID、卡片可见或契约可见都不构成资源授权。模型请求仍通过真实资源授权取用内容，在请求边界固定环境。

作用域检查维护 SDK 职责和执行授权，不构成完全信任插件的沙箱。资源之外的跨插件、跨会话共享须另有显式接口，不能靠转发一个 ID 隐式授予。

同会话的对象 A 与 B 也不能仅通过复制引用共享内容；拖到另一对象或跨对象复制需要未来的显式共享接口。模型回传引用同样要经当前对象／执行作用域校验。

## 传输与回收

renderer、preload、main 与 runtime 使用独立、具名且校验过的内容信封。上传分块有大小上限、顺序校验与确认，发送方等待确认后再发送下一块形成背压；未封存上传不能用于持久提交。公开作者接口隐藏分块协议，接受 Blob／字节来源并返回引用。

文件先写入私有临时位置，完成后封存，再允许数据库持久引用。失败或进程中断可留下孤儿内容；启动清理与运行期回收只删除没有持久引用、没有草稿／运行占用且没有读取占用的内容。回收判定与新增保留关系串行协调，不靠延迟时间猜测活动是否已结束。嵌套提交失败时，内容依赖随数据一起回滚。

大小、并发和临时容量限制属于宿主实现参数，失败必须可诊断；不把原始字节编码成 base64 JSON，不向 renderer 暴露任意文件访问。

单次 read 有上限，大内容使用 open 或范围读取；具体限额见 `src/runtime/content-store.ts` 的 `contentLimits`。完整读取校验摘要，范围读取校验文件长度；流式读取在完整消费结束时校验摘要。草稿由显式关闭、渲染页重载／退出及宿主关闭清理，不提供跨重启草稿恢复。

## 消费与扩展

创建和动作共用内容模块。后续的模型富媒体、工具结果附件、范围展示和会话导出复用内容身份、读取与持久依赖，领域消息协议分别维护。工具结果若携带内容，执行占用须交接到审计保存阶段，不能在 handler 返回时先释放。

实时对象流保持时序交付语义，不自动持久化。录制可把流写入内容模块，结束时封存；持续实时音视频的时序、丢帧和延迟规则不由有限文件导入决定。

内容可重试不等于业务幂等。创建回执丢失后的去重属于命令提交身份；本模块不自动重放创建或动作。
