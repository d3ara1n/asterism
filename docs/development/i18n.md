# Interface localization

Localization applies to application interface text. The English manual and engineering documents remain separate from UI language selection.

## Message ownership

Plain strings are valid `UiText` and display literally. External plugins can use one language without catalogs. The host and built-in plugin supply English and Simplified Chinese interface text.

FormatJS handles ICU MessageFormat parsing, formatting, matching, and extraction. The SDK declares message data and ownership rather than another translation engine.

Message identity combines owner and local ID. A declaration owns its source locale and default message. Public re-exports retain that original ownership.

Parameters are transferable scalar data. Date/time values use epoch milliseconds and ICU formatting; React nodes, functions, and Date objects do not cross the protocol as message parameters.

## Message IDs

Repository-owned messages use semantic, dot-separated local IDs. Each segment is lower camel case, starts with a lowercase ASCII letter, and contains only ASCII letters and digits. An ID has at least two segments: a domain followed by a purpose, with intermediate concepts when they clarify ownership. Examples include `settings.general.summary`, `tools.resources.list`, `tools.text.edit`, and `conversation.thinking.completed`.

The domain describes the feature or concept, not its current file or component. Local IDs omit the owner namespace, source paths, component names, sequence numbers, and translated wording. Related messages share a semantic prefix. Segments identify meaning rather than implementation position; moving code does not rename a message.

An ID identifies a translation role, not the current English sentence. Copy edits and locale changes retain the ID while the meaning stays the same. Distinct contexts keep separate IDs even when their English text matches; sharing an ID means sharing the translation meaning across locales. A semantic rename updates its declaration and catalog keys together, preserving the translated values.

Declaration property names are local code identifiers and may remain concise, such as `textMessages.edit`; the catalog ID supplies the full domain context. Public re-exports preserve both message ID and owner.

This naming convention governs repository-owned source declarations and catalogs. The SDK message contract accepts non-empty local IDs from external plugins without imposing the repository's naming style.

## Content boundaries

Translate navigation, actions, form labels, accessibility descriptions, status explanations, and recovery guidance. Preserve code, IDs, raw diagnostics, user content, model output, and saved titles.

Model-facing tools and harness text remain stable English. UI language does not rewrite model protocols or historical facts.

Errors can contain a stable machine code, an English diagnostic message, and a separate localized display value. A display explanation does not overwrite the original error.

## Catalog loading and fallback

Package metadata declares optional catalog files inside the package. Catalogs map local message IDs to ICU strings and can be incomplete.

The host reads catalogs without executing plugin code. Invalid entries produce diagnostics and fall back without failing unrelated business contributions.

Language preference is either system or an explicit BCP 47 locale. Matching respects language and script, including the difference between simplified and traditional Chinese.

For each message, select a compatible catalog for its owner. Missing or invalid translations fall back to the default message in its source locale. If default formatting also fails, show the original default text with a diagnostic rather than exposing only an internal ID.

Switching language updates formatters without changing business component identity, drafts, focus, geometry, or running work.

## Maintenance

Use SDK renderer formatting interfaces for plugin text and host-rendered labels.

Extraction and validation check ownership, conflicting ID declarations, ICU syntax, parameters, and built-in translation coverage. Repository checks also enforce the local ID syntax; semantic naming remains a review responsibility. Source declarations remain the source of default text.
