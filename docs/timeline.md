# 会话树、时间线与回溯

## 一棵会话级的树

每个 Session 是一段工作的容器，拥有唯一会话树和一个执行游标。会话树保存全部历史节点与父子关系；节点不可改写，树没有唯一末端，也不决定追加位置。节点用 `id / parent_id` 关联，扁平存储树状结构：

| 节点 | 含义與载荷 |
| --- | --- |
| message | 用户发给某个代理的消息，来源为接收代理资源，parts 有序保存文字与文件引用 |
| thinking / text | 代理输出的一个完整块（`Execution` 记录载荷）：`response_id`、`request_parent_id`、序号、正文/摘要、`complete`、续接资料与可空终态元数据 |
| toolcall | 同上请求身份与元数据，加本地/provider 调用 ID、工具名、参数与终结结局 |
| event | 资源创建、加入/移除工作台、链接/断开、对象自身事件等；大内容以 SDK 内容引用值关联 |
| notice | 来源对象、级别、类型、消息（错误、缓存过期、空响应诊断等） |

节点类型可扩展。每个节点带宿主写入的来源 `source: { plugin, resource } | null`，与事件来源共用 SDK 的 `Source` 类型：`plugin` 是写入通道所属插件身份，由宿主按操作柄打戳，插件不能填写，界面不显示、供诊断；`resource` 是经具名资源契约引用并由宿主校验（所属插件、会话内存在、类型一致）的发出资源 `ResourceRef`（含会话 ID），为 null 表示插件的会话级记录。插件写入必带来源，因此 `source: null` 可信地表示软件本身（宿主、工作台、环境）发出，不存在无插件却有资源的来源。来源只表示谁发出记录；被链接的代理等关联对象属于各契约的载荷。

宿主只认识通用记录（契约身份、来源、载荷）与工作台事件，不认识任何执行体的消息或输出块。内置代理的用户消息、模型输出块、通知与上下文摘要都是 `atelier.builtin` 的普通插件记录：响应身份、序号、完成状态、终态计量与协议续接资料都在其契约载荷内，由代理自己写入、校验与投影。系统提示词、角色正文、工具目录、模型参数和完整请求不持久化。其他执行体插件按自己的规划组织记录。

时间线的 thinking、text、toolcall 及其文字、参数与结果是公共领域表达。thinking 必填 `text`（明文思考）与 `summary`（思考摘要）：两者可同时存在或为空，不相互填充，也不宣称可见文字包含模型全部内部推理。续接资料独立保存在块级 `continuation`（保留 Anthropic `signature / redactedData`，以及 OpenAI `itemId / reasoningEncryptedContent / phase` 白名单，连同 `source` 记录来源作用域与适配版本）。原生资料不能覆盖公共正文，也不决定整段上下文是否可用；不保存原始 HTTP、凭据、响应头或未筛选的 provider metadata。

每个块保存 `request_parent_id`，指向本次请求取用的会话路径末端，空值表示起点。它与记录真实追加顺序的 `parent_id` 职责不同；同一响应的所有块共享请求起点和协议来源（adapter、模型表达式 `<providerId>/<modelId>[:<thinking>]`、协议作用域）。

## 写入时机与单一写入者

- **单一写入者**：Session 是时间线的单一写入者。含终态的成型记录、对象与链接事件均经同步事务提交；每条记录都取提交时的当前游标为父节点，追加记录与原子推进游标不可交错、没有例外，事务内不等待模型、文件系统或 IPC。审计信息是记录自身的数据，不形成隐藏节点或不推进游标的例外；记录提交后不改写。
- **用户输入先行**：用户输入受理后先落为 `message`，再开始模型请求。纯图片或 PDF 输入也形成可查看、可分叉的消息节点；文件引用依赖与节点同事务保留。后续模型投影和 UI 从保存的 parts 重建，不重新读取用户原始文件路径。
- **块终态一次提交**：流增量由代理执行侧在内存中按块累积，通过 `session.progress` 提供给 UI，不进树。块的数据准备齐全后一次追加：thinking/text 等待模型响应终态，toolcall 还须取得工具结局。用量、原始/归一化结束原因、服务端响应 ID、计时及 [领域扩展](runtime.md#请求诊断) 随响应中序号最大的实际块保存，其他块的终态字段为空；按响应筛选块并汇总 usage 即得该响应的已报告用量。不存在独立 completion 或请求诊断节点、事后补写或读取合并。回溯到该块时，终态计量和领域扩展一起可用。
- **多个代理并行**：节点按真实完成顺序追加。

## 不完整内容与异常收束

因取消、网络中断或请求失败而未完成的 thinking/text/toolcall 填充，仍以 `complete=false` 落库：UI 显示并标明未完成，供审计；进入历史路径、推进游标且可查看与继续。代理的模型投影跳过不完整块，不影响历史导航。正文已完成但终态缺失时保留正文，终态字段为空。工具一旦开始执行必有结局，确认取消记为 `cancelled`，无法确认写入影响的中止记为 `unknown`，均属完整节点。

异常流已经报告的终态与计量仍可归属到不完整块；未报告的计量保持未知。请求在产生任何块之前失败、取消或以空响应结束时，Agent 通过瞬态事件向在线界面交付 toast，时间线保持已有输入和实际产出；不追加失败／空响应通知、占位回复或计量节点。即使空响应携带 usage，也只供当次调用消费。重启后没有回复就是历史事实，不补写响应；有部分输出时保留实际部分块及其完整性。进程崩溃不做兜底与自动重放。

## 时间线、执行位置与分支

时间线（timeline）是从会话逻辑起点到指定末端的完整祖先路径，按根到末端排列，内部没有分支。沿父指针从末端回到根即可确定它。逻辑起点以 null 表达，不保存实体根节点；末端为 null 时得到空时间线。

末端可以是树上的任意节点，不要求它是整棵树的叶子。执行游标确定唯一的当前时间线，所有记录写入都在提交时向它的末端追加；其他位置的时间线和已取得的固定快照只读。读取旧快照不会激活其位置，写入位置始终取提交时的执行游标，不由此前取得的快照决定。

移动执行游标只重新确定当前时间线，不增加或修改节点。例如树中已有 `A → B → C`，游标移到 B 时当前时间线为 `A → B`；追加 D 后当前时间线为 `A → B → D`，旧后续 C 保留。分叉是会话树的结构变化，当前时间线始终线性。仅移动游标不会产生分叉；向已有后代的末端追加才产生另一条后续。

分支（branch）是 UI 对历史延伸方向的组织与命名，每个叶子对应一条根到叶子的完整时间线。UI 可以省略公共前缀、分段展示和组织跳转，不改变节点或路径含义。当前时间线可能抵达某个叶子，也可能只到多个分支的共同前缀；共同前缀上的执行游标不唯一归属于某个叶子分支，当前 Tab 的标记由 UI 展示规则决定。分支不增加独立存储对象，未激活分支不提供直接写入能力。

## 投影与派生状态

会话树保存完整历史事实；当前时间线确定本次执行采用的线性记录范围，模型与 UI 再各自投影：

- **工作台重建**：宿主工作台的当前存在性与链接由同一个重建入口提供，沿执行路径全量重放资源创建、移除、链接与解绑事件，不计算前后路径差异或逆操作。每个会话只复用当前游标的不可变结果；提交内读取按实际游标取用，事务完成前重建成功才提交，失败不沿用旧授权。工作台展示、对象操作校验和下一次请求授权使用同一结果；已捕获请求保持自己的授权。布局和笔记正文独立读取、不重放，资源领域状态由所属模块维护。
- **代理 UI 投影**：沿执行游标路径按真实顺序展示对话。
- **模型投影**：由执行体插件负责。以 core 代理为例：沿游标祖先路径，取该代理的 message 与块、发给它的链接通知等模型可见事件；按 `response_id` 和序号把块组合为 assistant 消息，再按序号展开 tool 结果。响应按 `request_parent_id` 插入模型投影，随后按序号展开工具结果；起点之后追加的可见事件保持相互顺序，放在该响应之后（首块落库前或工具执行期间的事件同样适用）。下一次请求采用这些事件，因此保留前次实际发送的消息前缀。执行游标回到响应块之前时，不提前显示尚未出现的响应。

模型上下文与时间线是不同层次。执行体可按协议与任务需要过滤、重排、组合、裁剪或压缩模型输入，但时间线仍保留完整祖先路径及原始历史顺序。上下文自动压缩以普通摘要记录替换模型输入中的旧前缀，近期原文继续保留，完整规则见 [上下文自动压缩](context-compression.md)。会话标题由命名模块在执行游标变化后按当前路径最新命名事件或首条用户输入同步，规则见 [自动会话命名](session-naming.md)。

记录提交观察 `committed` 与执行游标观察 `cursorChanged` 分开；观察快照以固定路径末端、会话追加上界和标题表达按需读取边界。具体 SDK 接口见 [插件 SDK](plugin-sdk.md#对象读取与执行)。

## 回溯与分叉

- 只有整个会话 settled（所有被捕获的资源都已收束）时允许回溯游标；包括代理的模型流、工具执行和其他会向会话树写入事件的资源活动。运行中需等待，或在资源支持时显式打断并等待收束。只引用外部状态的资源不因持续运行而阻止回溯。正常追加仍推进游标。
- 工作台与代理对话始终对应执行游标，不设独立查看位置。历史面板点击条目、切换分支或筛选只改变面板内的候选选择，不读取另一个位置的工作台。
- 点击「从这里继续」并确认后移动执行游标，统一重建对象存在性与链接；目标路径尚未创建或已经移除的对象不出现。跳转本身不追加节点，之后追加才产生新路径，原后代保留，可再次跳回。
- 显式游标选择进入独立的追加选择日志（`cursor_selections`），保存原位置、所选位置和时间，与当前游标更新同事务提交；日志不进入树或模型上下文。面板内选中条目和布局操作不写选择日志；正常追加引起的游标前进由节点记录本身表达。
- 宿主可从任何历史节点继续，不吸附、不判断位置是否适合某个执行体。记录可能因回溯、断网或取消停在任意块之后；执行体在投影上下文时自行截取到合理位置，这条规则只在其投影函数内处理。
- 回溯不恢复外部资源内容，也不反向执行工具；外部差异由模型通过 inspect 自行感知，不改写也不补写历史节点。
- 历史记录引用的不可变内容随原记录保留，当前数据不按分支复制；内容归属见 [不可变内容](content.md)。历史面板的 Tab、列表与筛选交互见 [工作台](workbench.md#时间导航与透明度)。

## 明确不承诺

- 不恢复任意外部系统到过去。
- 不因游标回溯删除现实文件或反向执行工具。
- 不保证重跑模型结果相同。
- 不保证共享可写资源的分支相互隔离。
- 不自动重放结果未知的操作。
