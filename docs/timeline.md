# 会话树、历史与回溯

## 一棵会话级的树

每个 Session 有唯一一棵只追加的会话树和一个会话游标。节点用 `id / parent_id` 关联，扁平而非嵌套：

| 节点 | 含义 |
| --- | --- |
| message | 用户发给某个代理的消息 |
| thinking / text | 代理输出的一个完整块 |
| toolcall | 一次工具调用及其结果，取得结局后才进树 |
| event | 资源创建、加入/移除工作台、链接/断开、对象自身事件等 |
| notice | 通知：错误、缓存过期、预算提示等，带级别 |

节点类型可扩展。代理产生的节点带 `agent_id`；同一次模型响应的块共享本地生成的 `response_id`，toolcall 带其在响应中的序号。用量与结束原因属于响应，挂在响应的末个块上。协议续接资料（Anthropic signature、OpenAI itemId/encrypted reasoning）作为块级不透明字段，带适配器版本，仅由对应适配器读取。

多个代理并行时，节点按真实完成顺序追加。text_delta 等流增量、toolcall 参数填充与执行中状态只存在于运行时，不进树。

## 不完整内容

因取消、网络中断或请求失败而未完成的 thinking/text/toolcall 填充，仍以 `complete=false` 落库：UI 显示并标明未完成，供审计；模型投影跳过；历史树不显示、不可选。工具一旦开始执行必有结局，用户打断记为取消，属于完整节点。请求在产生任何块之前失败时，代理发出错误级 notice 记录原因。进程崩溃不做兜底。

## 投影

会话树是唯一真值，模型与 UI 各自取所需：

- **UI 投影**按真实顺序，重建工作台对象、关系与各代理卡片。
- **模型投影**沿游标祖先路径，取该代理的 message 与块、发给它的链接通知等模型可见事件；按 `response_id` 和序号把块组合为 assistant 消息，再按序号展开 tool 结果。
- 某代理响应期间追加的、对它可见的事件，投影时延后到该响应的工具结果之后。规则只依赖已存在的节点，同一位置的投影结果确定，因此前缀缓存稳定。

链接通知（如“resource X connected”）既减少模型频繁查询资源列表，也用于回溯时重建链接；加入或移除工作台等事件只重建视图，不投影给模型。系统提示词不来自会话树。

## 回溯与分叉

- 只有整个会话 settled（无模型流、无运行中的工具）时允许移动游标；运行中需等待或打断。
- 选择任意可见节点即可查看该位置：工作台由祖先路径折叠得到，当时尚未创建的代理和资源不出现，当时已断开的链接重新出现。
- 选中位置后发送消息即沿该节点追加新路径，原后代保留，可随时切回。游标移动本身是追加事件。
- 继续位置不能使任一代理的投影以 thinking 结尾；不合法时退到最近的合法祖先，并在界面标出实际继续点。toolcall 进树即带结果，无需配对检查。
- 回溯不恢复外部资源内容，也不反向执行工具；外部差异由模型通过 inspect 自行感知，不改写也不补写历史节点。

## 用户导航

历史树是独立视图：可概览全部节点与分支、缩放、按节点类型过滤，粒度由视图决定。代理卡片保持当前路径的最终视图。

## 明确不承诺

- 不恢复任意外部系统到过去。
- 不因回看删除现实文件或反向执行工具。
- 不保证重跑模型结果相同。
- 不保证共享可写资源的分支相互隔离。
- 不自动重放结果未知的操作。
