# 会话树、历史与回溯

## 一棵会话级的树

每个 Session 有唯一一棵只追加的会话树和一个会话游标。节点用 `id / parent_id` 关联，扁平而非嵌套：

| 节点 | 含义 |
| --- | --- |
| message | 用户发给某个代理的消息，parts 有序保存文字与文件引用 |
| thinking / text | 代理输出的一个完整块 |
| toolcall | 一次工具调用及其结果，取得结局后才进树 |
| event | 资源创建、加入/移除工作台、链接/断开、对象自身事件等 |
| notice | 通知：错误、缓存过期、预算提示等，带级别 |

节点类型可扩展。每个节点带宿主写入的来源 `source: { plugin, resource }`：`plugin` 是写入通道所属插件身份（宿主工作台为 `atelier.host`），由宿主按操作柄打戳，插件不能填写，界面不显示、供诊断；`resource` 是经具名资源契约引用并由宿主校验（所属插件、会话内存在、类型一致）的发出资源，为 null 表示会话级记录。来源只表示谁发出记录；被链接的代理等关联对象属于各契约的载荷。

宿主只认识通用记录（契约身份、来源、载荷）与工作台事件，不认识任何执行体的消息或输出块。内置代理的用户消息、模型输出块、通知与上下文通知都是 `atelier.core` 的普通插件记录：响应身份、序号、完成状态、终态计量与协议续接资料都在其契约载荷内，由代理自己写入、校验与投影。其他执行体插件按自己的规划组织记录。

每个块保存 `request_parent_id`，指向本次请求取用的会话路径末端，空值表示起点。它与记录真实追加顺序的 `parent_id` 职责不同；同一响应的所有块共享请求起点和协议来源。

块的数据准备齐全后一次追加：thinking/text 等待模型响应终态，toolcall 还须取得工具结局。生成与执行期间的内容通过实时进度展示。用量、原始/归一化结束原因和服务端响应 ID 随响应中序号最大的实际块保存，其他块的终态字段为空；按响应筛选块并汇总 usage 即得该响应的已报告用量。不存在独立 completion 记录、事后补写或读取合并。

每条进入历史树的记录都以提交时的当前游标为父节点，并原子推进游标，均可显示与查看。审计信息是记录自身的数据，不形成隐藏节点或不推进游标的例外；记录提交后不改写。

多个代理并行时，节点按真实完成顺序追加。text_delta 等流增量、toolcall 参数填充与执行中状态只存在于运行时，不进树。

用户输入受理后先落为 message，再开始模型请求。纯图片或 PDF 输入也形成可查看、可分叉的消息节点；文件引用与节点同事务保留。后续模型投影和 UI 从保存的 parts 重建，不重新读取用户原始文件路径。历史文件随原节点保留，某条分支之外的引用不会因已知 ID 就进入当前请求。

## 不完整内容

因取消、网络中断或请求失败而未完成的 thinking/text/toolcall 填充，仍以 `complete=false` 落库：UI 显示并标明未完成，供审计；进入历史路径、推进游标且可查看与继续。代理的模型投影跳过不完整块，不影响历史导航。正文已完成但终态缺失时保留正文，终态字段为空。工具一旦开始执行必有结局，用户打断记为取消，属于完整节点。请求在产生任何块之前失败时，代理发出错误级 notice 记录原因。进程崩溃不做兜底。

异常流已经报告的终态与计量仍可归属到不完整块；未报告的计量保持未知。服务端正常结束却完全没有内容块属于异常，发出 `empty_response` 诊断 notice 并保留已收到的终态资料，不伪造模型输出。统计完整会话用量时包含这种无块诊断。

## 投影

会话树是唯一真值，模型与 UI 各自取所需：

- **UI 投影**按真实顺序，重建工作台对象、关系与各代理卡片。
- **模型投影**由执行体插件负责，以 core 代理为例：沿游标祖先路径，取该代理的 message 与块、发给它的链接通知等模型可见事件；按 `response_id` 和序号把块组合为 assistant 消息，再按序号展开 tool 结果。
- 响应按请求起点插入模型投影，随后按序号展开工具结果；起点之后追加的可见事件保持相互顺序，放在该响应之后。首块落库前的事件、工具执行期间的事件同样适用；起点即使是其他代理的不可见节点仍可定位。下一次请求采用这些事件，因此保留前次实际发送的消息前缀。回看早于响应块的路径时，不提前显示尚未出现的响应。

链接通知（如“resource X connected”）既减少模型频繁查询资源列表，也用于回溯时重建链接；加入或移除工作台等事件只重建视图，不投影给模型。系统提示词不来自会话树。

会话标题是由命名模块同步的派生当前值。命名只追加会话级命名事件；执行游标变化后，模块按当前路径最后一条命名事件同步标题，没有命名时从当前分支首条用户输入重建截断标题，两者都没有时保持不变。只查看历史不改变标题，回溯同步不追加恢复事件。命名事件的 model 为 null，不进入模型消息；规则见 [自动会话命名](session-naming.md)。

记录提交观察 `committed` 与执行游标观察 `cursorChanged` 分开。正常追加、回溯与分叉选择都以变化后的固定路径通知游标观察者，一次外层事务只通知最终位置。依赖历史的派生当前值由领域模块重建，模型上下文继续即时投影；接口与提交后同步边界见 [插件 SDK](plugin-sdk.md#记录提交与执行游标观察)。

## 回溯与分叉

- 只有整个会话 settled（所有被捕获的资源都已收束）时允许回溯游标；包括代理的模型流、工具执行和其他会向会话树写入事件的资源活动。运行中需等待，或在资源支持时显式打断并等待收束。只引用外部状态的资源不因持续运行而阻止回溯。正常追加仍推进游标。
- 查看位置由会话视图模块独立管理，可跟随执行游标或固定到历史位置；工作台与对话采用同一次读取的路径。后台进度与命令结果不会移动查看位置，布局操作也不追加选择日志。
- 选择任意可见节点即可查看该位置：工作台由祖先路径折叠得到，当时尚未创建的代理和资源不出现，当时已断开的链接重新出现。
- 选中位置后发送消息即沿该节点追加新路径，原后代保留，可随时切回。显式选择进入独立的追加选择日志，保存原位置、所选位置和时间，与当前游标更新同事务提交；日志不进入树或模型上下文。只查看历史不写选择日志；正常追加引起的游标前进由节点记录本身表达。
- 宿主可从任何历史节点继续，不吸附、不判断位置是否适合某个执行体。记录可能因回溯、断网或取消停在任意块之后；执行体在投影上下文时自行截取到合理位置，这条规则只在其投影函数内处理。
- 回溯不恢复外部资源内容，也不反向执行工具；外部差异由模型通过 inspect 自行感知，不改写也不补写历史节点。
- 历史记录引用的不可变内容随原记录保留，旁支、对象移除与插件缺席不释放这类依赖。当前数据不按分支复制，替换当前值后旧内容在没有其他依赖时可回收；查看旧位置不恢复它。内容归属见 [不可变内容](content.md)。

## 用户导航

历史导航是独立视图，以逐节点的紧凑列表为主。每条历史记录对应一个可查看节点，按真实追加次序排列；同一 response 的块、其他代理的块和期间的工作台事件不归组、不重排。条目以原文片段或标准事件文本识别，不依赖人工／模型生成的任务摘要；两行结构、来源区分与定位交互见 [工作台](workbench.md)。

分支以顶部 Tab 切换，每个 Tab 展示共享起点与独有后续；原后续保留在原 Tab，分叉点提供双向定位。同一父节点最早追加的后代延续原分支，其他后代各建立新分支视图；Tab 身份和编号由树的追加顺序推导，不增加存储对象或复制共同历史。切换定位该 Tab 最近查看的位置，首次进入定位末端；分叉点跳转则定位同一个共享节点。具体布局与导航发布规则见 [工作台](workbench.md)。

查看位置包含目标节点；查看某条之前使用它的真实父节点，而不是过滤后相邻的可见条目。来源／文本筛选不移动查看位置，分支切换与查看都不改变执行游标。选择用于继续时即为所选位置。代理卡片保持所查看位置的完整祖先路径投影，Tab 内只显示分支片段不会截断代理上下文，卡片内部的阅读聚合不决定历史导航的粒度。

## 明确不承诺

- 不恢复任意外部系统到过去。
- 不因回看删除现实文件或反向执行工具。
- 不保证重跑模型结果相同。
- 不保证共享可写资源的分支相互隔离。
- 不自动重放结果未知的操作。
