# 时间线、历史查看与恢复

## 历史由事件记录

任务记录对象与关系的创建、资源变化请求与生效、执行开始结束、工具操作及结果、配置应用、分叉等事件。

检查点保存可重建的状态以加速读取；不要求每个 turn 完整复制所有资源和对话。事件结构、检查点频率和迁移方案在实现时确定。

任务中的多代理事件有明确记录顺序，同时保留各执行消费的历史位置和来源关系。记录顺序不意味着并发执行彼此看到了全部信息。

## 用户导航

主入口是执行/用户输入的 summary list，而非必须实现空间上的真实 Z 轴。列表项定位到具体历史位置，需要时再展开更细事件。

查看过去时：

- 只显示该历史位置之前已经产生的对象与关系。
- 绑定是否有效由生效与结束区间决定。
- 资源内容使用对应历史记录，不以今天的内容冒充。
- 缺乏历史内容时明确显示不可用，而不是悄悄展示当前内容。
- 当前实时运行可以继续，但历史视图需要明确的历史模式标识。

打开、折叠或移动卡片通常是视图行为，不改变工作事实。可以在历史视图里展开当时已存在的操作，即使用户当时没有打开过该卡片。

## 能看与能恢复

| 对象或视图 | 可看历史 | 可恢复状态 |
| --- | --- | --- |
| 已保存的成功 edit diff | 可以查看实际变更 | 不代表文件可恢复 |
| 未保存旧内容的文件 view | 不可假装能看完整旧文件 | 不承诺 |
| 已保存游戏画面 | 可以查看画面 | 单独画面不够 |
| 完整游戏状态快照 | 可以构造相应视图 | 资源实现支持时可以 |

string-replace 参数仅能说明请求的变更；实际 diff 应结合执行是否成功、匹配位置和实际结果。部分成功需精确记录。

## 从历史继续与分叉

浏览历史不执行任何恢复。选择“从这里继续/分叉”才开始新的执行流程：

1. 以选定历史位置作为新分支来源。
2. 还原当时的对话和绑定意图，但不自动复活已撤销的当前授权。
3. 检查将要访问的外部资源是否仍可访问，授权不足时请求确认。
4. 对可变资源核验当前状态，并将与历史认知的差异告知代理。
5. 对支持恢复的资源，按明确选择恢复或创建隔离实例；不能覆盖其他活跃分支而不告知用户。
6. 产生新的执行记录，不重写原分支。

资源“恢复原实例”与“从快照创建新实例”是不同操作。后者的具体支持范围和初版 UX 尚待确定。

## 版本与 stale

不使用一个全局 stale 标记解释所有情况。

- 历史 diff 是过去的事实，不因当前文件改变而变成错误记录。
- 基于旧文件生成的计划可能不再适用于当前内容。
- 未检查外部当前状态时是未验证，不是已确认匹配或过期。
- 版本差异属于某份观察/执行/产物与某个当前资源之间的关系。

资源可以用内容 hash、版本号或其他原生版本标识进行核验。无法核验时保留未知，不能虚构一致性。

## 明确不承诺

- 不恢复任意外部系统到过去。
- 不因回看而删除现实文件或反向执行历史工具。
- 不因恢复对话而保证重跑模型结果相同。
- 不保证多个共享可写资源的分支相互隔离。
- 不将崩溃时结果未知的操作自动重放，尤其是存在非幂等副作用的操作。
