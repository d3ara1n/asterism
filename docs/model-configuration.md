# 提供商、模型角色与代理配置

本文定义全局提供商、具体模型、模型角色与代理配置的结构、发现、继承及消费语义。

## 设置职责

| 设置分类 | 管理内容 | 消费方 |
| --- | --- | --- |
| 提供商 / Providers | 连接、协议、端点、凭据、共用兼容包，以及连接下的具体模型、能力和生成参数 | 模型接入与连接测试 |
| 角色 / Roles | 模型角色配置表：模型引用、思考等级、启用、用途描述、隐藏 | 代理配置与需要模型的功能模块 |
| 代理 / Agents | agent 配置：提示词、工具策略、可委派代理、模型角色引用等 | 每个代理的每次请求 |

提供商下的具体模型决定服务端模型 ID、能力和温度等生成参数。模型角色引用具体模型，负责复用选择与思考等级，不另存一套温度等上游参数。相同服务端模型 ID 可能出现在不同连接下，引用必须能确定实际使用的连接。

四类全局配置保存于应用数据目录的 `configuration.json`，独立于会话数据库；角色与 agent 只保存用户覆盖及身份。配置文件仅首次创建时初始化，已有文件的删除状态保留；损坏或不支持的文件不自动重置。密钥由独立加密文件保存，配置只持有引用（见 [技术架构](architecture.md#存储归属与全局配置)）。

模型角色与代理配置都是可编辑的配置记录。工作台上的代理对象是采用配置创建的执行实例；模型角色不成为卡片、资源或独立执行对象。普通对话界面选择 agent 和具体模型，不增加一层模型角色操作流程。

## 提供商预设

预设只提供连接与端点兼容设置，不附带模型、模型能力或思考等级。目录随应用发布（定义于 `src/shared/provider-presets.ts`），声明名称、协议、端点、鉴权、共用兼容包、凭据页面，以及核实这些配置的官方资料和日期。不同地区、按量与订阅产品分别声明独立预设，即使端点相同也不混用凭据说明；不把消费者订阅视为 API 凭据。

选择器依次按按量计费（`usage`）、订阅（`subscription`）、不计费（`none`）分组，不按厂商分组，空组不显示。搜索跨组匹配名称、地区、套餐与计费说明；卡片只显示名称及地区／套餐细节，自定义连接独立放在末尾。

预设是已填好参数的自定义提供商。选择入口一次性生成普通连接草稿，显式带入兼容条目，然后打开与空白自定义连接相同的编辑器，统一展示全部连接字段和兼容设置。编辑器不保留预设身份、来源状态或更换预设入口。目录 ID 按量采用厂商 slug，订阅追加 `-plan`，地区后缀放最后（如 `kimi / kimi-plan / kimi-cn / kimi-plan-cn`）；重复添加同一预设时默认连接 ID 追加未占用数字后缀。保存不持久化预设身份、计费标签或资料来源；目录更新不修改已保存连接及其引用。

优先使用 Responses；Anthropic 使用原生 Messages。聚合服务对同一计费产品与地区默认只提供一个预设，支持 Responses 时优先选择；只有不同端点对应不同模型集合时才拆分提供商。当前目录包含 OpenAI、Anthropic、DeepSeek、xAI、OpenRouter、OpenCode Console／Go，以及 Kimi 和智谱／Z.ai：
- **OpenRouter / OpenCode Console**：分别使用 `https://openrouter.ai/api/v1` 与 `https://opencode.ai/inference/v1` 的单一 Responses 入口（Zen 保留为搜索别名）。
- **OpenCode Go**：预设 ID 为 `opencode-plan`，使用 `https://opencode.ai/inference/go/v1` 的 Responses 入口，显式带入 `opencodeSession` 兼容包。
- **Kimi**：按量提供国内 `api.moonshot.cn/v1` 与国际 `api.moonshot.ai/v1`；Kimi Code 订阅提供国内 `api.kimi.com/coding/v1` 与国际 `api.kimi.ai/coding/v1`；预设通过 `responsesReasoning` 省略未支持的 `encrypted_content` include 与 `reasoning.summary` 请求字段。
- **智谱／Z.ai**：国内 `open.bigmodel.cn/api/v1` 与国际 `api.z.ai/api/v1` 各提供按量与 Coding Plan 预设，共用单对象 `content` 编码并省略上述两个请求字段。

订阅入口标明仅限受支持客户端；预设不代表 Atelier 已获厂商客户端准入，不伪装其他工具身份。

## 模型发现与添加

保存提供商连接后，用户在模型区点击「获取模型」，使用已保存的 API 基础地址与鉴权获取候选列表（连接草稿有修改时先保存）。OpenAI Responses 与 Chat Completions 共用基础地址下的 `GET /models`；Anthropic 同样追加 `/models` 并使用自身版本头、鉴权与解析。基础地址已有路径保留，不固定替换成域名根部 `/v1/models`。

请求在后台运行，支持取消、30 秒整次超时和明确刷新，无隐式重试。分页按同一端点的 `has_more / last_id` 游标继续获取，全部成功后交付去重列表；分页失败不交付部分目录。候选支持搜索与多选添加，已添加项不可重复选择。

只采用端点明确返回且已适配的资料，不按模型名称推断能力：OpenAI 风格接口读取模型 ID；Anthropic 另读取显示名、`max_input_tokens`、思考能力和明确支持的 effort 等级（`off` 只在端点声明支持 `thinking.types.disabled` 时加入）。未返回的参数沿用手动新建初始值：思考与工具调用开启、可选思考等级全开、上下文与生成参数未设置。选中的模型在一次原子保存中加入，不覆盖已有模型；发现列表仅在内存保留，修改或删除连接使其失效。

## 从 models.dev 获取参数

「获取参数」只在已保存模型的设置页表单提供。点击后通过官方 `@opencode-ai/models` 客户端请求公开目录（无凭据、禁止重定向、10 秒超时、无隐式缓存），覆盖该模型的可映射参数并立即原子保存，不区分旧值来源；失败、无精确匹配或匹配有歧义时保留原值并提示。

- **覆盖范围**：`limit.context` → `contextWindow`；`limit.output` → `maxOutputTokens`；`reasoning` 与 `tool_call` 开关；`reasoning_options.effort`（全部值可映射且非空时替换等级集合，`none`/null 对应 `off`；无法直接表示时保留原等级并提示人工检查；不支持思考时关闭思考并清空等级）。缺失或占位零值的 token 限制保留原值。模型身份、显示名、启用状态、连接与兼容设置不在覆盖范围。
- **精确检索规则**：仅在查询时从服务端 `modelId` 取最后一个 `/` 后的部分（去掉厂商／路由前缀），与目录模型标识做同样处理后精确比较（大小写、连字符与后缀不变，不模糊匹配，连接地址与提供商 slug 不参与消歧）。匹配后读取原模型记录（缺失时取底层模型资料），不采用中转站参数覆盖。保存与实际请求继续携带完整服务端 `modelId`。
- **价格映射**：原模型记录的 `cost` 转换为下节的工坊价格结构，成功后整项替换；目录无价格、数据无效或包含无法表达的价格规则时保留整项旧价格，并在未填字段中提示，不影响其他有效参数的更新。标准 `tiers` 优先于旧 `context_over_200k`，阈值排序后保存；重复阈值拒绝转换。目录没有提供的分项单价写为未知，不继承基础价，也不保留被替换价格中的旧分项。

## API 参考价格

具体模型的 `cost` 是应用自有的价格配置，独立于模型协议与上游 `Usage`，不随请求发送。它描述用于估算的 API 参考价，不表示订阅扣款、中转站实际收费或账户余额。价格可手动编辑，也可通过「获取参数」填入；既有配置缺少此字段时读取为 `null`，不自动写回文件。

| 字段 | 语义 |
| --- | --- |
| `cost: null` | 未配置价格 |
| `currency` | 价格表的统一币种，固定为 `USD`；模态和计费项不另设币种 |
| `rates` | 基础价格，按 `text / image / audio / video` 模态组织 |
| 模态内的计费项 | `input / output / cacheRead / cacheWrite / reasoning`，各项独立保存价格，缺项或 `null` 表示未知 |
| 单项价格 | `{ amount, unit, per }`：每 `per` 个 `unit` 的金额为 `amount`；金额为有限非负数，`0` 表示免费 |
| `unit / per` | 单位为 `token / image / second`，基数为有限正数；例如每百万 token、每张、每 60 秒 |
| `tiers` | 按 `fromInputTokens` 严格递增的档位列表；每项包含独立完整的 `rates`，空列表表示固定价格 |

模态与单位是独立维度，同一模态的不同计费项可以采用不同单位。例如 `image.input` 按百万 token 定价，`image.output` 按张定价，`audio.input` 按 60 秒定价；不能由模态推断单位。基础价和每个档位使用同一结构。设置按模态分组，每项可编辑金额、单位和基数。

价格字段由工坊定义，外部目录只提供其中可映射的资料。models.dev 的普通输入／输出、缓存与思考价映射到 `text`，`input_audio / output_audio` 映射到 `audio` 的输入／输出；这些目录价格统一显式标为 `unit: token, per: 1000000`，不换算金额。未提供的模态和计费项保持未知，不从文本单价推断图片、音频或视频价格。

已有配置的平铺价格仅在存储边界转换：普通输入／输出、缓存与思考归入 `text`，图片／音频／视频输入输出归入各自模态，原金额保留并显式标记为每百万 token；未知值和所有档位保持语义。读取不重写原文件，后续显式保存使用新结构。公共配置契约只接受按模态组织且包含单位的价格。

分档依据是单次请求输入 token 总量（含缓存）。`fromInputTokens` 为非负安全整数且含边界，达到多个起点时取最高档，否则取基础价；选中档位的整套单价适用于整次请求，不进行分段累进，档内未知单价不从基础价继承。models.dev 的 `tiers[].tier.size` 映射为该起点；仅有旧 `context_over_200k` 时转换为起点 `200001`。外部字段名、目录类型和特殊兼容字段仅存在于导入转换边界，不进入价格配置。

费用是既有请求用量与当前价格的派生结果，不属于上游 usage，也不另存消费账本或历史价格快照。逐请求选取实际模型和档位后才能汇总，不能先汇总用量再套价；修改价格会改变历史请求的参考估值，展示须说明按当前价格估算。每项费用依据匹配模态、计费项及单位的数量按 `数量 / per × amount` 求得，不能以 token 数代替张数或秒数；价格配置不代表已经具备对应单位的用量。未知价格或缺失用量不能当零费用。思考、各模态和缓存分项的保存不表示可以与输入／输出总量直接相加，消费者须依据用量口径避免重复计费。

## 输入能力与思考等级

具体模型的能力声明 `reasoning`、`thinkingLevels` 与 `tools`。输入模态属于服务端能力，不在客户端配置：文件（首批适配 JPEG、PNG、GIF、WebP、PDF）按 `mediaType` 如实发送，由服务端反馈是否接受（见 [模型输入与协议适配](runtime.md#用户输入文件与模型协议适配)）。

标准思考等级全局统一为 `off / minimal / low / medium / high / xhigh / max`（`xhigh` 与 `max` 独立，不互相映射）。模型的 `thinkingLevels` 保存可用等级集合，新建时全开，空集合合法；关闭思考总开关保留集合与已有选择。选择器只提供可用等级，配置保存与选择传递不拦截等级可用性。

请求末端解析模型和等级继承后校验：`reasoning: true` 时，最终等级为空或不在可用集合中均以 `thinking_unavailable` 失败，不自动降档；`reasoning: false` 时省略等级及历史思考部件；`off` 是普通等级，不触发历史过滤。所有情况下均正常接收、保存和展示服务端返回的思考。

## 模型引用与模型目标

提供商与具体模型一律以可读 slug 引用，不以随机记录 ID 对外引用：
- **提供商 ID**：用户可编辑的 slug，不含 `/`。
- **模型 ID**：发往服务端的模型名，可含 `/`；显示名仅供阅读。
- **模型表达式（`ModelExpression`）**：`<providerId>/<modelId>`，结构化为 `{ provider, model }`，按第一个 `/` 切分。思考等级不属于模型表达式（记录用串可附加 `:<thinking>`）。

请求以模型目标 `ModelTarget = { role, model?, thinking? }` 表达选择：给出的字段覆盖角色，未给出的沿用角色。代理选择 `AgentSelection = { agent, model, thinking }` 允许 `model / thinking` 为 null，转换为 `ModelTarget` 时省略相应覆盖。最终仍无模型，或角色／模型／凭据不可用时，分别以 `role_unavailable`、`model_unavailable`、`credential_unavailable` 明确失败；非空失效引用不降级为继承。

## 模型兼容包

兼容包是应用预定义、数量有限的行为声明（定义于 `src/shared/model-compatibility.ts`），包含稳定 `id`、参数 `schema` 与仅供 UI 参考的 `appliesTo`（协议／端点列表，不用于自动启用或运行时匹配）。不加载用户 patch 或 processor。

提供商与具体模型分别以 `compatibility` 保存稀疏列表（标签型 `{ id }`，参数型 `{ id, value }`）。提供商条目对连接下所有模型生效；请求时按 `id` 合并，模型同名条目**整项覆盖**提供商条目（不逐字段深合并，省略的可选字段不从提供商补齐；不支持模型单独禁用提供商条目或使用墓碑）。合并结果不回写配置。

正式目录包含五项：
- `systemMessageInMessages`（标签）：将 Responses 系统提示从 `instructions` 改为首条 `system` 消息。
- `toolFilesAsUserMessage`（标签）：允许 Chat Completions 将工具结果文件搬运到后续 `user` 消息。
- `responsesReasoning`（参数）：适配 Responses 明文 `content` 的 array/object 形状，以及是否请求 `encrypted_content` 和 `reasoning.summary`。
- `customUserAgent`（参数）：以必填 `userAgent` 覆盖 HTTP 客户端身份头。
- `opencodeSession`（标签）：将本次请求的会话 ID 写入 `x-opencode-session`。

具体协议投影规则见 [三协议编码与跨模型续接](runtime.md#三协议编码与跨模型续接)。

## 模型角色

| 字段 | 含义 |
| --- | --- |
| 模型引用 | 指向提供商下的具体模型；可为空，继承发起调用的当前对话模型 |
| 思考等级 | 可为空，继承当前对话的思考等级；空值与明确关闭思考（`off`）不同 |
| 启用 | 停用后在软件内不可用，代理、功能模块与对话均不能选用或解析，只在设置中保留 |
| 用途描述 | 说明角色适合什么工作，供用户理解和功能、代理选择 |
| 隐藏 | 不向代理开放为可选择的模型角色；软件内部功能仍可按名称使用，设置中仍可管理 |

内置角色为 `default`（普通对话默认参考）、`heavy`（强推理）、`fast`（速度与成本敏感）、`smart`（架构建议与决策咨询）、`utility`（标题命名等内部功能，默认隐藏）。内置角色不可删除，其余字段可编辑；用户可增删自定义角色。`utility` 未配置可用模型时不可用，不自动回退到对话模型。

## 代理配置

所有代理共用 agent 配置，规定职责、提示词、工具策略和委派范围，并引用模型角色作为默认模型参考：

| 配置内容 | 作用 |
| --- | --- |
| 名称、描述、任务示例、选择条件 | 让用户与委派方知道何时选择此 agent |
| 系统提示词 | 规定职责、工作方式与输出要求 |
| 模型角色引用 / 备用模型角色 | 提供默认模型与思考等级（允许调用覆盖）及备用参考 |
| 工具允许列表或排除列表 | 限定独立工具目录中的二级工具，两种策略互斥；允许列表为空表示无资源工具，一级宿主入口仍可用 |
| 可委派代理列表 | 限定能创建哪些子代理，与自身工具策略一起生效 |
| 启用状态、超时与轮次 | 管理配置可用性及单次循环的 `timeout`、`maxTurns` 限制 |

内置 agent 为 `worker`（默认）、`explorer`、`reviewer`、`researcher`、`advisor`（使用 `smart` 角色）。agent 可删除，删除内置 agent 后不自动重现。只读代理（如 `advisor`）受工具策略、委派范围与资源执行层授权三重约束，不能通过创建可写代理或切换强模型绕过限制。

## 内置定义与用户覆盖

模型角色与代理配置统一采用「内置原始定义 + 用户局部覆盖 → 最终生效配置」：

| 配置类型 | 未覆盖字段的继承基准 |
| --- | --- |
| 同名内置模型角色 / 代理 | 该项的内置原始定义 |
| 自定义模型角色 | 内置原始 `default` |
| 自定义代理 | 内置原始 `worker` |

基准永远取内置原始定义，不读取其他项的最终视图（修改用户的 `worker` 或 `default` 不会连带改变自定义项）。用户存储只记录显式覆盖字段；提示词留空或清空表示撤下覆盖、恢复内置值，`false`、空列表与表示继承的 `null` 保留各自业务含义。工具允许／排除列表作为一组互斥策略整组替换。

每次模型请求开始时按当前选择读取最新配置并解析本次环境，不将配置正文存入对话历史。删除提供商、模型、角色或 agent 不做跨配置外键拦截或级联清空，下一次请求解析发现缺失或停用时明确失败。
