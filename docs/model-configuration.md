# 提供商、模型角色与代理配置

本文定义全局提供商、具体模型、模型角色与代理配置的结构、发现、继承及消费语义。

## 设置职责

| 设置分类 | 管理内容 | 消费方 |
| --- | --- | --- |
| 提供商 / Providers | 连接、协议、端点、凭据、共用兼容包，以及连接下的具体模型、能力和生成参数 | 模型接入与连接测试 |
| 角色 / Roles | 模型角色配置表：模型引用、思考等级、启用、用途描述、隐藏 | 代理配置与需要模型的功能模块 |
| 代理 / Agents | agent 配置：提示词、工具策略、可委派代理、模型角色引用等 | 每个代理的每次请求 |

提供商下的具体模型决定服务端模型 ID、能力和温度等生成参数。模型角色引用具体模型，负责复用选择与思考等级，不另存一套温度等上游参数。相同服务端模型 ID 可能出现在不同连接下，引用必须能确定实际使用的连接。

四类全局配置保存于应用数据目录的 `configuration.json`，独立于会话数据库；角色与 agent 只保存用户覆盖及身份。配置文件仅首次创建时初始化，已有文件的删除状态保留；损坏或不支持的文件不自动重置。密钥由独立加密文件保存，配置只持有引用（见 [技术架构](architecture.md#存储归属与全局配置)）。

模型角色与代理配置都是可编辑的配置记录。工作台上的代理对象是采用配置创建的执行实例；模型角色不成为卡片、资源或独立执行对象。普通对话界面选择 agent 和具体模型，不增加一层模型角色操作流程。

## 提供商预设

预设组合连接配置与编辑规则，不附带模型、模型能力或思考等级。目录由插件贡献，内置插件目录定义于 `packages/builtin/src/providers/presets.ts`；宿主只拥有目录校验与消费机制。预设声明名称、协议、端点、鉴权、共用兼容包、账户用量查询、固定字段、凭据页面，以及核实这些配置的资料和日期。不同地区、按量与订阅产品分别声明独立预设，即使端点相同也不混用凭据说明；不把消费者订阅视为 API 凭据。

选择器依次按按量计费（`usage`）、订阅（`subscription`）、不计费（`none`）分组，不按厂商分组，空组不显示。搜索跨组匹配名称、地区、套餐与计费说明；卡片只显示名称及地区／套餐细节，自定义连接独立放在末尾。

预设是普通连接的组合模板。选择入口一次性深复制连接值、兼容条目和编辑规则，打开与空白自定义连接相同的编辑器。连接不保存提供商类型 `kind` 或预设身份；编辑与执行均不根据品牌、名称、ID 或端点反推预设。目录 ID 按量采用厂商 slug，订阅追加 `-plan`，地区后缀放最后（如 `kimi / kimi-plan / kimi-cn / kimi-plan-cn`）；重复添加同一预设时默认连接 ID 追加未占用数字后缀。保存不持久化计费标签或资料来源；目录更新不修改已保存连接及其引用，执行端继续消费连接自身的协议、鉴权和兼容组合。

插件可以新增预设，或按预设 ID 修改已有预设的名称、连接配置及编辑规则，包括把 `usage` 指向自己的查询提供方。设置选择器读取当前成功加载的目录；修改只作用于后续新建草稿，不改写既有连接。贡献顺序、依赖、冲突与撤销规则见 [提供商贡献](plugin-sdk.md#提供商贡献与账户用量api-92)。

### 连接编辑规则

连接以可选的 `fixedFields` 保存固定配置项，有限取值为 `protocol / baseUrl / auth / compatibility / usage`，不得重复；缺省或空列表表示全部可编辑。规则与连接值共同持久化，不依赖预设目录。自定义连接与没有规则的既有连接保持自由配置。

- **通用编辑器**：只根据字段规则隐藏固定项，不展示禁用控件或按提供商品牌分支；认证控件根据认证方式呈现。当前内置预设固定上述五项，名称、提供商 ID、启用状态、凭据和模型的普通参数仍可编辑。固定协议也不出现在连接列表和详情标题的技术摘要中。
- **认证与凭据**：固定 `auth` 只固定认证方式，API key 的填写、更换和清除保持可用；密钥继续经独立凭据命令保存，不进入连接配置或编辑规则。
- **兼容设置**：固定 `compatibility` 时，提供商与其模型都不展示兼容编辑器。模型不能新建或修改自己的兼容覆盖；普通参数、获取参数与连接测试不受影响。兼容条目仍按既定合并规则消费，不根据编辑规则改写请求。
- **保存边界**：新建时接收连接的配置与规则；后续保存不允许更改固定项或固定字段集合，依据已保存连接校验，不查询预设目录。模型保存同样检查所属连接的兼容编辑限制。拒绝修改时配置与原凭据不变，名称和身份调整不丢失规则。

预设固定的配置值由连接自身保存；需要其他端点、协议或兼容组合时使用自定义连接，不提供解除固定或切换预设入口。规则仅管理应用中的配置编辑，不构成凭据或资源执行授权。

工坊通过提供商预设提供已核实的连接与兼容配置。自定义提供商的协议、端点与兼容包由用户依据其上游要求自行选择和配置；不提供独立的模型级兼容推荐或自动匹配入口。模型发现与参数获取沿用各自的字段范围，不推断或自动添加兼容包。

### 内置目录

优先使用 Responses；Anthropic 使用原生 Messages。聚合服务对同一计费产品与地区默认只提供一个预设，支持 Responses 时优先选择；只有不同端点对应不同模型集合时才拆分提供商。当前目录包含 OpenAI、Anthropic、DeepSeek、xAI、OpenRouter、OpenCode Console／Go，以及 Kimi 和智谱／Z.ai：
- **OpenRouter / OpenCode Console**：分别使用 `https://openrouter.ai/api/v1` 与 `https://opencode.ai/inference/v1` 的单一 Responses 入口（Zen 保留为搜索别名）。
- **OpenCode Go**：预设 ID 为 `opencode-plan`，使用 `https://opencode.ai/inference/go/v1` 的 Responses 入口，显式带入 `opencodeSession` 兼容包。
- **Kimi**：按量提供国内 `api.moonshot.cn/v1` 与国际 `api.moonshot.ai/v1`；Kimi Code 订阅提供国内 `api.kimi.com/coding/v1` 与国际 `api.kimi.ai/coding/v1`；预设通过 `responsesReasoning` 省略未支持的 `encrypted_content` include 与 `reasoning.summary` 请求字段。
- **智谱／Z.ai**：国内 `open.bigmodel.cn/api/v1` 与国际 `api.z.ai/api/v1` 各提供按量与 Coding Plan 预设，共用单对象 `content` 编码并省略上述两个请求字段。

订阅入口标明仅限受支持客户端；预设不代表 Atelier 已获厂商客户端准入，不伪装其他工具身份。

## 账户用量

连接以可选的 `usage` 引用查询提供方的目录 ID，`null` 或缺省表示关闭。预设 ID 与对应查询 ID 可以同名，例如 `zai-plan-cn`；关联由预设的 `connection.usage` 显式建立，连接改名和重复添加不改变查询引用。自定义连接从已加载的查询目录选择；已保存的失效引用保留并标明不可用，不按端点、名称或其他提供方自动回退。

账户用量独立于模型响应的 token usage 和按参考价格计算的费用。查询提供方只收到本次连接的身份、端点、凭据与取消信号；消费者只取得归一化结果，不取得凭据。查询和预设提供方、消费方可来自不同插件；SDK 作者接口见 [提供商贡献](plugin-sdk.md#提供商贡献与账户用量api-92)。

### 结果结构

一次查询返回结果项列表，各项持有稳定 `id`、可本地化名称和 `account / plan / key` 作用范围。列表可同时包含多个余额与多个额度窗口，条目身份不得重复：

- **`balance`**：`remaining` 为剩余金额，`currency` 为三字母币种；可以表达负余额。不伪造限额、百分比或重置周期。
- **`quota`**：每项对应一个窗口，`value` 为剩余额度。`ratio` 直接表达 0–1 的剩余比例；`quantity` 表达剩余量、正数上限与单位，剩余不得超过上限，展示比例由数量派生。百分比不得伪装成 token 或金额。
- **窗口**：`mode` 为 `rolling / fixed / unknown`；已知固定时长用 `durationMs`，无法确定则为 null；`resetAt` 为上游报告的毫秒时间戳或 null。周期长度与下一次重置时间独立，未知周期不按倒计时推断，也不把自然月折算成固定天数。

查询状态包含连接身份与修订、查询 ID、`disabled / loading / ready / error`、结果项、最近成功时间与错误类别。成功的空列表表示未报告额度，不等于查询失败；错误不借用空列表或零余额表达。消费者展示规则见 [账户用量工具栏](workbench.md#账户用量工具栏)。

### 查询生命周期

运行时按连接及修订共享在途请求和短期结果，不跨连接合并账户。每次查询固定连接与凭据，整次请求最多等待 10 秒，不隐式尝试其他地址、鉴权方式或重试。提供方仍受插件真实收束约束：超时取消不表示其处理器已经退出。

结果仅在内存缓存，60 秒内普通读取复用最近查询状态，显式刷新可以重新查询；刷新失败保留同一修订的上次成功数据并记录错误。连接、凭据或查询方式修改、连接删除和提供方撤销均使旧结果失效，迟到结果不能重新交付旧账户数据。重置时间到达后仍以远端下一次实报为准，不在本地把额度恢复为满额。

### 内置查询目录

内置查询与支持的预设同名绑定，使用当前连接 origin 下的明确路径。智谱／Z.ai 使用裸 `Authorization`，其余使用 Bearer；均复用连接凭据、禁止重定向，不在失败后改发官方站点。自定义代理需实现所选查询方式要求的路径。

| 查询 ID | 返回内容 | GET 路径与依据 |
| --- | --- | --- |
| `deepseek` | 各币种的账户总余额 | `/user/balance`；[官方接口](https://api-docs.deepseek.com/api/get-user-balance) |
| `kimi-cn / kimi` | Moonshot 账户可用余额，分别为 CNY / USD | `/v1/users/me/balance`；[国内](https://platform.kimi.com/docs/api/balance)、[国际](https://platform.kimi.ai/docs/api/balance) |
| `openrouter` | 当前 key 的有效预算；管理 key 另取得账户余额 | `/api/v1/key`，管理 key 再读 `/api/v1/credits`；[key 与预算](https://openrouter.ai/docs/api_reference/limits)、[credits](https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits) |
| `opencode-plan` | Go 的 5 小时、每周与每月窗口 | `/zen/go/v1/usage`；[官方套餐说明](https://opencode.ai/docs/go/)、[查询路由](https://github.com/anomalyco/opencode/commit/2b8a5969e932c15083e599c82d34ce0268f81b9e) |
| `kimi-plan-cn / kimi-plan` | Kimi Code 周汇总及返回的额度窗口 | `/coding/v1/usages`；[官方讨论中的响应](https://forum.moonshot.ai/t/error-code-429-were-receiving-too-many-requests-at-the-moment/191/7)、[地区入口](https://www.kimi.ai/help/kimi-code/membership-guide) |
| `zai-plan-cn / zai-plan` | 智谱／Z.ai Coding Plan 额度窗口 | `/api/monitor/usage/quota/limit`；复用已核实的接口结构 |

- **余额**：DeepSeek 的 `total_balance` 已包含充值和赠送部分，按各币种独立显示；Moonshot 使用 `available_balance`，币种由所选地区查询方式确定，不重复累加子余额。
- **OpenRouter**：`effective_budget` 存在时优先消费，否则使用当前 key 的 `limit_remaining`；有周期及限额时表达为 quota，无周期金额预算表达为 `scope: key` 的 balance。普通 key 不请求需要管理权限的 credits 接口；不限额且没有有效预算时返回空列表，不伪造账户余额。只有 `/key` 明确报告 `is_management_key: true` 时才查询 `total_credits − total_usage`，作为独立账户余额返回。
- **OpenCode Go**：把各窗口的已用 `percent` 转为剩余比例；滚动窗口为 5 小时，周窗口按服务端的 UTC 周重置，月窗口以订阅日期为基准。自然月的 `durationMs` 留空，重置时间沿用远端。按量 OpenCode Console 不借用 Go 查询。
- **Kimi Code**：接受数字或数字字符串的额度数量，优先采用明确的 `remaining`，否则由 `limit − used` 求得；单位标为额度单位，不推断成 token 或请求数。周汇总优先于重复的周窗口，等价周期只显示一次，月周期不折算成固定天数。未知周期保留名称、额度和已报告重置时间。额外充值钱包 `boosterWallet` 暂未适配；国际端点依据官方地区入口与已知客户端实现，接口本身仍属未正式文档化的查询。
- **智谱／Z.ai**：读取 `data.limits` 中的 `TOKENS_LIMIT / CREDIT_LIMIT`，把已用 `percentage` 转为剩余比例，`nextResetTime` 按毫秒读取。`unit: 3` 为小时，`unit: 6` 为每周；每周的 `number` 有 1/7 两种已知形态，不解释成周数。未知周期保留额度及真实重置时间，`TIME_LIMIT` 工具预算不混入模型套餐额度。

OpenAI、Anthropic、xAI、OpenCode Console 和智谱／Z.ai 按量预设未绑定账户查询。推理响应的 TPM/RPM 限流余量不作为套餐额度接入。新增预设默认值只影响后续创建，既有连接不自动改写。

## 模型发现与添加

保存提供商连接后，用户在模型区点击「获取模型」，使用已保存的 API 基础地址与鉴权获取候选列表（连接草稿有修改时先保存）。各消息协议均请求基础地址下的 `GET /models`，保留已有路径，不固定替换成域名根部 `/v1/models`，也不探测其他地址。请求头沿用连接约定：OpenAI Responses／Chat Completions 使用 Bearer 鉴权，Anthropic 使用自身版本头与 `x-api-key`；无鉴权连接不发送凭据。

模型列表格式与消息协议独立，按响应结构自动识别，不按提供商、域名或所选消息协议绑定解析器，也无需用户另选列表协议。当前支持：

- **OpenAI 风格**：`data[].id` 提供模型身份。
- **Anthropic 风格**：同样使用 `data[].id`；条目的 `type: model`、`display_name`、`max_input_tokens` 或 `capabilities` 中的 `thinking / effort` 标识其元数据，另读取显示名、输入上限、思考能力与明确支持的 effort 等级（`off` 只在端点声明支持 `thinking.types.disabled` 时加入）。
- **Codex 风格**：`models[].slug` 提供模型身份，`display_name` 提供可选显示名；其余字段未适配，不导入客户端指令、工具配置或能力参数。

识别仅限已适配的结构；未知结构、同时包含两种列表容器、条目身份无效或已识别元数据损坏均报响应格式错误，不尝试其他解析路径掩盖错误，不交付部分目录。空的 `data` 或 `models` 数组是合法空列表。新增格式依据官方文档或真实响应样本扩充独立解析器。

请求在后台运行，支持取消、30 秒整次超时和明确刷新，无隐式重试。分页按同一端点的 `has_more / last_id` 游标继续获取，全部成功后交付去重列表；分页失败不交付部分目录。候选支持搜索与多选添加，已添加项不可重复选择。

只采用端点明确返回且已适配的资料，不按模型名称推断能力。未返回或未适配的参数沿用手动新建初始值：思考与工具调用开启、可选思考等级全开、上下文与生成参数未设置。选中的模型在一次原子保存中加入，不覆盖已有模型；发现列表仅在内存保留，修改或删除连接使其失效。

## 从 models.dev 获取参数

「获取参数」只在已保存模型的设置页表单提供。点击后通过官方 `@opencode-ai/models` 客户端请求公开目录（无凭据、禁止重定向、10 秒超时、无隐式缓存），覆盖该模型的可映射参数并立即原子保存，不区分旧值来源；失败、无精确匹配或匹配有歧义时保留原值并提示。

- **覆盖范围**：`limit.context` → `contextWindow`；`limit.output` → `maxOutputTokens`；`reasoning` 与 `tool_call` 开关；`reasoning_options.effort`（全部值可映射且非空时替换等级集合，`none`/null 对应 `off`；无法直接表示时保留原等级并提示人工检查；不支持思考时关闭思考并清空等级）。缺失或占位零值的 token 限制保留原值。模型身份、显示名、启用状态、连接与兼容设置不在覆盖范围。
- **精确检索规则**：仅在查询时从服务端 `modelId` 取最后一个 `/` 后的部分（去掉厂商／路由前缀），与目录模型标识做同样处理后精确比较（大小写、连字符与后缀不变，不模糊匹配，连接地址与提供商 slug 不参与消歧）。匹配后读取原模型记录（缺失时取底层模型资料），不采用中转站参数覆盖。保存与实际请求继续携带完整服务端 `modelId`。
- **价格映射**：原模型记录的 `cost` 转换为下节的工坊价格结构，成功后整项替换；目录无价格、数据无效或包含无法表达的价格规则时保留整项旧价格，并在未填字段中提示，不影响其他有效参数的更新。标准 `tiers` 优先于旧 `context_over_200k`，阈值排序后保存；重复阈值拒绝转换。目录没有提供的分项单价写为未知，不继承基础价，也不保留被替换价格中的旧分项。

## API 参考价格

具体模型的 `cost` 是应用自有的价格配置，独立于模型协议与上游 `Usage`，不随请求发送。它描述用于估算的 API 参考价，不表示订阅扣款、中转站实际收费或账户余额。价格可手动编辑，也可通过「获取参数」填入；既有配置缺少此字段时读取为 `null`，不自动写回文件。

| 字段 | 语义 |
| --- | --- |
| `cost: null` | 未配置价格 |
| `currency` | 价格表的统一币种，固定为 `USD`；模态和计费项不另设币种 |
| `rates` | 基础价格，按 `text / image / audio / video` 模态组织 |
| 模态内的计费项 | `input / output / cacheRead / cacheWrite / reasoning`，各项独立保存价格，缺项或 `null` 表示未知 |
| 单项价格 | `{ amount, unit, per }`：每 `per` 个 `unit` 的金额为 `amount`；金额为有限非负数，`0` 表示免费 |
| `unit / per` | 单位为 `token / image / second`，基数为有限正数；例如每百万 token、每张、每 60 秒 |
| `tiers` | 按 `fromInputTokens` 严格递增的档位列表；每项包含独立完整的 `rates`，空列表表示固定价格 |

模态与单位是独立维度，同一模态的不同计费项可以采用不同单位。例如 `image.input` 按百万 token 定价，`image.output` 按张定价，`audio.input` 按 60 秒定价；不能由模态推断单位。基础价和每个档位使用同一结构。设置按模态分组，每项可编辑金额、单位和基数。

价格字段由工坊定义，外部目录只提供其中可映射的资料。models.dev 的普通输入／输出、缓存与思考价映射到 `text`，`input_audio / output_audio` 映射到 `audio` 的输入／输出；这些目录价格统一显式标为 `unit: token, per: 1000000`，不换算金额。未提供的模态和计费项保持未知，不从文本单价推断图片、音频或视频价格。

已有配置的平铺价格仅在存储边界转换：普通输入／输出、缓存与思考归入 `text`，图片／音频／视频输入输出归入各自模态，原金额保留并显式标记为每百万 token；未知值和所有档位保持语义。读取不重写原文件，后续显式保存使用新结构。公共配置契约只接受按模态组织且包含单位的价格。

分档依据是单次请求输入 token 总量（含缓存）。`fromInputTokens` 为非负安全整数且含边界，达到多个起点时取最高档，否则取基础价；选中档位的整套单价适用于整次请求，不进行分段累进，档内未知单价不从基础价继承。models.dev 的 `tiers[].tier.size` 映射为该起点；仅有旧 `context_over_200k` 时转换为起点 `200001`。外部字段名、目录类型和特殊兼容字段仅存在于导入转换边界，不进入价格配置。

费用是既有请求用量与当前价格的派生结果，不属于上游 usage，也不另存消费账本或历史价格快照。逐请求选取实际模型和档位后才能汇总，不能先汇总用量再套价；修改价格会改变历史请求的参考估值，展示须说明按当前价格估算。每项费用依据匹配模态、计费项及单位的数量按 `数量 / per × amount` 求得，不能以 token 数代替张数或秒数；价格配置不代表已经具备对应单位的用量。未知价格或缺失用量不能当零费用。思考、各模态和缓存分项的保存不表示可以与输入／输出总量直接相加，消费者须依据用量口径避免重复计费。

### 已报告用量的费用消费

- **模型定位**：优先使用响应 `source.scope` 保存的实际提供商和模型身份读取当前价格；仅有模型表达式的历史须唯一匹配完整表达式或其标准思考等级后缀，不任意截断模型名中的冒号。停用模型仍可提供参考价格；删除或匹配有歧义时价格未知，不借用当前对话所选模型。
- **输入拆分**：已报告 `input` 包含缓存读取／写入量，普通文本输入量为 `input − cacheRead − cacheWrite`。缺失子项时不补零，无法确定的余量保持未知；总量为零且无矛盾子项时，可确定各子项为零。已知子项之和超过总量时，整个拆分组标为无效。
- **输出拆分**：`output` 包含思考量。选中价格档位明确提供 `text.reasoning` 时，按 `output − reasoning` 和 `reasoning` 分别计价；没有独立思考价时，输出总量按输出价计算一次，不额外计思考费。有独立价格却缺少数量时保持未知。
- **模态与单位**：现有模型协议只提供 token 总量与缓存／思考细分。历史输入仍含文件或无法确定模态时，文本输入计费数量统一视为未知，不从总量推断模态细分；没有张数、时长或模态细分，就不能消费相应价格。压缩只改变后续请求的输入投影，不移除此前请求的费用。
- **完整性**：结果区分完整估算、已知部分和未知。正数量缺少单价、数量未知、计价单位不一致或有分档却缺少输入总量时，对应项不能计算；同单位的已知零数量不需要单价，但零 token 也不能替代零秒或零张。已知部分仅汇总可计算项，并显式标记资料不完整；既无可计价的正数量、也不能证明总消费为零时，金额显示未知。浮点结果仅用于参考估值，展示舍入不回写用量或价格。

## 输入能力与思考等级

具体模型的能力声明 `reasoning`、`thinkingLevels` 与 `tools`。输入模态属于服务端能力，不在客户端配置：文件（首批适配 JPEG、PNG、GIF、WebP、PDF）按 `mediaType` 如实发送，由服务端反馈是否接受（见 [模型输入与协议适配](runtime.md#用户输入文件与模型协议适配)）。

标准思考等级全局统一为 `off / minimal / low / medium / high / xhigh / max`（`xhigh` 与 `max` 的公共身份独立，不隐式互换）。模型的 `thinkingLevels` 保存可用等级集合，新建时全开，空集合合法；关闭思考总开关保留集合与已有选择。选择器只提供可用等级，配置保存与选择传递不拦截等级可用性。

请求末端解析模型和等级继承后校验：`reasoning: true` 时，最终等级为空或不在可用集合中均以 `thinking_unavailable` 失败，不自动降档；`reasoning: false` 时省略等级及历史思考部件；`off` 是普通等级，不触发历史过滤。所有情况下均正常接收、保存和展示服务端返回的思考。

### 思考等级与预算映射

标准等级是角色、对话选择与历史的公共值；effort 字符串和思考预算只在请求编码时生成，不回写公共等级。协议适配自带默认映射，兼容包仅覆盖映射值，不选择或切换思考模式。

- **等级映射**：Responses 编码 `reasoning.effort`，Chat 编码 `reasoning_effort`；默认 `off` 为 `none`，其他等级同名。Anthropic 自适应思考编码 `output_config.effort`，默认 `minimal` 为 `low`，其他非 off 等级同名；手动预算模式默认不附带 effort。Anthropic 的 `off` 编码 `thinking.type: disabled`，默认省略 effort。
- **`customThinkingLevels`**：以标准等级为可选键，值为去除首尾空白后的非空上游字符串，`null` 明确省略 effort，缺项使用协议默认。手动预算模式也可通过显式条目附带 effort；省略 effort 不等于关闭思考。模型不接受某等级时，应从可用集合中移除；不自动降级，不将服务端拒绝解释成切换协议或重试的信号。
- **默认预算**：Anthropic 的手动预算模式无需兼容包即可使用。按本次有效总输出上限 `L` 乘下表比例、向下取整并至少取 1024 tokens；`L` 使用调用方与模型配置取较小值后的上限，两者均未设置时固定为 4096 tokens，不从 SDK 已叠加预算的请求字段反推。工坊的输出上限包含思考，不再额外叠加预算。

| 标准等级 | minimal | low | medium | high | xhigh | max |
| --- | --- | --- | --- | --- | --- | --- |
| 默认预算占总输出上限的比例 | 2% | 10% | 30% | 60% | 90% | 95% |

- **`customThinkingBudgets`**：以非 off 标准等级为可选键，值为至少 1024 的安全整数，直接指定绝对 token 数；缺项使用内置比例。预算必须小于 `L`，不满足时在 HTTP 发送前以 `thinking_budget_unavailable` 拒绝，不静默缩小预算。`off` 不属于预算映射，不能表示为零预算。
- **模式识别**：Anthropic 自适应／手动预算模式仍由 SDK 的模型适配识别；预算包仅在手动预算模式消费，不将 adaptive 模型强制切为 enabled。宿主在最终 HTTP 正文应用等级和预算映射，避免 SDK 删除自定义字符串、改写等级或扩大输出上限；不开放任意请求补丁。
- **配置覆盖**：先按下节规则确定生效兼容包，再将其显式条目覆盖到协议默认映射；模型包的缺项不继承提供商同名包的值。空对象表示使用协议默认映射，`null` 只作为等级包内部的 effort 省略值，不是兼容包禁用标记。
- **消费范围**：对话、命名和摘要共用请求编码；连接测试保持最小连通性请求，不消费等级或预算映射。`reasoning: false` 时两张映射均不参与请求。

## 模型引用与模型目标

提供商与具体模型一律以可读 slug 引用，不以随机记录 ID 对外引用：
- **提供商 ID**：用户可编辑的 slug，不含 `/`。
- **模型 ID**：发往服务端的模型名，可含 `/`；显示名仅供阅读。
- **模型表达式（`ModelExpression`）**：`<providerId>/<modelId>`，结构化为 `{ provider, model }`，按第一个 `/` 切分。思考等级不属于模型表达式（记录用串可附加 `:<thinking>`）。

请求以模型目标 `ModelTarget = { role, model?, thinking? }` 表达选择：给出的字段覆盖角色，未给出的沿用角色。代理选择 `AgentSelection = { agent, model, thinking }` 允许 `model / thinking` 为 null，转换为 `ModelTarget` 时省略相应覆盖。最终仍无模型，或角色／模型／凭据不可用时，分别以 `role_unavailable`、`model_unavailable`、`credential_unavailable` 明确失败；非空失效引用不降级为继承。

## 模型兼容包

兼容包是应用预定义、数量有限的行为声明（定义于 `src/shared/model-compatibility.ts`），包含稳定 `id`、参数 `schema` 与仅供 UI 参考的 `appliesTo`（协议／端点列表，不用于自动启用或运行时匹配）。不加载用户 patch 或 processor。

提供商与具体模型分别以 `compatibility` 保存稀疏列表（标签型 `{ id }`，参数型 `{ id, value }`）。提供商条目对连接下所有模型生效；请求时按 `id` 合并，模型同名条目**整项覆盖**提供商条目（不逐字段深合并，省略的可选字段不从提供商补齐；不支持模型单独禁用提供商条目或使用墓碑）。合并结果不回写配置。

配置是否可编辑由[连接编辑规则](#连接编辑规则)决定，不改变兼容条目的执行语义。

正式目录包含七项：
- `systemMessageInMessages`（标签）：将 Responses 系统提示从 `instructions` 改为首条 `system` 消息。
- `toolFilesAsUserMessage`（标签）：允许 Chat Completions 将工具结果文件搬运到后续 `user` 消息。
- `responsesReasoning`（参数）：适配 Responses 明文 `content` 的 array/object 形状，以及是否请求 `encrypted_content` 和 `reasoning.summary`。
- `customUserAgent`（参数）：以必填 `userAgent` 覆盖 HTTP 客户端身份头。
- `opencodeSession`（标签）：将本次请求的会话 ID 写入 `x-opencode-session`。
- `customThinkingLevels`（参数）：自定义标准等级对应的上游 effort，见[思考等级与预算映射](#思考等级与预算映射)。
- `customThinkingBudgets`（参数）：覆盖手动思考的 token 预算，见[思考等级与预算映射](#思考等级与预算映射)。

具体协议投影规则见 [三协议编码与跨模型续接](runtime.md#三协议编码与跨模型续接)。

## 模型角色

| 字段 | 含义 |
| --- | --- |
| 模型引用 | 指向提供商下的具体模型；可为空，继承发起调用的当前对话模型 |
| 思考等级 | 可为空，继承当前对话的思考等级；空值与明确关闭思考（`off`）不同 |
| 启用 | 停用后在软件内不可用，代理、功能模块与对话均不能选用或解析，只在设置中保留 |
| 用途描述 | 说明角色适合什么工作，供用户理解和功能、代理选择 |
| 隐藏 | 不向代理开放为可选择的模型角色；软件内部功能仍可按名称使用，设置中仍可管理 |

内置角色为 `default`（普通对话默认参考）、`heavy`（强推理）、`fast`（速度与成本敏感）、`smart`（架构建议与决策咨询）、`utility`（标题命名等内部功能，默认隐藏）。内置角色不可删除，其余字段可编辑；用户可增删自定义角色。`utility` 未配置可用模型时不可用，不自动回退到对话模型。

## 代理配置

所有代理共用 agent 配置，规定职责、提示词、工具策略和委派范围，并引用模型角色作为默认模型参考：

| 配置内容 | 作用 |
| --- | --- |
| 名称、描述、任务示例、选择条件 | 让用户与委派方知道何时选择此 agent |
| 系统提示词 | 规定职责、工作方式与输出要求 |
| 模型角色引用 / 备用模型角色 | 提供默认模型与思考等级（允许调用覆盖）及备用参考 |
| 工具允许列表或排除列表 | 限定独立工具目录中的二级工具，两种策略互斥；允许列表为空表示无资源工具，一级宿主入口仍可用 |
| 可委派代理列表 | 限定能创建哪些子代理，与自身工具策略一起生效 |
| 启用状态与请求次数 | 管理配置可用性及单次循环的 `maxTurns` 限制；执行期限见 [运行时](runtime.md#执行轮次与循环) |

内置 agent 为 `worker`（默认）、`explorer`、`reviewer`、`researcher`、`advisor`（使用 `smart` 角色）。agent 可删除，删除内置 agent 后不自动重现。只读代理（如 `advisor`）受工具策略、委派范围与资源执行层授权三重约束，不能通过创建可写代理或切换强模型绕过限制。

## 内置定义与用户覆盖

模型角色与代理配置统一采用「内置原始定义 + 用户局部覆盖 → 最终生效配置」：

| 配置类型 | 未覆盖字段的继承基准 |
| --- | --- |
| 同名内置模型角色 / 代理 | 该项的内置原始定义 |
| 自定义模型角色 | 内置原始 `default` |
| 自定义代理 | 内置原始 `worker` |

基准永远取内置原始定义，不读取其他项的最终视图（修改用户的 `worker` 或 `default` 不会连带改变自定义项）。用户存储只记录显式覆盖字段；提示词留空或清空表示撤下覆盖、恢复内置值，`false`、空列表与表示继承的 `null` 保留各自业务含义。工具允许／排除列表作为一组互斥策略整组替换。

每次模型请求开始时按当前选择读取最新配置并解析本次环境，不将配置正文存入对话历史。删除提供商、模型、角色或 agent 不做跨配置外键拦截或级联清空，下一次请求解析发现缺失或停用时明确失败。
