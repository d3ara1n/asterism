# 提供商、模型角色与代理配置

本文定义配置与消费语义。提供商、具体模型、模型角色、agent 配置和连接测试已实现，首页可选择 agent、模型和思考等级；单代理执行及前端能力接口已实现，首页发送与代理对话视图已接通，真实端点与 GUI 验收已确认（2026-10-13），实施记录见 [模型接入计划](../plans/archived/todo-2026-10-01-model-protocol-storage.md)。

## 设置职责

| 设置分类 | 管理内容 | 消费方 |
| --- | --- | --- |
| 提供商 / Providers | 连接、协议、端点、凭据、共用兼容包，以及连接下的具体模型、能力和生成参数 | 模型接入与连接测试 |
| 角色 / Roles | 模型角色配置表：模型引用、思考等级、启用、用途描述、隐藏 | 代理配置与需要模型的功能模块 |
| 代理 / Agents | agent 配置：提示词、工具策略、可委派代理、模型角色引用等 | 每个代理的每次请求 |

提供商下的具体模型决定服务端模型 ID、能力和温度等生成参数。模型角色引用具体模型，负责复用选择与思考等级，不另存一套温度等上游参数。相同服务端模型 ID 可能出现在不同连接下，引用必须能确定实际使用的连接。

四类全局配置保存于应用数据目录的 `configuration.json`，独立于会话数据库；角色与 agent 只保存用户覆盖及身份。配置文件仅首次创建时初始化，已有文件的删除状态保留；损坏或不支持的文件不自动重置。密钥继续由独立加密文件保存，配置只持有引用。具体文件格式与保存职责见 [技术架构](architecture.md#提供商配置)。

模型角色与代理配置都是可编辑的配置记录。工作台上的代理对象是采用配置创建的执行实例；模型角色不成为卡片、资源或独立执行对象。普通对话界面选择 agent 和具体模型，不增加一层模型角色操作流程。

## 输入能力

具体模型的能力声明 `reasoning`、`thinkingLevels` 与 `tools`。`reasoning` 决定当前请求是否发送思考等级和历史思考内容，`tools` 决定是否发送工具声明。输入模态属于服务端能力，不在客户端配置：文件按 mediaType 如实发送，端点是否接受由服务端反馈。

标准思考等级全局统一为 `off/minimal/low/medium/high/xhigh`，定义不随提供商或兼容设置改变。模型的 `thinkingLevels` 保存可用等级集合，新建时全开，空集合合法；设置页以能力卡片承载思考总开关，内部用紧凑复选框组逐项增减等级，并说明保存后生效、具体等级在对话或模型角色中选择。空集合显示使用提示，不阻止保存。关闭总开关保留集合与已有选择。选择器只提供可用等级，不自动改写失效选择；配置保存与选择传递不检查等级可用性。

请求末端先解析模型和等级的继承：模型缺失或不可用时明确失败；`reasoning:true` 时，最终等级为空或不在集合中均以 `thinking_unavailable` 失败，不自动降档。`reasoning:false` 时，等级不参与校验，当前请求省略等级及历史思考部件。`off` 是普通等级，只按协议编码，不触发历史过滤，也不保证服务端不生成思考。所有情况下都正常接收、保存和展示服务端返回的思考。输入过滤不修改历史或展示，重新开启能力后下一请求可重新携带历史思考。

首批适配编码覆盖 JPEG、PNG、GIF、WebP 和 PDF。模型声明与协议编码支持共同决定本地是否允许发送，端点的实际格式拒绝仍作为请求错误报告。首期不自动 OCR、转码或拆页。完整内容引用与作用域规则见 [模型输入](conversation-core.md#用户输入与文件)。

## 模型引用

提供商与具体模型一律以可读 slug 引用，不以随机记录 ID 对外引用、保存或展示：

- 提供商 ID：用户可随时编辑的 slug，不含 `/`。
- 模型 ID：发往服务端的模型名，即全局共识的模型名，可含 `/`；显示名只供用户阅读。
- 模型表达式 `ModelExpression`：`<providerId>/<modelId>`，结构化为 `{ provider, model }`，两者必定成对；字符串按第一个 `/` 切分。思考等级不属于模型表达式，记录用串可附加 `:<thinking>`，如 `deepseek/deepseek-flash:medium`。

ID 可编辑、提供商与模型可删除，引用失效不可避免：保存的表达式保持原值，请求时找不到即明确失败，不级联改写引用方。

模型角色分别设置模型表达式与思考等级，均可为空。请求以模型目标 `ModelTarget = { role, model?, thinking? }` 表达“选择一个角色、可能覆盖模型或思考等级、把请求发给对应端点”：给出的字段覆盖角色，未给出的沿用角色。代理选择 `AgentSelection = { agent, model, thinking }` 的 model 与 thinking 均允许 null，转换为 ModelTarget 时省略相应覆盖，继续沿用代理所引用的角色。最终仍无模型才失败；非空失效引用不作为继承。角色停用或缺失、模型缺失、凭据不可用分别以 `role_unavailable`、`model_unavailable`、`credential_unavailable` 失败。宿主内部与插件 API 共用这组类型。

## 模型兼容包

兼容包是应用预定义、数量有限的行为声明，不加载用户 patch，也不作为 processor 执行。基础协议决定消息与工具的基础格式，模型能力描述支持什么，兼容包描述端点需要的请求编码、响应解码或历史投影差异；三者分别表达。定义包含稳定 id、schema 与适配协议；名称和说明直接取 schema 元数据原文，标签型无参数，参数型由 schema 生成编辑器。

提供商与具体模型分别以 `compatibility` 保存用户已添加的稀疏列表：标签型为 `{ id }`，参数型为 `{ id, value }`，初始为空列表。同一层内 id 不重复，未知 id 或不符合 schema 的参数不能保存。提供商条目对连接下所有模型生效，模型条目补充该模型的差异；请求时按 id 合并，同 id 由模型条目整项覆盖，不逐字段深合并。移除模型条目恢复使用提供商的同名条目；模型列表为空仍使用提供商条目。模型不能单独禁用提供商已添加的包，不使用 false/null 墓碑。两层分别保存，合并结果不回写配置；模型角色和 agent 不另存兼容配置。

参数必填性由各包 schema 声明；必填参数缺失不能保存，可选字段允许未设置，其省略行为由包定义，不代表禁用整个包。模型整项覆盖后，其中省略的字段不从提供商条目补齐。无参数标签以条目存在表示启用。

提供商与模型设置页均提供「添加兼容设置」，复用同一目录与参数编辑器。模型页只读展示来自提供商的条目；参数条目可复制为模型覆盖，已覆盖项标明来源，移除覆盖恢复提供商设置。已添加项可以编辑、移除，名称、参数与适用参考信息由定义目录驱动。schema 之外的 `appliesTo` 包含协议列表和可选端点列表，添加菜单与已添加项都展示。它只供用户参考，不阻止添加，也不提供自动启用或运行时匹配规则；协议编码器只解释其认识的已添加行为。内置目录可以推荐，是否添加由用户决定，不按品牌、域名或模型名自动启用。

每次请求取用当时提供商与模型的完整配置，统一合并兼容条目后消费，并与该请求及其工具批次保持一致；修改从下一次请求取用。声明本身不执行行为，协议投影按 id 消费适用条目，不能通过兼容设置重新开放模型已关闭的标准思考等级。连接测试保持最小 probe，不验证兼容行为；配置修改不改写历史。

正式请求消费已接入三个标签：`systemMessageInMessages` 将 Responses 系统提示从 instructions 改为第一条 system 消息；`thinkingInDeepSeekFormat` 将公共思考编码为明文 reasoning item；`toolFilesAsUserMessage` 允许 Chat 工具结果文件搬运到后续 user 消息。未添加时使用协议基线，不按域名自动启用。正常密文／签名续接、原始思考流读取与解码属于基线，不需要兼容标签；具体投影规则见 [模型适配](conversation-core.md#模型适配)。

正式目录仅包含上述三个标签，参数型定义与编辑能力保留；`customThinkingLevels` 编码暂缓。完整 GUI 与真实端点验收进度见 [模型兼容计划](../plans/todo-2026-10-10-model-compatibility.md)。

## 模型角色

| 字段 | 含义 |
| --- | --- |
| 模型引用 | 指向提供商下的具体模型；可为空，继承发起调用的当前对话模型 |
| 思考等级 | 可为空，继承当前对话的思考等级；空值与明确关闭思考不同 |
| 启用 | 停用后角色在软件内不可用，代理、功能模块与对话均不能选用或解析，只在设置中保留；比隐藏更严格 |
| 用途描述 | 说明角色适合什么工作，供用户理解和功能、代理选择 |
| 隐藏 | 不向代理开放为可选择的模型角色；软件其他功能仍可按名称使用，也不阻止用户在设置中管理 |

模型引用与思考等级分别解析空值，不因模型继承而强制覆盖思考等级。功能模块按角色请求模型，由统一解析能力返回实际模型与思考配置，避免各模块各自实现默认值和继承。

内置角色如下，初始模型引用可为空：

| 角色 | 用途 | 默认隐藏 |
| --- | --- | --- |
| `default` | 普通对话的默认模型参考 | 否 |
| `heavy` | 需要较强推理能力的工作 | 否 |
| `fast` | 对速度与成本敏感的工作 | 否 |
| `smart` | 基于证据的判断、架构建议与决策咨询 | 否 |
| `utility` | 标题命名、辅助整理，以及未来的记忆整理等内部功能 | 是 |

内置角色不能删除，其余设置允许用户编辑，包括模型、思考等级、启用、用途描述和可见性。用户可新增、编辑和删除自定义角色；自定义角色可供代理等功能引用。

`utility` 隐藏时，内部功能仍可按名称引用；代理不能将其作为自主选择或临时覆盖的模型角色。用户可以取消隐藏，使其进入可选范围。隐藏角色仍能在设置中找到和编辑，也不构成资源授权。停用角色不进入任何选择范围；已引用停用或隐藏角色的配置保留原值并标示不可选，请求时停用角色解析失败。

## 代理配置

所有代理共用 agent 配置，用户可以新增和编辑配置。配置规定代理的职责、提示词、工具策略和委派范围，并引用模型角色作为默认模型参考。

配置设计沿用 pi-subagent 的角色定义：

| 配置内容 | 作用 |
| --- | --- |
| 名称、描述、任务示例、选择条件 | 让用户与委派方知道何时选择此 agent |
| 系统提示词 | 规定职责、工作方式与输出要求 |
| 模型角色引用 | 提供默认模型与思考等级，允许本次调用覆盖 |
| 工具允许列表或排除列表 | 限定独立工具目录中的工具，两种策略互斥；允许列表为空表示无资源工具，宿主一级操作入口仍可用 |
| 可委派代理列表 | 限定能创建哪些子代理，与自身工具策略一起生效 |
| 启用状态、超时与轮次 | 管理配置可用性及执行限制 |
| 备用模型角色 | 表达备用配置；实际重试仍遵循工坊的执行与副作用契约 |

工具策略检查 `resource_call` 内的工具名，不检查 resource_list/inspect/call 等固定宿主入口。工具支持关系独立于白名单；链接后的工具暴露、inspect 和调用执行采用同一外部策略结果；资源操作仍须满足显式绑定与执行层授权。目录可见、模型角色选择或 agent 配置都不自动授予资源权限。

只读 advisor 直接与用户对话时，同样受只读工具和委派范围限制，不能通过创建可写代理绕过限制。切换为更强的模型也不会增加工具或资源权限。提示词说明职责，执行层落实工具、委派和资源授权检查；无限制 shell 加“只读”提示词不足以构成只读保证。

内置 agent 为 `worker / explorer / reviewer / researcher / advisor`，默认选中 worker。初始配置与提示词来源于参考插件及用户明确指定的本机 `subagent.agentOverrides`；worker 按工坊约定启用，advisor 使用内置 `smart`。不导入本机模型或凭据。agent 可删除，内置模型角色不可删除；删除内置 agent 后不因重新解析内置定义而自动重现。

## 内置定义与用户覆盖

模型角色与代理配置统一采用“内置定义 + 用户局部覆盖 → 最终生效配置”。内置定义随应用提供，用户存储只记录自己提供的字段；最终视图由统一解析入口生成，不作为用户编辑内容整体回存。

| 配置类型 | 未覆盖字段的来源 |
| --- | --- |
| 同名内置模型角色 | 该模型角色的内置原始定义 |
| 自定义模型角色 | 内置原始 `default` |
| 同名内置代理 | 该代理的内置原始定义 |
| 自定义代理 | 内置原始 `worker` |

自定义项保留自己的身份与名称，继承的是行为配置字段。基准永远取内置原始定义，不读取其他项的最终视图；修改用户的 worker 或 default 不会连带改变自定义项，也不建立最终视图之间的继承关系。

用户未提供字段表示未覆盖；提示词文本框留空或清空表示移除该字段覆盖，最终取内置值。编辑器的 value 表示用户填写的内容，placeholder 可显示覆盖前的继承内容；不能将继承内容当作用户填写内容保存。不另存与字段存在性重复的覆盖标记。

字段缺省与业务值须区分：`false`、明确的空工具列表，以及模型引用/思考等级中表示继承调用方的 `null` 均有业务含义，不能统一按空值删除。配置覆盖解析先完成，再进行模型角色的调用方继承与存在性校验。

覆盖保存提交完整的用户覆盖集合；省略字段撤下覆盖，说明与提示词的空白文本也按未提供处理。列表整项替换，不追加合并。工具允许/排除列表作为一组互斥策略：指定任意一侧即替换整组，两侧都缺省才继承内置策略；显式 null 表示该侧无列表，空允许列表表示无工具。委派 null 表示不限定代理列表，空列表表示不允许委派。

编辑器的选择项和布尔值提供“内置”选项；数值输入留空恢复内置，也可明确选择 null 所代表的运行时默认。恢复整项内置值撤下全部覆盖，自定义项保留自己的名称，保存后生效。内置 agent 删除后保持删除状态；原始 worker 仍可用作自定义代理的继承基准。费用预算字段（maxCost）已于 2026-10-13 移除。

未覆盖字段随内置定义更新。每次模型请求开始按当前选择读取最新 agent、模型角色与模型配置，解析出本次环境；环境在该请求及其工具批次内保持一致，不存入对话历史。修改提示词、工具策略或模型参数后，已有对话从下一次模型请求采用新配置。内置版本与覆盖来源是配置投影的信息，不是历史恢复执行环境的依据。

局部覆盖、设置入口“角色”、编辑器继承展示已实现并获 GUI 验收（2026-10-13）。用户可在编辑器恢复继承。新初始化的内置项只保存身份与空覆盖。实施记录见 [模型接入计划](../plans/archived/todo-2026-10-01-model-protocol-storage.md)。

## 对话创建与覆盖

应用每次启动进入独立首页，不自动打开会话。首页不属于任何会话，输入与选择是创建前草稿。首次发送被接受时才生成会话 ID、第一个代理资源与首条输入，并将主内容切换为工作台；不要求填写标题。core `naming` 模块通过用户消息提交观察，调用 `utility` 异步执行一级或二级命名并追加来源事件；执行游标变化后按当前路径同步标题，用户命名保护限于包含它的路径。规则见 [自动会话命名](session-naming.md)。`utility` 须配置可用模型，模型不可用或命名失败时保留当前路径的标题。标题不是身份，也不是创建或展开工作台的前置条件。完整导航约定见 [应用与工作台交互](workbench.md)。

1. 新建对话选择 agent；模型与思考等级提供“代理默认”，对应 null。选中或切换 agent 不把角色默认值复制进选择，也不改变已有显式覆盖。
2. 每次请求沿代理所引用的模型角色解析默认值，本次明确选择的模型与等级优先，不修改 agent 或模型角色的持久配置。UI 可读取生效模型来限制等级选项，不把投影结果回存为选择。
3. `default` 用作普通新对话的默认参考；有明确角色引用的 agent 使用该引用提供默认值，不强制覆盖成 `default`。
4. 模型与等级为空仍允许提交，最终请求解析不到可用值时明确报错；不自动沿用另一个会话的模型。角色设置中的模型为空时，没有目标模型可据以限制等级，保留全局标准选项，实际请求时再校验。
5. 对话期间允许切换 agent 配置、具体模型与思考等级，工作台上的代理对象身份和消息树不变。修改从下一次模型请求生效，在途请求及其工具批次按已取用环境完成；协议资料兼容与中断处理由执行契约定义。
6. 委派时可指定子代理使用的另一个模型；未覆盖时使用目标 agent 的模型角色，角色空值从发起委派的对话继承。
7. 标题命名等模块通过显式模型目标引用 `utility` 等角色；未提供模型覆盖时使用角色配置的模型。`utility` 未配置模型时不可用，不自动回退到对话模型，也不使用全局“当前窗口模型”。

配置修改不改写历史。当前选择的 agent 配置 ID、具体模型 ID 与思考等级保存在可修改的会话设置中，独立于追加事件；只记选择身份，不复制配置正文。模型输出块保留适配器及协议作用域以解释响应续接资料，不保存 agent 正文、工具目录、生成参数或完整请求投影。只有消息从对话历史重建，执行环境即时解析。

## 按需读取与消费检查

配置是取用信息的来源，不建立需要维护的引用图。代理选择只保存身份与显式覆盖，每次请求读取所选身份对应的当前配置并解析角色默认值，不用历史快照代替。各消费方通过统一解析入口检查存在性与启用状态，不各自实现配置同步协议。

删除提供商、具体模型、角色或 agent 不检查其他配置的引用，不级联清空其他配置与会话的选择。提供商删除时移除其拥有的具体模型，但角色中旧模型 ID 保持原值。空模型 ID 表示继承，找不到非空 ID 则表示不可用，不能把两者混淆。

返回首页或打开会话时重新读取选择项，UI 根据当前可用信息显示；删除配置不主动清空选择，下一次请求检查发现缺失或停用时明确失败，不回退到旧快照或其他代理。模型角色与代理配置保存更新用户覆盖，无额外版本冲突门槛。配置修订号标识本次取用版本；可修改的会话选择另有修订号，避免异步查询把新选择覆盖回旧值。

连接测试取用点击测试时的配置快照，后续编辑或删除不会重写它；结果标记测试时修订。取消、超时与应用退出终止在途请求，迟到结果不改变已经结束的状态。配置保存本身不访问外部服务。

连接测试与真实执行共用请求选项解释入口。测试保留最小 probe，只验证端点与基础协议连通性，不选择或验证思考等级，不验证兼容行为；执行路径在同一入口解释生成参数及协议选项。
