# 提供商、模型角色与代理配置

本文定义配置与消费语义；实施顺序、待定字段和验收见 [模型接入计划](../plans/todo-2026-10-01-model-protocol-storage.md)。提供商、具体模型、模型角色、agent 配置和连接测试已实现，首页可选择 agent、模型和思考等级；真实发送与代理执行尚未接入。

## 设置职责

| 设置分类 | 管理内容 | 消费方 |
| --- | --- | --- |
| 提供商 / Providers | 连接、协议、端点、凭据，以及连接下的具体模型、能力和生成参数 | 模型接入与连接测试 |
| 模型 / Models | 模型角色配置表：模型引用、思考等级、启用、用途描述、隐藏 | 代理配置与需要模型的功能模块 |
| 代理 / Agents | agent 配置：提示词、工具策略、可委派代理、模型角色引用等 | 主代理与子代理创建 |

提供商下的具体模型决定服务端模型 ID、能力和温度等生成参数。模型角色引用具体模型，负责复用选择与思考等级，不另存一套温度等上游参数。相同服务端模型 ID 可能出现在不同连接下，引用必须能确定实际使用的连接。

模型角色与代理配置都是可编辑的配置记录。工作台上的代理对象是采用配置创建的执行实例；模型角色不成为卡片、资源或独立执行对象。普通对话界面选择 agent 和具体模型，不增加一层模型角色操作流程。

## 模型角色

| 字段 | 含义 |
| --- | --- |
| 模型引用 | 指向提供商下的具体模型；可为空，继承发起调用的当前对话模型 |
| 思考等级 | 可为空，继承当前对话的思考等级；空值与明确关闭思考不同 |
| 启用 | 控制角色是否可用；与隐藏分开 |
| 用途描述 | 说明角色适合什么工作，供用户理解和功能、代理选择 |
| 隐藏 | 控制是否向代理开放为可选择的模型角色；不阻止用户在设置中管理 |

模型引用与思考等级分别解析空值，不因模型继承而强制覆盖思考等级。功能模块按角色请求模型，由统一解析能力返回实际模型与思考配置，避免各模块各自实现默认值和继承。

内置角色如下，初始模型引用可为空：

| 角色 | 用途 | 默认隐藏 |
| --- | --- | --- |
| `default` | 普通对话的默认模型参考 | 否 |
| `heavy` | 需要较强推理能力的工作 | 否 |
| `fast` | 对速度与成本敏感的工作 | 否 |
| `smart` | 基于证据的判断、架构建议与决策咨询 | 否 |
| `utility` | 标题命名、辅助整理，以及未来的记忆整理等内部功能 | 是 |

内置角色不能删除，其余设置允许用户编辑，包括模型、思考等级、启用、用途描述和可见性。用户可新增、编辑和删除自定义角色；自定义角色可供代理等功能引用。

`utility` 隐藏时，内部功能仍可按名称引用；代理不能将其作为自主选择或临时覆盖的模型角色。用户可以取消隐藏，使其进入可选范围。隐藏角色仍能在设置中找到和编辑，隐藏不等于停用，也不构成资源授权。

## 代理配置

主代理与子代理共用 agent 配置，用户可以新增和编辑配置。配置规定代理的职责、提示词、工具策略和委派范围，并引用模型角色作为默认模型参考。

配置设计沿用 pi-subagent 的角色定义：

| 配置内容 | 作用 |
| --- | --- |
| 名称、描述、任务示例、选择条件 | 让用户与委派方知道何时选择此 agent |
| 系统提示词 | 规定职责、工作方式与输出要求 |
| 模型角色引用 | 提供默认模型与思考等级，允许本次调用覆盖 |
| 工具允许列表或排除列表 | 限定可用工具，两种策略互斥；允许列表为空表示无工具 |
| 可委派代理列表 | 限定能创建哪些子代理，与自身工具策略一起生效 |
| 启用状态、超时、轮次与费用预算 | 管理配置可用性及执行限制 |
| 备用模型角色 | 表达备用配置；实际重试仍遵循织台的执行与副作用契约 |

工具策略只约束工具范围；资源操作仍须满足显式绑定与执行层授权。目录可见、模型角色选择或 agent 配置都不自动授予资源权限。

只读 advisor 用作主代理时，同样受只读工具和委派范围限制，不能通过创建可写代理绕过限制。切换为更强的模型也不会增加工具或资源权限。提示词说明职责，执行层落实工具、委派和资源授权检查；无限制 shell 加“只读”提示词不足以构成只读保证。

内置 agent 为 `worker / explorer / reviewer / researcher / advisor`，默认选中 worker。配置与提示词复制自参考插件及用户明确指定的本机 `subagent.agentOverrides`；worker 按织台约定启用，advisor 使用内置 `smart`。不导入本机模型或凭据。默认项仅首次初始化写入，用户编辑后不重置；agent 可删除，内置模型角色不可删除。

## 对话创建与覆盖

应用每次启动进入独立首页，不自动打开会话。首页不属于任何会话，输入与选择是创建前草稿。首次发送被接受时才生成会话 ID、主代理与首条输入，并将主内容切换为工作台；不要求填写标题，utility 异步命名。标题不是身份，也不是创建或展开工作台的前置条件。完整导航约定见 [应用与工作台交互](workbench.md)。

1. 新建对话选择 agent 和具体模型。选中 agent 后，其模型角色若定义了模型，则填入模型选择；用户可以随后改为其他模型。
2. 模型角色只提供默认参考。本次明确选择的模型优先，不因选用另一个模型而修改 agent 或模型角色的持久配置。
3. `default` 用作普通新对话的默认参考；有明确角色引用的 agent 使用该引用提供默认值，不强制覆盖成 `default`。
4. 没有当前对话可继承，且配置不能解析出具体模型时，要求用户明确选择后再开始；不自动沿用另一个会话的模型。
5. 对话开始后 agent 固定，允许切换具体模型。切换时的生效边界、协议资料兼容与中断处理由执行契约定义。
6. 委派时可指定子代理使用的另一个模型；未覆盖时使用目标 agent 的模型角色，角色空值从发起委派的对话继承。
7. 标题命名等模块使用 `utility` 等角色引用；继承来源是该功能所属的对话，不使用全局“当前窗口模型”代替明确上下文。

配置修改不改写历史。实际执行需保留采用的 agent 配置、模型角色解析来源、具体模型及非秘密配置版本，保证临时覆盖与历史请求可解释。

## 按需读取与消费检查

配置是取用信息的来源，不建立需要维护的引用图。选择 agent 时取它的配置与模型角色默认值；之后的设置编辑不主动刷新该选择，也不改变已有对话。各消费方通过统一解析入口检查存在性与启用状态，不各自实现配置同步协议。

删除提供商、具体模型、角色或 agent 不检查其他配置的引用，不级联清空其他配置与会话的选择。提供商删除时移除其拥有的具体模型，但角色中旧模型 ID 保持原值。空模型 ID 表示继承，找不到非空 ID 则表示不可用，不能把两者混淆。

返回首页或打开会话时重新读取选择项，UI 根据当前可用信息显示；进行中的会话不会因为离开到设置删除配置而被主动清空选择，实际发起下一次模型调用时再检查，配置缺失便明确失败。配置保存直接覆盖该项，无额外版本冲突门槛。内部修订号仅用于标识连接测试及未来实际执行取用了哪份配置，不驱动级联刷新。

连接测试取用点击测试时的配置快照，后续编辑或删除不会重写它；结果标记测试时修订。取消、超时与应用退出终止在途请求，迟到结果不改变已经结束的状态。配置保存本身不访问外部服务。
