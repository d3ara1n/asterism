# Shared interface localization

Completed and archived after user GUI acceptance on 2026-10-12. The work introduced SDK message declarations, language selection, static catalogs, display transport, and host/built-in message conversion.

Localization served ordinary interface users. Developer diagnostics and model-facing protocols remained untranslated. Plain strings stayed valid, translations were optional, and each descriptor retained its original owner and source locale.

FormatJS and ICU supplied formatting and extraction. Language matching respected scripts; missing or invalid translations fell back per message. Language changes updated display context without restarting plugins, replacing business components, losing drafts, or changing history.

Catalogs loaded independently of plugin code, including backend-only packages. Current settings and error presentation used transferable descriptors and scalar parameters rather than rendered text.

The real extraction CLI was verified against author syntax and rejected conflicting default messages. Typechecks, tests, localization checks/extraction, and build passed. Isolated partial external catalogs remained valid.

User acceptance covered language switching and persistence, focus/draft preservation during work, cards, history filters, application menus, creation forms, plugin configuration, and rich text. Automation did not substitute for real GUI or provider checks.

Later cleanup removed developer-only translations, kept message identity/text stable while organizing semantic declarations, and centralized error/display adaptation. Native default Electron menus remained outside the task's managed menu scope.
