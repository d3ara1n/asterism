# Directory Git status refactor design

Proposed on 2026-11-22, following the directory refresh comparison. This record preserves the approved implementation scope and design rationale. Windows console behavior, executable selection, and the terminal resource are out of scope.

## Scope and ownership

The builtin Directory plugin owns status scoped to the linked directory. Keep the Files badges, Changes list, line totals compared with HEAD, and live updates of an open file diff. A directory inside a repository is not authorization or a reason to publish the rest of the checkout's changes. Keep Git itself authoritative. Do not introduce a host service, another VCS library, global checkout cache, or on-disk status state.

Use the existing view-owned Directory watch channel for both filesystem invalidation and Git status. Serve the root listing independently through `DirectoryChildren`; the generic TreeStore remains usable by Manual without Git. Add separate channel messages for files invalidated, Git snapshot, and watcher or status failure, and a manual refresh request. Migrate the card's only `DirectoryStatus` caller, then remove the separate status RPC. Reuse the existing store across a card's header, body, and open diff; distinct Directory resources do not share subscriptions in the first slice.

- **Repository layout:** Resolve the canonical resource directory. An ancestor `.git` file or directory is a cheap gate for ordinary worktrees, not a Git parser; when a Git environment selects a repository explicitly, use Git discovery without that gate. One `rev-parse` returns the worktree root, Git directory, common directory, and repository-relative prefix. An ordinary non-repository does not spawn Git. Distinguish unsupported or absent Git from Git failures on real repositories; do not blanket-classify all exit-128 failures as absence.
- **Watcher:** Begin observing directory contents independently. Use the discovered layout to classify events and add any external Git metadata watches, reusing a recursive watch where it already covers the metadata. Worktree file changes invalidate Git; paths affecting directory entries also invalidate listings. Git metadata events invalidate status only, except worktree marker changes that also affect the filesystem listing. Ignore internal churn such as index lock files, objects, and logs. Recompute layout for repository marker creation/removal/replacement, or on manual refresh or reopening. Do not add broad recursive watches of ancestors just to discover a newly initialized enclosing repository; reopening or manual refresh rechecks that case.
- **Refresh:** Read one complete Git snapshot scoped to the resource, not partial status inferred from watcher paths. Keep one in-flight Git read and coalesce invalidations; an invalidation received during a read queues a follow-up read. The channel aborts watchers and Git work when the last consumer closes; the renderer may keep the last snapshot for that same resource and show it while revalidating on return. A Git failure does not prevent file browsing, and a native watcher failure does not prevent an explicit refresh. A file diff reacts to Git refreshes even if its path and classification did not change.

## Implementation sequence

1. Extract discovery and make the watcher and status reader consume the same layout. Exercise a repository root, a resource subdirectory, a .git directory, a newly initialized repository, and a linked worktree; verify the latter's external metadata paths. A temporary Git experiment confirmed the combined absolute `rev-parse` form also works for an unborn HEAD and a subdirectory with spaces.
2. Decouple file listing and Git state in the card and implement the existing channel as the lifetime owner. The current status command and numstat semantics can stay in place while wiring and invalidation behavior change. Refresh listings only for relevant filesystem events; manual refresh covers both sides. Preserve file diff notifications for content edits with stable badges and totals, and expose failures without erasing a good snapshot.
3. Remove the HEAD-only probe from normal status refresh by reading `status --porcelain=v2 --branch -z --no-ahead-behind`, or keep the current parser if the change cannot preserve its classifications. In v2 the branch OID names the diff base and `(initial)` indicates an unborn branch. Keep the existing HEAD-to-worktree numstat semantics, computing the empty tree only when needed. Skip numstat on clean status only with tests for equivalent behavior. Do not bundle a switch to `diff-index` or partial-status merging into this refactor.

Expected command budget for one card, excluding file diff requests and watcher-triggered follow-ups: ordinary non-repository zero; first clean open one discovery plus one status; subsequent clean refresh with unchanged layout one status; dirty refresh can add one numstat call and unborn HEAD can need an empty-tree computation. Counts are targets, not measurements of the new design.

Acceptance: root listings appear without waiting for Git. Match existing outcomes for resource-relative paths, staged and unstaged changes, renames, binary files, untracked entries, and unborn branches. Check real staging/unstaging, edits that leave the same status label, refs and switching branches, external Git metadata for linked worktrees, and missing Git. Check manual refresh when watch is unavailable and verify no work continues after the last consumer leaves. Use focused parsing and behavior tests and real Git fixtures for command semantics; GUI acceptance is manual.

## Implementation validation

Implemented with the existing Git CLI and view channel. Focused tests exercise porcelain parsing, scoped line totals, unborn HEAD, staging, and linked worktree discovery. A macOS backend check using the native watcher and Git Trace2 observed zero Git commands on a plain-directory open, `rev-parse` plus `status` on a clean linked-worktree open, and reuse of the discovery result on later file edits. Staging triggered a refresh from the external Git index. This is backend evidence; Windows and desktop GUI acceptance were not performed.
