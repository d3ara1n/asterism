# 时间线派生状态与历史模型

## 已完成

1. **快照按需按路径构造**：SDK 快照固定时间线末端、会话追加上界和标题，记录与资源在实际查询时读取；后续提交、回溯和分叉不改写此前快照。接口、首尾查询与 unknown 规则见 [插件 SDK](../../docs/plugin-sdk.md#对象读取与执行)。
2. **工作台统一按执行游标重建**：宿主重放资源创建、移除、链接与解绑，工作台展示、对象校验和请求授权共用当前结果；移除独立 `at` 和卡片历史模式。历史面板只选中候选节点，明确「从这里继续」才移动执行游标。机制与交互见 [时间线](../../docs/timeline.md#投影)、[工作台](../../docs/workbench.md#时间导航与透明度) 和 [决策](../../docs/decisions.md)。
3. **会话树、时间线与分支概念及 API 整理**：会话树保存全部节点，时间线为逻辑根到任意末端的完整祖先路径，执行游标确定可追加的当前时间线；分支属于 UI 组织，模型上下文另行投影。查询保留 `timeline / session` 两个范围，命名继续按全会话首条输入触发一级命名；宿主使用 `timeline()`、`appendToTimeline()` 与 `sessionTimeline()` 明确读取及当前时间线追加。正式定义见 [时间线](../../docs/timeline.md#时间线执行位置与分支)、[词汇表](../../docs/glossary.md) 与 [插件 SDK](../../docs/plugin-sdk.md#对象读取与执行)。

## 实现边界

- 时间线记录不可改写。当前工作台按执行游标全量重放，不对前后路径求差异或逆操作；布局和笔记正文没有历史性，Agent 上下文继续在请求时即时投影。
- 宿主工作台的存在性与链接参与执行校验，在原提交成功前完成重建，失败回滚；每个会话复用当前游标的不可变结果，重开按持久游标恢复。
- 插件领域派生值由 `cursorChanged` 在原提交后同步，失败只记日志，不回滚原提交。`committed` 只通知新增记录；观察者追加按序排队，队列清空后每个会话通知界面一次。宿主不解释插件的领域事件，不新增 `atChanged`。
- 会话命名已接入游标观察，标题规则见 [自动会话命名](../../docs/session-naming.md)。宿主建会话与命名模块的首条消息截断分别维护，不合并。
- 固定 SDK 快照保留按需查询语义，不维护跨快照查询缓存；工作台当前状态复用不改变此前快照。未来资源的领域状态由资源自己维护，当前工作台重建不需要通用 `lastBy`。
- `cursor_selections` 仅记录显式执行游标选择，不记录历史面板内的候选选择；日志不进入时间线或模型上下文。
