# Directory Git discovery and refresh

Investigated on 2026-11-22 after the Windows Terminal flash persisted in Asterism 1.1.0-prerelease.2. This record compares source code and upstream reports; it does not identify the process that opens the visible window on the affected machine or establish Windows GUI acceptance.

## Asterism baseline

The released Windows installer was unpacked and its bundled directory Git helper was verified to pass `windowsHide: true`. The builtin plugin runs in an Electron utility process and currently hands `git` by name to Node's `execFile`. The terminal resource is not needed to reproduce the reported flash. Windows can create a hidden console host even for a hidden spawn; seeing a `conhost.exe` process does not by itself identify a visible window.

For an ordinary repository with a committed HEAD, mounting a directory card starts up to six Git commands before subsequent invalidations: `watch.ts` probes for a worktree and reads the Git directory and common directory in three invocations; `git-status.ts` probes again, then runs `status` and `diff --numstat`. A plain non-repository still gets one probe from each path. Later file-system events already coalesce into refreshes and the card store permits one refresh at a time, but each refresh in Files mode requests both Git status and all loaded directories. Closing the card's last consumer stops its watch and drops the live status snapshot; the retained store mainly preserves UI intent. The tree uses status for file decoration, and its header displays line totals, so tying all Git work to the Changes tab would remove existing behavior.

## Comparable implementations

- **T3 Code:** Resolves and caches executables. [Its Windows Git change](https://github.com/pingdotgg/t3code/pull/17707) prefers the real Git for Windows binary beside a recognized launcher (`ucrt64`, `clangarm64`, `mingw64`, `mingw32`); it preserves the launcher when `MSYSTEM` is set and leaves unknown shims alone. [A separate change](https://github.com/pingdotgg/t3code/pull/19288) uses detached, hidden launch only for allowlisted metadata reads against a known real binary. It keeps the ordinary launch for `status` and `diff-index`, which can do more work and start helpers. The reported gain was fewer hidden console hosts, not a reproduction of Asterism's visible flash. The [status broadcaster](https://github.com/pingdotgg/t3code/blob/a8363dad7fa72f7f313dbcae5f7576a6383381c5/apps/server/src/vcs/VcsStatusBroadcaster.ts) holds local and remote state separately; [client revalidation](https://github.com/pingdotgg/t3code/blob/a8363dad7fa72f7f313dbcae5f7576a6383381c5/packages/client-runtime/src/state/vcsStatusRevalidation.ts) shares work by checkout and revalidates on wake or reconnect. Remote polling is a separate, subscription-owned path. Its [change totals fix](https://github.com/pingdotgg/t3code/pull/35770) uses `diff-index --numstat` instead of porcelain `diff --numstat` to avoid refreshing and locking the real index.
- **OpenCode:** [Repository discovery](https://github.com/anomalyco/opencode/blob/ee5fe34e136488a1839ac73bcca8321c51a31b75/packages/core/src/git.ts#L213-L278) searches ancestors for `.git` before invoking Git, then uses one `rev-parse` for repository paths. Its metadata fingerprint uses filesystem reads rather than rerunning Git. The [file-tree watcher](https://github.com/anomalyco/opencode/blob/ee5fe34e136488a1839ac73bcca8321c51a31b75/packages/app/src/workspaces/files/watcher.ts#L16-L41) refreshes affected loaded paths rather than every loaded folder. The [Git adapter](https://github.com/anomalyco/opencode/blob/ee5fe34e136488a1839ac73bcca8321c51a31b75/packages/core/src/plugin/vcs/git.ts#L80-L133) separates status and diff requests; the server's [branch refresh](https://github.com/anomalyco/opencode/blob/ee5fe34e136488a1839ac73bcca8321c51a31b75/packages/core/src/vcs.ts#L129-L175) listens for relevant metadata events. OpenCode's session snapshots are separate from live worktree status.
- **VS Code:** [Resolves Git once for the extension](https://github.com/microsoft/vscode/blob/aeda48593263735daaaf7b85b5f77c3d7ff4a48a/extensions/git/src/git.ts#L146-L181), consulting path hints, standard Windows locations, and then PATH. It can use the stock `cmd\git.exe` launcher. [Worktree and Git metadata watchers](https://github.com/microsoft/vscode/blob/aeda48593263735daaaf7b85b5f77c3d7ff4a48a/extensions/git/src/repository.ts#L966-L993) invalidate Git status; the [auto-refresh path](https://github.com/microsoft/vscode/blob/aeda48593263735daaaf7b85b5f77c3d7ff4a48a/extensions/git/src/repository.ts#L3378-L3449) debounces, throttles, and waits for idle/focus. [Status](https://github.com/microsoft/vscode/blob/aeda48593263735daaaf7b85b5f77c3d7ff4a48a/extensions/git/src/git.ts#L2845-L2908) streams `status -z` with optional locks disabled and a result limit.
- **Zed:** [Uses the Git CLI for worktree status](https://github.com/zed-industries/zed/blob/f4fe0be1f8c7974db07e01c5cd05bee0cf4eb8d9/crates/git/src/repository.rs#L1886-L1903). For ordinary worktree events it [batches changed repository paths into a keyed job](https://github.com/zed-industries/zed/blob/f4fe0be1f8c7974db07e01c5cd05bee0cf4eb8d9/crates/project/src/git_store.rs#L10598-L10660), limits/coalesces paths, and sends path prefixes to status and diff instead of rereading the whole worktree for every event.

## Recommended experiment and implementation scope

1. Validate the Windows launch separately in the packaged app. Capture the executable path and process chain for the same directory-card flow with the current PATH-selected launcher and with the real Git for Windows binary. Compare a non-repository, a normal repository, and a linked worktree. Count both visible console flashes and Git launches; don't count a hidden `conhost.exe` as a flash. If both binaries still flash, isolate the triggering command and descendants before changing creation flags. Do not copy a blanket detached launch or change the terminal resource.
2. Keep Git as the authority on worktree status and the native watcher as the invalidation source. Separate filesystem listing from Git refresh, and share one discovery result between the metadata watcher and Git status. Use an ancestor `.git` check to avoid starting Git for ordinary directories, without assuming `.git` is a directory; re-evaluate on relevant metadata changes and when reopening or manually refreshing. Resolve worktree and common Git metadata together. Share status over simultaneous consumers of the same checkout and directory scope, or slice a checkout-wide result by scope if it preserves the current semantics. Retain the last snapshot without keeping background watches alive after the last consumer closes.
3. Continue to coalesce events and keep one in-flight read per scope. Serve cached status on re-entry while revalidating if required. Read file status before requesting line totals; a clean result does not need a diff. Consider `diff-index --numstat` only with fixtures showing equivalent totals for staged, unstaged, unborn HEAD, and linked-worktree cases. Scoped partial reclassification can wait until there is evidence full status itself is a bottleneck; ref, index, ignore-rule, and ambiguous watcher events can affect paths beyond the event.

First-slice acceptance targets: no Git subprocess for a regular non-repository and Git agreement after external edits, staging, branch changes, and reopen, including two cards for one scope and a linked worktree. Separately, verify on Windows that the packaged build no longer opens a visible console. Reducing subprocess frequency is useful even if the flash requires a distinct launch fix.
