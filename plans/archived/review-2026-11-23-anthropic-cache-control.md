# Anthropic Messages prompt caching review

Filed: 2026-11-23. Reviewed commit `aac3f0a5`. Scope: request encoding, saved connections, usage pricing, and focused local tests. No authenticated provider requests were made.

## Product decision after review

Keep saved connection behavior unchanged. The built-in official Anthropic preset enables automatic prompt caching for new connections and does not need a user-facing off switch. This supersedes the rollout finding and the in-place opt-in and opt-out recommendation below. The requested simplification is to omit TTL configuration and use the service default. The reason is to avoid a rarely useful setting, not to make reference pricing reconcile with the provider's bill. The follow-up made the pack parameterless before release, localized its settings copy, and tightened request-body and probe assertions. No connection migration or pricing change was added. Live cache hit measurement remains outside this local verification.

## Original findings

- **P2 — Existing official connections cannot adopt the change in place.** The preset at `packages/builtin/src/providers/presets.ts:39` seeds only newly created connections. `src/shared/provider-presets.ts:6` copies the values without keeping a preset identity, and `src/configuration/store.ts:156` locks saved compatibility at both provider and model scopes for fixed connections. An existing Anthropic preset connection still sends no marker and has no settings path to enable it. Conversely, a newly created Anthropic preset connection sends the marker on every execution and has no settings path to turn it off. This follows the existing preset contract; it is a rollout gap, not a reason to make all fixed fields editable or to match connections by name, ID, or protocol.
- **P2 — The new 1h option can understate estimated cost and overstate cache savings.** `src/model/protocols/anthropic-usage.ts:14` keeps only the total write count. `packages/sdk/src/model-cost-estimate.ts:64` and `:100` use one configured write rate, and the built-in catalog supplies the 5m rate (Sonnet 4.6: $3.75 per million writes, versus $6 for 1h). A model-level override can send 1h without changing that price. Keep the first release at the provider default TTL, or carry the provider-reported `cache_creation` TTL split through usage and price it explicitly. If the rate or split is unknown, do not report a complete estimate from a known-wrong price.
- **P3 — The wire test does not establish exact omission or upstream hits.** `src/model/compatibility.test.ts:377` uses a partial matcher; an unexpected `ttl` on the default marker would pass. An exact check of `body.cache_control` can replace the partial assertion. The mocked streaming and probe paths establish local serialization and probe omission, not upstream acceptance or writes and reads.
- **P3 — The new compatibility labels bypass translation.** `src/shared/model-compatibility.ts:61` adds user-facing titles and descriptions through schema metadata. The editor renders that metadata directly (`src/renderer/features/configuration/ModelCompatibilityEditor.tsx:37`, `:55`, `:73`), so English appears in the Chinese interface even though `i18n:check` passes. Use the owning presentation layer to provide translatable text.

## Recommendation

Keep call-level `providerOptions.anthropic.cacheControl`, translated by `@ai-sdk/anthropic` into the top-level Messages `cache_control`. The official [2023-06-01 Messages reference](https://platform.claude.com/docs/en/api/http/messages/create?version=2023-06-01) documents this field, so no header migration or serialized-body rewrite is needed. Treat it as a selectable connection policy: provide an explicit in-place opt-in for existing official connections and a way to disable it on new ones. Keep unverified compatible endpoints unchanged, and do not retry a rejected execution without the marker. The [prompt caching guide](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#automatic-caching) documents a 400 for top-level caching on Bedrock `bedrock-runtime`; block markers should be a separate, tested endpoint policy if needed.

Validate with two official streaming requests through the actual adapter, within 5 minutes, with an identical prefix above the selected model's minimum cacheable token count. Extend the first conversation rather than replacing its last user message. Verify `cache_creation_input_tokens` on the first request and `cache_read_input_tokens` on the second; a normal connection probe intentionally checks neither. For a representative Agent run, check the same counters across a tool round trip. Consider adding a stable-prefix breakpoint only if measurements show persistent misses: automatic caching still has a 20-position lookback, and an explicit breakpoint helps only if the prefix through it is stable and large enough. `src/model/system-prompt.ts:4` currently flattens all system blocks to one string, so independently caching a stable portion would require preserving that boundary in the Anthropic projection rather than marking the current system block indiscriminately.
