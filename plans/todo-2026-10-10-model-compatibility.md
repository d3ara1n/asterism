# 可组合的模型兼容包与提供商／模型配置

> 立案 2026-10-10，延后。已确认采用显式、可组合的兼容包，由用户在提供商与具体模型上配置；本轮只立案，不修改运行时、配置存储、IPC 或设置 UI。设计原则见 [模型配置](../docs/model-configuration.md#模型兼容包) 与 [技术架构](../docs/architecture.md#模型兼容边界)。

## 目标

用户选择基础协议，再为提供商连接选择兼容组合；具体模型继承提供商的兼容选项，并可局部覆盖或选择不同组合。兼容包集中处理请求编码、响应解码和历史续接，适应同一协议下不同服务、模型或中转端点的真实差异，避免在各处累积按域名或模型名分支的判断。

基础协议、模型能力、兼容行为分别表达：协议决定基础消息与工具格式，能力描述模型支持什么，兼容包描述如何将工坊语义映射到该端点的实际格式。兼容组合不要求与品牌一一对应；不同模型可复用同一种思考格式，不因同属一家提供商就必须使用同一组合。

## 已确认方向

- 兼容包包含集中维护的适配策略与受校验的配置，可组合成便于用户选择的兼容预设；不只提供一个品牌开关。
- 提供商连接可以选择兼容包组合并设置选项，作为该连接下模型的默认值；具体模型继承这些选项并允许覆盖。模型角色与 agent 继续引用具体模型，不另存一套兼容配置。
- 请求参数编码、响应正文与流事件解码、历史消息及工具结果的续接投影使用同一份生效兼容组合。不得只修显示而忽略保存与后续请求。
- 用户显式设置适用于官方、自定义、中转和本地端点。内置目录可提供推荐组合；端点或模型名称不是运行时兼容行为的唯一依据，也不能覆盖用户选择。
- 兼容行为集中注册和装配。通用模型循环、会话存储与前端不识别 DeepSeek、Qwen 等品牌，不承载各自的条件链。
- 保留 Vercel AI SDK 为基础接入层。优先利用 SDK 的公开能力和扩展接口，确有覆盖缺口时由兼容模块补充；不修改 node_modules，也不引入另一套会话真值。
- 每次模型请求开始时统一解析兼容组合，并与该请求环境固定到底；配置修改从下一次请求生效。连接测试与真实执行使用同一解析与适配机制。

## 兼容模块的职责

| 边界 | 需要支持的差异 |
| --- | --- |
| 请求编码 | 思考开关与等级映射、预算、参数名称和支持范围、system/developer 角色、工具 schema 与调用格式 |
| 响应解码 | 思考摘要／纯文本／特定字段或标记、流增量与完整块、工具参数、终态和用量 |
| 历史续接 | 思考正文的回传形式、签名或加密资料、工具调用与结果配对、必要续接资料的解释 |
| 组合与校验 | 与基础协议的适用关系、选项继承与覆盖、组合顺序、策略冲突与缺失实现 |

以上是职责范围，不提前固定接口函数、模块颗粒度或配置字段。兼容包最终仍向工坊现有 thinking/text/toolcall 等契约输出，不让前端按服务商猜测格式；原始响应不因兼容需要而整包落库或写入日志。

## 实施前需细化

1. 兼容模块的粒度与组成方式：思考请求编码、正文解码、续接策略是否独立选择，哪些需要作为不可拆分的一组保证一致性。
2. 组合的确定性顺序、重复策略和冲突规则；未知模块或不适用协议的处理，不采用最后加载者静默覆盖。
3. 提供商与模型的覆盖单位，以及继承、明确禁用、移除某个继承模块、替换组合和恢复继承的区别；不把用户缺省值误当成禁用。
4. 模型能力声明、生成参数和兼容选项的职责与优先级，避免同一能力有多个冲突来源。
5. 兼容实现更新与配置变更对旧历史续接的影响：必要的最小身份、版本、作用域及不兼容处理。维持只追加历史，不复制完整兼容配置或改写旧正文。
6. 首批内置模块与预设范围。第三方兼容代码的安装、动态加载或任意用户脚本不是本次已确认需求，若需要另行讨论。

## 验收

- 同一提供商的不同模型可继承默认兼容配置，也可采用不同组合；修改提供商后，只有继承项在下一请求采用新值，模型显式覆盖保留。
- 提供商和模型配置在保存、重开、恢复继承后具有一致的生效结果；界面能说明当前值的来源。
- DeepSeek 官方与合成中转端点通过同一显式组合取得思考正文增量，正常结束或中断后按既有契约保存，后续请求使用正确的续接投影。
- 普通 OpenAI Responses、Chat Completions 与 Anthropic 的基础行为保留；空思考、文本与工具混合、终态及必要续接资料按各自协议正确处理。
- 组合冲突、未知包、协议不适用及不兼容历史有明确结果，不静默丢弃思考正文或续接资料。
- 验证以已核实的协议样本和合成流为依据，在对应边界检查配置解析、实际编码、增量解码、保存与续接；不访问真实会话或凭据。真实端点和 GUI 由用户验收。

## pi 参考

核验本机 `@earendil-works/pi-ai@1.1.0` 与 pi coding-agent 的配套构建产物：

- `dist/core/provider-composer.js`：提供商 compat 与模型 compat 的合并，以及已有模型的覆盖。
- `pi-ai/dist/providers/data/deepseek.json`：当前官方 DeepSeek 使用 `thinkingFormat: "deepseek"`，同时声明 developer 角色、token 参数与 assistant 思考回传等兼容选项。
- `pi-ai/dist/api/openai-completions.js`：thinkingFormat 包含 qwen、deepseek 等请求策略；qwen 使用 enable_thinking。这说明品牌和可复用格式应分开表达，也说明 thinkingFormat 不能等同于全部响应解码。
- `docs/models.md`、`docs/custom-provider.md`：显式兼容配置与已有协议实现复用。

借鉴显式配置、模型覆盖和格式复用，不照搬已有条件链，也不把 Chat Completions 的某种 thinkingFormat 自动应用于 Responses。实施时重新核验相应版本和实际编码／解码行为。
