# 事件投递与插件互相调用

## 当前状态与范围

**机制层与会话标题已接入。** SDK、宿主总线、来源 stamp、按序投递、latest 合并、跨进程逐条转发与订阅生命周期已经可用；会话标题由宿主发布 SDK 公共契约 `SessionTitleChanged`，外壳订阅更新列表；`session.changed` 合并重读只保留列表结构更新。

资源通知、资源状态与插件调用都缺少真实消费者，不先做机制：等出现实际发布方（如下载器、自动改名工具）时再定契约并接入，届时由该消费者验证。本计划保留在 `plans/`，全部结束后再归档。

已确认的接口与行为以 [插件 SDK](../docs/plugin-sdk.md#瞬态事件与插件调用) 为准，执行边界见 [运行时](../docs/runtime.md#瞬态通信与执行生命周期)，交互见 [工作台](../docs/workbench.md#会话列表状态与资源通知)。遵循 KISS 与「信任插件，暴露问题」。

## 已完成：事件机制

- [x] SDK 0.11.0／宿主 API 7.1：`ns.event`、`ModuleContribution.events`、插件／资源发布、全局具型订阅及前端 prepare.events／useRendererEvents；作者示例包含类型反例。
- [x] 宿主登记领域契约，校验共享实例、声明归属与发布来源；公共契约可以被不同插件使用，不授予资源操作权限。
- [x] 每订阅无界按序队列，snapshot 契约可选 latest 按来源与业务键合并；消费失败只结束该订阅。
- [x] runtime、main、preload 与 renderer 的独立事件协议，逐条转发原始信封，latest 在接收端合并。
- [x] 事件不参与事务，publish 即投递；需确保已生效时在提交成功后发布。事件不追加历史、不移动游标，不改变真实资源活动判定。
- [x] 统一订阅建立、结束与取消状态；后台消费复用 RunLifecycle，取消不等于真实结束，设施等待回调收束后释放。
- [x] 装配失败、窗口导航、关闭、渲染进程退出与运行时失联清理旧订阅；晚订阅和重连不补发。

实现入口：`src/plugins/events.ts` 负责契约与路由，`event-scope.ts` 连接插件装配与运行生命周期，前后台共用 `src/shared/event-queue.ts`（订阅队列与 latest 合并）与 `event-subscription.ts`。模块地图见 [src/README.md](../src/README.md)。

机制层验证已通过：`npm run typecheck`、全量测试与 `npm run build`。测试覆盖来源、契约隔离、按序与 latest 合并、消费失败隔离、取消与收束、装配失败、跨进程 schema 转换和断连清理。真实 Electron GUI 尚未验收。

## 延后：资源状态与 badge

资源状态与资源通知是不同契约。通知表示一次用户提示，状态表示持续展示的当前条目，均沿用公共 `UiText`。资源状态可以来自下载器、代理或其他资源，应用消费公共语义，无须解释各插件私有记录。

- [ ] 确定资源状态公共载荷、条目键与更新／撤回语义：每资源一项还是多项，进度与严重度的表达。
- [ ] 明确状态持有方，以及完成、错误、撤回、资源移除、插件不可用、重启与历史游标变化时的保留和恢复；不默认新增存储格式。
- [ ] 接入公共资源状态事件与领域当前值读取／恢复，再实现会话列表 badge 和资源详情。
- [ ] 验证多资源聚合和状态生命周期，GUI 由用户验收。

已确认交互：badge 是会话列表行上的独立入口，点击展示具体资源与状态，不要求打开会话正文。单条进度显示进度环，单条错误显示错误；多项保留各自详情。进度汇总为旋转指示、状态取最高严重度是候选，混合优先级待定。“资源移除时清理”也是候选，不是已定统一生命周期。

条目不因事件投递结束或页面切换而消失。展示状态不替代宿主真实活动；下载进度、长期外部活动或保留错误不自动阻止回溯或资源移除。

## 延后：插件互相调用

- [ ] 有真实需求后确定目标定位、输入／输出、失败、来源传播与跨会话校验；明确与现有动作队列、准备和执行授权的关系。
- [ ] 在共享通信机制下实现独立请求／结果／取消协议及收束，不以事件拼装请求／应答。

调用可以面向未打开会话中的对象，仍校验真实目标与适用授权，不通过加载前端控制器激活目标。目前只在设计中为 `plugin.ipc.calls` 留位，不导出空 API，也不固定完整调用接口。
