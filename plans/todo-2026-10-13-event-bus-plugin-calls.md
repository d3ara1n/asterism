# 事件投递与插件互相调用

## 目标与范围

建立具名、有归属、具型的瞬态事件投递机制（event bus），与插件互相调用机制一起设计。应用外壳和插件作为消费者，显式订阅自己认识且需要的契约；投递覆盖不同会话，不以用户是否打开会话、是否挂载卡片为条件，也不按当前打开的会话统一过滤。

本计划承接会话观察与后台跨插件通信。自动改名、下载器、跨会话代理消息与传送门都是机制的消费者示例，不作为本计划必须实现的业务功能。待办以本计划为准；已确认原则见 [插件 SDK](../docs/plugin-sdk.md#瞬态事件与插件调用) 与 [交互约定](../docs/workbench.md#会话列表状态与资源通知)。

## 当前基础与缺口

- 后台按会话与对象身份查询数据、受理命令和运行任务，不要求先打开会话页面；会话页面的读取与订阅不控制后台任务生命周期。
- `session.changed` 只有会话身份与 revision；`session.progress` 已含实时模型块与通用 `unsettledObjectIds`，不限于代理活动。
- 应用控制器监听全部 `session.changed`，合并 300ms 后重读 `workspace.read` 更新列表。流式 progress 不直接触发这次重读，但与标题无关的持久变化仍触发。
- 运行时通知已能抵达未打开会话的外部消费者，但缺少通用具型事件契约、插件发布／订阅入口与应用摘要消费。
- 公共模块已支持同一运行环境的导出实例共享；前端资源动作已有具型调用路径，通用后台跨插件调用尚未提供。
- 宿主运行生命周期已统一登记任务、动作、模型调用与准备工作。公开展示状态不能替代这套真实活动／收束判定。

## 已确认方向

### 瞬态事件与订阅

- 事件是瞬态投递，本身不写会话树，不构成模型上下文，不产生历史位置。需要历史的业务继续按自己的记录契约提交。
- 每种事件有具名契约、声明归属与具型载荷；订阅者显式消费自己认识且关心的契约。声明形式、SDK 命名与传输信封在接口设计时确定。
- 应用外壳与插件均可作为订阅者。跨会话投递不依赖目标会话页面加载；不同消费者可以选择不同事件与作用域。
- 通用机制负责身份、校验、路由与订阅生命周期，领域含义由契约定义。公共领域事件可由应用层直接消费，插件专有事件由持有相应契约的消费者解释。
- 声明归属与发起者来源分别表达：公共事件契约可以被不同资源使用，其声明所有者不因此变成每次发出的来源。

### 来源 stamp

- 事件复用时间线记录的来源身份原则：插件 stamp 由宿主按发布通道确定；资源来源由绑定并校验的资源身份确定。载荷中的关联对象不等于发起者。
- 资源发出的事件携带插件与资源来源，并可定位所属会话；插件级事件也有插件归属，资源字段的适用范围与具体信封待定。
- 消费公共契约不取得契约所有者的身份；知道会话／对象 ID、收到事件或导入调用契约，也不构成资源操作授权。

### 公共领域事件

| 契约类别 | 含义与消费者 |
| --- | --- |
| 会话标题变化 | 会话标题实际改变时投递，应用外壳据此更新列表，不依赖打开会话 |
| 资源通知 | 资源向用户发出的瞬态提示，必须有资源 stamp 与插件 stamp；外壳订阅后显示 toast |
| 资源状态推送 | 资源向外发布状态或进度，应用层据此维护会话列表的状态条目与 badge；不绑定 Agent 语义 |

资源通知通过事件机制投递，复用其来源 stamp，不另立一套通知 API。资源通知与资源状态是不同契约：toast 用于提示，状态推送用于持续展示。展示文案沿用公共 `UiText` 约定。

下载器可以推送下载进度，代理可以推送运行或错误状态；应用层消费公共状态语义，不需要理解下载器或代理的私有记录。

### 会话列表 badge

- 每个会话在列表行上提供独立的概要 badge，作为与 more 按钮类似的行级入口；点击展示具体资源及其状态列表，不要求先打开会话正文。
- 只有一个状态条目时，badge 显示该条目的概要：详情为进度条时，外侧显示进度环；详情为错误时，外侧显示错误。
- 多个资源状态需要聚合。当前候选规则：进度类汇总为旋转指示，状态类显示最高严重度；两类同时存在时的组合或优先级、严重度枚举仍待定，不在本轮固定。
- 展开列表保留各资源的独立状态，不用概要覆盖详情。badge 的具体视觉实现沿用公共控件与设计系统，GUI 由用户验收。

### 瞬态投递与持续状态

事件只负责一次投递，badge 列表持有可更新的状态条目，两者生命周期分别定义。状态不会因为承载它的事件投递结束就消失，也不因打开／关闭会话页面而被清空。

当前条目清理候选是“资源被移除时清理”。这尚不是最终统一生命周期：完成、失败、撤回、资源移除、插件不可用、重新订阅与应用重启时如何处理，留待设计。是否需要当前状态读取、重新发布或其他恢复机制，以及状态由谁持有、是否持久化，均未决定；瞬态总线本身不因此成为历史日志。

资源主动发布的展示状态与宿主真实收束状态是两条契约。下载进度、长期外部活动或保留的错误条目，不自动阻止会话回溯或资源移除。

### 插件互相调用

- 与事件机制共同设计契约归属、调用／发布来源、目标定位、运行环境边界和生命周期。
- 插件调用表达明确目标与输入、完成或失败；事件表达向感兴趣的消费者投递信息。具体调用形式、返回值契约与错误规则待定，不预先用事件拼装请求／应答。
- 复用现有公共模块、具型创建／动作、准备与执行校验、取消与收束能力；哪些接口可直接复用、哪些需要新增公开入口，在设计时明确。
- 调用可以指向未在界面打开的会话中的对象；执行仍检查真实目标及适用的资源授权，不通过加载前端控制器来激活目标。

## 待定设计

1. 事件声明与发布／订阅接口：契约身份、schema、声明归属与发起者 stamp、会话／资源定位，以及公共契约的包归属。
2. 进程内派发与后台到应用外壳的传输边界；顺序、异步订阅者失败、取消订阅、关闭清理与高频进度合并规则。
3. 标题等与事务结果相关的事件在何时发布，避免回滚或中间派生值泄漏给消费者。
4. 状态条目的键与更新／撤回语义：每资源一条还是支持多项，进度与严重度的公共表达、详情与概要的聚合规则。
5. 状态保留与恢复：资源移除方案是否足够，晚订阅、断连恢复、插件停用、重启与历史游标变化的处理；不默认新增存储格式。
6. 插件调用的公开入口、输入／输出与失败契约、来源传播、跨会话目标校验、与既有动作队列及准备阶段的关系。
7. 新事件与现有 `session.changed`、`session.progress`、会话控制器及对象流的关系：按职责决定复用、并存或迁移，避免复制状态真值。

## 落地与验收

- [ ] 给出事件投递与插件调用的接口方案，确认上述待定项，同步 SDK、运行时与交互文档。
- [ ] 实现发布、订阅、来源 stamp、契约校验、调用路由与生命周期；内置模块和外部插件遵守同一契约。
- [ ] 接入公共标题、资源通知与资源状态事件，应用外壳消费标题、toast 与 badge，替换无差别重读标题的路径。
- [ ] 验证未打开会话也可发出事件、更新外壳并受理适用的后台调用；订阅只消费所声明契约，来源不可由载荷冒充。
- [ ] 验证瞬态事件不追加历史、不移动游标；状态条目按最终确认的生命周期维护，展示状态不改变宿主收束判定。
- [ ] 按最终契约验证多资源聚合、晚订阅／重连与失败清理；toast、badge、详情列表由用户在 GUI 验收。

本计划只立案，不表示上述公开接口和界面已经实现。具体自动改名工具、下载器、代理通信与传送门功能另按需求推进。
