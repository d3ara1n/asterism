# 上下文自动压缩

> 立案 2026-10-13，自模型接入计划拆出。已确认：压缩是 agent 插件自身的策略，与其他 agent 层能力一致——达到阈值后在响应结束由 agent 决定并执行，models.run 不承担压缩，模型层只提供用量与窗口数据。

## 现状

- `src/execution/request.ts` 在响应结束后当输入用量超过模型 contextWindow 的 80% 时发出 `context_budget` 警告诊断，仅此而已；没有压缩节点或自动压缩。
- 历史为只追加会话树（`docs/conversation-core.md`），压缩不得改写既有节点，只能以新节点或事件表达。

## 待设计

1. 触发阈值与判定口径：当前诊断阈值 80%，压缩触发设想约 90%，最终值实施前拍板；用量取本轮 input 还是含历史重复编码，按请求实际口径确定。
2. 执行形态：agent 在响应结束后发起压缩（一次性补全），生成摘要作为后续请求的上下文起点；压缩期间是否阻塞用户回合、可否取消。
3. 历史表达：压缩产物作为何种节点/事件保存，旧上下文保持可查看；分叉、继续与历史导航以哪个位置为准；与 [跨模型桥接](todo-2026-10-13-cross-model-continuation.md) 的摘要材料关系。
4. 压缩使用的模型与角色：当前对话模型或 utility 角色；失败与取消的处理。
5. 手动压缩入口与自动策略的关系。

## 验收

- 用量超过阈值后，下一轮请求使用压缩后的上下文；压缩前内容在历史中仍可查看，既有节点不被修改。
- 压缩失败或取消不破坏对话，可重试；不压缩时请求投影与现状完全一致。
- 自动化验证使用合成会话；真实端点与 GUI 由用户验收。
