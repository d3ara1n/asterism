# 测试契约化清理

测试只验证契约。一个契约由一处测试覆盖，下游信任上游契约，不重复测试上游行为；需要在下游重测上游，说明契约封装有缺口，应修契约而不是加测试。覆盖率不是目标，测试数量越少、每个测试守护的契约越明确越好。

## 判定规则

每个用例必须能回答两点，答不出即删除或合并：

1. 它捕获哪一种具体失败。
2. 预期结果来自哪条契约（`docs/` 中的约定或 SDK 公开接口），而不是当前实现的输出。

## 清理对象

- 断言内部实现：调用次数、私有字段、英文诊断消息原文、整份快照逐字段比对。
- 守护已删除或错误规则的残留用例，以及只剩空断言的用例。
- 一个用例同时验证多个关注点的大型集成测试（如 `src/runtime/sessions.test.ts`、`src/plugins/sdk-runtime.test.ts`），按契约拆分或删除重复覆盖。
- 下游重复测试上游契约的用例：保留上游契约测试，删除下游重测；若下游必须重测，记录对应契约缺口。
- 依赖时序、单独运行会失败的用例（如目录 `see` 图片用例）。

## 保留基线

契约边界：记录解码、来源打戳与校验、插件配置校验与变更通知、IPC 校验、事务原子性；有明确失败机制的状态逻辑：工具参数部分 JSON 预览、响应状态机、历史分支导航、投影末尾截取。

## 步骤

- [ ] 逐文件列出用例，标注保留／合并／删除及对应契约；清单交用户确认。
- [ ] 按确认清单执行；发现的契约缺口另行记录。
- [ ] typecheck、测试、i18n 检查通过；本计划归档。
