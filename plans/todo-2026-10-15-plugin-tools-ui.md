## 已确认范围与分层

1. 插件可静态声明顶层工具，定义与 handler 一体提供；当前三个宿主入口不是数量上限。调用上下文由宿主提供，声明与每次运行的数据分离，不为资源工具增加 self 或免链接例外。
2. 外部插件通过 `@atelier/builtin-api` 扩展已有 Agent，无须重写资源或替换整个 renderer。内置实现也消费公共包，公共包不注册第二个插件。
3. Agent 界面机制全部归内置插件；通用 SDK 不建立跨资源 UI 槽位。应用组合负责公共出口绑定及宿主服务注入。
4. 界面通信需要通用请求／结果能力，不能局限于工具结果 renderer，也不为 ask_user 拼装专用事件问答协议。
5. UI 可独立于工具存在；与工具等待的绑定由插件业务负责。首个完整消费者是 ask_user；todo 只检验持续内容的表达能力，不实现完整产品功能。
6. 插件身份与关联对象分别表达。插件仍拥有自己的数据、调用与偏好，Agent 是关联对象；界面挂载不授予额外资源权限。

各阶段先用最小作者示例审视接口，再实施。示例应表达：工具和 UI 共用插件业务服务，回答能结束对应工具等待，持续内容无须依赖未结束的工具。

| C1 顶层工具 | 静态插件装配、现有执行链路与取消生命周期 | 声明与 handler 形状、调用上下文、重名及工具选择策略 |
| C2 通用调用与关联状态 | 稳定身份、公共契约、瞬态事件、运行生命周期 | 请求／结果／取消协议、关联对象绑定、状态读取与提交通道 |
| D ask_user 消费者 | 已有 Agent 界面 API | 工具等待、答案提交、取消／超时、重挂载状态读取 |

### C1 顶层工具

当前 `src/execution/core.ts`、`request.ts` 仍以固定入口声明和解析；`packages/sdk/src/runtime-contracts.ts` 没有插件直接顶层工具贡献。

- [ ] 设计完整声明、handler 和绑定本次调用的上下文；复用现有调度、取消、过程、结局与审计。
- [ ] 明确重名处理、工具选择及 `agent.tools / excludeTools` 的关系，不直接照搬资源工具策略。
- [ ] 明确只读／执行门面、关联对象、内容资格与活动期边界。
- [ ] 验证工具在首个请求即声明，资源 attach/detach 不改变静态目录，授权没有自身访问例外。

### C2 通用调用与插件关联状态

`docs/plugin-sdk.md` 只预留插件调用，没有已导出的 `plugin.ipc.calls`。现有事件总线是瞬态订阅，不保存当前值，不是请求／结果通道。`src/plugins/sdk-context.ts` 的对象 get/commit 检查资源类型归属；外部插件目前不能直接在内置 Agent 上保存自己的对象级数据。

- [ ] 设计具型请求／结果／取消通道，与事件和当前状态读取协作；不把问题另存为资源来运输 UI，不在事件上临时拼请求／应答。
- [ ] 绑定调用插件与真实关联对象，明确数据归属、事件／记录来源和清理。不得直接删除 `own(ref.kind)` 检查或开放 Agent 私有状态。
- [ ] 同一插件业务服务能被工具 handler 与前端调用共同消费；答案提交通道不被正在等待的工具占住对象队列。
- [ ] 处理先订阅后读取的竞态，校验交互身份与当前状态，重复／迟到答案不能二次结束工具调用。
- [ ] 区分前端重挂载、通信断连与运行时重启；不可恢复的 Promise 不宣称恢复，长期展示不等于必须持久化。

### D ask_user 联调

候选业务路径：handler 从调用上下文取得 Agent 与会话，建立插件拥有的待回答项；UI 按该身份读取／订阅当前值，显示问题；用户提交后后台校验作用域和交互状态，结束对应等待并返回工具结局。临时表单可只在内存，最终调用与回答通过既有工具历史保存。

- [ ] 验证工具调用→问题面板→答案→模型收到结果的闭环。
- [ ] 验证不同 Agent、会话与并发交互不串答，重复／迟到答案不重复完成。
- [ ] 设计工具取消、插件释放及异常退出如何结束等待、撤销问题 UI 和清理订阅，不遗留可写执行门面。
- [ ] 明确 Agent 整次执行超时是否计入用户等待，以及暂停等待对活动、回溯和收束的影响；不能默默取消已有超时。
- [ ] GUI 验证问题等待期间历史可读、输入区完全隐藏；允许的回答／退出操作由插件定义。
