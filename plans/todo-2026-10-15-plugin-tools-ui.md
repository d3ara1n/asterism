# 内置插件公共包、顶层工具与 Agent 界面扩展

立案日期：2026-10-15。

## 状态与用途

**A/B 的代码与自动验证已完成，可以进入 C 阶段接口设计。** 内置分包、身份、依赖解析和真实契约共享已有实际消费者验证；分包后的 GUI 回归待用户验收。顶层工具、通用调用与 UI 插槽尚未实现，后续候选接口和生命周期策略仍不是已定 API。

已确认的顶层工具边界见 [运行时](../docs/runtime.md#工具匹配与宿主操作入口) 与 [插件 SDK](../docs/plugin-sdk.md#工具贡献)。本计划是这组后续工作的唯一实施清单；接口定案后将最终规则写入对应真值文档，完成后归档。

## 已确认需求

1. **插件可声明顶层工具。** `resource_list / resource_inspect / resource_call` 是此前已有的三个入口，不是数量上限，也不排斥插件扩展。顶层工具是 harness 普通工具，模块直接声明名称、说明、参数、结果与 handler 后注册；不要求走资源工具的“共享定义、导出定义、资源实现”链路。注册在装配时完成，运行期间不动态增删。
2. **调用上下文由宿主提供。** 顶层工具声明与某次运行的数据分离，handler 调用时通过上下文取得当前执行对象、会话及所需运行信息。资源工具保持显式目标与链接要求；不引入自链接、自身访问免链接、`self` 标记或无参 inspect 自身的扩展。
3. **外部插件能扩展内置 Agent。** todo 等功能不应要求作者重写 Agent 资源或替换整个卡片。内置插件拆成两个物理包：随应用分发的实现包，以及供其他插件依赖的公共契约／API 包。实现包也依赖该公共包；公共包包含扩展内置插件所需的契约，不依赖内置实现，不自行注册第二个插件。
4. **Agent 扩展点属于内置插件。** 卡片槽位、输入区控制及 Agent 领域能力由 `atelier.builtin` 公开；通用 SDK 提供声明、贡献装配、通信与生命周期机制，不内置 Agent 专有插槽名称。
5. **界面通信是通用能力。** 不将前后端交互局限为工具结果 renderer，或只支持 ask_user 的专用问答通道。工具、用户操作和其他插件业务均应能使用相同机制。
6. **UI 可以独立于工具存在。** 支持长期展示的内容，也支持一次性交互；界面可在工具调用前存在，也可由调用触发显示，工具结束后仍可保留。关闭、隐藏组件不应被机制自动解释为回答、取消工具或删除业务状态。
7. **需要多种呈现与输入区协作。** 需求包含对话框、编辑区上方的卡片，以及卡片上下左右区域或覆盖底部的内容；扩展可请求输入区不可操作或隐藏。具体槽位集合与组合方式待设计，不预先枚举为 ask_user、todo 两种组件类型。
8. **本专项以 ask_user 作为首个验收消费者。** 优先验证通用机制，问题 UI 和 tool result 第一版可简单。todo 用于检验设计能否支持独立面板和持续状态，不在本专项实现完整 todo 功能。

## 建议的分层与解决方向

### 1. 内置分包与公共提供方（已完成）

当前包、身份、实例共享和兼容规则以 [插件 SDK](../docs/plugin-sdk.md#公共模块与契约身份) 为准，作者说明与可编译示例见 [公共 API 包](../packages/builtin-api/README.md)。

- [x] `@atelier/builtin` 与 `@atelier/builtin-api` 两个物理包；通用 SDK 独立；基础控件归内部 `@atelier/ui`。
- [x] 插件身份改为 `atelier.builtin`，宿主 `core.*` 协议保持职责独立；开发数据不做兼容迁移。
- [x] 公共 Agent 动作／输入／配置／记录与私有状态分开；应用配置仅投影所需目录字段；应用信息注入，装配留在应用侧。
- [x] 公共提供方登记、依赖与 semver 校验、环境出口、真实导出转接；后台和前端分别共享，缺失／失败沿依赖传播。
- [x] 两个独立源码消费者验证真实声明引用、re-export、私有安装副本隔离、版本拒绝，以及真实 Agent 动作的外部准备；独立中间 npm 包的嵌套安装／symlink 按包自身依赖校验。
- [x] 前端依赖装配及提供方视图登记失败传播；测试验证环境各自绑定的实例；混合失败路径仍先完成消费者清理。
- [x] 作者示例消费现有动作契约；不以尚未实现的 UI 插槽作为包分离验收前置。
- [ ] 用户 GUI 验收迁移后的首页、Agent 卡片、设置及源码插件加载；工具与 UI 扩展仍按下方阶段推进。

### 2. 通用机制与 Agent 领域扩展分开

| 层次 | 建议职责 |
| --- | --- |
| SDK／宿主 | 具型扩展点与贡献装配；按贡献插件绑定上下文；前后端调用、事件与生命周期；静态顶层工具注册 |
| 内置插件公共包 | Agent 槽位与上下文契约、输入区控制语义、明确公开的领域操作 |
| 内置 Agent 实现 | 安放槽位、组合贡献、处理布局和焦点、合并输入区约束、维持 Agent 执行规则 |
| 扩展插件 | 顶层工具、组件、自己的前后端业务接口、状态与可选持久化 |

插槽贡献应静态注册，实际是否展示及展示内容可以随业务状态变化。通过具名契约引用扩展点，不靠 DOM 选择器或任意字符串 hook 注入。

### 3. 将呈现、可见性、业务状态和工具等待分开

不把“持久 UI”与“非持久 UI”做成两套组件协议。设计时分别回答：

- **位置与呈现**：由哪个公开槽承载；是参与布局、覆盖还是对话框。初始位置由真实消费者决定，允许提供方后续增加槽位。
- **可见性**：当前是否展开、能否关闭、从哪里重新打开；界面卸载与业务结束分离。
- **输入区影响**：正常、禁用或隐藏。多个扩展同时请求时必须合并，关闭一个不能解除另一个仍有效的约束；停止运行的入口不能随输入区一起失去。
- **业务状态**：由插件拥有；可为运行时内存、当前对象／会话数据，或需要历史语义的记录投影。长期显示不等于写数据库，UI 组件本身不作为持久业务实体。
- **工具等待**：handler 是否等待某个交互结果由该工具决定，UI 机制本身不要求挂到某个 callId。ask_user 可以关联本次调用，todo 不需要依附未结束的工具。

界面隐藏后仍有等待事项时，需要可见的重新进入入口。重挂载／重连读取插件当前状态；运行时重启后无法恢复的 Promise 不冒充恢复。具体关闭、恢复与超时策略见下方待决定项。

### 4. 通用前后端调用，加现有事件与状态读取

优先评估独立的具型请求／结果／取消通道，与现有瞬态事件协作。前端组件向其所属插件提交输入或读取当前状态，后台发布状态变化；同一插件业务服务可被工具 handler 和前端调用处理器消费。不通过把问题持久化为资源来运输 UI，也不在瞬态事件上临时拼装请求／应答。

ask_user 的候选路径：

1. 顶层 handler 从本次上下文取得发起 Agent 和会话，建立插件拥有的待回答项。
2. Agent 槽中的扩展组件读取该作用域下的当前待回答项，并订阅后续变化。
3. 用户通过插件调用接口提交回答，后台校验作用域、交互身份与当前状态。
4. 对应等待结束，handler 返回正常工具结果；工具历史仍由既有执行链路保存。

临时表单及待回答状态可以只保存在内存中；最终调用与回答作为工具结局进入历史。同步读取与订阅之间的竞态、重复／迟到回答、取消传播需在机制或该业务服务的明确边界验证。通用通信不依赖工具 renderer 当前是否挂载，也不应被等待中的工具占住对象队列而无法提交答案。

### 5. 插件身份与关联对象必须分别表达

例如外部 todo 插件扩展内置 Agent：插件仍是数据与调用的所有者，Agent 是关联对象。挂载 UI 不把外部插件变成 `atelier.builtin`，也不自动授予其他资源的执行权限。

需设计能以真实对象为作用域保存插件自己契约数据的途径，并明确门面、事件来源、记录来源和清理规则。可以评估受宿主绑定的扩展作用域，而不是直接删除现有 `own(ref.kind)` 检查。默认不开放内置插件私有状态；需要领域操作时消费内置插件的公开契约。

## 递进实施顺序

各阶段先审视接口和边界，再决定实施；不要先堆砌一个 ask_user 专用闭环，再倒推扩展机制。

| 阶段 | 工作 | 依赖与完成标准 |
| --- | --- | --- |
| A | 已完成：内置公共包与最小外部作者示例 | 公共范围、纯契约入口、本地包分发与版本边界已确定；示例使用现有动作准备 |
| B | 已完成：公共提供方装配及身份共享 | 内置提供方与两个外部消费者共享真实声明；依赖、版本、环境及失败传播有契约验证 |
| C1 | 插件顶层工具声明与调用上下文 | 基于 A/B 已有身份机制确定每次调用的上下文；复用调度、取消、过程、结果及审计，不增加资源 self 例外 |
| C2 | 通用前后端调用与插件作用域状态 | 依赖 A/B 的身份边界；调用能脱离工具视图存在，插件状态可关联现有 Agent |
| C3 | 通用贡献装配与内置 Agent 公共槽 | 依赖 B；槽和输入区语义归内置插件，第三方贡献身份保持独立；具体交互可与 C2 联调 |
| D | ask_user 消费者 | 依赖 C1/C2/C3；用最小问题界面验证回答、关闭／重开、取消、并发作用域隔离 |
| E | 契约与 GUI 验收、文档收尾 | 自动验证机制，用户验证实际交互；todo 只检查表达能力，不实现产品功能 |

C1、C2、C3 可在共同边界确定后分别推进，不要求把彼此无关的实现串成一条长链。

## 待审视、尚未定案

- 公共包新增前端／后台子入口时按实际消费者设计，当前只提供纯契约 `/contracts`；Agent UI 作者示例随 C3 一起验证。
- 顶层工具和插件通信的具体声明形状；重名处理、工具选择策略与现有 `agent.tools / excludeTools` 的关系。不能将此前只针对资源工具的策略直接推定适用于所有顶层工具。
- 运行上下文提供哪些只读／执行门面，外部插件如何操作自己的关联数据，生命周期及内容访问范围如何绑定。
- 通用扩展点贡献接口；Agent 初版槽位、同槽多个组件的顺序、对话框作用域、多卡片并存及输入区约束合并规则。
- UI 关闭、暂时隐藏、显式取消、重新打开和停止 Agent 的行为；ask_user 等待期间输入区是否禁用或隐藏。
- 当前 Agent 整次执行有超时；等待用户是否消耗该预算，以及暂停等待如何影响活动、回溯和收束。不可默默取消原有超时或无限延长运行。
- 通信断连、前端重挂载与运行时重启的区别；待回答项重读与事件竞态如何处理，哪些交互明确不恢复。
- 插件关联当前数据、时间线记录与 UI 偏好的归属；todo 将来是否要求随历史投影恢复，不能由界面是否常驻反推。
- 先前讨论的自身身份提示块、插件提示块贡献是否仍有实际需要；不作为顶层工具或 UI 扩展的默认前置，不向系统提示词复制 Agent 资源工具目录。

## 验收边界

- [ ] 外部源码插件只消费 SDK 与内置公共包即可向现有 Agent 贡献 UI，不声明新的 Agent 资源、不替换内置 renderer；复用现有插件加载测试设施验证依赖与契约身份。
- [ ] 顶层工具在首个请求即有声明；资源 attach/detach 不增删这份静态注册目录；资源工具授权无自访问例外。
- [ ] ask_user 从工具调用到界面回答再到模型收到结果形成闭环；不同 Agent、会话和并发交互不串答，重复／迟到回答不会再次完成调用。
- [ ] 工具等待不会阻塞回答提交通道；取消、关闭与插件释放能结束等待及清理订阅，不遗留可写执行门面。
- [ ] UI 关闭／重挂载与工具结束独立；无需运行中的工具也能贡献组件，足以表达未来 todo 常驻或按需显示的需要，无须实现 todo 工具。
- [ ] 多贡献者的输入区控制按已定规则合并与释放，停止／重新打开入口可达；具体布局、键盘、焦点与交互由用户验收。
- [ ] 每项自动测试对应上述明确的失败机制；类型检查、必要的加载／契约测试与构建按实施阶段选择，不为视觉配置编写测试或扩建无关测试框架。
