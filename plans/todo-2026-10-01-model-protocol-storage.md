### 配置与作用域

提供商连接作为本机应用级配置，各任务可复用；不随某个任务创建或销毁，也不因此取得任务资源访问权。开发版与发布版沿用既有数据目录隔离。

一条连接配置对应一个协议与服务端点；同一服务若提供多个协议，可以建立不同连接。模型列表归属于连接，首批允许手动填写模型 ID，不依赖供应商具备统一的模型发现接口。自动发现仍在本计划跟踪，首批延后。

| 数据 | 建议字段与含义 |
| --- | --- |
| 连接 | 稳定 ID、显示名称、协议 ID、base URL、启用状态、配置修订号 |
| 模型 | 稳定本地 ID、连接 ID、服务端模型 ID、显示名称、启用状态、能力与生成参数 |
| 鉴权 | `api_key` 或 `none`；API key 仅存凭据引用 |
| 凭据状态 | 缺失、可用、存储不可用、解密失败；不回读 key |
| 测试结果 | 绑定连接/模型及配置修订号，记录结果与耗时；不是模型完整能力认证 |

首批提供 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages 三种适配。协议注册可扩展，服务商名称不作为协议判定条件。首批支持 API key 与无鉴权本地服务；OAuth、自定义鉴权头和模型自动发现延后，继续由本计划跟踪。温度等生成参数配置在提供商下的具体模型上，模型角色不重复保存；具体字段与协议支持范围在实施前细化。

### 存储与凭据

在现有 `db/weft.sqlite` 增加连接与模型配置表，使用正式数据库迁移；保存非秘密配置和凭据引用，不向任务事件写入 API key。配置修改递增修订号；后续真实执行需捕获当次非秘密配置快照，不能仅依赖可变的最新配置。具体表字段在恢复实施前细化。

API key 由 Electron 主进程调用 `safeStorage` 加密，密文在应用数据目录的 `credentials/` 保存。它是系统保护的加密能力，密文文件仍由织台管理，不等同于直接将每条 API key 作为系统钥匙串条目保存。本机 Electron 44.5.1 类型已包含 `isAsyncEncryptionAvailable/encryptStringAsync/decryptStringAsync`，可使用异步接口。

任务运行时继续作为数据库与密文文件写入者；主进程提供窄范围的加解密能力，解密后的秘密只在实际调用所需进程内使用，不提供给 renderer 查询。renderer 输入 key 时可以短暂持有待提交值，保存后读取接口只返回凭据状态。主进程与运行时之间需补充私有的凭据服务通信，不能复用可供 renderer 任意调用的解密命令。

系统加密不可用或 Linux 仅提供 `basic_text` 时，拒绝持久保存 API key，允许保留未配凭据的非秘密配置；不静默回退明文。无鉴权服务仍可使用。凭据无法解密时保留配置并要求重新填写，不把空 key 当作成功读取。平台实际效果仍需验证。

替换凭据使用新引用，先持久化密文再提交数据库关联；失败处理与旧密文清理要避免破坏当前可用配置。更新命令明确区分保持、替换、清除凭据；空白输入不隐式删除旧 key。凭据引用生成于能力层，不接受任意路径。

### 能力接口与测试

配置能力提供列出、创建、修改、启用/停用、移除连接和管理模型的接口。测试能力提供开始、查询状态、取消与结果通知。返回公开配置和结构化状态，界面自行选择表单与展示组件。设置入口复用既有控件与视觉，不改变整体交互范式。

连接测试使用用户选择的已保存配置与模型，发送独立的短生成请求；明确此操作会请求所选服务并可能产生费用。测试内容不含任务正文，不写入任务 transcript；测试输出只作为诊断结果。一次生成成功不代表工具、推理、多模态或全部兼容能力已经验证。

开始测试需快速返回测试 ID，网络请求异步执行并可取消。现有 `RuntimeRequests` 在 15 秒命令超时后终止运行时，不能让模型网络请求占用该等待；网络超时应结束测试任务并返回结构化错误，不能当成 runtime 崩溃。相同配置的修改与测试使用修订号关联，旧测试结果不能覆盖新配置的状态。

错误至少区分配置错误、凭据缺失/解密失败、鉴权失败、模型不可用、限流、网络/超时、协议响应错误和用户取消；仅在服务端提供可靠信息时细分，保留通用服务端错误。错误信息脱敏，不直接向日志或 renderer 转发含请求配置的 SDK 错误对象。保存配置不自动请求外部服务。

### 本阶段验收

- 可创建连接、添加模型、保存后重开读取；凭据更新的保持/替换/清除语义正确。
- 配置读取、日志和错误不回传明文 key；凭据不可用有明确状态。
- 连接测试使用选择的协议、端点和模型，正常/失败/取消都能结束；慢请求不影响工作台或触发运行时终止。
- 数据库迁移和存储错误在隔离目录验证，协议适配使用合成响应做针对性验证；真实 key 只在用户本机应用配置，真实服务调用需已有明确测试授权。
- GUI 保存、重开、系统凭据后端与真实连接效果由用户操作验收，不进行自动启动后杀进程的冒烟。

提供商阶段交付连接与具体模型，模型角色和 agent 配置按下一节接入；真实 transcript 与工具批次在执行契约明确后实施。

## 1. SDK 与协议边界（建议）

| 接入层 | SDK / 协议 | 职责 |
| --- | --- | --- |
| 统一模型适配 | `ai`、`@ai-sdk/openai`、`@ai-sdk/anthropic` | 请求、流式解码、协议映射；实际版本实施前核验并锁定 |
| OpenAI 原生协议 | Responses | OpenAI 官方服务优先使用；显式选协议，不依赖 SDK 默认值 |
| OpenAI 兼容协议 | Chat Completions | 为只支持此接口的服务提供独立配置；不把兼容聊天等同于兼容 Responses |
| Anthropic 协议 | Messages | 明确内容块、工具结果、thinking 续接约束 |
| 厂商官方 SDK 备选 | `openai`、`@anthropic-ai/sdk` | 如统一适配确有无法覆盖的能力，再评估局部原生适配；不预先安装两套重复实现 |

供应商、协议、模型分开配置。候选配置包括：配置身份与版本、协议类型、base URL、模型 ID、凭据引用、经验证的能力与参数。相同协议可以对应不同服务端点；不只靠模型名称推测全部能力。

首批 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages 三种协议已接入连接测试；真实对话与工具执行尚未接入。

接入不要求使用 Vercel AI Gateway。服务端点和凭据由用户明确配置，不隐式转发到其他平台。

运行时自行控制模型与工具循环。SDK 的工具辅助能力不得绕过织台授权、操作记录或轮次边界。一次执行轮次可以含多次模型请求，二者使用不同身份。

## 2. 三种不同的数据（建议）

1. **织台历史**：用户输入、模型输出、工具请求与执行结果、资源变化、配置生效、失败与中断；用于重建与分叉。
2. **provider 请求投影**：从历史位置和冻结配置构造 SDK 消息，再映射为目标协议；是派生数据。
3. **工作台投影**：代理流、执行段、操作卡片、用量、状态；同样是派生数据。

数据库的公开长期契约不直接采用某版 SDK 的 `UIMessage[]` 或 `ModelMessage[]`。SDK 格式可作为带适配器版本的续接资料保存，但不能成为理解整个任务的唯一依据。

对话记录采用平铺条目，保留每项内容的类型、顺序、关联与协议续接资料；平铺不意味着将一次响应合并成一段无类型的文字。

## 3. 平铺 Transcript（组织方式已确认，具体字段待定）

基础条目为 `message`（用户消息）、`thinking`（模型思考）、`toolcall`（模型工具调用）与 `text`（模型正文），后三类均属于模型输出。所有条目同级平铺，按发生顺序排列；不存在包裹后三类的模型消息容器。界面独立决定分组与折叠，不反向规定能力层的数据结构。

条目身份、代理身份、所属分支、执行轮次与模型请求分别关联。用户输入可以先持久化、后开始轮次，因此不是所有条目在创建时都有轮次/模型请求身份。协议要求的消息边界与原始项目身份作为关联信息保留，由适配层恢复；不能只凭相邻条目的类型猜测分组。

| 基础条目类型 | 来源与含义 | 必需信息 |
| --- | --- | --- |
| `message` | 用户输入 | 正文、来源，必要时包含附件引用 |
| `thinking` | 模型返回的思考 | 实际返回的内容、所属请求、必要不透明资料；不宣称获得隐藏推理全文 |
| `toolcall` | 模型提出的工具调用 | 调用身份、工具名、参数、所属请求、解析与完成状态 |
| `text` | 模型正文 | 输出正文、所属请求、完成状态 |

工具执行结果属于能力层的执行事实，通过调用身份关联 `toolcall`；结果保存位置、事件载荷与查询形状在能力契约中明确，不因此增加第五种基础 transcript 类型，也不将执行器返回的内容称为模型输出。条目载荷可以包含附件或结构化数据。必要的 provider 原始块作为续接资料关联条目，不决定 transcript 或 UI 的分组。

规则配置和资源绑定事件保留自身来源，不伪造成用户亲口发言。模型投影负责用目标协议允许的角色表达这些信息；资源正文始终属于数据。

新增类型需要同时明确校验、保存、展示和模型投影方式。条目可以与其他类型交错；同一响应可以产生多个同级条目。具体字段、扩展封套与未知类型处理尚未冻结。

### 提供商配置闭环之后：能力层最小契约

先以独立于 UI 的接口草案和具体事件样例收敛以下事项，再实施：

1. 四种 transcript 条目的字段、生命周期与扩展契约；条目增量、模型请求与执行轮次分别关联。
2. 模型输入构建：规则、历史、资源事件、工具目录与结果如何组成实际请求；保留什么可以解释某次调用实际收到的内容，排除凭据。
3. 执行与错误：正常完成、工具拒绝/失败、模型失败、取消、流中断、结果未知；明确谁重试、重试什么、如何继续。
4. 持久化与恢复：哪些事实先落盘、哪些状态可重建、哪些副作用不能自动重放，以及中断条目如何进入后续上下文。
5. 对外能力接口：提交输入、取消、显式重试/继续、查询记录/调用结果/实际模型输入、订阅增量与状态；具体命名与参数待定。

用正常工具往返、工具失败、模型流中断、取消后重开四类场景核对契约。界面在这些能力上自定义渲染和交互，折叠组、卡片等组件结构不进入执行与存储契约。

## 4. 续接所需的 provider 数据（建议）

通用内容与必要协议资料一并保留。候选例子包括 OpenAI reasoning item 的身份与 encrypted content，以及 Anthropic thinking 的 signature、redacted thinking 数据。所需字段因协议、模型和功能而异；只保存 API 实际返回的内容。

这些资料关联具体 transcript 条目及对应协议项目，并带 provider 配置作用域、协议、模型与适配格式版本。相同协议并不保证不同服务端点或模型可复用同一签名/服务端身份。

OpenAI Responses 默认建议显式 `store:false`，由本地重建上下文，并保存适用推理响应中的 encrypted reasoning。当前 OpenAI 官方文档说明无状态请求默认返回 encrypted content，AI SDK 文档仍展示显式 `include`；具体取回方式按锁定 SDK、服务端与模型核验，不把某个参数写法当成持久化契约。不以 `previous_response_id` 或云端 conversation 作为唯一历史。`store:false` 不等于服务商完全不留存任何数据。

已确认对话期间允许切换模型，agent 保持不变。跨 provider 不传递对方的签名、不透明推理块或服务端对象 ID。初版建议在轮次交界切换；切换前验证可投影性。无法忠实投影时明确阻止直接续接，或通过用户明确选择的摘要/新对话上下文继续，不能静默丢块。生效边界与不兼容时的具体流程仍需拍板。

## 5. 工具请求与资源操作（建议）

工具协议采用独立操作名和显式 `resource_id`，例如文件读取与编辑分别有自己的参数 schema。调用经过：完整响应判定 → 参数解析/校验 → 身份与冻结授权校验 → 操作开始记录 → 实际执行 → 结果落盘 → 下一次模型请求。

模型提出调用不表示操作已经开始。授权拒绝、参数错误和未知资源也必须能记录为调用结果，而不要求先建立有效资源操作。

本地调用身份、provider 调用 ID 与 `operation_id` 分开关联，避免重试、分支和不同响应的 ID 混淆。首批目录工具可约束为一个被接受的调用对应一个操作，但不能据此将两种概念合并。

已确认同一批次所有工具调用共同收束后，统一把结果交给模型，再发起下一次模型请求；进度可以逐项发布，不能用部分结果提前续轮。成功、失败和授权拒绝分别记录，取消或结果未知按执行状态处理。批次通过身份关联平铺的调用与结果，不改变 transcript 结构。流式参数未完成且未校验时不得执行；具体并发度、调用启动时机与取消策略仍待明确。

工具调用/结果由适配层按目标协议合法配对：织台内部工具结果不等于某个 provider 固定的消息角色。未知副作用保留未知，不能转成已失败后自动重试。

## 6. SQLite 与对象存储格式（建议）

沿用现有事件表与对象存储，扩展正式事件契约和可重建索引。无需改成每次覆盖一个会话 JSON 文件。

- 事件只追加；消息正文、附件和协议资料可用不可变对象引用。消息列表/状态索引可以更新，但必须可由历史重建。
- 为消息接收、模型请求开始与终结、输出片段与收束、工具调用与结果补齐事件。最终事件名、关联和事务边界在实施前冻结。
- 每次模型请求记录实际消费的历史位置、具体内容引用/投影清单、规则/工具/绑定版本、provider 配置版本、模型、生成参数与适配器版本。仅有一个分支最新位置不足以解释某个代理实际看到了什么。
- 规则正文、工具定义与非秘密配置采用不可变版本引用，避免版本号仍在而旧内容已被覆盖。
- 存储格式应是可序列化的 JSON 与明确的二进制引用；不持久化 SDK 类实例、Buffer 的隐式 JSON 结果或只能在进程内使用的对象。
- 当前对象存储仅支持 UTF-8 正文；图片/二进制支持不能假定已经存在，接入时扩展对象类型与完整性检查。

版本分开管理：SQLite 表结构版本、事件载荷版本、内容格式版本、provider 续接资料/投影版本。数据库升级不能代表旧消息已经自动兼容新 SDK。

旧事件由版本化读适配解释；不通过改写旧事实完成迁移。可迁移表结构、索引与派生缓存。旧记录没有的模型内容必须明确缺失，不能补造。

检查点继续是可丢弃、可重建的缓存。首批可先不生成检查点，避免其格式阻塞真实消息落盘；已有检查点设计事项仍由运行时能力计划跟踪。

## 7. 流式、取消与崩溃（建议）

UI 接收即时增量；持久化按有序片段批量追加，并在完成、取消或错误时记录收束。持久化片段不必与网络每个 token 一一对应；只有已提交的片段才具备崩溃恢复保证，最近尚未提交的增量可能丢失。

每段带稳定关联与序号，避免重连造成重复正文。正常结束形成完整消息投影；部分输出继续可查看，并明确未完成，不自动作为完整 assistant 回复续发。

流结束不等于正常完成：区分正常终结、输出截断、取消、网络断开和进程退出。用量缺失记未知；保留 provider 原始结束原因及归一化状态，不把异常折算成成功。

重开应用时追加中断/对账事件，不修改已有开始事件；不自动重新提交模型请求或执行未完成工具。需要为不完整工具配对定义显式继续策略，不伪造成功结果。

首批建议关闭 SDK 隐式请求重试，由运行时记录明确的重试尝试；模型请求重试与工具副作用重试分开。取消模型网络请求不承诺能撤销已经发生的资源副作用。

## 8. 凭据与内容保留（凭据方案已定，内容保留待定）

凭据保存沿第 0 节已确认方案：主进程使用系统安全存储能力保护，运行时仅在请求所需范围获得凭据；数据库配置保留凭据引用，renderer 不回读秘密。平台加密不可用时不保存明文 key，实际跨平台行为需验证。

候选保留策略：用户输入、实际输出、工具结果与必要续接数据作为本地任务历史保留；删除/清理另设明确的数据生命周期，不用普通 detach 代替删除。新保留策略不默认承诺历史正文永久可用。

完整 HTTP 请求/响应抓包默认关闭；默认保存无凭据的请求清单、版本引用、实际输出与必要协议数据。调试抓包是独立可选能力，需要明确脱敏、保留期限和删除方式；未定前不实现。

API key、认证头、带秘密的 URL/自定义 header 不进入任务事件、普通错误消息或日志。任务正文与 thinking 资料也不是普通运行日志。原始 provider 数据不能未经筛选整包塞入所谓 metadata。

## 9. 第一批交付与验收

提供商与具体模型、加密保存与连接测试、模型角色与 agent 配置、首页选择已实现；下一阶段为执行契约与真实单代理对话。首页发送当前禁用，不生成占位会话。执行阶段接入首次消息创建、utility 命名、真实流式回复、多次请求组成的单代理轮次、工具批次与结果记录、取消/中断、重启后读取与合法续接。目录 IO 与操作 diff 随运行时能力计划衔接。

针对具体风险验证：

- 三种协议各自的调用与结果关联；拒绝/失败结果同样可合法投影。
- 文本与多个工具块的顺序，以及适用模型的必要续接资料往返不丢失。
- 中断流中不完整工具参数不执行，部分消息不冒充完成。
- 同一轮次多次模型请求仍使用冻结绑定；下一轮应用 pending。
- 重启从本地记录构造下一请求，不依赖 provider 的云端会话记录。
- 旧数据库可读、迁移失败回滚、较新格式不被旧程序误读。
- 测试使用合成协议样本与隔离数据；真实 provider 验收单独使用用户配置，真实会话与凭据不入仓库。

多代理、自动压缩、MCP、完整资源恢复和性能优化继续由既有计划跟踪；agent 配置预留委派语义不表示已实现多代理执行。跨 provider 切换的兼容流程、图片/文件输入、调试抓包的首批范围由本计划在拍板时明确，延后项不能从计划中消失。
