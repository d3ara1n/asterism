# 时间轴派生状态与历史模型

## 背景

游标观察已落地：`committed` 只交付新增记录，`cursorChanged` 以当前分支固定快照统一表达追加、回溯与分叉；会话命名是首个消费者，标题 = `last(SessionNamed, path)?.title ?? 截断(first(UserMessage, path))`，两者皆无时保持不变。会话标题经 `title.set` 直接覆盖。机制见 `docs/plugin-sdk.md#记录提交与执行游标观察`。

宿主建会话时的首条消息截断与命名模块的回落截断分两处独立维护，属于各自领域，不合并。

## 设计依据

以下取舍已与用户确认，后续实施直接沿用，不再重新论证。

- **问题来源**：标题、资源状态等依赖时间轴保存的当前值，需要随追加、回溯、分叉同步；但命名事件属于插件领域，宿主不认识，不能在宿主里写 `if 命名事件 then 改标题` 一类分支。因此宿主只提供「游标移动」这一通用通知，由领域模块自行按当前分支重建。
- **三类状态**：依赖时间轴的派生当前值（标题、资源存在性与状态）在游标变化时重建；直接派生自时间轴的值（Agent 上下文）在请求时即时投影，只有时间轴一个真值，不接入本机制。
- **两个入口分开**：`committed` 表示新增记录，`cursorChanged` 表示游标移动，形状各自固定，消费方不必写 `if 提交 else if 回溯`。追加、回溯、分叉统一视为游标移动，入口不带变化原因。
- **命名两步走**：用户消息触发命名，结果只追加 `SessionNamed`；游标观察者看到新事件后按规则改标题。同一规则同时覆盖新命名与回溯，回溯不追加恢复事件。
- **只看当前分支**：观察参数和查询都指向当前分支（时间轴）。历史分支不在「时间轴」概念内，树本身暂无已知消费者。
- **初始标题只是概念**：它不另存，也不提供 get 或接口，每次由当前分支首条用户消息临时推导。没有命名插件时，宿主建会话时得到的标题就是整个生命周期的标题。
- **标题直接覆盖**：标题只有业务层 `sessions.title` 一个真值，UI 只读它。不需要 CAS，写入不会失败，也不报告失败。两个命名插件互相覆盖属于安装问题，机制不处理。
- **观察者可以追加**：存在观察后追加的真实需求。追加会再次移动游标，所以派发排队、不递归，重建必须是「按当前分支重算一遍」的幂等逻辑。
- **派生值写入时机**：派生值在原提交之后用独立事务写入，失败只记日志，不回滚原提交。队列清空后，每个会话发一次界面通知。
- **资源用全量重放**：在当前分支上按资源分组取 last，得到逻辑状态，再与派生存储对比两个当前值。不对移动前后的两条时间轴做 diff 再求逆，因为求逆需要给每种事件定义逆操作，分叉与多次回溯叠加后容易出错；全量重放能直接适配各种情况。
- **截断分两处**：领域与心智模型的隔离比消除重复更重要，将来两处出现维护分歧也可以接受。

## 待办

### 1. 快照按需按路径构造

现状：有观察者时，每次提交都读取全会话节点、映射记录并构造快照（`src/plugins/loader.ts` 的 `afterCommit`，`src/plugins/sdk-context.ts` 的 `snapshot()`）；Agent 每写一个块都触发一次。

- 快照改为惰性：观察者实际调用 `records.*` 时才读取。
- 首尾索引按路径直接定位，不先读全会话再过滤。
- 保持固定快照语义：后续排队提交不改写此前快照。

### 2. 资源状态迁移到游标重建

现状：资源存在性与状态在 `runtime/workbench.ts` 中按路径折叠，未走游标观察。

- 采用全量重放：游标移动后在当前分支上按资源分组取各自的 last，得到逻辑状态，再与派生存储（工作台卡片、存在性）reconcile；不对前后两条时间轴做 diff 求逆。
- SDK 在快照上提供分组查询（候选 `records.lastBy(Contract, key)`），复用首尾索引。
- 明确哪些资源状态是派生当前值、哪些即时投影，与 Agent 上下文的即时投影划清。

### 3. 历史树（session）与时间轴（path）模型审阅

观察入口参数已统一指向当前分支；树本身目前没有明确消费者。审阅并给出改进方案：

- `RecordQuery.scope: "path" | "session"` 是否保留 `session`；列出现有调用点及其是否真需要跨分支。
- 树与时间轴在 SDK、宿主（`SessionTree`、`shared/session-path.ts`）、文档中的术语与职责是否一致，对照 `docs/glossary.md`。
- 游标、查看位置（history view）、执行位置三者的语义与接口是否清晰；`cursor_selections` 审计日志的定位。
- 跨分支需求（若有）应以何种独立能力提供，而非混入时间轴查询。

结论属于对象模型与 SDK 语义，需用户拍板后写入 `docs/timeline.md`、`docs/plugin-sdk.md` 与 `docs/decisions.md`。
