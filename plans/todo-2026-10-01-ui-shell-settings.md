# 补齐 UI 壳子与设置入口

> 立案 2026-10-01。当前优先任务，UI 实施在独立会话推进，完成情况与用户验收回填本计划。保留已确认的原生材质、内容表面与公共控件风格；设置容器、导航和页面布局在 UI 实施会话中确定。提供商能力与存储继续暂缓。

## 当前缺口

已实现 Window/Titlebar/Space 窗口层次、设置屏（织台菜单进入，在工作台左侧）、浮岛编织、shadcn 公共控件、lucide 图标、Motion 动效与单语文案；三个辅助面板已拆至 `SidePanel.tsx`。约定见 `docs/design-system.md`。设置的通用与模型分类为示意内容，About 已迁入设置。

提供商配置需要可访问、可扩展的设置界面承载。因此先补齐并验收本阶段 UI，再推进已确认的提供商配置与存储方案。模型 SDK、数据库迁移与凭据实现暂缓，不以缺少设置页为由建设另一套临时配置入口。

## 能力与界面的边界

- 设置界面组织页面与交互，不直接调用 provider SDK、读写数据库或解密凭据。
- 后续配置页消费提供商管理、凭据状态、连接测试等能力接口；接口不绑定某种设置容器或表单组件。
- 本阶段提供商业务未接入时，明确显示尚未接入；不提供伪保存、伪连接成功或无效的可操作按钮，不在 renderer/localStorage 另存一份提供商配置。
- 本阶段完成的是可用的应用导航与设置壳子。真实的“添加提供商 → 保存 → 重开 → 测试连接”由后续提供商阶段验收。

## 阶段完成标准

- [ ] 用户能从应用中找到并进入设置，切换已提供页面，再返回工作台；空工作区和已有任务均可操作。
- [ ] 设置页有稳定的导航与布局承载方式，后续添加提供商页面无需重做应用壳子。
- [ ] 页面状态与能力实际情况一致；公共控件、键盘、焦点与窄窗口交互经用户确认。
- [ ] 已发现的壳子交互缺口完成或另行明确立案；不将尚未验收的内容标为完成。
- [ ] agent 完成必要的类型检查和构建；GUI 由用户操作验收，不为视觉配置新增测试，不进行启动等待杀进程式冒烟。
