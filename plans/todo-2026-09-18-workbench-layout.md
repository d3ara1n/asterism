# 验证工作台自动布局与更新策略

> 立案 2026-09-18。正式应用已接入 React Flow 与新卡片初始空位策略；本计划继续验证完整自动布局、动态端点和更新策略，ELK 等布局引擎依赖尚未确定。

## 范围与候选

- 保留 @xyflow/react，节点和连线是业务对象与关系的视图投影。
- React Flow 核心不含自动布局算法。优先验证 ELK（elkjs）的端点与复杂关系布局，Dagre 作为简单布局的对照；尚未确定新增依赖。
- 布局引擎仅提供位置与路径计算。用户位置保留、触发布局的时机和卡片尺寸测量由工作台负责，不假定引擎自动满足交互约定。

## 验证场景

- 新增代理、资源与操作卡片后可获得可读布局，已由用户移动的卡片不被随意重排。
- 卡片展开、折叠和动态尺寸变化后，连线仍定位正确端点；折叠显示不丢失底层执行端点关系。
- 流式长消息局部更新，不按每个文本增量触发整图重排；按需加载与列表虚拟化不导致对象身份变化。
- Monaco 只在需要时挂载，关闭编辑视图不删除文件或操作对象。
- 历史与当前视图使用相同业务身份规则，布局变化不追加工作事件，也不修改授权。

## 完成条件

- 记录代表性卡片数量、尺寸与流式负载下的测量结果，由用户确认布局稳定性、端点定位和文本交互。
- 将布局引擎选择与最终策略落入 `docs/architecture.md`、`docs/workbench.md` 和 `docs/decisions.md`，不把整个画布状态作为业务真值持久化。
- 不满足需求时先说明具体限制，再确认替代方案；不因此擅自改换白板框架或产品交互范式。
