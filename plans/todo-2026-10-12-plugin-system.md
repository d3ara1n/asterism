## 已完成接入

按会话／事件／资源主干、可选模型分支、内置消费者迁移与管理验收的顺序推进：

- [x] SDK 架构方向收敛：工作台、会话、时间轴事件与资源为主干，模型能力为可选分支；宿主实现服务，插件提供贡献。具名、具型扩展；资源 creation／actions 内联；run 无跨调用状态，只执行一次补全及完整工具批次，外层 Agent 推动循环。context 唯一真值在时间轴，Agent 只持非 context 状态。纯会话事件、独立资源与自有 Agent 用例及类型反例纳入项目类型检查。
- [x] SDK 与宿主 adapter 主干：会话／对象快照、具型事件与当前数据同步提交、资源内联 creation／actions、工具贡献、提交后观察、prepare 与 closing 已接到宿主。公开接口不含 `SessionNode`、`FoldedObject` 或裸节点写入；未知记录保留，升级失败回退 unknown。数据与事件保存独立契约版本，创建数据采用 JSON 对象编码，具体限制见 [SDK 说明](../packages/sdk/README.md)。纯事件／独立资源／工具适配与只依赖 SDK 的源码包已通过自动测试。
- [x] 可选模型分支的单次执行：无状态 run 已接到公开 SDK，内置 Agent 自行推动多次调用，每次从时间轴重建消息；stream 用于命名等一次性补全。具型输出交付消费者保存，共识载荷 schema、模型来源、既有模型块与终态映射、对象活动／取消／关闭已实现；请求输入固定，消费者失败时批次仍收束，不增设独立环境、批次、记录或活动服务。
- [x] 内置消费者：目录、笔记、命名与 Agent 通过公开 SDK 接入；装配只接受 SDK 模块描述。原有模型／代理配置和注册机制保留，首页原子提交与幂等由宿主协调；普通动作按对象排队，Agent 再检查去重与执行冲突。core 的模型与对话投影消费具型记录，存储编码由宿主承担。renderer 对象接口提供创建、动作、事件读取、流订阅、配置目录与通用进度。链接接收使用静态声明；已捕获授权的批次保留资源快照与调用期间的数据提交能力。自动测试覆盖这些行为，GUI 仍由用户验收。
  - [x] 目录与笔记：共享正文契约与算法归 core；保留路径边界、冲突和 unknown 分类。笔记正文用 `NoteContent` v1 保存于 `session_data` 对象作用域，不追加正文历史。工作数据库格式 13，只支持当前格式；应用配置格式仍为 1。
  - [x] 命名与 Agent：命名使用具型首条用户输入和 stream；Agent 自推循环，选择及提交去重保存于对象数据，每次从时间轴重建消息。续接吸附后重新确认对象存在，失败同事务回滚。
- [x] 插件配置表单：承接 `plugin.config(schema, defaults)`，按已加载插件分组；常见字段使用公共控件，复杂 schema 保留完整 JSON 编辑。独立配置 IPC 提供读取／保存／恢复默认，原始 Zod schema 最终校验，沿用 `.atelier/config.json`。恢复默认先改草稿再保存，其他分组更新不覆盖未保存草稿。存储、SDK 与 IPC 契约已验证，GUI 待用户验收。
- [x] 流通道：main／preload 共用严格消息 schema，校验后按会话与对象交付 `Uint8Array`；无效信封不转发。自动测试覆盖入口拒绝、二进制视图与空帧、对象订阅隔离与取消。
- [x] 内置消费者自动验证：复用目录、笔记、Agent、SDK 与视图注册的现有测试，覆盖对象创建／动作、prepare、授权、当前数据、事件与记录投影；二进制流与插件配置有专项契约测试。类型检查、单元／契约测试和构建通过。

## 未来事项

以下能力已延后，按后续需求分别推进。

- [ ] npm 插件安装与升级：接通 npm 来源的添加、安装、精确版本锁定、完整性管理与升级流程；沿用同一包清单、装配与重启生效规则。当前仅有来源数据结构和包根解析，管理页只支持本地包目录。
- [ ] 卸载数据清理：移除插件时可选择同时删除其私有目录与凭据，会话对象与历史保留。当前移除只删除管理列表项。
- [ ] 后台跨插件命令：以普通领域库共享命令契约，补齐稳定身份、输入／输出 schema、类型推导与宿主路由校验，并与 prepare 的接受／替换／拒绝语义一致。当前只有前端对象动作与资源 prepare，使用原始 JSON。
- [ ] 跨插件共享包与实例：支持作者通过普通 npm 核心包或类型包共享契约；需要实例共享时，保证消费者访问同一运行时实例。依赖解析、打包多副本与实例获取规则待设计，不以类型一致推断实例一致；纯契约共享与取得插件实例分别处理。
- [ ] 插件间通信：按具名、具型原则设计通信契约、路由与生命周期；资源命令是现有入口，不预先限定未来全部协作方式。与共享类型、共享实例的需求一并评估，暂不实施。
- [ ] core 领域共识包（确定延后）：抽取 core 的资源、Agent 与时间轴事件契约，供相关插件显式依赖。纯事件插件解释已有事件也需要对应领域知识；独立会话命名须依赖首条用户输入契约，是明确消费者。领域包提供共识类型与接口，不包含 core 运行时实例，不加入所有插件必需的 SDK；具体功能扩展接口按真实需求继续补充。
- [ ] 模型请求缓存控制：按实际 provider 支持补充显式缓存策略、必要句柄与续接资料的输入／输出和失效规则；不得在 Agent 或 run 内维护第二份 context。当前只有缓存命中预期和用量诊断，不能视为完整缓存管理；与模型兼容层一并核验，暂不实施。
