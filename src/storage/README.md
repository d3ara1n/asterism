# 数据准备实现

生命周期与兼容承诺以[数据准备与迁移](../../docs/architecture.md#数据准备与迁移)为准，恢复交互见[启动屏](../../docs/workbench.md#启动屏)。

| 文件 | 职责 |
| --- | --- |
| `migrations.ts` | 连续迁移路径检查、JSON 内存转换与原子保存、SQLite 事务转换 |
| `files.ts` | 区分缺失与损坏的 JSON 读取、临时文件替换 |
| `preferences.ts` | 主进程偏好的格式声明和无版本基线转换 |
| `application.ts` | 宿主声明装配、插件存储发现、持久附件存在性校验 |
| `preparation.ts` | 整组备份、持久操作状态、失败重试、还原和保留旧数据后重新开始 |
| `../runtime/prepare-data.ts` | 独立准备进程入口 |
| `../main/data-preparation.ts` | 主进程等待准备进程退出、日志与取消 |

新增格式变化时，修改所属模块的当前版本及初始化结构，再追加迁移函数。SQLite 工作库声明位于 `runtime/storage.ts`，模型配置位于 `configuration/store.ts`，插件目录位于 `plugins/packages.ts`，主进程偏好位于本目录。键 n 表示 n → n+1；JSON 的平铺文档转换函数同时产生下一版 `version`，信封文档转换仅处理 `data`。SQL 步骤使用传入连接，事务及版本号提交由适配器承担。

已发布的迁移函数与旧格式定义保持固定，避免调用会随当前业务规则变化的转换 helper。新增转换用独立旧数据夹具验证保留的具体值与关系；通用路径、备份和恢复机制已集中测试，下游只覆盖自己的格式变化。正常初始化和当前格式读取不添加空迁移。

插件静态声明与示例见 [SDK 存储准备](../../docs/plugin-sdk.md#插件存储准备api-182)。新增宿主持久文件时同步加入 `preparation.ts` 的数据范围，使备份、还原及重新开始保持一致；可再生成的缓存独立于工作数据。
